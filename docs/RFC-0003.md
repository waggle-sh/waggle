# RFC-0003: Waggle Architecture & v0.1 Bootstrap Specification

- **Status:** Frozen for v0.1 Implementation, Amendments 1 and 2 applied (see Appendix A). Supersedes RFC-0001, RFC-0002.
- **Licenses:** `Apache-2.0` (Waggle CLI & `waggled` Engine) / `MIT-0` (Injected `.waggle/` Repository Templates)
- **Target Stack (v0.1):** Go (`waggle` CLI + `waggled` daemon), Git Refs (`CombBackend`), GitHub + GitHub Actions (Forge Adapter), Claude Code (`AgentRuntime` v0.1 implementation)

---

## 1. Core Thesis
Coding velocity is no longer the bottleneck in software engineering; human-scale review bandwidth, merge coordination, context bloat, and execution security are. **Waggle** is an open-source, git-native coordination, execution, and review framework that scales from **1 solo Keeper** to **500+ distributed Keepers** donating local compute and tokens.

---

## 2. The Unified Hive Taxonomy

### 2.1 Places, Binaries & Mechanisms
- **The Hive:** A repository initialized with Waggle (`.waggle/`, `.devcontainer/`, `WAGGLE.md`).
- **The Comb (`CombBackend`):** A single unified state codepath backed by Git refs (`refs/waggle/claims/ticket-<id>`). Works identically against a local `.git` repository (Scale = 1) or a remote Forge (Scale = 500+). `WORKPLAN.md` is a derived human/agent-readable view rendered from Comb refs by `waggled`, never a competing state store.
- **Cell:** An isolated worker execution sandbox: a `git worktree` run under a `CellRuntime` backend that gives the worker read-only (`ro`) access to the repository, read-write (`rw`) access only on the task's leased directories, zero host credentials, and network access only through a host egress proxy. The default backend is the OS sandbox (Seatbelt on macOS, bubblewrap on Linux); a Docker-compatible container backend, configured by `.waggle/control/devcontainer.json`, serves CI and stricter isolation. Each backend reports which of these targets it enforces on the current host, and `waggled` refuses to start a Cell whose backend cannot enforce all of them. *(Amended: A2)*
- **`waggle` (CLI):** The operator command-line interface (`waggle init`, `waggle status`, `waggle claim`, `waggle release`, `waggle gate`).
- **`waggled` (Daemon):** The background Go orchestration daemon managing the worker wait-loop, local UNIX domain socket mailbox (`.waggle/run.sock`), Cell provisioning, runtime context-cap hooks, and derived views.
- **Nectar & Quorum (v0.2):** Reputation earned from merged commits surviving 30 days on `main` without revert, powering Quadratic Voting ($\text{Weight} = \sqrt{\text{Nectar}}$) + Master Keeper veto.

## 3. Core Architecture & Security Invariants

### 3.1 Single Comb Codepath & The Lease TOCTOU Model
- **Unified Ref Storage:** All task claims and leases live behind `CombBackend` as one Git ref per ticket, `refs/waggle/claims/ticket-<n>`. The ref points to a **commit** whose tree holds exactly one entry, `lease.json` (mode `100644`), the JSON-encoded lease. A first claim is a root commit with no parent. A **renewal** (the same Keeper re-acquiring its own active claim) and a **takeover** (any Keeper acquiring an expired claim) write a child commit whose single parent is the previous claim commit, so while the ref exists `git log refs/waggle/claims/ticket-<n>` is the claim's audit chain. **Release deletes the ref**; only the owning Keeper may release, and a non-owner takes over an expired claim by claiming instead. After release the chain is unreachable and may be garbage collected: claim history is not durable past release in v0.1. Every write is an atomic Compare-And-Swap on the ref: in solo local mode `waggled` updates the local ref against the exact object ID it read; in distributed mode it first fetches the claim namespace from the configured remote (`origin`) and then pushes atomically with a force-with-lease guard, so the remote is authoritative and local claim refs are only a mirror. A lost race is reported as the ticket already being claimed. *(Amended: A1)*
- **Lease Record (v0.1):** `lease.json` carries `version`, `ticket_id` (canonical display form, below), `keeper_id`, `role`, `gate`, `directories`, `claimed_at` and `expires_at` (UTC, whole seconds). `version` is `2` for every claim written after the role rename; a `version` `1` claim predates it and is read with its role mapped (`scout` to `forager`, `forager` to `builder`, `guard` unchanged), never taken literally, and is never written again. `role` must be a claim role, `forager`, `builder` or `guard`; the `queen` and the `scout` never hold a claim. `gate` is `light` or `full`. `keeper_id` is 1 to 128 characters, starting with a letter or digit and continuing with letters, digits, `.`, `_`, `@`, `+` or `-`. `expires_at` defaults to `claimed_at` plus `leases.default_ttl_minutes` (120 by default) and must lie in the future at claim time; a claim whose `expires_at` has passed is inactive: it blocks nothing and anyone may take it over. *(Added: A1)*
- **Ticket ID Canonicalization:** A ticket ID is accepted as `T-<digits>` or `<digits>` matching `^(T-)?[0-9]{1,6}$` with a value of at least 1 and an uppercase `T-` only; anything else is rejected before any Git call, which also blocks ref-name injection. The **canonical display form** is `T-%03d` (`1`, `001`, `T-1` and `T-001` all display as `T-001`; `T-1234` stays `T-1234`); it matches the `T-<id>.md` brief names and the `T-<id>:` commit prefix that `waggle-gate.yml` checks, and the lease's `ticket_id` always stores it. The **canonical ref form** is `ticket-<n>` with the decimal integer and no zero padding (`T-001` is `refs/waggle/claims/ticket-1`), so leading zeros can never produce two refs for one ticket. Throughout this RFC, `<id>` in `ticket-<id>` means this unpadded integer `<n>`. A ref under `refs/waggle/claims/` whose suffix is not canonical `ticket-<n>` (for example `ticket-007`) is **malformed**: it is reported, never parsed or silently honored. *(Added: A1)*
- **Optimistic Lease Check (Documented TOCTOU):** Pushing `refs/waggle/claims/ticket-<id>` provides atomic Compare-And-Swap (CAS) per *ticket*, not per *directory path*. Two Keepers claiming different tickets (`ticket-42` and `ticket-43`) with overlapping directories can both pass the pre-push fetch check.
  - *Invariant:* Directory leases are **optimistic at claim time, authoritative at merge time**. `waggle-gate.yml` enforces strict lease verification before landing.
- **Claim-Time Tier 3 Rejection:** `CombBackend` refuses, at claim time and before any Git write, a lease in which any directory **equals**, **is contained by**, or **contains** a hardcoded Tier 3 path from section 3.3. Examples: `.github` contains `.github/workflows/`; the repository root (`.`, `./`, or anything that cleans to the root) contains `.gitlab-ci.yml`. A worker lease never includes any part of `.waggle/`: the `.waggle/hive/**` carve-out of section 3.3 lowers the merge tier of hive records but never makes them leasable, so `.waggle/hive/tasks` is refused like `.waggle/control`, and hive files change only through `waggle` commands or the Head Keeper. Tier 3 membership is compared **case-insensitively** at claim time, because macOS and Windows checkouts are case-insensitive (`.WAGGLE/` and `.GitHub/workflows` are rejected). This is a defense-in-depth check and does not replace merge-time enforcement: `waggle-gate.yml` remains authoritative, and Tier 3 changes still require Head Keeper approval under section 3.3. *(Added: A1)*
- **Other Claim-Time Validation (v0.1):** A lease names literal directories, never globs. Each entry is repo-relative (no leading `/`, no drive letter), never escapes with `..`, never lies under `.git` (any case), and uses only `[A-Za-z0-9._/-]` (no spaces, no non-ASCII), at most 1024 bytes per entry and 255 per path segment; no segment ends with `.` or starts with `-`, and no segment is a Windows reserved device name (`CON`, `PRN`, `AUX`, `NUL`, `COM0` to `COM9`, `LPT0` to `LPT9`, any case, before the first `.`) on any operating system. Entries are cleaned to slash form without a trailing slash, deduplicated and sorted; a lease needs at least one entry and at most `leases.max_directories_per_claim` (5 by default) distinct entries. A `light` gate is refused for any directory that equals, contains, or is contained by a Tier 2 minimum path of section 3.3. A directory that overlaps, on a path-segment boundary, a directory of another ticket's active claim is refused (`internal` overlaps `internal/comb`; `internal/comb` does not overlap `internal/combx`); overlap is compared exactly, and case-insensitive overlap is deferred. *(Added: A1)*
- **Reading Claims:** Every stored claim is re-validated with the current rules each time it is read (the per-claim directory count excepted, so a config change never turns an existing claim malformed), and callers only ever see canonical ticket IDs and normalized directories. A claim is **malformed** when its ref name is not canonical, the ref does not point to a commit, the tree has no `lease.json` blob, the JSON does not decode, the `version` is unsupported, the `role` is unknown, `ticket_id` does not match the ref, any field or directory fails the rules above, or `claimed_at` is after `expires_at`. A malformed claim on another ticket is skipped by the overlap check and reported alongside the valid leases; a malformed claim on the target ticket refuses both claim and release until it is cleared. `WORKPLAN.md`, the derived view of active claims, is rendered by a renderer that does not trust its input: it re-validates each lease it is given, any cell whose value fails its field check renders as the literal `(invalid)`, no part of the rejected value is echoed, and every cell is escaped, so the file never carries free text into steering context. *(Added: A1)*
- **Public OSS Permission Relay:** `CombBackend` supports **Direct Ref Mode** (push access) and **Forge Action Relay Mode** (untrusted contributors comment `/waggle claim`, triggering `waggle-gate.yml` to write the ref using the repo's native token). In v0.1 only Direct Ref Mode is implemented: a backend configured for relay mode refuses every claim operation rather than falling back to direct writes. *(Amended: A1)*

### 3.2 Two-Layer Lease Enforcement & Per-Task Gate Verification
1. **Cell Lease Enforcement:** The Cell's backend exposes the worktree **read-only (`ro`)** and grants **read-write (`rw`) access exclusively on the directories listed in the task's lease**. bubblewrap and the container backend do this with a `ro` bind of the worktree and `rw` bind mounts on the leased directories. Seatbelt has no mount namespace; it applies the same split as path-based write rules on the host paths and denies hard-link creation. The repository's `.git` directory is read-only in every backend, so `waggled` makes the task's commits on the host after checking the diff against the lease, and creates any leased directory that does not yet exist before the Cell starts. `git sparse-checkout` is an optional speed toggle, never a lock. *(Amended: A2)*
2. **Authoritative Per-Task CI Gate (`waggle-gate.yml`):** Even when multiple Light-gate tasks ride together in an integration lane (`int-<release>-<n>`) for a single consolidated `guard` review pass, **lease enforcement never collapses**. `waggle-gate.yml` inspects each task's commits (`T-<id>:`) against that specific task's `refs/waggle/claims/ticket-<id>` lease individually.

### 3.3 Semantic Risk Tiers & Protected Paths
- **Tier 0 (Trivial):** Comments, formatting, typo fixes in non-steering docs.
- **Tier 1 (Isolated / Light Gate):** Isolated changes `<150 lines` with unit tests that do not touch schemas, auth, shared modules, dependencies, or steering docs. Eligible for lane integration review.
- **Tier 2 (Logic & Steering Context / Full Gate):** Standard feature implementation within lease.
  - **Hardcoded Tier 2 Minimum:** `.waggle/hive/**` (the hive record: `tasks/`, `reviews/`, `media/`, `specs/`, `DECISIONS.md`, `ROADMAP.md`, `WORKPLAN.md`), root `CLAUDE.md` and root `AGENTS.md` are hardcoded at **Tier 2 minimum**, matched case-insensitively. Because agents read these files as steering context, an injected roadmap can misdirect Builders across the hive; they can never be classified as Tier 0/1 Light-gate tasks. Root `DECISIONS.md`, `ROADMAP.md`, `WORKPLAN.md`, `docs/specs/**` and `docs/tasks/**` left the list when the hive record moved under `.waggle/hive/`; Waggle no longer reads them. *(Amended: A1)*
- **Tier 3 (Control Plane & Security / Hardcoded Controller-Only):**
  - **Hardcoded Tier 3:** `.waggle/**` except the `.waggle/hive/**` carve-out above, `.github/workflows/**`, `.gitlab-ci.yml`, and `.devcontainer/**` are hardcoded as Tier 3 in the binary and CI gate. Matching is case-insensitive, and the carve-out matches exact case only, so `.waggle/HIVE/` is Tier 3; every new subfolder of `.waggle/` defaults to Tier 3. `WAGGLE.md` lives at `.waggle/control/WAGGLE.md` and is covered by `.waggle/**`; a root `WAGGLE.md` is no longer protected. They require explicit Head Keeper approval and cannot be downgraded via config. *(Amended: A1)*

### 3.4 `AgentRuntime` Interface & Configurable Context Caps
Token nudge and hard-stop limits are properties of the model and runtime, not constants in the Go binary. Waggle wraps CLI agents behind an `AgentRuntime` interface configured in `.waggle/config.yaml`:
```yaml
runtimes:
  default: claude-code
  adapters:
    claude-code:
      binary: claude
      nudge_tokens: 200000
      max_tokens: 300000
```

### 3.5 Host-Daemon Security & Network Egress
- **Zero Credentials in Cell:** The Cell holds no Git credentials, SSH keys, Forge PATs, or host `~/.config` mounts. The Cell environment is built from an allowlist, never by removing known secret names, and the Cell gets its own empty home directory. The agent's inference credential stays on the host; the egress proxy adds it to inference requests. A hive may opt into `cell.inference_credential: passthrough` (D-120), which places the agent's own login token in the Cell; the zero-credentials target is then reported as not enforced, the one exception to the refusal rule in 2.1. `waggled` runs on the host and communicates with the Cell over `.waggle/control/run.sock`. *(Amended: A2)*
- **Egress Lockdown:** Cell outbound network access is blocked by the backend (no network namespace route, or sandbox deny rules) except to a per-Cell host egress proxy run by `waggled`. The proxy admits only the LLM inference endpoint and allowlisted package registry hosts, by host name; it refuses IP literals and names that resolve to loopback, link-local or private addresses, and logs every request. Pre-built toolchains that fail closed on dependency changes remain the default for registries. Egress lockdown limits where data goes, not what the agent sends to its inference provider. *(Amended: A2)*
- **Escalation Safety:** `AskUserQuestion` cards of kind `publish`, `spend`, `delete`, `credentials`, `strategy`, or `policy` never auto-apply a default.

## 4. v0.1 MVP Scope (Hand-Built Bootstrap)

Every line of v0.1 is built manually to reach self-hosting as fast as possible:
1. **`waggle init` (Flags Only):** Scaffolds `.waggle/config.yaml`, `.waggle/roster.json` (`cli` profile), core role prompts (`queen`, `scout`, `forager`, `builder`, `guard`), `.devcontainer/`, `WAGGLE.md`, and `.github/workflows/waggle-gate.yml`.
2. **`CombBackend` (Unified Git Ref Path):** Per-ticket refs (`refs/waggle/claims/ticket-<id>`) working identically on local-only and GitHub repos, plus derived `WORKPLAN.md` generation.
3. **Cell Runner (`CellRuntime`):** One interface with three backends: Seatbelt (macOS) and bubblewrap (Linux) as the default OS sandbox, and a Docker-compatible container backend for CI and stricter isolation. Every backend provides `git worktree` provisioning, `ro` repository and `rw` lease access, a zero-credential environment, and egress lockdown through the host egress proxy. Each backend's probe reports, per target, whether it is enforced on this host (`waggle doctor` prints it), and no backend falls back to running unsandboxed. Built after `waggle dispatch` and the `run.sock` loop (D-014). *(Amended: A2)*
4. **`waggled` with `run.sock`:** Host daemon implementing the `queen` / worker wait-loop split.
5. **`AgentRuntime` Interface + Claude Code Adapter:** Reads configurable `nudge_tokens` and `max_tokens` from `.waggle/config.yaml`.
6. **`waggle-gate.yml` & `waggle gate`:** Enforces per-task lease diff checks (even across Light lanes), hardcoded Tier 2/Tier 3 path floors, and Public OSS Action Relay claims.
7. **`waggle status`:** Plain-text terminal output derived from Comb refs and `run.sock`.
