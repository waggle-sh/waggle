# RFC-0003: Waggle Architecture & v0.1 Bootstrap Specification

- **Status:** Frozen for v0.1 Implementation (Supersedes RFC-0001, RFC-0002)
- **Licenses:** `Apache-2.0` (Waggle CLI & `waggled` Engine) / `MIT-0` (Injected `.waggle/` Repository Templates)
- **Target Stack (v0.1):** Go (`waggle` CLI + `waggled` daemon), Git Refs (`CombBackend`), GitHub + GitHub Actions (Forge Adapter), Claude Code (`AgentRuntime` v0.1 implementation)

---

## 1. Core Thesis
Coding velocity is no longer the bottleneck in software engineering; human-scale review bandwidth, merge coordination, context bloat, and execution security are. **Waggle** is an open-source, git-native coordination, execution, and review framework that scales from **1 solo Keeper** to **500+ distributed Keepers** donating local compute and tokens.

---

## 2. The Unified Hive Taxonomy

### 2.1 Places, Binaries & Mechanisms
- **The Hive:** A repository initialized with Waggle (`.waggle/`, `.devcontainer/`, `WAGGLE.md`).
- **The Comb (`CombBackend`):** A single unified state codepath backed by Git refs (`refs/waggle/claims/ticket-<id>`). Works identically against a local `.git` repository (Scale = 1) or a remote Forge (Scale = 500+). `WORKPLAN.md` is a derived human/agent-readable view rendered from Comb refs by `waggled`, never a competing state store.
- **Cell:** An isolated worker execution sandbox (`git worktree` + `.devcontainer` with a `ro` root filesystem, `rw` bind mounts on leased paths, blocked network egress, and zero host credentials).
- **`waggle` (CLI):** The operator command-line interface (`waggle init`, `waggle status`, `waggle claim`, `waggle release`, `waggle gate`).
- **`waggled` (Daemon):** The background Go orchestration daemon managing the worker wait-loop, local UNIX domain socket mailbox (`.waggle/run.sock`), Cell provisioning, runtime context-cap hooks, and derived views.
- **Nectar & Quorum (v0.2):** Reputation earned from merged commits surviving 30 days on `main` without revert, powering Quadratic Voting ($\text{Weight} = \sqrt{\text{Nectar}}$) + Master Keeper veto.

### 2.2 The Roster (`.waggle/roster.json`)
The roster is data-driven in `.waggle/roster.json`. v0.1 ships with the `cli` profile and core build roles; specialized roles (`weaver`, `studio`, `assembly`, `nurse`) are deferred to v0.2 to be built by Waggle itself.

## 3. Core Architecture & Security Invariants

### 3.1 Single Comb Codepath & The Lease TOCTOU Model
- **Unified Ref Storage:** All task claims and leases are stored as JSON blobs at `refs/waggle/claims/ticket-<id>` behind `CombBackend`. In solo local mode, `waggled` reads/writes local refs directly; in distributed mode, it syncs refs with the configured remote (`origin`).
- **Optimistic Lease Check (Documented TOCTOU):** Pushing `refs/waggle/claims/ticket-<id>` provides atomic Compare-And-Swap (CAS) per *ticket*, not per *directory path*. Two Keepers claiming different tickets (`ticket-42` and `ticket-43`) with overlapping directories can both pass the pre-push fetch check.
  - *Invariant:* Directory leases are **optimistic at claim time, authoritative at merge time**. `waggle-gate.yml` enforces strict lease verification before landing.
- **Public OSS Permission Relay:** `CombBackend` supports **Direct Ref Mode** (push access) and **Forge Action Relay Mode** (untrusted contributors comment `/waggle claim`, triggering `waggle-gate.yml` to write the ref using the repo's native token).

### 3.2 Two-Layer Lease Enforcement & Per-Task Gate Verification
1. **Cell VFS Mount Enforcement:** The Cell container mounts the repository working tree **read-only (`ro`)**, overlaying **read-write (`rw`) bind mounts exclusively on the directories listed in the task's lease**. `git sparse-checkout` is an optional speed toggle, never a lock.
2. **Authoritative Per-Task CI Gate (`waggle-gate.yml`):** Even when multiple Light-gate tasks ride together in an integration lane (`int-<release>-<n>`) for a single consolidated `guard` review pass, **lease enforcement never collapses**. `waggle-gate.yml` inspects each task's commits (`T-<id>:`) against that specific task's `refs/waggle/claims/ticket-<id>` lease individually.

### 3.3 Semantic Risk Tiers & Protected Paths
- **Tier 0 (Trivial):** Comments, formatting, typo fixes in non-steering docs.
- **Tier 1 (Isolated / Light Gate):** Isolated changes `<150 lines` with unit tests that do not touch schemas, auth, shared modules, dependencies, or steering docs. Eligible for lane integration review.
- **Tier 2 (Logic & Steering Context / Full Gate):** Standard feature implementation within lease.
  - **Hardcoded Tier 2 Minimum:** `DECISIONS.md`, `ROADMAP.md`, `WORKPLAN.md`, and `docs/specs/**` are hardcoded at **Tier 2 minimum**. Because agents read these files as steering context, an injected roadmap can misdirect Builders across the hive; they can never be classified as Tier 0/1 Light-gate tasks.
- **Tier 3 (Control Plane & Security / Hardcoded Controller-Only):**
  - **Hardcoded Tier 3:** `.waggle/**`, `WAGGLE.md`, `.devcontainer/**`, `.github/workflows/**`, and `.gitlab-ci.yml` are hardcoded as Tier 3 in the binary and CI gate. They require explicit Master Keeper approval and cannot be downgraded via config.

### 3.4 `AgentRuntime` Interface & Configurable Context Caps
Token nudge and hard-stop limits are properties of the model and runtime, not constants in the Go binary. Waggle wraps CLI agents behind an `AgentRuntime` interface configured in `.waggle/config.yaml`:
```yaml
runtimes:
  default: claude-code
  adapters:
    claude-code:
      binary: claude
      nudge_tokens: 200000
      max_tokens: 300000
```

### 3.5 Host-Daemon Security & Network Egress
- **Zero Credentials in Cell:** The Cell holds no Git credentials, SSH keys, Forge PATs, or host `~/.config` mounts. `waggled` runs on the host and communicates with the Cell over `.waggle/run.sock`.
- **Egress Lockdown:** Cell outbound network access is blocked except for the LLM inference endpoint and allowlisted package registry proxies (or pre-built toolchains that fail closed on dependency changes).
- **Escalation Safety:** `AskUserQuestion` cards of kind `publish`, `spend`, `delete`, `credentials`, `strategy`, or `policy` never auto-apply a default.

## 4. v0.1 MVP Scope (Hand-Built Bootstrap)

Every line of v0.1 is built manually to reach self-hosting as fast as possible:
1. **`waggle init` (Flags Only):** Scaffolds `.waggle/config.yaml`, `.waggle/roster.json` (`cli` profile), core role prompts (`queen`, `scout`, `forager`, `builder`, `guard`), `.devcontainer/`, `WAGGLE.md`, and `.github/workflows/waggle-gate.yml`.
2. **`CombBackend` (Unified Git Ref Path):** Per-ticket refs (`refs/waggle/claims/ticket-<id>`) working identically on local-only and GitHub repos, plus derived `WORKPLAN.md` generation.
3. **Cell Runner:** `git worktree` provisioning + `ro` root / `rw` lease container mounts + zero-credential environment + egress lockdown.
4. **`waggled` with `run.sock`:** Host daemon implementing the `queen` / worker wait-loop split.
5. **`AgentRuntime` Interface + Claude Code Adapter:** Reads configurable `nudge_tokens` and `max_tokens` from `.waggle/config.yaml`.
6. **`waggle-gate.yml` & `waggle gate`:** Enforces per-task lease diff checks (even across Light lanes), hardcoded Tier 2/Tier 3 path floors, and Public OSS Action Relay claims.
7. **`waggle status`:** Plain-text terminal output derived from Comb refs and `run.sock`.
