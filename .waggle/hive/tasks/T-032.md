## 1. Goal

The gate's value is a lease written by someone other than the agent (note section 6, first risk). Today only `waggle dispatch` writes a claim, and only `waggle dispatch release` gives one back, under hive assumptions (a `t-<nnn>` branch, `.waggle/local.yaml`, `.waggle/worktrees/`). This ticket adds two top-level verbs that a human or any orchestrator can call, with JSON output a program can parse:

1. `waggle claim T-<id> --dirs a,b --gate light|full [--ttl <duration>] [--owner <id>] [--base <rev>] [--repo <dir>] [--json]`
2. `waggle release T-<id> [--branch <name>] [--unmerged] [--owner <id>] [--repo <dir>] [--json]`

It also finishes what T-031 section 4 deferred to G2: repo protected paths (`gate.protected_paths`) apply when a lease is written (`AcquireLease`, and dispatch before it claims) and in dispatch's post-run check, read from the base revision and raise-only, as the gate reads them.

## 2. Design (recommended options)

### 2.1 One code path for claims and releases

The verbs are thin CLI wrappers in a new `cmd/waggle/claim.go`. The logic lives in `internal/dispatch`, next to the code it reuses (`AcquireClaim`, `claimError`, `Release`, `branchMerged`, `ResolveBase`, `blobAt`, `printable`). Nothing is copied.

- **`dispatch.ClaimTask(ctx, ClaimTaskRequest) (ClaimTaskResult, error)`** in `task.go`. It builds a `Request{Role: "builder", ...}`, runs `Request.Validate` (ticket, directories, gate; it refuses only the repo root) and then `refuseDirs` (the hardcoded Tier 3 list and `.waggle/`, before any fetch, as `Run` does), loads the working-tree config for Comb options as dispatch does, reads the base policy (2.3), refuses a covered directory (2.3), builds the `GitBackend` with `Options.Protected` set and `DefaultTTL` set to `--ttl`, and calls the existing `AcquireClaim` unchanged. Passing the TTL through `DefaultTTL` keeps `AcquireClaim`'s signature and its tests as they are. Claims written this way carry role `builder`, so a later `waggle dispatch T-<id> --role builder` by the same owner renews the claim, and the dispatch guard reads it like any builder claim. The role is not a flag and is not printed. `ClaimTaskRequest` fields: `RepoDir`, `GitBin`, `Ticket`, `Dirs`, `Gate`, `TTL time.Duration` (zero: config default), `Owner`, `Base`, `Now func() time.Time` (nil: `time.Now`; passed to the backend's `Options.Now` and to `AcquireClaim`), and `Backend ClaimBackend` (nil: built from config). With an injected backend, `ClaimTask` still runs its own `CoversDir` refusal (2.3), so tests see the same refusals.
- **Working-tree config.** Both verbs load `.waggle/control/config.yaml` from the working tree for Comb options (`config.Load`, as `Release` does today) and exit 3 without it. G4's `waggle init --gate-only` writes that file.
- **`dispatch.ReleaseTask(ctx, ReleaseRequest) (ReleaseTaskResult, error)`** in `release.go`: today's `Release` body, returning a result instead of printing. `Release(ctx, r, out) error` stays, as a wrapper that prints exactly the lines it prints today, so `waggle dispatch release` output and `release_test.go` stay unchanged (Q-T032-2). `ReleaseRequest` gains `Owner string`; empty means `keeper_id` from `.waggle/local.yaml`, as today.
- **`waggle dispatch release`** stays, routed through the same `Release` (Q-T032-2). Its usage line notes that `waggle release` is the same verb with JSON output.
- No `waggle claim` or `waggle release` code path writes or deletes a ref itself. Every write is `AcquireLease`, every delete is `ReleaseLease`, both compare-and-swap as today.

### 2.2 The verbs

**`waggle claim`**

- `<task>`: any `comb.ParseTicketID` form (`T-32`, `32`, `T-032`).
- `--dirs a,b`: one comma-separated value, required. Commas cannot appear in a directory (the allow-list is `[A-Za-z0-9._/-]`), so the split is exact. An empty element (`a,,b`, a trailing comma) is a usage error. Normalization and limits are `Request.Validate`'s and the Comb's.
- `--gate light|full`: required.
- `--ttl <duration>`: Go duration syntax; default `leases.default_ttl_minutes`. It must be a whole number of minutes from `config.MinTTLMinutes` to `config.MaxTTLMinutes` (1 minute to 7 days); anything else is a usage error before any git call.
- `--owner <id>`: the claim's owner (Q-T032-1). Default `keeper_id` from `.waggle/local.yaml`. Without `--owner`, any `LoadKeeperID` error (file missing, key missing or empty, the placeholder value with a remote set) exits 2 with its own text followed by `; or pass --owner <id>`, so the placeholder case is not reported as a missing file. The Comb validates the value (`keeperIDPattern`).
- `--base <rev>`: the revision whose config supplies protected paths (2.3). Default `<forge.remote>/main` after a fetch, else local `main` (`ResolveBase`). Same refusal rules as dispatch's `--base` (no leading `-`, no whitespace or NUL).
- Outcome: `claimed`, `renewed` (same owner, active claim; the claim may change directories, gate or expiry, and the change is reported as a note) or `taken_over` (expired claim of any owner), from `AcquireClaim`'s verb. An active claim held by another owner is refused (exit 4). No lock is taken: the claim write is a compare-and-swap and needs none.

**`waggle release`**

- Same checks and order as T-030 section 2 (merged check, owner check through `ReleaseLease`, worktree refusals), with three widenings for repos that are not this hive:
  1. **Owner:** `--owner` as for `claim`.
  2. **Branch forms:** `--branch` accepts `t-<nnn>[-suffix]` (as `checkBranch`) and `waggle/T-<nnn>[-suffix]` (the two forms the gate binds, D-237), each for this task's number only; the new form's check lives in `release.go`, so `checkBranch` and dispatch's `Request` rules do not change. With no `--branch`, the merged check uses `t-<nnn>` when that branch exists (remote or local, the T-030 lookup), and only otherwise `waggle/T-<nnn>`; only that one head is checked against T-030's rule (a second or later parent of a merge on main's first-parent history). So a `waggle/T-<nnn>` branch someone pushes at another PR's merged head cannot stand in for an unmerged `t-<nnn>`. Neither present, or the chosen head not merged: refused without `--unmerged`, as today. The suffix set stays `[A-Za-z0-9._-]`, stricter than the gate's binding pattern; a task whose branch has another suffix passes `--unmerged`.
  3. **No hive directories:** when `.waggle/worktrees/` does not exist (`os.Lstat` reports it absent), `release` takes no `dispatch.lock`, runs no worktree check and creates nothing (Q-T032-5). Any other state, including a symlink or a file at that path, goes through `lockRepo` exactly as today, which refuses what it refuses today.
- Squash and rebase merges still count as unmerged (Q-T032-3).
- `no claim` is exit 0 with outcome `no_claim`, as today.

**Exit codes** (the dispatch set, `request.go`): 0 done (including `no_claim`); 1 interrupted; 2 usage, before any git write; 3 environment (git, config, a held `dispatch.lock`, a base config that is invalid); 4 refused (overlap, held by another owner, protected path, gate too low, malformed claim, not owner, concurrent update, not merged, a worktree or marker of the task present).

**Output.** Without `--json`: one line on stdout (`claimed T-032 for <owner> until <RFC 3339 UTC>: <dirs> (gate full, claim <12 hex>)`; `release` prints the T-030 line), notes as `note: ...` lines on stdout, warnings and errors on stderr prefixed `waggle claim: ` or `waggle release: `. Every value that came from a ref, the remote or config goes through `printable`. With `--json`: stdout carries exactly one JSON object followed by one newline, for success and for every failure after flag parsing, and nothing else; stderr carries only human text (lock warnings, read-back warnings are also in the object). A flag-parse failure (unknown flag, missing value) prints usage on stderr, nothing on stdout, exit 2, because `--json` is not known yet.

**JSON schema, version 1.** Field names are fixed; new fields may be added later, existing ones never change meaning. Times are RFC 3339 UTC. Encoded with `encoding/json` (control bytes escaped).

```json
{"version":1,"command":"claim","ok":true,"task":"T-032","outcome":"claimed",
 "claim":{"task":"T-032","owner":"alice","gate":"full","directories":["cmd/waggle","internal/comb"],
          "claimed_at":"2026-10-23T18:00:00Z","expires_at":"2026-10-23T20:00:00Z",
          "ref":"refs/waggle/claims/ticket-32","oid":"<40 or 64 hex, empty if the read-back failed>"},
 "notes":[],"warnings":[]}

{"version":1,"command":"release","ok":true,"task":"T-032","outcome":"released",
 "oid":"<claim commit released, empty for no_claim>","merged":true,"branch":"t-032","warnings":[]}

{"version":1,"command":"claim","ok":false,"task":"T-032",
 "error":{"code":"overlap","exit":4,"message":"<text>"}}
```

- `outcome`: `claimed`, `renewed`, `taken_over` (claim); `released`, `no_claim` (release). `merged` is false with `--unmerged`; `branch` is the head that passed the merged check, or `""`.
- `task` is the canonical ID, or `""` when the argument did not parse.
- `error.code`, first match in this order: `invalid_task` (`comb.ErrInvalidTicketID`); `usage` (any other error whose exit code is 2); `protected_path` (`comb.ErrTier3Path`, which `ErrProtectedPath` and `ErrWaggleDir` also wrap, so a hardcoded entry such as `vendor` maps here too); `gate_too_low` (`ErrGateTooLow`); `invalid_lease` (`ErrInvalidLease`); `overlap` (`ErrLeaseOverlap`); `already_claimed` (`ErrAlreadyClaimed`); `malformed_claim` (`ErrMalformedClaim`); `not_owner` (`ErrNotOwner`); `concurrent_update` (`ErrConcurrentUpdate`); `not_merged` and `task_busy` (two unexported sentinels in `release.go`, wrapped with `%w` where `Release` makes those errors today); `interrupted` (exit code 1); `environment` (anything else, exit 3, a held `dispatch.lock` included). There is no `locked` code: the held-lock errors are made in `takeLock` (`worktree.go`) and share `lockRepo`'s return path with other environment errors, and telling them apart would widen the lease. `error.exit` always equals the process exit code (`dispatch.ExitCode`). `error.message` is the error text; JSON encoding makes it safe, and existing Comb wording is not reworded here (section 4).

### 2.3 Repo protected paths at lease time and in the post-run check

- **Read from the base revision only.** `dispatch.basePolicy(ctx, g, baseOID) (comb.TierPolicy, error)` reads `.waggle/control/config.yaml` at `baseOID` through `blobAt` with `config.MaxFileSize` as the cap, then `config.Parse`, and returns `TierPolicy{ExtraTier3: cfg.Gate.ProtectedPaths}`. `blobAt` already refuses a symlink, a tree, a submodule and an oversized blob. Missing file: empty policy. Present but not a regular file, over the cap, or failing `Parse`: exit 3 (fail closed, as D-239 rules for the gate). Never the working tree, the head branch or a merge-base. Dispatch's base is the run's `baseOID`; `waggle claim`'s is `--base` or `ResolveBase`'s default. `basePolicy` lives in `task.go`.
- **Default base, fully qualified.** `ResolveBase` today runs `rev-parse --verify <remote>/main^{commit}` (or `main^{commit}`) after a plain `fetch`, which also fetches tags; by gitrevisions order `refs/tags/<name>` beats `refs/remotes/<name>` and `refs/heads/<name>`, so a pushed tag named `origin/main` (or a local tag `main`) picks the base (the queen reproduced this on 2026-10-23). The default becomes `refs/remotes/<remote>/main^{commit}` in remote mode and `refs/heads/main^{commit}` in a local-only repo, with no fallback across modes. An explicit `--base` is resolved as given (the caller is trusted, section 5). The change is in `ResolveBase` only, so `Run`, `ReadInputs`, `basePolicy` and `branchMerged` all get it. The working-tree config still supplies Comb options (remote, TTL, directory cap) as it does today; only protected paths come from base, because only they are policy.
- **Matching** is T-031's: case-insensitive, equal or string prefix. A lease directory is covered when it equals, sits inside or contains an entry, the same relation `isTier3Dir` uses for the hardcoded list (`touchesPrefixes`). New exported method `TierPolicy.CoversDir(dir string) bool` in `changecheck.go`, used by both the Comb and dispatch.
- **Raise-only.** The policy only adds refusals and violations. It never removes a hardcoded refusal, never lowers a tier, never changes the Tier 2 light-gate rule.
- **Comb, at write time only.** `comb.Options` gains `Protected TierPolicy`. `prepareLease` (the `AcquireLease` path, so first claims, renewals and takeovers) refuses a covered directory with an error wrapping both a new `comb.ErrProtectedPath` and `ErrTier3Path`, so `claimError` maps it to exit 4 with no change. Stored claims are not re-validated against the policy when read (`loadClaims`, `ReadClaim`, `ListActiveLeases` unchanged; Q-T032-4): a config change must never turn a live claim malformed, because the overlap check skips malformed claims and would then let another task lease the same directories. The gate still fails the PR at merge. `CheckChanges` and `CheckChangesPolicy` keep their signatures and results.
- **Dispatch, before the claim.** In `Run`, a new step right after `ResolveBase` reads `basePolicy` and, for a builder or forager, refuses a covered directory with exit 4 (`directory "<d>" is a protected path listed in .waggle/control/config.yaml; leases never cover it`). This keeps the refusal when a test injects `d.Backend`. When `Run` builds the backend itself it sets `opts.Protected` too. `refuseDirs` (hardcoded, before any fetch) is unchanged.
- **Dispatch, after the run.** `checker` gains `policy comb.TierPolicy`, set from the same read, and `run` calls `comb.CheckChangesPolicy(c.lease, changes, c.policy)` instead of `CheckChanges`. A repo-listed hit is a `tier3` violation with T-031's message, so `outcome` treats it as any Tier 3 hit (`lease_violation`, exit 1). With an empty policy the results equal today's.

## 3. Questions for the Head Keeper

- **Q-T032-1: who owns a claim written by `waggle claim`?** (a) `--owner <id>`, falling back to `keeper_id` in `.waggle/local.yaml`. (b) `keeper_id` only. (c) Detect it from git config or the forge login. **Recommended: (a).** An orchestrator running several agents needs a stable owner name per run without a local file; the hive keeps its habit through the fallback. The owner is a label, not authentication: anyone who can push claim refs can write any owner today (note in section 5). (b) blocks orchestrators in repos without `local.yaml`. (c) adds a forge call to a verb that should run offline. Cost: a few lines; reversible by dropping the flag before v0.1.
- **Q-T032-2: what happens to `waggle dispatch release`?** (a) Keep it as an alias of `waggle release` through the same function, with today's text output, and drop it in G4. (b) Remove it now. (c) Keep two implementations. **Recommended: (a).** The queen's habits and T-030's tests use it; an alias costs about 5 lines. (b) breaks the queen's routine mid-sequence for no gain. (c) is the duplication this ticket exists to avoid. Reversible.
- **Q-T032-3: does `release` count a squash or rebase merge as merged?** (a) No, as T-030 rules (D-222); such users pass `--unmerged`; revisit with the forge's PR state in G3 or G4. (b) Accept a branch whose changes are all on main (`git cherry` or patch IDs). (c) Read the PR's merged state through `internal/forge` now. **Recommended: (a).** (b) has false positives (a branch whose patch also landed by another path) and is new Tier 3 logic on a delete path. (c) needs `internal/forge/`, which is G3's lease. Cost of (a): squash-merge users need one extra flag, which the G5 recipes document. Reversible.
- **Q-T032-4: when the base config gains a protected path, what happens to claims that already cover it?** (a) Nothing at read time: the rule applies when a lease is written (claim, renewal, takeover), the post-run check flags commits, and the gate fails the PR. (b) Re-validate stored claims against the policy on every read, so they read as malformed. **Recommended: (a).** (b) makes a config edit silently drop live claims out of the overlap check, which loosens protection, and requires every reader to fetch base config. Cost of (a): a live claim keeps its lease until it expires or renews. Reversible.
- **Q-T032-5: what does `release` do in a repo with no `.waggle/worktrees/`?** (a) Take no lock, check no worktree, create nothing. (b) Create the directory and take `dispatch.lock` as today. **Recommended: (a).** A gate-only repo (G4) has no dispatch runs to wait for, and (b) leaves an untracked directory in a user's repo. Cost: a release racing a dispatch run that starts at the same moment in a repo that never ran dispatch; the claim compare-and-swap still refuses the loser (note in section 5). Reversible.

## 5. Threat model (D-203)

Attacker: an agent working under a lease, or any contributor who can push branches. It controls its commits, its head branch and branch names on the remote, and the text of claim refs other parties wrote only through the Comb's validation. It cannot write claim refs directly, push to the base branch, change the base revision's config, or run `waggle claim` or `waggle release` itself; the human or orchestrator running those verbs is the lease authority and is trusted with its own flags.

Must-fix: protected paths read from anywhere but the base revision (working tree, head, merge-base) in dispatch or `claim`; a default base that a tag, or any ref other than `refs/remotes/<remote>/main` or `refs/heads/main`, can select; any way the policy lowers a tier or removes a hardcoded refusal; a covered directory leased through `AcquireLease`, `ClaimTask` or `Run` (with a built or an injected backend); a stored claim made malformed or dropped from the overlap check by a policy change; dispatch's post-run check not applying the base policy, or its results changing when the policy is empty; a release of a claim the caller does not own, of another task's claim, or of an unmerged task without `--unmerged`; a merged check that a pushed branch name can satisfy without a real second-parent merge on main (the `waggle/T-<nnn>` form included); any ref write or delete not through `AcquireLease` or `ReleaseLease`; with `--json`, stdout holding anything but one JSON object, or `error.exit` differing from the process exit; a value from a ref, the remote or config printed raw in text mode; an unbounded read (a config blob past `config.MaxFileSize`); a config symlink, tree or submodule read as config; a panic on hostile input; any change to `CheckChanges`'s or `CheckChangesPolicy`'s signatures or results, or to files outside the lease rule.

Note, not must-fix: anyone who can push claim refs can write any owner (owner is a label, Q-T032-1); the claim-time overlap check's existing race across tasks (the gate is authoritative); a `waggle claim` renewal by the owner changing directories while a dispatch run of that task is live (the claimer's call; dispatch checks against the lease it acquired); a `release` racing a dispatch start in a repo with no `.waggle/worktrees/` (Q-T032-5; the compare-and-swap refuses the loser); a flag value the trusted claimer passes that weakens only its own lease-time check (for example `--base` at a revision without the entry, or an unqualified explicit `--base` that a tag shadows; the gate reads the PR base anyway).

Guard prompt sentence (repeat verbatim): "Threat bar (D-203): a finding whose attacker needs to write claim refs directly, push to the base branch, change the base revision's config, or run waggle claim or waggle release with flags of its choosing is a note, not a must-fix; must-fix is for what an agent or contributor can trigger through its commits, its branches, branch names on the remote, or claim refs as the Comb validates them, and for any claim write or delete that bypasses AcquireLease or ReleaseLease."

D-193: nothing in this ticket sends a kill signal, calls `sweep()` or reaps a process. The release path reaches `takeLock`, whose `processAlive` sends signal 0 to the pid in an existing lock file (`worktree.go`); that delivers nothing, and AC7's held-lock test writes `os.Getpid()` into the lock, as `release_test.go` does today, so no test probes a foreign pid. The `Run` edits are two steps before the session starts and one call in the post-run check. New tests are data tests (`TierPolicy.CoversDir`, `prepareLease`, error-code mapping, JSON encoding) and git-only fixture tests through `ClaimTask`, `ReleaseTask` and `basePolicy`; no new test calls `Run`, `sweep()` or sends a signal.
