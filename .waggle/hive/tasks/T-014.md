## 1. Goal

Make `waggle-gate.yml` authoritative, as RFC-0003 section 3.1 promises. Today it prints warnings and loops over commits with a placeholder. After this ticket:

1. Every `T-<id>:` commit in a PR may touch only paths inside the directories of `refs/waggle/claims/ticket-<n>`.
2. Tier floors fail instead of warn: a Tier 3 path fails the check; a Tier 2 path under a `light` claim fails the check.
3. Tier matching is case-insensitive, closing the `GO.MOD` and `waggle.md` gaps (Q-T008-3).
4. The checker is built from the base revision, runs with `contents: read`, and folds T-007's decisions check in as one subcommand of a single `waggle gate verify`.

Go 1.23, module `github.com/waggle-sh/waggle`, **standard library only**. Do not touch `go.mod`.

## 4. Phase B: `waggle gate verify` (target under 350 non-test lines)

### 4.1 CLI

```
waggle gate verify  --base <rev> --head <rev> [--repo <dir>]
waggle gate leases  --base <rev> --head <rev> [--repo <dir>]
waggle gate tiers   --base <rev> --head <rev> [--repo <dir>]
waggle gate decisions ...   (T-007, unchanged)
```

- `verify` runs `leases`, `tiers`, then `decisions`, all against the same merge-base and head, and reports every failure (it does not stop at the first). Exit code is the highest of the three under the order `0 < 1 < 3`; usage errors are `2` before anything runs.
- Same flag validation, revision resolution, merge-base rule, exit codes, `GITHUB_ACTIONS` annotation switch, single git helper and read-only plumbing as T-007 sections 5, 6, 6.1, 6.2. No override, skip, or allow flag.
- Annotations: `::error file=<path>::<reason>`. Encode both the path and the reason per GitHub's workflow-command rules (`%` to `%25`, `\r` to `%0D`, `\n` to `%0A`; in the `file=` property also `:` to `%3A` and `,` to `%2C`). A path is attacker-chosen text; it must never start a new workflow command.

### 4.2 Commits in scope

`git rev-list --reverse --parents <mb>..<head>`. Limits: more than 500 commits, or more than 5,000 changed paths in one commit, fails (exit 1, "PR too large for the gate; split it").

Classify each commit by subject (`git log -1 --format=%s`):

| Class | Rule | Result |
| :--- | :--- | :--- |
| Merge commit (more than one parent) | any | **fail**: "merge commit in PR; rebase onto main". Evil merges can hide edits outside any lease. |
| Ticket | subject matches `^T-[0-9]{3,6}: ` and `comb.ParseTicketID` accepts it | checked per 4.3 |
| Head Keeper | subject starts with `Head Keeper: ` | **fail** in `leases` with hint "Head Keeper commit: merge with a Head Keeper bypass" (section 6) |
| Anything else | | **fail**: "commit has no T-<id>: prefix" |

A subject is attacker-chosen text. Only the parsed ticket number is used; never echo more than the first 72 bytes of a subject, encoded per 4.1.

### 4.3 Per ticket commit (`leases` and `tiers`)

For commit `c` with parent `p`: `git diff-tree -r -z --no-renames --raw <p> <c>` (raw format gives old and new modes). Every path counts, including deletions and both sides of a rename.

`leases`:
1. `ReadClaim(ticket)`. `ErrNotFound`: fail, "no claim for T-<id>; claims must stay until merge". `ErrMalformedClaim`: fail with the reason.
2. An expired claim is accepted with a `::warning` (Q-T014-2). The claim's current directories are authoritative, including after a takeover.
3. Each path must be inside a claim directory: equal to `d` or prefixed by `d + "/"`, **exact case**. A path that matches only case-insensitively fails ("case differs from lease"): on a case-sensitive checkout it is a new directory outside the lease.
4. A new mode `120000` (symlink) or `160000` (submodule) fails: either can point a later build step outside the lease.

`tiers`:
5. `comb.RequiredMinTier(path)` (case-insensitive since T-011) is `Tier3ControlPlane` (T-011's name for `Tier3ControlAuth`): fail, "Tier 3 path; needs Head Keeper commit and bypass".
6. `Tier2Logic` while the claim's gate is `light`: fail, "Tier 2 path under a light claim".
7. Non-ticket commits are not exempt from `tiers`: a Head Keeper commit touching Tier 3 fails both checks. One failure per path per check is enough; do not repeat it per commit.

### 4.4 Case collisions (`tiers`)

`git ls-tree -r -z --name-only <head>`: if two paths are equal under `strings.EqualFold` but differ in bytes, fail naming both. Generalizes T-007's `DECISIONS.md` rule to the whole tree. Paths over 4,096 bytes fail.

## 6. How Tier 3 changes merge

The gate cannot tell who wrote a commit: author, committer and subject are all forgeable. So a PR that touches a Tier 3 path, or carries a `Head Keeper:` commit, always fails `verify`. The Head Keeper merges it through the branch ruleset's bypass after reviewing it. That is the "explicit Head Keeper approval" RFC-0003 section 3.3 requires, enforced by GitHub permissions rather than by text in a commit. Consequence: T-007, T-008, T-012 phase B, T-014 and T-015 each merge by bypass. See Q-T014-1 for the approval-aware alternative.

### 9.1 Follow-up: bot-signed claims (D-068)

D-068 implements D-015 with git's built-in SSH commit signing. It replaces any plan to rely on GitHub's verified-commit badge: no API call, no forge-specific data, and the same check runs locally and in CI. The follow-up ticket adds it to `leases`; this ticket only keeps room for it:

1. **Trust root from base.** The allowed-signers file lives in `.waggle/control/` (Tier 3; filename set by the follow-up). The check reads it from the merge-base with `git cat-file blob`, writes it to a temp file, and never reads it from head or the working tree: a PR could otherwise add its own key. Same rule as building the checker from `BASE_SHA` (section 7).
2. **What is verified.** For each claim `leases` reads, every commit on the claim chain (`comb.ClaimOID`, then first parents back to the root claim commit) passes `git -c gpg.ssh.allowedSignersFile=<tmp> verify-commit <oid>`. Any failure fails `leases` with "claim commit not signed by an allowed signer". The force-release audit chain (T-005) is verified on its first parents only, by the same function.
3. **When.** Only in team mode, switched on by a config key the follow-up adds. Solo and direct-mode hives write unsigned claims and are unaffected.
4. **Runner needs.** git 2.34 or later and `ssh-keygen`; both are on GitHub-hosted Ubuntu runners. No secret is needed to verify, so the job keeps `contents: read`.
5. **Keep for it now.** `leases` reads each claim in exactly one function, so the follow-up adds one call there. T-002's `buildCommit` and T-005's audit-commit builder are the signing seams on the write side.

## 11. Open Questions for the Keeper

- **Q-T014-1 (policy): Tier 3 PRs always fail the gate and merge by Head Keeper bypass.** Recommended for v0.1: yes (section 6). It is the only rule commit text cannot forge. Cost: every control-plane PR shows a red check and needs a bypass merge, and the ruleset must list the Head Keeper as the only bypass actor (T-015 setup). Alternative later: the gate passes Tier 3 paths when the PR has an approval from a login listed in `.waggle/control/` config, read from the base revision via the GitHub API. Needs `pull-requests: read` and a `pull_request_review` trigger.
- **Q-T014-2 (policy): Expired claims at merge time.** Recommended: accept with a warning. Rejecting them would fail every PR whose review outlasts the 120 minute TTL. Claims must still exist, so `waggle release` runs after merge, not before.
- **Q-T014-3 (policy): Merge commits fail.** Recommended: yes, require rebased branches. It removes the evil-merge hole and matches T-007's net-change reasoning. Cost: contributors must rebase instead of merging `main` in.
- **Q-T014-4 (process): Architect and docs commits need a ticket.** With this gate, a commit without `T-<id>:` fails. Brief-writing work then runs under a planning ticket with a `full` claim on `.waggle/hive/tasks/` (Tier 2, leasable after T-011), or merges by bypass. Recommended: planning tickets.
- **Q-T014-5 (operations): Local-only hives.** A hive with no `forge.remote` keeps claims only on the Keeper's machine, so CI sees none and every PR fails `leases`. Recommended: the gate stays strict; any hive that runs the CI gate must push claim refs (set `forge.remote`). Document in RFC-0003 after merge.
