## 1. Goal

After this ticket the gate treats a claim with no branch list the way it treats a claim whose list misses the PR head: it fails every commit bound to that ticket, under `leases`, with the T-039 renew hint. The ticket-branch-name fallback D-291 allowed for the transition is removed. Nothing else in the branch check, binding or claim writing changes.

## 2. Behavior change

T-039 2.4 item 3 (to confirm after T-039 merges) has three outcomes for a claim that decodes with an empty or nil `Branches`:

- under (b), today on `t-039`: a same-repo head whose name `branchTicket` does not ignore and that is exactly `t-<d>` or `waggle/T-<d>`, or either followed by a non-digit and anything, with `<d>` the canonical digits of the claim's ticket, passes with one warning `claim for <id> names no branch; accepted on ticket branch name`;
- every other head (a fork, an ignored name, any other name): one failure `<id>: claim names no branch; renew it with waggle claim --branch`.

After this ticket only the second outcome remains, for every known head:

- **Head known, claim lists no branch:** one failure `<id>: claim names no branch; renew it with waggle claim --branch`, filed under `leases` with no path, outside the path loop, exactly as T-039 files its other branch failures (so the approver filter never drops it and no approval clears it), once per ticket through the `s.claims` cache. The claim's path rules still run (`cl.ok` stays true).
- **The warning `claim for <id> names no branch; accepted on ticket branch name` is removed** and no longer printed in any case.
- **Unchanged:** the head-unknown case (T-039 2.4 item 1: local warning once per run outside Actions, `<id>: pull request branch unknown` under Actions) runs before the list is looked at, so a local run with no `--branch` still skips the check with its one warning, whatever the claim holds. The listed-branch case (2.4 item 2) is untouched. An ignored head name is known and still fails; it now fails through this case, as it already did through the (a) message.

The message is the T-039 renew hint, word for word, with only the canonical ticket ID substituted. It carries no head name, repo name or claim entry (T-039 AC14). This ticket does not reword it; T-040 does not touch it either (its section 3 has no row for T-039's texts).

**Why the hint works:** under T-039 2.2 (to confirm after T-039 merges) `waggle claim T-<nnn> --dirs <same> --gate <same>` with no `--branch` on a same-keeper renewal of a claim with no stored list records `[t-<nnn>]` (the stored list is empty, so `AcquireClaim` falls through to `req.Branch`), and `--branch <name>` records the names given. Either one clears the failure on the next gate run, which must be re-run by hand or by the next push or review (a claim write does not trigger the workflow, T-039 2.2).

## 3. Delete the fallback, do not keep it unreachable

**Recommended: delete it outright** (Q-T042-1). The no-list case becomes a single failure return. The canonical ticket-branch-name test, its digit-string handling, the same-repo and ignored-name checks that only the fallback used, and the warning string all go. Reasons:

- Kept code with no caller is a fallback one edit away from being wired back in, and in the gate that edit would reopen the D-278 gap in a diff that reads as small. A guard reviewing a later ticket cannot tell an unused fallback from a planned one.
- `go vet` does not flag an unused unexported function, so nothing would catch it rotting or being called by accident.
- Reversal is a revert of this commit, which is as cheap as re-enabling dead code and leaves a record.

If T-039's merged code shares a helper between the fallback and another path (for example a canonical-digits helper also used by binding; to confirm after T-039 merges), the shared helper stays and only the fallback's call goes. The finalize round names each deleted function.

**Step 1, pin move (Head Keeper commit, D-271).** After T-039 merges, the Head Keeper builds `cmd/waggle` at the merge commit (or a later main that carries it) and runs, from that build, `waggle upgrade` (dry run, reviewed on the pin card) then `waggle upgrade --apply`, and commits `.waggle/control/config.yaml` and the re-rendered `.github/workflows/waggle-gate.yml` as one Head Keeper commit, recorded on its own D-entry like D-269. **Step 2, list every claim ref, live and expired.** `waggle status` is not enough: it hides expired claims and does not print branches (T-039 section 4). Read the refs:

```
git fetch --prune origin '+refs/waggle/claims/*:refs/waggle/claims/*'
git for-each-ref --format='%(refname)' refs/waggle/claims/
git cat-file -p refs/waggle/claims/ticket-<n>:lease.json
```

The first command mirrors the remote's claim refs (the same refspec `sync` fetches, `internal/comb/git.go:286-289` at `32adb18`), so a ref deleted on the remote goes locally too. The third prints one claim; read `ticket_id`, `keeper_id`, `gate`, `directories`, `expires_at` and `branches`. Because `branches` is `omitempty` (T-039 2.1), a claim with no list has no `branches` key at all.

**Step 3, renew or release each claim with no `branches` key.**

- Live work: `waggle claim T-<nnn> --dirs <dirs from lease.json, comma-separated> --gate <gate from lease.json> --branch t-<nnn> [--branch t-<nnn><phase>]... [--owner <keeper_id from lease.json>]`. Same dirs and gate, so the only change the renewal note reports is the branch list. `--owner` is needed only when the claim's `keeper_id` differs from the local `keeper_id`; a different owner on a live claim is refused, not a takeover. An expired claim re-claimed this way is a takeover and records only the `--branch` values given (T-039 2.2), which is what is wanted here.
- A phase in flight: name every branch its PRs will use, for example `--branch t-038b` while phase B is open.
- A Copilot task (D-279): add `--branch copilot/<slug>`.
- Finished or abandoned work: `waggle release T-<nnn>`, which refuses until `t-<nnn>` (or `--branch <name>`) is merged into main, or `waggle release T-<nnn> --unmerged` on a Head Keeper card for work that merged by squash or rebase or made no PR (`internal/dispatch/release.go:150-158` at `32adb18`).

**Step 4, verify that no claim lacks a list.** After Step 3, rerun the fetch from Step 2, then:

```
git for-each-ref --format='%(refname)' refs/waggle/claims/ | while read -r r; do git cat-file -p "$r:lease.json" | grep -q '"branches"' || echo "$r"; done
```

Empty output means every claim ref names branches. Then `waggle status` must show no `malformed:` line (a claim with a bad list reads as malformed, T-039 2.1). The queen runs Steps 2 and 4 again just before the Head Keeper merges T-042, since a claim written in between by an older binary would put it back.
