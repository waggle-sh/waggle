## 3. Delete the fallback, do not keep it unreachable

**Recommended: delete it outright** (Q-T042-1). The no-list case becomes a single failure return. `ticketBranchName`, the same-repo and ignored-name test that only the fallback used, and the warning string all go; `branchTicket` stays, since binding calls it. Reasons:

- Kept code with no caller is a fallback one edit away from being wired back in, and in the gate that edit would reopen the D-278 gap in a diff that reads as small. A guard reviewing a later ticket cannot tell an unused fallback from a planned one.
- `go vet` does not flag an unused unexported function, so nothing would catch it rotting or being called by accident.
- Reversal is a revert of this commit, which is as cheap as re-enabling dead code and leaves a record.

If T-039's merged code shares a helper between the fallback and another path, the shared helper stays and only the fallback's call goes. The finalize round names each deleted function (at 8978c62: `ticketBranchName` only).

## 9. Preconditions: commands for the queen and the Head Keeper

Run from the hive's main checkout. **Every command that writes a claim or dispatches runs `bin/waggle`**, rebuilt from the pin and checked in Step 1 (precondition 2), never another installed `waggle`. Flags and output are at 8978c62, recheck at merge.

**Step 1, pin move (Head Keeper commit, D-271).** After T-039 merges, the Head Keeper builds `cmd/waggle` at the merge commit (or a later main that carries it) and runs, from that build, `waggle upgrade` (dry run, reviewed on the pin card) then `waggle upgrade --apply`, and commits the result as one Head Keeper commit, recorded on its own D-entry like D-269. That commit always holds `config.yaml`; since D-250 the workflow usually reports `[same]`, so this step does not promise a change to `.github/workflows/waggle-gate.yml`, and it also regenerates the gitignored `.claude/agents/` shims. Then the queen:

```
ls .waggle/worktrees/dispatch.lock
pgrep -fl '[w]aggle dispatch'
git worktree add --detach <tmpdir> <pin>
go -C <tmpdir> build -o <main checkout>/bin/waggle ./cmd/waggle
go version -m <main checkout>/bin/waggle
git worktree remove <tmpdir>
bin/waggle status
```

The worktree step is never run while a dispatch run is live: the `ls` and `pgrep` checks come first, and if either finds a run, the queen stops there. The build runs in a detached checkout at the pin, never in the main checkout, whose HEAD is past the pin and whose untracked files would stamp `vcs.modified=true`. `go version -m` on the binary it writes into the main checkout must show `vcs.revision=<pin>` and `vcs.modified=false`; anything else, remove the worktree and rebuild the same way. `bin/waggle status` checks the config side only: its header's `pin` names the new build. `ls` must report no such file and `pgrep` must print nothing, so no dispatch run from an older binary is alive (a run holds `dispatch.lock` for its whole life; the bracket keeps `pgrep` from matching its own shell). The lock must be absent. If it is present and no process is running, it is a stale lock from a crash: it goes to the Head Keeper as a card, is never removed by hand, and Step 2 waits for that ruling.

**Step 2, list every claim ref, live and expired.** `bin/waggle status` is not enough: it hides expired claims and does not print branches (T-039 section 4). Read the refs:

```
git fetch --prune origin '+refs/waggle/claims/*:refs/waggle/claims/*'
git for-each-ref --format='%(refname)' refs/waggle/claims/
git cat-file -p refs/waggle/claims/ticket-<n>:lease.json
```

The first command mirrors the remote's claim refs (the same refspec `sync` fetches, `internal/comb/git.go:286-289` at `32adb18`), so a ref deleted on the remote goes locally too. The third prints one claim; read `ticket_id`, `keeper_id`, `role`, `gate`, `directories`, `expires_at` and `branches`. Because `branches` is `omitempty` (`internal/comb/backend.go:123` at 8978c62), a claim with no list has no `branches` key at all.

**Step 3, renew or release each claim with no `branches` key.** Never renew a claim while a dispatch run holds it: the keepalive writes back the list the run read at its start (`internal/dispatch/run.go:409` at 8978c62), so a renewal during the run is overwritten at the next keepalive. Renew after the run exits, or repeat the renewal then. Under precondition 2 a claim that needs Step 3 has no live new-binary run, since that binary writes a list.

- Live work: `bin/waggle claim T-<nnn> --dirs <dirs from lease.json, comma-separated> --gate <gate from lease.json> --branch t-<nnn> [--branch t-<nnn><phase>]... [--owner <keeper_id from lease.json>]`. With the same dirs and gate, the renewal note (`internal/dispatch/claim.go:68` at 8978c62) reports the branch list. `waggle claim` always claims as role `builder` (`task.go:50`), so a claim a forager-role dispatch wrote also reports `forager -> builder`; that is expected, not a mistake. `--owner` is needed only when the claim's `keeper_id` differs from the local `keeper_id`; a different owner on a live claim is refused, not a takeover. An expired claim re-claimed this way is a takeover and records only the `--branch` values given (T-039 2.2), which is what is wanted here.
- A phase in flight: name every branch its PRs will use, for example `--branch t-038b` while phase B is open.
- A Copilot task (D-279): add `--branch copilot/<slug>`.
- Finished or abandoned work: `bin/waggle release T-<nnn>`, which refuses until `t-<nnn>` or `waggle/T-<nnn>` (or `--branch <name>`) is merged into main, or `bin/waggle release T-<nnn> --unmerged` on a Head Keeper card for work that merged by squash or rebase or made no PR (`internal/dispatch/release.go:149-158` at `32adb18`).

**Step 4, verify that no claim lacks a list.** After Step 3, rerun the fetch from Step 2, then:

```
git for-each-ref --format='%(refname)' refs/waggle/claims/ | while read -r r; do git cat-file -p "$r:lease.json" | grep -q '"branches":\[' || echo "$r"; done
```

The pattern `"branches":\[` matches Go's `encoding/json` output, which writes no spaces, and does not match a claim whose directory list holds a directory named `branches`. If `jq` is installed, `jq -e '(.branches // []) | length > 0'` is an equivalent test. A hand-written `"branches":[]` passes the grep and then fails closed at the gate, which is acceptable. Empty output means every claim ref names branches. Then `bin/waggle status` must show no `malformed:` line (a claim with a bad list reads as malformed, T-039 2.1).

**The freeze.** The queen runs Steps 2 and 4 again just before the Head Keeper merges T-042. From that last Step 4 run until the merge, no dispatch runs and no `waggle claim` runs in the hive. Right after the merge the queen runs Steps 2 and 4 once more; any hit is renewed per Step 3 and its gate check re-run. The freeze narrows the window but cannot close it: a claim stripped later by an older binary fails its next PR closed (section 5), and the remedy is one Step 3 renewal and a re-run of the check.
