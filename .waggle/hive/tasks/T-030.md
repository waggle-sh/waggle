## 1. Goal

A builder's claim (`refs/waggle/claims/ticket-<n>`) lives for `leases.default_ttl_minutes` (120 in our config) after its last write, whatever happened to the run. The Comb refuses any other ticket whose directories overlap an unexpired claim (exit 4). Nothing releases a claim: `comb.ReleaseLease` and `comb.ForceRelease` exist, but no CLI verb calls either, and `clean` never touches a claim ref (D-202). The trial had to use a fresh scratch hive per probe run on a Keeper card. In this hive the same rule makes T-027, T-028 and T-029, which share `internal/dispatch/`, wait up to two hours after each merge.

The claim must stay until merge: the gate fails a PR whose ticket has no claim ref and accepts an expired one with a warning (`claimFor`), and the guard reads the builder's claim, active or expired (T-023 10.2). So a release is safe only once the ticket's PR has merged, or when the ticket will not produce a PR.

## 2. Design (recommended options)

New verb: `waggle dispatch release <ticket> [--branch <name>] [--unmerged] [--repo <dir>]`.

1. Validate the ticket id and branch as the other verbs do; default branch `t-<nnn>`.
2. Take `dispatch.lock` through the same path `clean` uses (`lockRepo`), so no run in this repo is live while it releases. A held lock is exit 3 with the existing message.
3. Refuse (exit 4) while any `.waggle/worktrees/T-<nnn>-<role>` worktree of the ticket exists: a kept builder worktree means a fix round or `clean` card is still pending. The message names the worktree's base name and says to run `clean` first (on its card).
4. Merged check: in remote mode, fetch the remote (host side, as `ResolveBase` does), then require the branch head to be an ancestor of `<remote>/main` (`merge-base --is-ancestor`, pinned git): `<remote>/<branch>` when it exists, else the local `<branch>` (GitHub may delete the head branch on merge; dispatch's worktree removal leaves the local branch). In a local-only hive, the local branch against `main`. The queen rebases a branch onto main before merging it (`handoff/queen.md`); the rebased head is what merges, so the check must use the head as pushed, never the branch point. A branch that is absent everywhere, or not merged, is refused with exit 4 unless `--unmerged` is given. `--unmerged` exists for a ticket that will not produce a PR (a `no_change` run, a withdrawn ticket); the queen uses it only on a Keeper card (Q-T030-2).
5. Release through `comb.ReleaseLease(ctx, ticket, keeperID)` with the `keeper_id` from `local.yaml` and the same `ExtraEnv` as dispatch's Comb (`combEnv`: no hooks, no auto maintenance). Map errors: `ErrNotFound` exit 0 with `no claim for T-<nnn>`; `ErrNotOwner` and `ErrMalformedClaim` exit 4 (the malformed hint names the Head Keeper force-release as `claimError` does); `ErrConcurrentUpdate` exit 4; transport failure exit 3.
6. Print one line: `released T-<nnn> (claim <short oid>, <merged into main | unmerged>)`. Every printed value from a ref or the remote goes through `printable`.
7. Usage text in `cmd/waggle/dispatch.go` gains the verb.

Not in this ticket: Head Keeper force-release of another Keeper's claim (`comb.ForceRelease` and its audit chain need their own card), auto-release at the end of a run, release from CI after merge.

## 3. Questions for the Keeper

- **Q-T030-1: how does a finished ticket give back its directories?** (a) An explicit owner-only `release` verb that refuses until the branch has merged, with `--unmerged` for tickets that produce no PR (section 2). (b) Dispatch releases the claim itself at the end of a run that committed nothing and pushed nothing (`no_change`, `error`, `interrupted`, `timeout` with zero commits). (c) No code: lower `leases.default_ttl_minutes` in `.waggle/control/config.yaml` (Tier 3, a Head Keeper commit), for example to 30; renewals during a run keep live claims, overlap ignores expired claims, the gate accepts an expired claim, and the guard reads one. **Recommended: (a).** (b) fixes only the trial's case (a run that did nothing), not the common one in this hive (a merged ticket blocking the next ticket on the same directory), and adds a claim delete to the run path, which every later dispatch review must re-check. (c) is free and reversible and is a fair stopgap while (a) is built, but it shortens the protection of every open PR, including one waiting on a long review, and a 30 min gap between a builder run and its fix round turns the fix round's claim into a takeover race with any overlapping ticket.
- **Q-T030-2: who may run `release`?** (a) The queen, without a card, on a ticket whose PR she has merged (the merged check makes it a bookkeeping step); `--unmerged` always on a Keeper card. (b) Every release on a Keeper card. **Recommended: (a).** A merged ticket's claim protects nothing; a card per merge adds Keeper load for no decision. `--unmerged` gives up a live lease, so it stays a Keeper decision. The queen's role template and `handoff/queen.md` habits change in a later records batch, not in this ticket.

## 4. Out of scope

- Any change to `internal/comb/` (the backend already implements the release, owner check and remote compare-and-swap).
- `clean` behavior: it still never touches a claim ref (D-202).
- `waggle status` and `list` output.

## 5. Threat model (D-203)

Must-fix: a release of a claim the Keeper running the verb does not own; a release while the ticket's PR is open or unmerged without `--unmerged`; a release while a run in this repo holds `dispatch.lock` or a worktree of the ticket exists; any claim ref deleted other than the named ticket's own; a release on the remote that is not a compare-and-swap against the claim OID read (it must go through `ReleaseLease`, never a hand-built `push :<ref>` or `update-ref -d`); the merged check run unpinned, or against a ref the worker can write without the check noticing (it must read the remote after a fetch, or the local `main` in a local-only hive); a value from a ref or the remote printed raw; any change to `clean`, the gate, the guard's claim read or `AcquireClaim`. Note, not must-fix: a release racing a new claim of the same ticket from another machine (the Comb's compare-and-swap refuses it with `ErrConcurrentUpdate`); a forged merge on the remote (needs push access to `main`, which the ruleset guards); anything that needs write access to the git dir, to `.waggle/worktrees/` outside a worker's own tree or to another ticket's worktree, or a process that already escaped the tracker.

Guard prompt sentence (repeat verbatim): "Threat bar (D-203): a finding whose attacker needs write access to the git dir, to `.waggle/worktrees/` outside the worker's own tree or to another ticket's worktree, or a process that already escaped the tracker, is a note, not a must-fix; must-fix is for what a worker inside its lease, a guard or ordinary repo state can trigger, and for any signal or delete outside the worker's own tree from ordinary inputs."

## 6. Verification

The worker's Bash allowlist is `WAGGLE.md` section 3 plus git. Run, in this order:

- `go build ./...`
- `go vet ./...`
- `go test -race ./... -run '<regexp>'` naming only the new release tests and existing git and file tests of `cmd/waggle` and `internal/dispatch` (for example `TestRelease|TestDispatchUsage`).

Do not run tests that go through `Run`, the tracker or `sweep()` on this host (D-193, D-195): no full `go test -race ./...` and no `-run` pattern that matches `TestRun*`, `TestGuard*`, `TestClean*` or the `reap_*` tests. Release tests build claims with the Comb on git-only fixture repos (`newFixture`, `newRepo`, with `quietGit` from T-026), a local bare origin for remote mode included. Until T-028 merges, tests that push to a local origin fail inside the worker (trial follow-up 3): the builder runs the local-mode tests, and names the remote-mode ones in the final report for product-ci and the guard. No new test calls `Run`, `sweep()` or sends a signal. State in the final report which commands ran and their result.

## 7. Acceptance criteria

- [ ] AC1: `go build ./...` and `go vet ./...` pass; product-ci green on the PR.
- [ ] AC2: the diff changes only the files the lease rule names; `go.mod` unchanged; nothing in `internal/comb/` changes.

- [ ] AC4: refused, with nothing deleted, for: a claim owned by another Keeper (exit 4); an unmerged or absent branch without `--unmerged` (exit 4); an existing worktree of the ticket (exit 4); a held `dispatch.lock` (exit 3). `--unmerged` releases an owned, unmerged claim.
- [ ] AC5: no claim for the ticket is exit 0 with `no claim for T-<nnn>`; a malformed claim is exit 4 with the force-release hint.
- [ ] AC6: in remote mode, a claim changed on the origin between the read and the delete is refused (`ErrConcurrentUpdate`, exit 4) and the origin ref is unchanged.
- [ ] AC7: no new test calls `Run`, `sweep()` or sends a signal; no `t.Skip`.
