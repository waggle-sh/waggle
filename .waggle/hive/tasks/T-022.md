## 1. Goal

RFC-0003 section 5 item 7: `waggle status` is plain-text terminal output derived from Comb refs and `run.sock`. Today `cmd/waggle/main.go` prints one fixed line. Replace it with a real report in three parts: the hive header, active claims, and per-ticket token and cost use (D-075: `waggle status` reports tokens and dollars per ticket). Dollar figures are the runtime's own estimate, labeled `est. $`, with no price table in Waggle (D-082).

The command is read-only. It never writes to the repo, to `refs/waggle/*`, to the ledger, or to `WORKPLAN.md` (that is `waggled`'s job, T-002 section 11).

## 2. Command and output

```
waggle status [--repo <dir>]
```

`--repo` defaults to the current work tree root (`git rev-parse --show-toplevel`). No other flags in v0.1 (`--json` is out of scope, section 7).

```
Hive: waggle  pin 3f9c1e2...  comb direct (local)
waggled: stopped (no .waggle/control/run.sock)

Claims (2 active):
  T-012  builder  paul  full   internal/runtime/ internal/config/   expires in 1h42m
  T-016  builder  paul  full   internal/scaffold/ cmd/waggle/       expires in 12m
  malformed: 1 (refs/waggle/claims/ticket-7: lease.json: invalid character ...)

Usage (this machine, .waggle/control/usage.jsonl):
  T-012  builder 3 sess  guard 2 sess  in 1.84M (81% cached)  out 52k  est. $4.10  [guard floored]
  T-016  builder 1 sess                in 310k (64% cached)   out 9k   est. $0.62
  total                                in 2.15M (79% cached)  out 61k  est. $4.72
  Not counted: sessions a Keeper starts directly (today the queen and the planning role) and other Keepers' machines.
```

Rules:
- **Header.** Repo root basename; `waggle.pin` from `config.yaml` (T-011 section 6.3; `unpinned` printed as is); `comb_mode` and `forge.remote` from T-004's `Config` (`(local)` when the remote is empty).
- **Daemon line.** `running (socket present)` when `layout.Socket` exists, else `stopped (no <path>)`. Existence only: there is no socket protocol yet. When `waggled` lands, a ping replaces this check; note that in a code comment.
- **Claims.** `ListActiveLeases` output sorted by ticket number. Columns: ticket, role, keeper, gate, directories (space-separated), time to expiry rounded down to minutes (`expires in 1h42m`, `expires in 12m`, `expires in 0m`). `0 active` prints the heading and nothing else. Expired claims are not listed (the backend already filters them). A `*MalformedClaimsError` adds one `malformed:` line with the count and the first ref and reason; the valid leases still print and the exit code stays 0, because status is a report, not a check.
- **Role names** are printed as the backend returns them. After T-020, version 1 claims come back mapped (D-080), so status never maps or hardcodes a role name.
- **Usage.** One line per ticket that has at least one ledger record, sorted by ticket; a `total` line; then the fixed footer sentence. Absent or empty ledger: `Usage: none recorded (<path> absent)` and no footer. Phase A prints that line unconditionally; phase B replaces it.
- **Line format.** `in` is input plus cache write plus cache read tokens; the cached share is cache read over `in`, rounded to a whole percent, omitted when `in` is 0. `out` is output tokens. `est. $` is the sum of `cost_usd` with two decimals; `est. $ n/a` when any record for that ticket has a null cost. `[guard floored]` appears when any record for the ticket has `floored` true (only the guard is ever floored, T-021 section 5). Token counts: below 1,000 plain; below 1,000,000 as `NNNk` (rounded); else `N.NNM`. Per-role session counts are the distinct `session` values per role, listed in the order roles first appear in the ledger.
- No U+2013 or U+2014 anywhere in output.

Exit codes: 0 report printed (including with malformed claims or an unreadable ledger line), 1 refused (not a hive, legacy layout, config invalid), 2 usage, 3 git or I/O failure. `runStatus(args []string, stdout, stderr io.Writer) int`, no `os.Exit` inside; the clock and the socket-existence check are injectable for tests.

## 4. Phase B: usage ledger (`internal/usage/`) and the usage section

Standard library only. The record type is the one T-021 section 8 specifies, so T-023's writer and this reader share it; T-023 imports this package and adds no second definition.

```go
type Record struct {
    TS               time.Time `json:"ts"`
    Ticket           string    `json:"ticket"`
    Role             string    `json:"role"`
    Session          string    `json:"session"`
    Adapter          string    `json:"adapter"`
    Model            string    `json:"model"`
    Profile          string    `json:"profile"`
    Floored          bool      `json:"floored"`
    InputTokens      int64     `json:"input_tokens"`
    CacheWriteTokens int64     `json:"cache_write_tokens"`
    CacheReadTokens  int64     `json:"cache_read_tokens"`
    OutputTokens     int64     `json:"output_tokens"`
    CostUSD          *float64  `json:"cost_usd"` // nil when the adapter reports none
    End              string    `json:"end"`      // done | handoff | max_turns | max_sessions | max_tokens | error
}

type BadLine struct{ Line int; Err error }

func Append(path string, r Record) error                     // one JSON line, O_APPEND, creates the file with 0600; the launcher's writer
func Read(path string) ([]Record, []BadLine, error)          // absent file: nil, nil, nil; malformed lines are skipped and reported, never fatal
func Summarize(recs []Record) []TicketSummary                // sorted by ticket number (comb.ParseTicketID), then by first appearance
func Render(s []TicketSummary, path string) []byte           // the section 2 usage block, footer included; empty input renders the "none recorded" line
```

`TicketSummary` holds the ticket, per-role session counts in first-appearance order, `In`, `CacheRead`, `Out`, `Cost float64`, `CostKnown bool`, `Floored bool`. `Read` streams with a 1 MiB per-line buffer and rejects a ticket that fails `comb.ParseTicketID` as a bad line. Validation of `End` values and roles is the writer's job; the reader reports what it finds.

`status.go` then calls `usage.Read(filepath.Join(root, layout.Usage))`, prints one `warning: <n> unreadable ledger lines (first: line <k>: <err>)` line on stderr when any, and renders. A `Read` I/O error other than not-exist is exit 3.

Target under 250 non-test lines.

## 5. Tests (never skip)

Real `git init` repos with `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, as T-002 and T-016 do. Fixed clock `2026-10-17T12:00:00Z`.

Phase A:
1. Fresh hive (`waggle init` into a temp dir): header shows the pin and `comb direct (local)`; `waggled: stopped`; `Claims (0 active):`; the phase A usage line. Golden.
2. Two leases acquired through `comb.GitBackend` print sorted by ticket with the right expiry text; an expired lease (clock moved past `ExpiresAt`) is absent.
3. A malformed claim ref (hand-written blob) yields the `malformed:` line, the valid lease still prints, exit 0.
4. Socket file present gives `running (socket present)`.
5. No `.waggle/`: exit 1 with the not-a-hive message. Legacy layout: exit 1 with the 6.5 message. Invalid config: exit 1. Unknown flag: exit 2.
6. `git status --porcelain` and `git for-each-ref refs/waggle/` are byte-identical before and after a run.
7. No U+2013 or U+2014 in any output.

Phase B:
8. `Render(Summarize(Read("testdata/usage.jsonl")))` matches a golden file covering: two roles with multiple sessions, a floored guard record, a null cost (ticket line shows `est. $ n/a`, total shows `n/a`), and tickets out of order in the file.
9. Number formatting table: `999`, `1000`, `52381`, `999950`, `1840000`, `2150000`.
10. Cached share: `in` 0 omits the percentage; rounding to a whole percent.
11. A malformed line and a line with a bad ticket id are reported as `BadLine` with the right line numbers; the rest load.
12. Absent file: empty summary, no error, the "none recorded" line.
13. `Append` then `Read` round-trips one record byte for byte on the JSON fields; `Append` on a missing directory fails with a wrapped error and creates nothing.
14. `status` with a ledger present prints the usage block and the footer; the stderr warning appears only when bad lines exist.
