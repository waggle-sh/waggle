## 1. Goal

D-067: Waggle's core stays plain git. Claims, leases, gate logic, decisions, WORKPLAN and Cells never call a code host. Everything that needs one goes through a small `Forge` interface, and a setup check tells each repo plainly what it enforces and what it does not. This ticket ships:
1. The `Forge` interface, sized to what v0.1 calls (section 3).

3. A GitHub adapter that uses `gh` if logged in, else `GITHUB_TOKEN` (D-061) (section 5).
4. A capability probe and a plain-language report, run by `waggle doctor` and, read-only, by `waggle init` (sections 6 and 7).

Go 1.23, module `github.com/waggle-sh/waggle`, **standard library only** (`net/http`, `encoding/json`, `os/exec`). Do not touch `go.mod`.

## 3. Interface (phase A, `internal/forge/forge.go`)

What v0.1 calls: `waggled` opens a PR per task branch, posts the guard's Intent Packet, and merges with a real merge commit on pass (D-017); `waggle init` writes the CI shim; `waggle doctor` probes. Relay claims and bot identity are named in D-067 but have no v0.1 caller yet (section 3.2).

```go
// Forge is the code host behind a hive. Core packages never import it.
type Forge interface {
    Name() string // "github" or "none"
    OpenChange(ctx context.Context, req ChangeRequest) (Change, error)
    Comment(ctx context.Context, c Change, body string) error
    Merge(ctx context.Context, c Change, req MergeRequest) error
    CIShim() (Shim, bool) // false: this forge runs no CI shim
    Probe(ctx context.Context, opt ProbeOptions) (Report, error) // phase C; phase A adapters return the local-only report
}

type ChangeRequest struct {
    Head, Base  string // branch names, validated with git check-ref-format --branch
    Title, Body string // Title: 1..256 bytes, one line. Body: up to 64 KiB.
}

type Change struct {
    Head, Base string
    Number     int    // 0 for none
    URL        string // "" for none
}

type MergeRequest struct {
    Subject, Body   string // merge commit message: Intent Packet and trailers (D-017)
    ExpectedHeadOID string // required; merge refuses if the head moved (CAS, like claims)
    Auto            bool   // merge when required checks pass, where the forge supports it
}

type Shim struct {
    Path     string // repo-relative, e.g. ".github/workflows/waggle-gate.yml"
    Template string // template name under internal/scaffold/templates/
}
```

- The merge method is always a real merge commit (D-017). It is not a parameter.
- Sentinels: `ErrUnsupported`, `ErrHeadMoved`, `ErrNotMergeable`, `ErrNoForgeAuth`, `ErrForgeRemote`. Every error names the operation and wraps one of them or a transport error.
- `New(provider string, opt Options) (Forge, error)` with `Options{RepoDir, Remote string; Getenv func(string) string; LookPath func(string) (string, error)}`. `provider` comes from T-004's `forge.provider` (`github` or `none`). Phase A's `New` returns `none` and errors on `github`; phase B wires `github`.
- **Forge calls never run inside a Cell.** Cells hold zero credentials (D-061, RFC-0003 3.5). Only the host CLI and `waggled` construct a `Forge`. State this on the package doc.

### 3.1 CI annotations (phase A, `annotate.go`)

T-007 and T-014 print `::error file=...::` workflow commands when `GITHUB_ACTIONS=true`. That format belongs to GitHub Actions, so it lives here, not in the gate:

```go
type Annotator interface { Annotate(w io.Writer, level, file, msg string) }
func AnnotatorFromEnv(getenv func(string) string) Annotator // GitHub format when GITHUB_ACTIONS == "true", else plain "level: file: msg"
```

The GitHub implementation encodes exactly as T-014 section 4.1 specifies (`%`, `\r`, `\n`, and in `file=` also `:` and `,`). One encoder, tested here. See section 9 for how T-007 and T-014 adopt it.

### 3.2 Reserved, not built here

- **Relay** (public contributors comment `/waggle claim`; the CI shim writes the claim). Built by the relay-mode ticket, as an optional interface in this package (`type Relay interface{...}`, discovered by type assertion), so forges without relay simply do not implement it.
- **Bot identity** (team mode: who writes and signs claims, D-015, D-068). Same pattern, built by the team-mode ticket. The bot signs with git's SSH signing, so the interface will carry only where the key lives, never a forge API for writing commits.
- Phase C's probe reports both as "not configured" with the consequence (section 7).

## 4. `none` adapter (phase A, `none.go`)

A hive with no code host, or one whose remote is a plain git server. Also the adapter every core test uses.

- `OpenChange`: validates and returns `Change{Head, Base}`. The branch is the change. No network.
- `Comment`: returns `ErrUnsupported`. Callers log the text locally.
- `Merge`: `Auto` returns `ErrUnsupported` (there is nothing to wait on). Otherwise merge `Head` into `Base` without touching any working tree:
  1. Resolve both refs; `Head` must equal `ExpectedHeadOID`, else `ErrHeadMoved`.
  2. `git merge-tree --write-tree <base> <head>`. A conflict is `ErrNotMergeable` with the conflicting paths, and no ref changes.
  3. `git commit-tree <tree> -p <base> -p <head>` with the message from `Subject` and `Body`.
  4. `git update-ref refs/heads/<Base> <new> <base>` (CAS). A lost race is `ErrHeadMoved`.
  5. If `Options.Remote` is set: `git push --porcelain <remote> <new>:refs/heads/<Base>` with `--force-with-lease=refs/heads/<Base>:<base>`. Rejection is `ErrHeadMoved`.
  - Needs git 2.38 or later for `merge-tree --write-tree`; older git returns an error naming the version.
  - It does **not** run `waggle gate`. The caller runs the gate before merging (D-017: same Go code locally and in CI). Section 7 states that nothing outside Waggle enforces this.
- `CIShim`: `(Shim{}, false)`.
- `Probe`: section 6, git probes only.

Git execution: one helper, `exec.CommandContext`, separate argv, no shell, `GIT_TERMINAL_PROMPT=0`, `LC_ALL=C`, every ref and OID validated before argv (T-002 section 6 rules).

## 5. GitHub adapter (phase B)

### 5.1 Auth and transport (D-061)

Order, decided once in `New`:
1. `gh` on `PATH` and `gh auth status --hostname github.com` exits 0: **gh transport**. Every call is `gh api --method <M> --include -H "Accept: application/vnd.github+json" --input - <path>`; the status code comes from the `--include` header block. Waggle never reads gh's config or keyring.
2. Else `GITHUB_TOKEN` non-empty: **token transport**. `net/http` to `https://api.github.com` (base URL injectable for tests only), headers `Authorization: Bearer`, `X-GitHub-Api-Version: 2022-11-28`, 30 second timeout, response bodies capped at 1 MiB.
3. Else `ErrNoForgeAuth`: "GitHub needs `gh auth login` or a GITHUB_TOKEN environment variable."

Both transports implement one unexported `do(ctx, method, path string, in, out any) (status int, err error)`. GraphQL goes through the same function (`POST /graphql`, or `gh api graphql`). No secret-manager integration; users wrap commands themselves (`op run`, D-061). **The token never appears in argv, logs, errors, or files**; tests assert it.

### 5.2 Repository identity (`remote.go`)

`git remote get-url <forge.remote>`, then accept only `https://github.com/<owner>/<repo>[.git]`, `git@github.com:<owner>/<repo>[.git]`, `ssh://git@github.com/<owner>/<repo>[.git]`. Owner `^[A-Za-z0-9-]{1,39}$`, repo `^[A-Za-z0-9._-]{1,100}$`. Any other host with `provider: github` is `ErrForgeRemote` naming the host. GitHub Enterprise Server is out of scope (D-069). An empty `forge.remote` with provider `github` is `ErrForgeRemote` ("set forge.remote, or use provider none for a local-only hive").

### 5.3 Operations

| Method | REST or GraphQL call | Notes |
| :--- | :--- | :--- |
| `OpenChange` | `POST /repos/{o}/{r}/pulls` (`title`, `head`, `base`, `body`) | 422 "already exists": `GET /repos/{o}/{r}/pulls?head={o}:{head}&state=open` and return that PR. |
| `Comment` | `POST /repos/{o}/{r}/issues/{n}/comments` | |
| `Merge`, `Auto=false` | `PUT /repos/{o}/{r}/pulls/{n}/merge` with `merge_method: merge`, `commit_title`, `commit_message`, `sha: ExpectedHeadOID` | 409: `ErrHeadMoved`. 405: `ErrNotMergeable` with GitHub's message (failing checks, branch behind, rules). |
| `Merge`, `Auto=true` | GraphQL `enablePullRequestAutoMerge(pullRequestId, mergeMethod: MERGE, commitHeadline, commitBody, expectedHeadOid)` | Node ID from `GET` on the PR. "Auto-merge is not allowed" maps to `ErrUnsupported`. |
| `CIShim` | none | `Shim{".github/workflows/waggle-gate.yml", "waggle-gate.yml.tmpl"}` (`layout.GateWorkflow`). |

Merge never uses squash or rebase; a repo that disables merge commits fails with GitHub's message, and the probe reports it in advance (section 7).

## 6. Capability probe (phase C)

`Probe(ctx, ProbeOptions{Write bool, MergeStrategy, GateCheck string})`. `GateCheck` defaults to `verify-leases-and-tiers` (the gate job name, T-014). Each probe yields one `Finding{ID, Status, Required bool, Summary, NotEnforced, Fix string}`. Status is `ok`, `missing`, `unknown`, or `skipped`.

### 6.1 Git probes (every forge with a remote, so `none` too)

| ID | How | Required |
| :--- | :--- | :--- |
| `remote` | `git ls-remote --heads <remote>` | yes |
| `custom-refs` | Write probe: push the remote's default-branch tip OID (already on the remote, so no upload) to `refs/waggle/probe/<16 hex>-a` and `-b` with `--atomic`, then delete both with `--atomic` | yes (claims live there) |
| `atomic-push` | From the same push: "does not support --atomic" means `missing`, then retry without `--atomic` to still answer `custom-refs` | yes (T-002, T-005 rely on it) |

- Write probes run only when `Write` is true. Otherwise both are `skipped` with "not tested; run waggle doctor".
- A failed delete leaves the probe ref: report its exact name and the delete command. Never retry with force.
- **Claim storage fallback.** If `custom-refs` is `missing`, D-067's fallback is claims on a dedicated branch. That backend is not built (section 10). The finding says so plainly: "This remote rejects refs/waggle/*. Claims cannot be shared through it. Branch-based claim storage (D-067) is not built yet." Waggle never switches storage on its own.

### 6.2 GitHub probes (read-only API calls)

| ID | Call | Required |
| :--- | :--- | :--- |
| `auth` | `GET /user`, `GET /repos/{o}/{r}`: login, `permissions.push` and `admin` | yes |
| `merge-commits` | `allow_merge_commit` from the repo object | yes (D-017) |
| `required-gate` | `GET /repos/{o}/{r}/rules/branches/{default}`: a `required_status_checks` rule whose contexts include `GateCheck` | yes |
| `up-to-date` | Same rule, `strict_required_status_checks_policy: true` | yes when `merge_strategy` is `up_to_date` |
| `merge-queue` | Same rules list, a `merge_queue` rule | yes when `merge_strategy` is `native_queue`; otherwise reported as info |
| `auto-merge` | `allow_auto_merge` | no |
| `actions` | `GET .../actions/permissions` `enabled`; `GET .../actions/workflows` has the shim path `active`; `GET .../actions/runs?event=pull_request&per_page=1` is 0 while `GET .../pulls?state=all&per_page=1` is non-empty | yes |
| `bypass` | `GET .../rulesets` then each ruleset's `bypass_actors` | no (Tier 3 merges rely on it, T-014 section 6) |
| `bot` | none in v0.1 | no: always "not configured" (section 3.2) |

Rules for interpreting answers:
- **Capabilities, not account types (D-067).** No code branches on `owner.type` or plan names. A personal repo that lacks merge queue reports `merge-queue` exactly as an org repo on a plan without it does. The report may print the owner type as information only.
- A 403 or 404 whose message says the feature needs another plan or a public repo is `missing` with "not available for this repository on its current plan". A 403 for lack of permission is `unknown` with "needs repo admin; rerun with an admin login". Classic branch protection (`GET .../branches/{b}/protection`) is read only to explain a `missing` rules result; it needs admin, so a 403 there adds nothing.
- `actions` covers the `waggle-sh/waggle` case from T-019 section 5: Actions enabled, workflow active, PRs exist, zero runs. Summary: "GitHub Actions has never run for a pull request here. The gate cannot check anything." Fix: the T-019 section 5 list.

## 7. Report and commands (phase C)

### 7.1 Report format (`report.go`, phase A renders it; phase C fills it)

```
Waggle setup check: github waggle-sh/waggle (remote origin)
Auth: gh CLI as paulternate (admin)
Claims: refs/waggle/claims/* on origin
Merge strategy: up_to_date
Enforcement: advisory (main has no required checks)

  ok        custom-refs     refs/waggle/* can be pushed and deleted.
  ok        atomic-push     The remote accepts atomic multi-ref pushes.
  missing   required-gate   No rule on main requires the verify-leases-and-tiers check.
                            Not enforced: a pull request can merge with a failing or missing Waggle gate.
                            Fix: add a branch ruleset on main that requires verify-leases-and-tiers.
  unknown   bypass          Ruleset bypass list is not readable with this login.
                            Not enforced: cannot confirm only the Head Keeper can merge Tier 3 changes.
                            Fix: rerun waggle doctor as a repo admin.
  skipped   merge-queue     Not used: merge_strategy is up_to_date.

Not enforced on this repo (2):
  - A pull request can merge with a failing or missing Waggle gate.
  - Cannot confirm only the Head Keeper can merge Tier 3 changes.
Waggle runs here, but it cannot stop the merges listed above.
```

- Fixed order: header, findings in table order, then the "Not enforced" summary. Deterministic; golden-tested.
- **Every `missing` or `unknown` finding carries a `Not enforced:` line and a `Fix:` line.** `unknown` counts as not enforced. Nothing is hidden or softened; this is what "never silently degrades" means.
- `Enforcement` is the mode the check picks: `enforced` when `required-gate` (and `up-to-date` or `merge-queue` for the configured strategy) are `ok`; otherwise `advisory`. `Claims` names the storage in use (`refs` is the only one built).
- **`none` forge.** Header `Waggle setup check: none (remote origin)` or `(local-only, no remote)`. Fixed finding: "No code host. Not enforced: nothing outside Waggle runs the gate or blocks a merge; anyone with git access to main can merge anything. Fix: none needed for a solo local hive; use provider github to get enforced checks."
- Plain words only: no decision IDs, no em or en dashes, lines under 100 columns.

### 7.2 `waggle doctor` (`cmd/waggle/doctor.go`)

```
waggle doctor [--repo <dir>] [--no-write]
```

- Loads config with T-004's `config.Load` (`layout.Config`), builds the forge with `forge.New`, runs `Probe` with `Write: !noWrite`, prints the report to stdout.
- Prints one line before any write probe: `Testing pushes to <remote> with temporary refs under refs/waggle/probe/ (deleted afterwards).`
- Exit codes: `0` every required finding `ok` or `skipped`; `1` any required finding `missing` or `unknown`; `2` usage; `3` config, git, or transport error before a report could be built. `runDoctor(args []string, stdout, stderr io.Writer, getenv func(string) string) int`, no `os.Exit` inside.
- Never edits config, never changes repo settings, never creates rulesets. It reports and points to the fix.

### 7.3 `waggle init` hook (`internal/scaffold/init.go`)

After files are written:
- `forge.remote` empty (the template default, D-007): print one line, `Local-only hive: no forge checks. After adding a remote and setting forge.remote, run waggle doctor.` No network.
- `forge.remote` set: run `Probe` with `Write: false` and print the report. Init's exit code does not change on findings; it never fails because a repo enforces less than it could.

## 10. Claim storage on a branch (D-067 fallback): follow-up, not this ticket

If a host rejects `refs/waggle/*`, claims move to a dedicated branch. `internal/comb` would need a **second storage backend**:
- Branch `waggle/claims` with an orphan history; tree `ticket-<n>/lease.json`. Acquire, renew, takeover and release are each one commit.
- CAS on the branch tip with a plain fast-forward push (no force). A rejected push re-reads the tip and retries only if this ticket's file did not change; otherwise the same lost-race errors as T-002.
- All claims serialize on one ref, so contention rises with Keepers. T-005's audit becomes commits on the same branch.
- `Backend` (acquire, release, list) already abstracts most of it, but `ClaimOID`, T-005's `ForceRelease` and T-014's `ReadClaim` are methods on `*GitBackend` only. They would move behind a second interface both backends implement. The gate, signature check (D-068) and WORKPLAN renderer read claims through that interface instead of ref names.
- About 350 to 450 non-test lines plus a parallel test suite.

**Recommended: a follow-up ticket after v0.1** (Q-T018-1). GitHub accepts `refs/waggle/*` and is the only v0.1 forge (D-069), so nothing in v0.1 needs it. T-018 detects the rejection and says so (6.1). Keep one rule now for T-005 and T-014: claim reads go through one function each, so the swap is local later.

## 11. Tests

All git-backed tests skip without git and use `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `t.TempDir()`. No test touches the network: GitHub tests use `httptest.Server` (token transport) and a fake `gh` via the helper-process pattern (`GO_WANT_HELPER_PROCESS`).

**Phase A**
1. `none.OpenChange` returns the branches, no number, no URL; an invalid branch name errors.
2. `none.Merge` writes a two-parent commit on `Base` with the exact subject and body; the working tree and index are unchanged.
3. `none.Merge` with a stale `ExpectedHeadOID`, or `Base` moved between read and write: `ErrHeadMoved`, no ref change.
4. Conflicting branches: `ErrNotMergeable` naming the path, no ref change. `Auto: true`: `ErrUnsupported`. `Comment`: `ErrUnsupported`.
5. With a bare remote: the merge is pushed with a lease; a concurrent push to `Base` on the remote gives `ErrHeadMoved`.
6. Report renderer golden files: all four statuses, the summary, the `none` header and fixed finding, `advisory` and `enforced`. No U+2013 or U+2014 in output.
7. Annotator: T-014 test 15's injection strings produce no unencoded newline and no second `::`; plain format when `GITHUB_ACTIONS` is unset.

**Phase B**
8. Auth order: gh logged in wins over a set token; gh missing uses the token; neither gives `ErrNoForgeAuth`; gh present but logged out falls through to the token.
9. Remote parsing table: the three accepted URL forms with and without `.git`; `gitlab.com`, a GHES host, an owner with `_`, a repo named `..`, and an empty remote all rejected.
10. `OpenChange`: request body fields; 422 path returns the existing PR.
11. `Merge`: body has `merge_method: merge` and `sha`; 409 gives `ErrHeadMoved`; 405 gives `ErrNotMergeable` with GitHub's message; `Auto` sends `mergeMethod: MERGE` and `expectedHeadOid`.
12. A known token value never appears in any error string, argv of the fake `gh`, or captured output.

**Phase C**
13. Git probes against a local bare remote: `ok` for both; a `pre-receive` hook that rejects `refs/waggle/*` gives `custom-refs` `missing` with the not-built sentence; `receive.advertiseAtomic=false` gives `atomic-push` `missing` while `custom-refs` stays `ok`; no probe ref remains afterwards.
14. `Write: false`: both write probes `skipped`, no push attempted (bare remote's refs unchanged).
15.
