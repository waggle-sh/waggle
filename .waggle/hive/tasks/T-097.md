## 1. Goal

The failure lines the gate and doctor print are the first thing a user searches for, and the docs only mention a few.

## 2. Scope

- New `docs/troubleshooting.md` covers at least ten failure lines, each a quoted message exactly as printed by `waggle gate verify`, `waggle doctor` or `waggle claim` (for example `claim names no branch`, `path is outside the claim directories`, `symlink or submodule mode`), the cause in one sentence, and the fix command. Each entry names the exit code.
- One link each in `README.md` and `docs/recipes/README.md`.
- `site/scripts/sync-docs.mjs` maps the page to `troubleshooting`, so the site build still passes. If node 22 is available, `cd site && npm ci && npm run build` passes, otherwise the PR body says it was not run.
- New `cmd/waggle/docs_messages_test.go` extracts each quoted message from the page and fails when no non-test Go file under `cmd/` or `internal/` contains it (matching the static part of a format string).
- Plain terms per CONTRIBUTING (task, claim, lease; bee words only with a gloss).

## 3. Checks

`go test -race ./cmd/waggle/...`, vet, gofmt, site build if node is present.
