## 1. Goal

Show each Keeper's Nectar from the CLI, so a Keeper or a maintainer can read it from any clone without a hosted service. Explain one task's credit, including every rule that gave it less than full credit (RFC 1 "Nothing is excluded silently"). Give Quorum and any static site a stable JSON export. No public dashboard is required (RFC 2, 9.1).

## 2. Scope

1. **`waggle nectar [--repo <dir>] [--keeper <id>] [--now <rfc3339>] [--recompute] [--json]`** (RFC 9.1).
   - Loads config, fetches receipts (item 3), and resolves its inputs once: `Main` is the commit OID of `main` by `dispatch.ResolveBase` with `forge.remote`, `Receipts` is the OID of `refs/waggle/receipts/main` or the zero OID when the ref is absent, `RulesVersion` is 1, and `Repo` is `owner/repo` parsed from the URL of `forge.remote` in the GitHub forms `githubRepo` accepts, else the empty string (it is display only; T-054 never reads it). It then calls `nectar.Score` with those values (T-051 section 2.2 item 1), so a receipt or commit that lands during the run never changes the output.
   - Prints a table with the RFC 9.1 columns `keeper_id`, `nectar`, `matured`, `pending`, `clawed_back`, one row per Keeper in the report's order, numbers at exactly 3 decimals as in the report. Then one counts line from `Report.Counts` with `unbound`, `unattributed`, `orphaned`, `unmerged`, `incomplete`, `third_party`, `fork_mismatch`, `self_merge`, `carried` and `unconfirmed_revert`, and, when any id is excluded, one line listing each excluded `keeper_id` and its weight (RFC 3.1). Then the `main_sha`, receipts OID and `rules_version` scored. A count of 0 still prints.
   - `--now` defaults to the wall clock, read only here in the CLI shell, never inside `Score` (RFC 7). An unparsable value is a usage error.
   - `--keeper` keeps only that row; with `--json` the shape is unchanged, with one or zero `keepers` entries. An invalid id (D-016 pattern) is a usage error.
   - `--recompute` sets `Input.Recompute`.
   - `--json` prints exactly the RFC 9.2 object (`json.Marshal` of the `Report`, which is `Report.Summary`, T-051 section 6), nothing else on stdout, with a trailing newline. Warnings go to stderr.
2. **`waggle nectar explain <task> [--repo <dir>] [--now <rfc3339>] [--json]`** (RFC 9.1). For one task, from `Report.Units`: its unit commit or commits, `merged_at`, `first_seen` when the direct-push rule applied, `matures_at`, state (`pending`, `matured`, `clawed_back`, `dropped`, `orphaned` with `rewritten` or `missing`, `unbound`, `unattributed`), weight with its `tier`, `size` and `review` factors, `changed_lines` split into code and docs lines, and the excluded generated or lock files; owner and each co-keeper with their share; the alive ratio and clawed-back share when set; and the chosen receipt: OID, `source` (`release`, `backfill` or `gate_run`), `status`, `merge_proof`, `incomplete`, `released_by`, `pr_number`, `head_branch`, `approvers`, and **`pr_author` beside `keeper_id`** (RFC 8 "Fork mismatch", RFC 10; Q-T052-2). It prints each flag that is set, one line each: `third_party` (with "released by a maintainer" when `maintainer` is set, per T-051 Q-T051-6), `relay`, `fork_mismatch`, `direct_push`, `self_merge`, `carried`. Then each reason code with a plain sentence, one line each. A revert commit that names the task's unit is listed under it. `--json` prints `Report.Detail()` narrowed to that task's units, under `detail_version: 1`. An unknown or malformed task id is a usage error; a task with no unit on `main` prints "no merged unit for T-<id>" and exits 0.
3. **Receipts.** Before scoring, when `forge.remote` is set, the command fetches `refs/waggle/receipts/*` through the T-051 phase A sync (non-forced), per Q-T052-3. A fetch that fails for the network warns on stderr and scores the local receipts, and the counts line says "local receipts only".
4. **Exit codes** (RFC 9.1, Q-T052-4): 0 success; 1 a scoring finding (any `orphaned` or `unattributed` unit, or `receipts rewound`); 2 usage; 3 unreadable repo, config or receipts. The finding still prints its full output before exiting 1, and `--json` output is the same on exit 0 and 1.
5. **Help text** passes `checkPlain` (`cmd/waggle/plain_terms_test.go`): no "Keeper", no "hive", no dashes. Suggested summary line for `main.go`: `nectar    Reputation from merged tasks that last 30 days on main without a revert: waggle nectar [explain <task>] [--json]`.
6. **`docs/nectar.md`.** A plain user doc: what the number is (a merged task's weight, `tier x size x review`, with docs at half weight), the 30-day window, clawback on revert with no time limit, re-landing restarting the clock, where owners come from (receipts written by `waggle release`, by `waggle nectar backfill`, and by the gate's post-merge job for claims that expire or fork contributors, T-051 phase D), what each count and flag means, the two commands and their exit codes, the JSON shape (linking RFC-0005 9.2), and the limits: receipts are writable by anyone who can push `refs/waggle/*`, forge facts are what the forge said when the receipt was written, a receipt written offline is `incomplete`, and a repo that allows force-push to `main` can rewrite the score (`docs/gate.md` receipts entry from T-051 phase A). The doc says "reputation score", with "Nectar" only as the command name (D-236).

## 3. Must stay

- Scoring rules and the RFC 9.2 shape are T-051's. This ticket does not change, reorder, rename or recompute any field; `--json` is `Report` marshalled as T-051 defines it, and `explain --json` is `Report.Detail()` narrowed by task.
- Determinism: with a fixed `--now`, two runs on the same clone, and two clones with the same remote repo, `main` and receipts, give byte-identical `--json` output, with or without the cache.
- No hosted service, no network other than the receipts fetch, no forge call (`pr_author` and `approvers` come from the receipt), no file written in the worktree, nothing committed.
- Other commands' output, including `waggle status`, does not change.
- VISION item 5: nothing in this ticket narrows what Nectar measures or who sees it. A display choice that would hide a Keeper's score, a clawback or any count from the CLI is a CUT and goes to the Head Keeper.

## 4. Out of scope

- Scoring (T-051) and Quorum weights (T-053, T-054). `sqrt(nectar)` is never printed here.
- A public dashboard, a hosted page, a README badge or a signed snapshot (RFC 7, 11.3 question 9).
- A Nectar line in `waggle status` or `waggle hives status` (follow-up candidate).
- The site page (`site/`, follow-up under the site lease) and a `README.md` command-list line (follow-up; README is code-owner gated).
- Confirming an `unconfirmed_revert` (RFC 11.3 question 4): shown, not editable here.
- Any forge call from `waggle nectar` or `explain`. The accepted RFC puts `pr_author` in the receipt, read once at write time (RFC 6.2), so the earlier draft's forge lookup option is no longer needed.
- Choosing tuned values (T-051 section 12 item 9). This command is the tool for it, not the decision.

## 6. Threat model (D-203)

**Boundary.** The command reads `main`, receipts and config, and prints. Its trust is the scorer's (T-051 section 7). The new risk is presentation: a reader trusting a number the inputs do not support.

**Must-fix:** a table or `explain` that hides `orphaned`, `unattributed`, `unmerged`, `incomplete`, `third_party`, `fork_mismatch`, `relay`, an excluded id or `receipts rewound`; `explain` without `pr_author` beside `keeper_id` when the receipt has one; a finding that exits 0; `--json` that differs from `Report` or carries anything but the 9.2 object on stdout; `--keeper` that changes another Keeper's numbers; scoring at a live ref instead of the OIDs resolved once; any wall-clock read outside the CLI shell; any forge call; a help or error line that fails `checkPlain`; files outside the lease rule; any em or en dash added.

**Note, not must-fix:** a reader on a clone that has not fetched receipts sees fewer attributed units; the fetch in section 2 item 3 narrows this, and the counts line shows it. `third_party`, `relay` and `pr_author` are self-asserted receipt fields (T-051 F4); the doc says so.

- N1: table: two Keepers, one pending unit, one clawed-back unit; columns, order, 3-decimal numbers, the counts line (every count, zeros included), the excluded line and the `main_sha` and receipts line match a golden.

- N3: determinism: two runs, and a run after deleting the cache, give identical `--json`; `--recompute` gives the same; `main_sha` is the OID `ResolveBase` gave.

- N5: `--keeper` filter: one row; unknown id: zero rows, exit 0; invalid id: exit 2.
- N6: `--now` before and after day 30 moves a unit from pending to matured; a bad `--now` exits 2.
- N7: exit codes: an orphaned receipt exits 1 with full output; an unattributed unit exits 1 with full output; a fixture with neither exits 0; a missing repo or unreadable config exits 3; an unknown flag exits 2.
- N8: `explain` for a matured, a pending, a clawed-back (late revert), a re-landed, a dropped (survival), an orphaned, an unbound and an unattributed task: each prints its state and reason lines. - N10: receipts fetch: with a local bare remote holding one more receipt, the score includes it; a rewound remote head exits 1 with `receipts rewound`; an unreachable remote warns and the counts line says "local receipts only".
- N11: `repo`: an https and an ssh GitHub remote URL give `owner/repo`; any other URL or no `forge.remote` gives the empty string.
- N12: `nectar -h` and `nectar explain -h` pass `checkPlain`, added to `TestHelpPlainTerms`.

## 10. Questions for the ruling

- **Q-T052-1: command name.** (a) `waggle nectar`, as RFC 9.1 names it, with plain help text. (b) A plain name such as `waggle reputation`. **Recommended: (a).** It matches the RFC, Quorum and the hive records; the plain-terms check bans "Keeper" and "hive" in help text, not "nectar", and VISION guard 4 lets help text stay plain around it.
- **Q-T052-2: who is shown beside `keeper_id` in `explain` (RFC 8, 10).** The accepted RFC 6.2 puts `pr_author` in the receipt, so the earlier forge-lookup option is gone. (a) The receipt's `pr_author` and `released_by`, and, when `pr_author` is null (an `incomplete` or direct-push receipt), the git author of the completing commit, labeled as such. (b) `pr_author` and `released_by` only. **Recommended: (a).** It needs no token, stays deterministic, and still shows something for offline receipts, where a squash author is usually the PR author.
- **Q-T052-3: fetching receipts.** (a) Fetch `refs/waggle/receipts/*` from `forge.remote` when set, before scoring; on a network failure, warn on stderr, score the local receipts and say so in the counts line. (b) Never fetch; the reader runs `git fetch` first. **Recommended: (a).** A clone that never fetched receipts shows every task as `unattributed`, which reads as a zero score; `git fetch` does not fetch `refs/waggle/*` by default.
- **Q-T052-4: exit 1 on `unattributed` (RFC 9.1).** RFC 9.1 makes any `unattributed` unit a scoring finding (exit 1). Every repo with history from before receipts has some, so `waggle nectar` would exit 1 there indefinitely and could not gate a script on exit 0. (a) As RFC 9.1: exit 1 on `orphaned`, `unattributed` or `receipts rewound`; the full output still prints. (b) Exit 1 on `orphaned` and `receipts rewound` only; `unattributed` is shown in the counts line and exits 0. **Recommended: (a)** until the Head Keeper says otherwise, since it is the accepted text and hides nothing; (b) is a one-line change and a better fit for scripts, and if wanted it belongs in the named fix to RFC 9.1, not in this ticket.
