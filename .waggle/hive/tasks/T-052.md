## 1. Goal

Let anyone with a clone read every Keeper's Nectar from the CLI without a hosted service: one table, every count of a rule that gave less than full credit, and the exact inputs it was scored at (RFC 1 "Nothing is excluded silently"). Let a Keeper see why one task earned what it did, with `pr_author` beside `keeper_id` (RFC 8, 10). Give Quorum, hand replays and static sites one export: `waggle nectar --json` prints exactly the RFC 9.2 object `Score` returns (RFC 9.1).

## 2. Scope by phase

### 2.1 Phase A: summary, export and inputs (RFC 7, 9.1, 9.2)

1. **Flags.** `--repo` defaults to `""`, the current work tree root, as `waggle status` does (`status.go:54`). `--main` and `--receipts` exist only under Q-T052-6 (a).
2. **Inputs, resolved once, in this order.**
   - Config and backend as `loadStatus` does (`status.go:130-142`). Under `--no-fetch` or with no `forge.remote`, set `opts.Remote = ""` (as `status.go:138-140` does), so `ReadReceipts` does not sync.
   - **Receipts first.** With a remote and no `--no-fetch`, call `ReadReceipts` for its sync only. A receipt is written only after its merge, so the `main` fetched next holds every `merged_sha` the receipts name (force-push aside). The reverse order can count a just-released task `orphaned`.
   - **Then `main`:** `dispatch.ResolveBase(ctx, g, forge.remote, "")`, which fetches and resolves `refs/remotes/<remote>/main`. Under `--no-fetch` with a remote: `remote` empty, explicit base `refs/remotes/<remote>/main`. No remote: both empty (`refs/heads/main`). Any `ResolveBase` error exits 3, including its `ExitUsage` for a missing explicit base.
   - **Fetch errors.** `ErrReceiptsRewound` warns, skips the `main` fetch, scores local state, prints `receipts rewound` and exits 1. Any other error from either fetch warns once on stderr, skips the remaining fetch and scores local state with `local only`. Neither API marks network errors, so the code does not try. Errors after the fetches exit 3.
   - **Pins.** `--main` and `--receipts` must be hex of the repo's object format length (T-051 2.2 item 1), checked before any git call. Fetches still run unless `--no-fetch`. `--main` replaces the resolved `main` after `git rev-parse --verify --quiet <oid>^{commit}`; no match exits 3 naming it. `--receipts` accepts the zero OID (no receipts).
   - `Receipts` is `--receipts`, else `git rev-parse --verify --quiet refs/waggle/receipts/main^{commit}`, else the zero OID. `Repo` is `owner/repo` when `forge.remote`'s URL matches `parseGitHubURL`'s regexp and patterns, else `""`. `RulesVersion` is 1. `Now` is `--now`, else `statusClock()`, read once (RFC 7).
   - One `nectar.Score` call, `Recompute` from `--recompute`. Later commits or receipts never change the output. A `--receipts` OID `Score` rejects exits 3 naming it.
3. **Table.** Columns `keeper_id`, `nectar`, `matured`, `pending`, `clawed_back`, `units`, one row per `Report.Summary.keepers` entry in order, numbers as given (3 decimals). `units` is added to RFC 9.1's five so a Keeper at `0.000` with pending work reads as active. No keepers: the header and `no attributed units`.
4. **Trailing lines**, always, zeros printed:
   - `counts:` every scalar of `Report.Counts` (`unbound`, `unattributed`, `orphaned`, `unmerged`, `incomplete`, `third_party`, `fork_mismatch`, `direct_push`, `self_merge`, `carried`, `unconfirmed_revert`);
   - `excluded:` each excluded id and weight, or `none`;
   - `reciprocal pairs:` each pair and share, or `none`;
   - `scored:` `main <oid>`, `receipts <oid or none>`, `rules_version 1`, `at <computed_at>`, `repo <owner/repo or (none)>`, then `local only` or `receipts rewound`. OIDs print in full; `receipts none` means omit `--receipts` or pass the zero OID.
   Every receipt or config string passes `clean` (`claim.go:96-103`).
5. **`--json`.** `json.Marshal(report)` plus one newline. Nothing else on stdout ever: warnings go to stderr; a failure with `--json` leaves stdout empty (Q-T052-5). `--keeper`: Q-T052-2.
6. **Exit codes** (Q-T052-4, Q-T052-5): 0 success; 1 a finding (any `orphaned` or `unattributed` unit, or `receipts rewound`), with full output and the same `--json` bytes; 2 usage (unknown flag, extra argument, bad `--now`, a `--keeper` failing `comb.ValidKeeperID` (t-051a2 `receipt.go:185`), a malformed pin); 3 not a Waggle repo, config invalid, `relay` mode (`ErrRelayNotImplemented`), a pin that does not resolve or `Score` rejects, any error after the fetches.
7. **Help.** A new summary usage constant; passes `checkPlain` (`plain_terms_test.go:20-39`: no "Keeper", "queen", "Cells", "waggled", no "hive" outside a `.waggle/hive/` path, no dash) in `TestHelpPlainTerms`. It says "reputation score", and "release records" as T-051's help does. Suggested `main.go` line: `nectar    Reputation score from merged tasks that last 30 days on main without a revert: waggle nectar [--json]; backfill adds missing release records`. Phase B adds `[explain <task>]`.

## 6. Threat model (D-203)

**Boundary.** Reads config, `main`, the receipt chain and T-051's cache; fetches from `forge.remote` with the user's git auth, as `status` and `dispatch` do. Trust in the numbers is the scorer's (T-051 section 7). New risks: presentation (a number the inputs do not support, a partial export read as whole) and terminal output of strings a receipt writer chose.

**Defended.** Every count and flag prints, zeros included. The inputs line names the OIDs and `local only` or `receipts rewound`. Receipts sync before `main`, so a mid-run release cannot show `orphaned`. A rewound chain is never taken and exits 1. `clean` stops a crafted `head_branch` or `released_by` from moving the cursor or forging a line. Pins are hex OIDs only, so no value reaches git as an option.

**Not defended (note).** An unfetched or `--no-fetch` clone shows fewer attributed units; the inputs line says so. Self-asserted fields show as stated, and the doc says so. Anyone who can push `refs/waggle/*` can delete the receipt ref; clones that hold it keep it.

**Must-fix:** any count, flag, excluded id, reciprocal pair or `receipts rewound` hidden, or a zero not printed; `pr_author` not beside `keeper_id`; an unknown reason code dropped; a finding that exits 0; `--json` other than `json.Marshal(report)`, or anything else on stdout; `--keeper` changing another Keeper's numbers or yielding a partial 9.2 object; scoring at a live ref; `main` fetched before receipts; a wall-clock read outside the CLI shell; a forge API call; a string printed without `clean`; a pin passed to git unchecked; help or errors failing `checkPlain`; a change to `nectarUsage` or `backfill -h`; files outside the lease rule; an added em or en dash.

## 10. Findings and questions for the ruling

- **F1 (Head Keeper): the export cannot be replayed alone.** 9.2 has `main_sha` and `computed_at` but no receipt head (`docs/RFC-0006-quorum.md:266`). **Recommended:** the named T-050 fix adds `"receipts_sha": "<40 hex, or null>"` to 9.2 at `schema_version: 1` before T-051 phase B dispatches (no reader exists yet): about 3 lines in T-051 phase B, its B12 golden, and T-054 section 6's fixture and parse (`T-054.md:53`, `:120`). This ticket then needs no change.
