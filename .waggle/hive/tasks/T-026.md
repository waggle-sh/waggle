## 1. Goal

product-ci flakes in `internal/dispatch` because fixture repos still start detached `git maintenance run --auto` (or `gc --auto`). Two failures are on record: maintenance rewriting `info/refs` under the post-run host-state check (`reviews/T-023c-reopus.md` R2), and `t.TempDir` cleanup failing with a non-empty directory (`TestRunBaseAndBranch/remote_tracking_only`, product-ci run 39604347542 at `c211ea0`).

`shIn` (`dispatch_test.go:30`) passes `-c maintenance.auto=false` to the git it runs. That covers only that client process. When a fixture pushes to a local bare `origin.git`, git runs `git-receive-pack` in the origin with `GIT_CONFIG_PARAMETERS` and `GIT_CONFIG_COUNT` cleared (local transport drops them), so the origin reads only its own config and runs auto maintenance after the receive. The same is true for pushes made by `Run` itself and by the fake worker's own `git commit`.

Fix: every repo a fixture creates, bare or not, gets the keys in its own repo config right after `init` or `clone`, before any commit, push or `Run`:

```
maintenance.auto=false
gc.auto=0
receive.autogc=false
```

## 2. Work

3. Keep `shIn`'s `-c maintenance.auto=false`; add `-c gc.auto=0` beside it.
4. Add one git-only test (no `Run`, no tracker, no signals) that builds `newFixture(t, true, false)` and asserts `git config --get` returns `false`, `0` and `false` for the three keys in both the work repo and `origin.git`, and the same for `newRepo`.
5. Do not change any non-test file. If a product change looks needed, stop and say so in the final report; do not make it.

Expected interaction: the host record hashes the common git dir's `config` (T-023 7.1). The keys are written before any `Run`, so the record each test takes already includes them. A test that compares `config` bytes across a run must still pass; if one fails because of the new keys, the fix is in that test's setup, not in product code.

## 6. Threat model (D-203)

Must-fix: a change outside `*_test.go`; a fixture still able to start auto maintenance in a repo that a test pushes to or runs `Run` against; a new test that signals a process, calls `sweep()` or goes through `Run`; a weakened assertion in an existing test. Note, not must-fix: auto maintenance started by a git the test does not control (a global or system config is already replaced by `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1`), or an attack that needs write access to the git dir, to `.waggle/worktrees/` outside the worker's own tree or to another ticket's worktree, since each can do the same damage directly.
