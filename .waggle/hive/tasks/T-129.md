## 1. Goal

Implement the tracker-neutral `Tracker` interface (T-127) for Linear issues over its GraphQL API: list issues by label or filter, read comments with server times, post and edit a comment, set and clear assignee and label, read the caller and the server time, and list the workspace admins (the T-141 owners default). Turn on the `linear:KEY-N` reference form that Level 1 reserves and refuses, and add `priority.source: linear` (current cycle first, then Urgent to Low, then No priority).

## 2. Scope

- No change to the v1 claim format or the claims core: if Linear needs one, that is a finding against D-412's tracker-neutral rule and goes to a card, not into this build.
- `LINEAR_API_KEY` read from the environment only, never logged or echoed.
- Fail closed when Linear is unreachable.
- The Linear threat model in T-124 section 10 (workspace membership as the trust boundary, the key as a full-access secret).
- Tests against a recorded fake server; one opt-in live test against the test workspace, with a short live check (a claim, a race and an expiry on a Linear team) the brief defines.

## 3. Out of scope

- Linear webhooks and `/claim` comments on Linear (need the hosted App, T-140). OAuth (unless the auth question picks it).
