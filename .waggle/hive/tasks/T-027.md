# T-027: Dispatch tells the worker its allowed Bash forms and turns off Claude Code's commit attribution

- **Status:** Brief written by the scout on 2026-10-22 from the T-023 phase F trial report (`media/T-023/trial/report.md`, "Not covered by the runbook", items 2 and 7). Not dispatched. Built through `waggle dispatch` (cutover D-220). Questions Q-T027-1 to Q-T027-3 are open; each has a recommended option, and the brief is written to the recommendations.
- **Layer:** `product` (`internal/runtime/`, `internal/dispatch/`). Nothing in `.waggle/` changes; the hive's own role files stay as they are (Q-T027-1).
- **Gate:** `full`
- **Risk Tier:** Tier 3 by content (T-023 rule): the change edits the settings file and prompt every worker runs under. Two guards (D-100, D-205): the policy guard, then `--second`. Head Keeper approval at merge.
- **Role:** `builder` (dispatch), `guard` (dispatch, twice).
- **Lease (rw):** `internal/runtime/`, `internal/dispatch/`
- **Lease rule:** only `internal/runtime/launch.go`, `internal/runtime/runtime.go`, `internal/dispatch/inputs.go`, `internal/dispatch/guard.go`, `internal/dispatch/run.go`, `internal/dispatch/check.go` and `*_test.go` files in the two directories may change. Any other file is a must-fix.
- **Bash forms:** Bash takes one command per call, in exactly these forms: `go build ./...`, `go vet ./...`, `go test -race ./... -run '<regexp>'` (the package path is always `./...`, never `./internal/runtime` or `./internal/dispatch`), `git add <paths>`, `git commit -s -m "T-027: ..."`, `git status`, `git diff`, `git log`, `git show`. `go test` always takes `-run`, never bare; section 4 decides which tests may run, so the regexp names only the tests it allows, never `TestRun*`, `TestGuard*`, `TestClean*` or `reap_*`. A `|` inside the quoted regexp should pass, since it is one shell word; if that call is denied, run one `-run '<name>'` per call instead. No `cd`, no `&&`, `;`, pipes or redirects, and no other commands (`python3`, `gofmt`, `grep`, `cat` and the rest are denied); the Read, Grep, Edit and Write tools stay available. `gofmt` is not allowed, but product-ci fails on any `gofmt -l` hit, so write gofmt-clean code by hand with the Edit tool (tab indentation, no trailing spaces, keep the alignment of the surrounding code); `go vet ./...` does not check formatting. A denied call means that form is not allowed, not that Bash is off.

## 1. Goal

Two trial findings, one cause each.

Follow-up 2: the worker's `settings.json` allows `Bash(<cmd>)` and `Bash(<cmd> *)` for each WAGGLE.md section 3 command and each `gitAllowed` entry (`workerSettings`, `launch.go`), under `dontAsk`. Nothing tells the worker that. In trial run 1 try 1 the builder made two compound calls, both were denied, it read the denial as "Bash is off" and stopped uncommitted. T-026 fixed it with a hand-written Bash forms bullet in the brief; every brief since copies one. The fix belongs in the product, generated from the same list `workerSettings` turns into allow rules, so the two cannot drift.

Follow-up 7: the builder committed with a `Co-Authored-By: Claude` trailer, which the queen had to drop when rewriting the commit for merge. Dispatch sets no attribution setting for the worker.

## 2. Design

### 2.1 One allowlist, two consumers

Add an exported function in `internal/runtime/launch.go`, for example `BashCommands(role string, commands []string) ([]string, error)`. It returns the hive commands followed by `gitAllowed`, minus `git add` and `git commit` for a guard, after the same validation `workerSettings` applies today (plain words, no wildcard, quote, control character, shell operator or rule syntax, no denied program, no `git push`). `workerSettings` calls it and builds the allow rules from its result, so the validation and the role filter live in one place. A refused command keeps the current `ErrAdapterConfig` error and exit 3.

In `Run`, compute `cmds` with `runtime.BashCommands(req.Role, waggleCommands(in.WaggleMD))` before the task lines are built (today `cmds` is set after `BuildPrompts`, in the same step), and pass the result to both the task lines and `Prepare` (as `Invocation.Commands`, which `Prepare` then must not filter a second time; or pass the raw list to `Prepare` and the filtered list to the task lines, as long as both come from `BashCommands`). The refusal still comes before `AcquireClaim`, so a bad command writes nothing (T-023 10.6 item 4).

### 2.2 The Bash task line

`TaskLines` and `guardTaskLines` gain one line after `Gate:`, built from the `BashCommands` result. Suggested wording, in one line:

`Bash: one command per call, and it must start with exactly one of these: ` + each command in backticks, comma separated + `. Add arguments after them (for example go test -race ./... -run 'TestX'); do not change the listed words or the package path. No cd, &&, ;, |, redirects, subshells or other programs; use the Read, Grep, Glob, Edit and Write tools for files. A denied call means that form is not allowed, not that Bash is off.`

The `go test` example appears only when a `go test` command is in the list; with an empty list the line says `Bash: no commands are allowed; use the Read, Grep, Glob, Edit and Write tools.` (the `no_waggle_commands` warning already covers the record). The line goes in the variable prompt with the other task lines, so the stable prompt stays byte-identical across tasks (T-023 10.1). Command text comes from WAGGLE.md at base, which a hive PR controls; it is already validated as plain words, so it needs no further escaping, but the builder must not add anything to the line that comes from the brief or the run.

### 2.3 Attribution off

`workerSettings` adds `"attribution": {"commit": "", "pr": ""}` at the top level of the settings JSON, next to `permissions`.

How the key was checked: the scout searched the pinned Claude Code binary (2.1.308, `media/T-023/trial/versions.txt`) for its settings schema. It defines `attribution` as `false`, `true` or an object with `commit` ("Attribution text for git commits, including any trailers. Empty string hides attribution."), `pr` and `sessionUrl`, and marks `includeCoAuthoredBy` "Deprecated: Use attribution instead". The error text for a bad value names the form `{ "commit": "", "pr": "" }`. Not checked: that a value passed inline through `--settings=` is applied when `--setting-sources=` is empty. The binary has special handling for the `attribution` key in flag settings whose effect the scout could not read. That is Q-T027-2.

`Verify` does not check for the key (there is no help token for it, and a missing attribution setting is not a security flag): a version that drops it degrades to a trailer, which 2.4 then reports.

### 2.4 Trailer warning

In the post-run checks (`check.go`), after the commit range is listed, read each new commit's message through the pinned git (`log --format=%B` over the same `CheckBase..head` range, or one `show -s` per commit already walked) and, when any line of a message matches `^co-authored-by:` case-insensitively, add one warning to `result.json`: `attribution_trailer: <n> commit(s) carry a Co-authored-by trailer; drop it before merge`. The warning never quotes the message (commit messages are worker output). It is a warning, not a violation (Q-T027-3): exit code and push are unchanged.

### 2.5 Out of scope

- `includeGitInstructions: false` (removes Claude Code's built-in commit and PR workflow text from the worker's system prompt). It would also drop the trailer text, but it changes worker behavior well beyond attribution; a later ticket can weigh it.
- The hive's `.waggle/control/roles/*.md` and the scaffold's `internal/scaffold/templates/roles/*.md` (Q-T027-1).
- The Bash forms bullet in existing briefs: once this merges, new briefs drop it and the queen's "Dispatched workers" habit in `handoff/queen.md` is updated in the next records batch.

(b) Add one line to `templates/roles/builder.md`, `guard.md` and `forager.md` and the hive copies pointing at the `Bash:` task line. **Recommended: (a).** A role-file line adds a second copy and a Head Keeper control commit for no new information; (b) can follow if a worker still misreads a denial.
- **Q-T027-2: how to prove the attribution setting takes effect?** (a) Unit test asserts the key in the settings JSON, and the queen confirms on the first dispatched builder commit after merge (no trailer, and no `attribution_trailer` warning in `result.json`); if a trailer still appears, a follow-up tries `"attribution": false` or `includeCoAuthoredBy: false`. (b) Add a live probe to the build (a real `claude` session making a commit). **Recommended: (a).** A live session cannot run inside a dispatched builder (no network tools, and the worker cannot launch `claude`), and the 2.4 warning makes a silent failure visible on every run.

## 6. Threat model (D-203)

Must-fix: any change that widens what the worker's settings allow (a new allow rule, a dropped deny rule, a validation step skipped on any path, a command reaching the allow list or the task line without passing the same validation); a task line that carries text from the brief, the review files or the run (only base WAGGLE.md section 3 and the fixed `gitAllowed` list may feed it); a guard gaining `git add` or `git commit`; the refusal moving after `AcquireClaim`; the trailer scan echoing commit message text into `result.json` or stdout, or running git unpinned. Note, not must-fix: a Claude Code version that ignores the attribution key (2.4 reports it); a worker that ignores the `Bash:` line (the allow rules still decide); an attack that needs write access to the git dir, to `.waggle/worktrees/` outside the worker's own tree or to another ticket's worktree, or to base WAGGLE.md (a hive PR, Tier 3).

Guard prompt sentence (repeat verbatim): "Threat bar (D-203): a finding whose attacker needs write access to the git dir, to `.waggle/worktrees/` outside the worker's own tree or to another ticket's worktree, or a process that already escaped the tracker, is a note, not a must-fix; must-fix is for what a worker inside its lease, a guard or ordinary repo state can trigger, and for any signal or delete outside the worker's own tree from ordinary inputs."
