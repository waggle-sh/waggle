## 1. Goal

RFC-0003 section 3.3 lists "dependencies" under Tier 3 (Control Plane & Security), and the Tier 3 constant in `backend.go` (`Tier3ControlPlane` after T-011) says "dependencies", but nothing enforces it: `go.mod` and `go.sum` are Tier 0 today. A Forager can add a module, and with it arbitrary code that runs at build and test time, under a Light gate.

Add the root Go dependency inputs to the hardcoded Tier 3 list in the binary and in the CI gate, so every dependency change needs Head Keeper approval:

| Entry | Why |
| :--- | :--- |
| `go.mod`, `go.sum` | module requirements and checksums |
| `go.work`, `go.work.sum` | a workspace file can `replace` any module without touching `go.mod` |
| `vendor/` | when `vendor/modules.txt` exists, `go build` compiles vendored code instead of the module cache |

Go 1.23, module path as on `main` at dispatch (post-T-010), **standard library only**. Do not touch `go.mod` / `go.sum` (this ticket must not trip its own check).

## 2. Ordering and T-002 matching semantics

**Start only after T-011 merges**, and read the merged `backend.go` before editing. If T-002 or T-011 changed matching, **follow the merged code**; this ticket adds entries, it does not change matching.

As specified by T-002 and T-011 section 4:

| Function | Case | Entry without `/` (file) | Entry with `/` (directory) |
| :--- | :--- | :--- | :--- |
| `RequiredMinTier` (path classification, gate side) | **insensitive** since T-011 (hive carve-out exact case) | equal **or string prefix** (`.gitlab-ci.yml.bak` matches `.gitlab-ci.yml`) | equal to bare name or prefix |
| `isTier3Dir` via `touchesPrefixes` (lease side) | **insensitive** | same prefix rule, plus "contains" via `DirsOverlap` | same |
| Shell `case` in `waggle-gate.yml` | sensitive | **exact** | glob `dir/*` |

Consequences for the new entries, all accepted for this ticket:

- `go.mod.bak`, `go.sum.orig`, `go.work.old` classify as Tier 3 in Go (prefix rule) but not in the shell gate (exact). Same existing asymmetry as `.gitlab-ci.yml.bak`. Tests below assert **parity with the `.gitlab-ci.yml` root-file entry**, not a fixed answer, so they keep passing if matching changes. (Earlier drafts used `WAGGLE.md`; after T-011 it is no longer a root entry.)
- `GO.MOD` is rejected at lease time and classifies Tier 3 in `RequiredMinTier` (case-insensitive since T-011). Only the shell gate misses it; it stays case-sensitive and becomes advisory once T-014's Go gate lands.
- Entries are **root-anchored**. A nested module such as `tools/go.mod` and a nested `internal/vendor/` stay Tier 0 (deferred, section 11).
- Leases are directories and the repo root is already rejected, so at lease time the new entries add rejection of a lease on `vendor` (or anything under it) and of a lease literally named `go.mod`, `go.sum`, `go.work`, `go.work.sum` (or a case variant). The main effect is on path classification and the CI gate.

### 3.3 `internal/scaffold/tier_sync_test.go` (new)
A drift test so the Go list and both shell gates can never disagree again:

1. Read the embedded template via the package's `templateFS` (`templates/waggle-gate.yml.tmpl`).
2. Collect the `case` pattern lines by the message on the line after each: the Tier 3 set is every pattern line followed by a `Tier 3` warning; the Tier 2 set is every pattern line followed by a `Tier 2` notice (T-011 has two Tier 2 groups: the hive line and the glossary line). Fail clearly if either set is empty.
3. Parse each line: trim spaces, strip the trailing `)`, split on `|`. Normalize each pattern: strip a trailing `/*`, then a trailing `/`; dedupe (so `.waggle|.waggle/*` becomes `.waggle`).
4. Normalize the Go lists the same way: strip a trailing `/` (`vendor/` to `vendor`).
5. Assert set equality: Tier 3 vs `comb.HardcodedTier3Prefixes`, Tier 2 vs `comb.HardcodedTier2MinPrefixes`. On failure print both sets sorted. Also assert every directory entry (Go entry ending in `/`) appears in the shell line in its `/*` form, so a bare-only pattern cannot hide a subtree.
6. Read the repo's own `../../.github/workflows/waggle-gate.yml` (relative to the package dir, which is the test's working directory) and assert its Tier 3 and Tier 2 `case` lines are byte-identical to the template's. Fail, do not skip, if the file is missing: it exists in this repo and the test exists to catch drift.

If T-011 already added an equivalent drift test, extend it instead of adding a second one, and say so in the PR.

Importing `internal/comb` from a test in `internal/scaffold` is fine (stdlib-only package, test-only import).
