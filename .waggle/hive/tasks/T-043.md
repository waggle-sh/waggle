## 1. Goal

A repo owner can say, in one committed place, how hard agents may push a keeper's machine: one thing at a time, a fixed small number in parallel, or as much as fits while the machine stays responsive. Each keeper picks a pace within that bound for their own machine. Waggle then:

1. **Shows it:** `waggle status` prints one pace line, and `waggle doctor` prints one pace finding with the current load and memory reading (phase A).
2. **Renders it:** `waggle pace` prints, for each agent tool with a matching knob, the exact setting that applies the pace, and says plainly when a tool has no knob and the pace is advice only (phase A). It writes no file (Q-T043-9).
3. **Enforces it where Waggle runs the agent:** `waggle dispatch` refuses to start a run when system load is at or over the CPU target or available memory is under the floor (phase B). Dispatch already runs one run at a time per repo (section 3.1); running more than one at once is phase C, which needs its own design round (section 9).

Waggle never caps CPU or memory per process (D-321): it has no process of its own to cap since D-229 and D-231, and macOS gives no simple per-process CPU cap anyway (section 4, rows O6 and O7).

## 2. Behavior

### 2.1 Config: the owner's bounds (`config.yaml`, Tier 3)

A new optional top-level section, parsed by a new `config.ParsePace` in `internal/config/pace.go`, pure, following `ParseContext` (`context.go:30-58`): same subset parser (`parseTree`), same `invalid(line, path, ...)` errors wrapping `ErrInvalidConfig`, sorted keys, unknown keys fail. **Package direction, as for `context:`:** the `Pace` and `Settings` types, the profile words and the profile table live in `internal/pace`, which imports nothing from `internal/config`; `config.ParsePace` returns a `pace.Pace`, so `internal/config` imports `internal/pace`, as it imports `internal/runtime` for `runtime.ContextPolicy` (`context.go:7`).

```yaml
# Agent pace (D-321 to D-323). Keepers pick a profile in .waggle/control/local.yaml.
pace:
  profile: steady   # default for a keeper who picks none: serial | steady | max
  limit: max        # the fastest profile a keeper may pick
  max:              # optional per-profile overrides of the raw keys
    parallel_runs: 3
```

- `pace.profile` and `pace.limit` take a profile word (Q-T043-5). `limit` defaults to `max`; `profile` defaults to `steady`. `profile` faster than `limit` is a config error.
- `pace.serial`, `pace.steady`, `pace.max` each take any of the four raw keys: `parallel_runs` (1 to 64), `subagents` (1 to 256), `cpu_target_percent` (10 to 100), `memory_floor_mib` (0 to 1048576). Values are plain digits (`intValue`, `config.go:332`). An override must keep the profiles ordered (serial no faster than steady, steady no faster than max, key by key), or the section fails with the key path. "Faster" means a higher `parallel_runs`, `subagents` or `cpu_target_percent`, and a lower `memory_floor_mib`; the clamp in 2.3 uses the same direction.
- **Absent section:** no pace is set. `ParsePace` returns a zero `Pace` with `Set: false`; status, doctor and dispatch behave exactly as today (Q-T043-11).
- **The gate does not read its meaning.** `config.Parse` ignores top-level sections it does not name (`config.go:118-228` handles only `version`, `forge`, `leases` and `gate`), so neither `waggle gate` nor any older Waggle build checks what `pace:` says. A **semantic** error that the subset parser accepts (an unknown key, a bad profile word, a value out of range, unordered overrides, `profile` faster than `limit`) is caught only by `ParsePace`, which is called only by `pace`, `status`, `doctor` and (phase B) `dispatch`; such an error can never fail `config.Parse`, the gate or a merge. AC2 pins this. A **syntax** error is different: `parseTree` (`internal/config/yaml_subset.go:51-128`) runs over the whole file at `config.go:118-119`, so a `pace:` block the subset parser rejects (bad indentation, a tab, a sequence) fails `config.Parse` exactly as a broken `context:` or `runtimes:` block does today. That reaches the gate, which parses the base config (`cmd/waggle/gate_verify.go:287-293`), and `waggle status`, `waggle doctor` (exit 3 at `doctor.go:52-53`) and `waggle dispatch`. This ticket does not change that: the section lives in a Tier 3 file, so such a block lands only through a change the owner approves, and the commented template example (AC9) parses.

### 2.3 Resolution (`internal/pace/`)

`pace.Resolve(owner Pace, pick string) (Settings, []string)` is pure. It returns the four raw values and warnings:

- No pick: the owner's `profile`.
- A pick slower than or equal to `limit`: that profile's values (with the owner's overrides).
- A pick faster than `limit`: the `limit` profile's values, with the warning `pace: local.yaml picks <p>, above the owner's limit <l>; using <l>` (Q-T043-8 (a), clamp).
- An unknown word: the owner's `profile`, with the warning `pace: local.yaml profile <word> is not serial, steady or max; using <default>`. The word is printed through a filter that drops control characters, like the unexported `printable` in `internal/dispatch/hostrecord.go:106`, never raw.

### 2.4 Profiles (Q-T043-5 sets the final values)

| Profile | Meaning | parallel_runs | subagents | cpu_target_percent | memory_floor_mib |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `serial` | one thing at a time | 1 | 1 | 50 | 4096 |
| `steady` | a fixed small number in parallel | 2 | 3 | 70 | 2048 |
| `max` | as much as fits without pinning the CPU | 4 | 8 | 85 | 1024 |

`parallel_runs` is how many agent sessions or dispatch runs at once; `subagents` is how many subagents one session runs at once; `cpu_target_percent` is the load ceiling a new run must start under (2.5); `memory_floor_mib` is the available memory a new run needs. Pace never changes models, context profiles, guard counts or second guards (the D-075 rule for `context:` applies here too).

### 2.5 Load reading and the CPU target (Q-T043-7, Q-T043-10)

`pace.ReadLoad()` returns the 1-minute load average, the logical CPU count (`runtime.NumCPU`, row O8), and available memory when the platform documents it:

- **Linux:** `/proc/loadavg` (first field) and `MemAvailable` from `/proc/meminfo` (row O4). Fixed paths, opened read-only, read capped at 64 KiB.
- **macOS:** `syscall.Sysctl("vm.loadavg")` decoded as `struct loadavg` (row O3; `syscall.Sysctl` is already used for `kern.proc.all` at `internal/dispatch/reap_darwin.go:31`, so no new dependency). The layout on amd64 and arm64 (both little-endian) is three `uint32` values `ldavg[0..2]` (bytes 0 to 11), 4 bytes of padding (12 to 15), and an `int64` `fscale` (16 to 23): 24 bytes. `syscall.Sysctl` drops one trailing NUL byte from what the kernel returns (Go `src/syscall/syscall_bsd.go`; the comment at `reap_darwin.go:35` handles the same thing), and `fscale`'s top byte is 0, so the call returns 23 bytes. The decoder pads its input with zero bytes to 24, as `reap_darwin.go:35-36` does, accepts only 23 or 24 bytes (anything else is unknown), and computes `load1 = ldavg[0] / fscale`; `fscale` of 0 is unknown. Available memory: not measured (row O5, Q-T043-10 (a)).
- **Other:** unknown; every reading prints as `unknown`.

**Load percent** is `100 * load1 / NumCPU`. Load average is system-wide while `runtime.NumCPU` counts the logical CPUs usable by this process (row O8); under an affinity mask or a container CPU set the two differ and the percent reads high, which errs toward refusing, the safe side for a pace check. A run may start when load percent is under `cpu_target_percent` and, where measured, available memory is at or above `memory_floor_mib`. Parsing is a pure function on bytes in each file, tested on fixed input; only a thin per-OS wrapper reads the system.

### 2.8 Dispatch (phase B)

## 3. Our code, mapped (at `a450280`)

### 3.1 Today dispatch already runs one run at a time

`Run` takes `.waggle/worktrees/dispatch.lock` with `takeLock` (`run.go:232-236`) after the runtime and identity checks and holds it to the end of `Run` (`defer os.Remove(lock)`), across `runSession`, the checks, the push, `saveHostRecord` and `appendLedger`. So `serial` (`parallel_runs: 1`) is enforced by today's code.

## 5. Threat model (D-203)

Pace is a liveness and resource control on the keeper's own machine, not a security boundary. **Attacker:** a PR author (commits, branch, PR body, fork) and a dispatched worker. **Trusted:** the owner (writes `config.yaml`, Tier 3), the keeper (writes `local.yaml` and runs the tools), the base revision, GitHub. A PR that adds or changes `pace:` touches a Tier 3 path and needs the owner's approval; the gate never checks what `pace:` means, though a YAML syntax error in it fails `config.Parse` as one in any section does today (2.1).

**Must-fix:** a `pace:` section that the subset parser accepts, valid or with a semantic error (2.1), that changes any `waggle gate` result or makes `config.Parse` fail; pace changing a model, context profile, guard count, second guard, claim, lease, worker tool list or worker permission; the render writing any file, running any program, or emitting a JSON key other than the four in 2.7 or a value that is not plain digits or `"0"`/`"1"`; a `local.yaml` value reaching output, env or argv without the exact-word check and control-character filter; a resolved value faster than the owner's `limit` on any key; the load reader opening any path other than `/proc/loadavg` and `/proc/meminfo`, or following a path from config; in phase B, the check placed after `worktreesDir`, `takeLock` or any other write, a clamped or unknown pick that does not reach `Result.Warnings`, an unknown reading that refuses a run, or any change to the lock, host-file check, claims, keepalive or process handling; a new `go.mod` dependency; a bare word from `bareWords` in new output; an em or en dash.

**Note, not must-fix:** a `pace:` block with a YAML syntax error that fails `config.Parse`, and with it the gate, status, doctor and dispatch (the same as a broken `context:` or `runtimes:` block today; it lands only through an owner-approved Tier 3 change); a keeper who edits `config.yaml` in their own checkout to raise the limit (the owner's file, in a place the keeper can already edit anything); load average counting more than CPU work, so the check is coarse; an old Claude Code that ignores C1 or C6; a worker that edits the main checkout's `local.yaml` (it can already edit anything there without a Cell; T-023 not_enforced).

**Guard prompt sentence (repeat verbatim):** "Threat bar (D-203): pace is a resource control, not a security boundary; a finding that needs the owner, the keeper, the base config or local.yaml write access is a note, not a must-fix; must-fix is any way pace changes a gate result, a model, a guard, a claim, a lease or worker permissions, any file the render writes, any value past the owner's limit, and in phase B any refusal placed after the first write or any change to the lock, host-file check or process handling."
