## 1. Goal

Let the gate's `verify-leases-and-tiers` accept a signed Head Keeper approval for listed protected paths, so those PRs merge through the normal gate with no admin bypass.

Today hardcoded Tier 3 control paths fail with `Tier 3 path; only an admin bypass merges it, approval does not`, and config-listed protected paths (`gate/`) report `needs an admin bypass to merge` unless a listed approver's approval and a re-run pass them (`docs/gate.md` sections 4 and 6, L11). D-374 records the interim rule: such PRs go to the Head Keeper case by case, with a one-line decision-log entry per admin bypass merge. This ticket is the home for removing that need.

## 2. Scope

1. `verify-leases-and-tiers` accepts a signed Head Keeper approval, verified with `ssh-keygen -Y verify` (D-372, Q-T054-1): shell out to `ssh-keygen -Y`, use the `allowed_signers` format, and make no `go.mod` change.
2. The approval covers these listed protected path classes:
   - `gate/`
   - `.github/workflows`
   - control paths: `.waggle/control` and the other hardcoded Tier 3 control-plane prefixes (`.gitlab-ci.yml`, `.devcontainer/`, and the dependency inputs the gate treats as Tier 3).
3. A valid signature at the exact PR head commit lets those findings pass, so the PR merges through the normal gate. A signature for any other commit does not count, so a push after signing moves the head and voids it.
4. **Signer source.** The gate must not fetch or read `refs/waggle/quorum/*` or the Quorum registry (T-054.md section 3, Must stay). It reads a separate `allowed_signers` file from the PR base commit: `git cat-file` the blob at the base into a temp file and pass that path to `ssh-keygen`. It never reads the worktree copy, which the PR could change. The file is `.waggle/control/allowed_signers` (one Head Keeper key, `ssh-keygen` allowed_signers format). If landing that file needs a later control-path merge, that merge is a Head Keeper step with an admin bypass under D-374 and is named in the build PR, not done here.
5. Only the Head Keeper's key counts. A key that is valid but not the Head Keeper's gives no pass.
6. Docs: update `docs/gate.md` sections 4, 6 and L11 to describe the signed approval, the exact-head rule and the signer file.

## 3. Out of scope

- T-054 phases and Quorum ballots.
- Changing rulesets or GitHub security settings.
- Standing admin bypasses (D-374 rejects them).
- Implementing the build in the records PR that opened this ticket.
- Edits to `.github/`, `gate/`, `.waggle/control`, `go.mod` or `go.sum` as part of the build lease.

## 4. Tests

- A valid Head Keeper signature at the head passes a change on each named protected path class: `gate/`, `.github/workflows`, and a control path.
- A bad signature fails. A missing signature fails.
- A signature made for an earlier commit (not this head) fails.
- A valid signature from a non-Head Keeper key fails.
- The signer file is read from the base commit, not the worktree: a PR that edits its own `allowed_signers` gains nothing.
- The gate does not touch `refs/waggle/quorum/*`.
- `go.mod` and `go.sum` are unchanged.

## 5. Acceptance criteria

- Every test in section 4 passes under `go test -race ./...`; `go vet ./...` and `gofmt -l .` are clean.
- `docs/gate.md` states the new rule and the remaining limits.
- A protected-path PR carrying a valid Head Keeper signature at its head merges with no admin bypass.
