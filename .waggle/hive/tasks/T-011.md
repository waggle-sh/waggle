## 1. Goal

Waggle must own one folder in a host repo and nothing else, so a team can adopt it, inspect it, and remove it cleanly. Today `waggle init` writes `WAGGLE.md` and `.devcontainer/` at the root, overwrites `CLAUDE.md`, and appends a `.gitignore` block that hides project-owned files (`.claude/`, `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.cursor/`, `.aider*`). Fix that, add `waggle uninstall`, record which Waggle build a hive runs, and make worker leases on `.waggle/` impossible.

This repo has two layers, and this ticket must leave them unambiguous:
- **Product:** Waggle itself. `cmd/`, `internal/` (including `internal/scaffold/templates/`, which is what other hives receive), `go.mod`, `LICENSE`, `README.md`, `docs/` (RFC, glossary). Ships.
- **Hive:** our own installation of Waggle, used to build the product ("own honey", D-044). After phase C: everything under `.waggle/`, plus `.github/workflows/waggle-gate.yml` and the marked import block. Never ships.

Today `.waggle/roles/*.md` and `internal/scaffold/templates/roles/*.md` are byte-identical and root `WAGGLE.md` mirrors `WAGGLE.md.tmpl`, so nobody can tell product from hive. After this ticket the templates are the only source, the hive copies are installed output (section 6.2), and the hive's `WAGGLE.md` describes this repo while the template is a generic skeleton.

## 6. `waggle init` (`internal/scaffold/`, phase A)

### 6.1 Writes
Templates render to the section 2 paths and nothing else. Create `.waggle/hive/{tasks,reviews,media}/` on disk with no placeholder files.

### 6.2 Managed versus seeded (the product and hive split)
- **Managed** files are pure template output. `--force` rewrites them. Hand edits to hive copies are not allowed (D-042); they change through `waggle upgrade` (new ticket, section 14) run from the pinned build.
- **Seeded** files (`config.yaml`, `WAGGLE.md`, `local.yaml`) are rendered once and then belong to the hive. `--force` never overwrites them (`[skip] seeded`). The Head Keeper edits them in hive PRs.

### 6.3 Pin (D-041)
`config.yaml.tmpl` gains a top-level block:

```yaml
waggle:
  pin: {{PIN}} # the Waggle build this hive runs: a release tag or a 40-hex commit. Change only through a logged upgrade.
```

Init fills `{{PIN}}` from `runtime/debug.ReadBuildInfo()`: the main module version if it is a release tag; else `vcs.revision` when `vcs.modified` is `false`; else the literal `unpinned` plus the warning `[warn] built from a modified or unstamped tree; set waggle.pin by hand`. Nothing enforces the pin in this ticket; T-004's loader must parse the key, and the upgrade and gate tickets use it.

### 6.4 Marked blocks (new `markers.go`, shared with phase B)
- `UpsertBlock(content, start, end, body string) (string, error)`: whole-line markers. No block: append one (adding a trailing newline first if missing). One block: replace its inside. Start without end, end without start, or two blocks: error, no change.
- `RemoveBlock(content, start, end string) (string, bool, error)`: exact inverse, same errors.
- `.gitignore` markers stay `# --- waggle:start ---` / `# --- waggle:end ---`, so rerunning init **replaces** the old block and drops the project-owned lines.
- Markdown markers: `<!-- waggle:start -->` / `<!-- waggle:end -->`.
- Import target: `CLAUDE.md` if it exists, else `AGENTS.md` if it exists; if neither, create `CLAUDE.md` for `--runtime=claude-code`, else `AGENTS.md`. Never both. Body: `@.waggle/control/WAGGLE.md` in `CLAUDE.md`; `Read .waggle/control/WAGGLE.md before working in this repo.` in `AGENTS.md`. If the target is `AGENTS.md` with runtime `claude-code`, print a note that Claude Code reads `CLAUDE.md`.

### 6.5 Legacy layout refusal
If `.waggle/config.yaml` or `.waggle/roles/` exists, exit 1 naming the legacy layout, write nothing. No automatic migration: our hive is the only install (phase C migrates it by hand).

## 9. `waggle uninstall` (product, phase B)

**Dry run by default; `--apply` executes.** It deletes the control plane and the hive record (tasks, reviews, decision log) and edits project-owned files. A clean tree makes tracked files recoverable, but `local.yaml` is untracked and lost. Printing the plan first costs one command; the reverse mistake costs a hive. Same convention as `git clean -n`.

Preconditions, all checked before any write; failure exits 1 with no change:
1. cwd is the work tree root (`git rev-parse --show-toplevel`).
2. `git status --porcelain=v1 --untracked-files=normal` is empty (message names the first dirty path).
3. `.waggle/control/config.yaml` exists (legacy layout gets the 6.5 message).
4. `.waggle/control/run.sock` does not exist.
5. Every marked block in `.gitignore`, `CLAUDE.md`, `AGENTS.md` parses.

Plan, one line per action (`[remove]`, `[edit]`, `[skip]`), applied only with `--apply`:
1. Remove `.waggle/` recursively; print the hive file count.
2. Remove the gate workflow only if it has the `waggle:managed` line, else `[skip]` with a warning; remove `.github/workflows/` and `.github/` only if empty.
3. Strip the block from `CLAUDE.md` and `AGENTS.md`; delete a file left with only whitespace. Same for `.gitignore`.
4. Remove `.claude/agents/waggle-*.md` files containing `# waggle:generated`; remove `.claude/agents/` and `.claude/` only if empty.
5. Never touch `refs/waggle/*`; print `git for-each-ref --format='%(refname)' refs/waggle/` as a cleanup hint.
6. Never commit. Last line: `Review with git status, then commit. Removing .waggle/control/ is Tier 3 and needs Head Keeper approval.`

Exit codes 0 ok (dry run or applied), 1 refused, 2 usage, 3 git or I/O. `runUninstall(args []string, stdout, stderr io.Writer) int`; no `os.Exit` inside.
