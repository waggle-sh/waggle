## 1. Problem

The gate counted a listed approver's APPROVED review when the commit GitHub reports for it equals the PR head. On #316, GitHub reported a review submitted at 14:42:14Z on e89e331 at the later heads 3933a59 and then e41b06e, both merges of main into the branch, and the gate passed hive paths with `hive paths approved by the Head Keeper ... at 3933a59` (run 45637211695). Anyone able to push to a PR branch holding an approval could ride it with new commits, on repo-listed protected paths and, for the Head Keeper, `.waggle/hive/`. Tier 3 control paths were not affected: only the Head Keeper's SSH signature on the head commit passes them.

## 2. Fix

An APPROVED review counts only when it is the approver's latest deciding review, GitHub reports it at the head, it was submitted after the last base change, and its body has a whole line `waggle-approve <40-hex head>`, the line a comment already needs (T-057). The body is read by GraphQL node ID for those candidates only, before comments, and never printed. A body edited by another account, or by an account GitHub no longer names, names nothing. An unreadable body does not count.

## 3. Checks

`TestApprovedBy`, `TestHeadKeeperHivePaths`, `TestApproverNamesHead`, `TestReviewBodyUnread`, `TestReviewBodyReadOnlyForCandidates`, `TestReviewApproves`, `TestReviewsNodeID`. The stale-approval cases fail on the old gate and pass on the fix. `go test -race ./...` green.
