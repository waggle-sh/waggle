## 1. Goal

Learn where Waggle causes friction without collecting personal data, turn that evidence into framework proposals the Head Keeper approves or rejects, and give private repos on GitHub Free an enforcing mode. Design: `docs/rfc-notes/telemetry-insights-held-hive.md`.

## 2. Scope

- Part 1: opt-in weekly telemetry, one config key, an allowlist schema of counts and rounded durations, `waggle telemetry show`, a rotating install id, k = 10 before anything is published, a collector design with cost estimate and a threat model.
- Part 2: an analyst role in a public `waggle-sh/insights` repo that opens proposals with evidence, keeps a rejection memory, and is dogfooded on the Head Keeper's own pilot repos first.
- Part 3: `gate.mode: hold` (held hive): `waggle merge`, a post-merge audit with a breach record, a write-access pattern, and `waggle doctor` capability probing.

## 3. Out of scope

- Any Go code, workflow, scaffold, Cloudflare resource or GitHub App. Code slices are T-104 to T-118.
- Offering `hold` where a required check is available (decision option 4, CUT, not adopted).
- Changing the Tier 3 status of `.waggle/control/config.yaml`.

## 4. Acceptance

- The RFC note covers telemetry fields, what is never sent, the install id, the payload command, k-anonymity, collector options with costs, a threat model, the analyst loop, the `hold` mode with a comparison to `open` and `guard`, and its honest limits.
- No em or en dashes, SPDX headers present, no private names or paths.
- The guard confirms nothing in the note lowers an existing protection in `guard` or `open`.
