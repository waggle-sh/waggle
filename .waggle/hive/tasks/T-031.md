## 1. Goal

Make the gate usable by agents that do not control their commit subjects, let a repo protect its own paths, and stop failing the merge commit GitHub's "Update branch" button makes. Four changes to `waggle gate verify` (and `gate leases`, `gate tiers`, which share `scanRange`):

1. **Ticket binding (D-234).** A commit binds to a ticket by its `T-<id>: ` subject prefix, a `Waggle-Ticket: T-<id>` trailer, or the PR's branch name. First match wins; two sources that name different tickets fail the gate.
2. **Repo-defined protected paths.** A `gate.protected_paths` key in `.waggle/control/config.yaml`, read from the PR base, adds paths the gate treats as Tier 3. Raise-only: it can never lower a path's tier.
3. **Base merges.** A merge commit whose second parent is already on the base branch is checked, not refused.
4. **T-008 folded in.** The root Go dependency inputs join the hardcoded Tier 3 list.

The D-233 listed-approver rule belongs in G3, not here: it needs the GitHub reviews API and a token through `internal/forge/`, which is G3's lease, while G1 reads only git. Until G3, a protected-path change fails as today and merges with the admin bypass.

## 2. Design (recommended options)

### 2.1 Ticket binding

- **Sources, in order.** (1) Subject: `ticketSubject` as today. (2) Trailer: `listCommits` adds `%(trailers:key=Waggle-Ticket,valueonly,unfold,separator=%x2C)` to its format so each commit stays a fixed number of lines; every comma-separated value must pass `comb.ParseTicketID`, and a value that does not is a lease failure (`malformed Waggle-Ticket trailer`, value not echoed). Two trailer values naming different tickets are a conflict. (3) Branch: a new `--branch <name>` flag on `gate verify|leases|tiers`; when it is absent and `GITHUB_ACTIONS=true`, the value of `GITHUB_HEAD_REF`. No workflow change is needed. The branch binds when it matches `^(waggle/T-|t-)([0-9]{3,6})(-.*)?$` (Q-T031-1); any other branch name binds nothing.
- **First match wins, a conflict fails.** Compare canonical IDs (`ParseTicketID`), so `t-31` and `T-031` agree. The first present source sets the ticket; any later present source with a different canonical ID fails leases for that commit with `ticket conflict: subject T-a, trailer T-b, branch T-c` (only the sources present, IDs only, never the raw subject or branch). A conflicting commit gets no lease rules but still runs the tier rules with an empty lease, as an unbound commit does today.
- **Head Keeper commits.** A subject starting with `Head Keeper: ` is never bound by trailer or branch and keeps today's message, so a Keeper commit on a `t-<id>` branch still says to merge with the bypass.
- **Unbound commits** keep today's failure, with the message widened to `commit has no ticket (T-<id>: subject, Waggle-Ticket: trailer, or ticket branch)`.
- The bound ticket feeds `claimFor` unchanged: the claim ref (D-232) is still the lease, read once per ticket.

### 2.2 Repo-defined protected paths

- **Config.** `internal/config` gains `Gate GateConfig` with `ProtectedPaths []string`, parsed from `gate.protected_paths`, a single scalar holding a comma-separated list (Q-T031-2), for example `protected_paths: "deploy/,infra/terraform/,package-lock.json"`. Unknown keys under `gate:` are rejected like the other sections. Older binaries ignore the whole `gate:` section (`Parse` reads only known top-level sections), so adding the key never breaks a pinned older build.
- **Validation** (in `validate`, `ErrInvalidConfig`): at most 64 entries, each 1 to 256 bytes after trimming spaces; no empty entry, no `.`, no leading `/`, no `\`, no `..` segment, no `*`, `?` or `[`, no control bytes; `path.Clean` of the entry without its trailing `/` must equal it. Duplicates are allowed.
- **Matching** is the hardcoded rule: case-insensitive, equal or string prefix (`matchesPrefix`), so `deploy` also covers `deployment.yaml`. Accepted, because over-matching only raises.
- **Raise-only.** `internal/comb` gains a `TierPolicy` (or similar) holding the extra prefixes, with a method returning `max(RequiredMinTier(p), Tier3ControlPlane if p matches an extra prefix)`. An entry inside `.waggle/hive/` therefore raises those files to Tier 3; nothing can lower a hardcoded entry. `CheckChanges` keeps its signature and behavior and becomes a wrapper over a new policy-taking function, so `internal/dispatch` (D-114) is unchanged and does not yet see repo entries (out of scope, 4).
- **Read from base only.** `scanRange` reads `<baseOID>:.waggle/control/config.yaml` with `git cat-file`, after checking its object type is `blob` and its size is at most `config.MaxFileSize`, then calls `config.Parse`. Missing file or path: no repo entries. Present but invalid, not a blob, or too large: gate error, exit 3, with the parse error passed through `annotData` (Q-T031-3). Never read the head tree, the worktree or the merge-base for policy.
- **Message.** A repo-entry hit reads `protected path (listed in .waggle/control/config.yaml); needs an admin bypass to merge`. A hardcoded hit keeps today's text.

### 2.3 Base merges

Replace the blanket refusal in `scan` with:

- Exactly two parents, and the second parent is an ancestor of `baseOID` (`git merge-base --is-ancestor <p2> <baseOID>`, exit 1 meaning no): a **base merge**. Anything else (three or more parents, or a second parent not on base, including a merge made with base as first parent) fails as today, with the message `merge commit %.12s in PR is not an update from the base branch; rebase onto main`.
- A base merge is bound by 2.1 like any commit; when it binds nothing, it takes the ticket its first parent bound to, if the first parent is in the range. With no ticket either way it fails like an unbound commit.
- Its changes are `diff-tree` from the **second parent** (the base side) to the merge, with the same flags and limits as `commitChanges`. That is what the PR now brings to base, so a conflict resolution that reverts or edits a base-side file shows up as a path outside the lease. Never diff a base merge against its first parent, and never skip it.
- Later commits diff against their first parent as today. `scanRange`'s merge-base already moves past the merged base commit, so base commits are not rescanned.

## 3. Questions for the Keeper

- **Q-T031-1: which branch names bind a ticket?** (a) `waggle/T-<id>` and dispatch's own `t-<id>`, each optionally followed by `-<anything>`. (b) `waggle/T-<id>` exactly, as the note wrote. (c) Any branch containing `T-<id>`. **Recommended: (a).** Dispatch already names branches `t-<nnn>` (`internal/dispatch/request.go`), so this hive and any dispatch user bind with no new habit; the suffix covers `t-031-fix` style branches. (c) binds by accident (`revert-T-012-in-T-031`).
- **Q-T031-2: what shape does `gate.protected_paths` take?** (a) One comma-separated scalar. (b) Add block sequences to the YAML subset. **Recommended: (a).** The subset rejects sequences today (`yaml_subset.go`, D-006); widening the parser that reads a Tier 3 file is new attack surface for a cosmetic gain. The format goes in the G5 gate spec.
- **Q-T031-3: what does the gate do when the base config is present but invalid?** (a) Error, exit 3. (b) Warn and run with no repo entries. **Recommended: (a).** The base config already passed review to land on main, so an invalid one is a real fault, and (b) would let a broken config silently drop protection.

## 5. Threat model (D-203)

Attacker: an agent or contributor writing the PR inside its lease. It controls the commits, subjects, trailers, branch name, merge commits and tree of the head. It cannot write claim refs, push to the base branch, or change the base config or the workflow; those are a note, not a must-fix.

Must-fix: any policy read from the head tree, the worktree or the merge-base instead of `baseOID`; any way a PR commit escapes both lease and tier rules (a base merge diffed against its first parent or skipped, a merge whose second parent is not on base accepted, a conflict between sources ignored, a malformed trailer treated as absent); a repo entry that lowers any path's tier; trailer, branch or config text reaching output without `gateReport.print`'s encoders, or echoed raw in a new message; an unbounded read (config blob, trailer values, branch flag); a panic on hostile input; any change to `CheckChanges`'s results for existing callers. Note, not must-fix: binding a commit to another ticket's claim with a wider lease (already possible with a subject prefix; closed by the signature check later); over-matching from the prefix rule.

Guard prompt sentence (repeat verbatim): "Threat bar (D-203): a finding whose attacker needs to write claim refs, push to the base branch, or change the base revision's config or workflow is a note, not a must-fix; must-fix is for what a PR author inside its lease can trigger through commits, subjects, trailers, the branch name, merge commits or the head tree."

No code here sends a signal, calls `sweep()` or deletes files outside `t.TempDir()`, so the D-193 Colima rule does not apply and the full `go test -race ./...` runs on the host (D-195). If a fix round adds such code, the D-193 rule applies to it.

## 7. Acceptance criteria

All are tests that run in `go test -race ./...` on product-ci (linux), unless marked as review.

- [ ] AC1: `go build ./...`, `go vet ./...`, `gofmt -l .` and `go test -race ./...` pass; product-ci green on the PR.
- [ ] AC2 (review): the diff changes only the files the lease rule names; `go.mod` and `internal/dispatch/` unchanged.
- [ ] AC3: binding. A commit with no prefix passes inside its claim when bound by (i) a `Waggle-Ticket:` trailer and (ii) a `--branch t-031` value, and (iii) a `GITHUB_HEAD_REF` value with `GITHUB_ACTIONS=true` and no flag; each fails outside its claim with the claim's ticket in the message. `--branch hive-records-20` binds nothing.
- [ ] AC4: conflicts. Subject `T-031:` with trailer `T-032`, subject `T-031:` on branch `t-032`, and two different trailer values each fail leases with `ticket conflict`; subject `T-031:` with trailer `T-31` on branch `t-031-x` passes. A malformed trailer value fails and the value does not appear in output.
- [ ] AC5: a `Head Keeper: ` commit on branch `t-031` fails with today's bypass message and is not lease-checked against T-031.
- [ ] AC6: protected paths. With `gate.protected_paths: "deploy/,Infra/"` in the base config, a commit inside its claim touching `deploy/x` or `infra/y` fails tiers with the 2.2 message; the same entry added only on the head side does not apply; an entry under `.waggle/hive/` raises a hive file to Tier 3; no entry lowers a hardcoded Tier 3 path.
- [ ] AC7: config. Table tests reject each 2.2 validation case with `ErrInvalidConfig` and accept the valid forms; an existing config without `gate:` parses to the same `Config` as before. A base config that is invalid, a symlink or larger than `MaxFileSize` makes `gate verify` exit 3; a missing one exits by the other checks alone.
- [ ] AC8: base merges. An "Update branch" style merge (second parent on base) passes when the PR's net change since that base is inside the claim; a conflict resolution in it that edits a base-side file outside the lease fails leases on that path; a merge whose second parent is not on base, and an octopus merge, fail with the 2.3 message. `TestVerifyMergeCommit` keeps its existing failing case.
- [ ] AC9: T-008. `HardcodedTier3Prefixes` ends with `go.mod`, `go.sum`, `go.work`, `go.work.sum`, `vendor/`; leases on them and their case variants fail with `ErrTier3Path` and write no ref; a PR commit touching `go.sum` fails tiers; `isTier3Dir` and `matchesPrefix` are unchanged (review).
- [ ] AC10: hostile text. A trailer and a branch name containing `%`, `\r`, `\n`, `::` and `,` cannot start a new output line or workflow command (extend `TestVerifyEncodesHostileText`).
- [ ] AC11: existing `CheckChanges` tests pass unchanged, and no existing gate test assertion is weakened (review).
