## 1. Goal

Make the gate usable by agents that do not control their commit subjects, let a repo protect its own paths, and stop failing the merge commit GitHub's "Update branch" button makes. Four changes to `waggle gate verify` (and `gate leases`, `gate tiers`, which share `scanRange`):

1. **Ticket binding (D-234).** A commit binds to a ticket by its `T-<id>: ` subject prefix, a `Waggle-Ticket: T-<id>` trailer, or the PR's branch name. First match wins; two sources that name different tickets fail the gate.
2. **Repo-defined protected paths.** A `gate.protected_paths` key in `.waggle/control/config.yaml`, read from the PR base, adds paths the gate treats as Tier 3. Raise-only: it can never lower a path's tier.
3. **Base merges.** A merge commit whose second parent is already on the base branch is checked, not refused.
4. **T-008 folded in.** The root Go dependency inputs join the hardcoded Tier 3 list.

The D-233 listed-approver rule belongs in G3, not here: it needs the GitHub reviews API and a token through `internal/forge/`, which is G3's lease, while G1 reads only git. Until G3, a protected-path change fails as today and merges with the admin bypass.

## 2. Design (ruled options)

### 2.1 Ticket binding

- **Sources, in order.** (1) Subject: `ticketSubject` as today. (2) Trailer: `listCommits` adds `%(trailers:key=Waggle-Ticket,valueonly,unfold,separator=%x2C)` to its format so each commit stays a fixed number of lines; every comma-separated value must pass `comb.ParseTicketID`, and a value that does not is a lease failure (`malformed Waggle-Ticket trailer`, value not echoed). Two trailer values naming different tickets are a conflict. Bounds: the trailer field of one commit is at most 256 bytes and holds at most 8 values; each value is trimmed of ASCII spaces and tabs and is at most 16 bytes after trimming; past any bound the commit fails leases with `Waggle-Ticket trailer too long` (nothing echoed). (3) Branch: a new `--branch <name>` flag on `gate verify|leases|tiers`; when it is absent and `GITHUB_ACTIONS=true`, the value of `GITHUB_HEAD_REF`. No workflow change is needed. The branch binds when it matches `^(waggle/T-|t-)([0-9]{3,6})(-.*)?$` (D-237); any other branch name binds nothing. A branch value over 255 bytes or holding a control byte binds nothing and adds one leases warning `branch name ignored` (the value is not echoed); it is never read past 255 bytes into a message.
- **First match wins, a conflict fails.** Compare canonical IDs (`ParseTicketID`): a trailer `T-31` and a subject `T-031:` agree. The branch's digit group goes to `ParseTicketID` as `T-<digits>`, unchanged, so `t-031` binds T-031 and `t-000` binds nothing (`ParseTicketID` rejects zero). The first present source sets the ticket; any later present source with a different canonical ID fails leases for that commit with `ticket conflict: subject T-a, trailer T-b, branch T-c` (only the sources present, IDs only, never the raw subject or branch). A conflicting commit gets no lease rules but still runs the tier rules with an empty lease, as an unbound commit does today.
- **Head Keeper commits.** A subject starting with `Head Keeper: ` is never bound by trailer or branch and keeps today's message, so a Keeper commit on a `t-<id>` branch still says to merge with the bypass.
- **Unbound commits** keep today's failure, with the message widened to `commit has no T-<id>: prefix, Waggle-Ticket: trailer or ticket branch`. It keeps the old substring `commit has no T-<id>: prefix`, so `TestVerifyNonTicketCommits` passes unchanged.
- The bound ticket feeds `claimFor` unchanged: the claim ref (D-232) is still the lease, read once per ticket.

### 2.2 Repo-defined protected paths

- **Config.** `internal/config` gains `Gate GateConfig` with `ProtectedPaths []string`, parsed from `gate.protected_paths`, a single scalar holding a comma-separated list (D-238), for example `protected_paths: "deploy/,infra/terraform/,package-lock.json"`. Unknown keys under `gate:` are rejected like the other sections. Older binaries ignore the whole `gate:` section (`Parse` reads only known top-level sections), so adding the key never breaks a pinned older build.
- **Validation** (in `validate`, `ErrInvalidConfig`): at most 64 entries, each 1 to 256 bytes after trimming spaces; no empty entry, no `.`, no leading `/`, no `\`, no `..` segment, no `*`, `?` or `[`, no control bytes; `path.Clean` of the entry without its trailing `/` must equal it. Duplicates are allowed.
- **Matching** is the hardcoded rule: case-insensitive, equal or string prefix (`matchesPrefix`), so `deploy` also covers `deployment.yaml`. Accepted, because over-matching only raises.
- **Raise-only.** `internal/comb` gains a `TierPolicy` (or similar) holding the extra prefixes, with a method returning `max(RequiredMinTier(p), Tier3ControlPlane if p matches an extra prefix)`. An entry inside `.waggle/hive/` therefore raises those files to Tier 3; nothing can lower a hardcoded entry. `CheckChanges` keeps its signature, and its results are unchanged except for the five T-008 entries (2.4); it becomes a wrapper over a new policy-taking function with an empty policy, so `internal/dispatch` (D-114) needs no code change and does not yet see repo entries (out of scope, 4). Dispatch's post-run check does see the T-008 entries, through the same call.
- **Read from base only.** `scanRange` runs `git ls-tree -z <baseOID> -- .waggle/control/config.yaml` (a blob type check cannot see a symlink, whose mode 120000 is also a blob). Empty output: the file is missing, no repo entries. Exactly one entry of type `blob` with mode `100644` or `100755`: check its size with `git cat-file -s <oid>` against `config.MaxFileSize`, then read it with `git cat-file blob <oid>` and call `config.Parse`. Anything else (a symlink, a tree, a submodule, more than one entry, a size over the cap, or a parse error): gate error, exit 3, with the error passed through `annotData` (D-239). Never read the head tree, the worktree or the merge-base for policy.
- **Message.** A repo-entry hit reads `protected path (listed in .waggle/control/config.yaml); needs an admin bypass to merge`. A hardcoded hit keeps today's text.

### 2.3 Base merges

Replace the blanket refusal in `scan` with:

- A **base merge** has exactly two parents, its second parent is an ancestor of `baseOID` (`git merge-base --is-ancestor <p2> <baseOID>`, exit 1 meaning no), and `git merge-base --all <M> <baseOID>` prints exactly one OID, equal to p2 (equivalently, every merge-base of p1 and `baseOID` is an ancestor of p2). The second rule matters: without it a crafted merge whose p2 is an older base commit, or a side-branch commit that base merged later, makes `p2..M` revert base-side files, Tier 3 included, with no finding. Anything else (three or more parents, a second parent not on base, p1 already holding base commits newer than p2, or a merge made with base as first parent) fails as today, with the message `merge commit %.12s in PR; rebase onto main (only an update from the base branch is accepted)`. It keeps the old substring `in PR; rebase onto main`, so `TestVerifyMergeCommit` passes unchanged.
- A base merge is bound by 2.1 like any commit; when it binds nothing, it takes the ticket its first parent bound to, if the first parent is in the range. With no ticket either way it fails like an unbound commit.
- Its changes are `diff-tree` from the **second parent** (the base side) to the merge, with the same flags and limits as `commitChanges`. That is what the PR now brings to base, so a conflict resolution that reverts or edits a base-side file shows up as a path outside the lease. Never diff a base merge against its first parent, and never skip it.
- Accepted limitation: a base merge is checked against one ticket's lease, so in a PR that carries two tickets it fails on the other ticket's paths. Such a PR rebases instead.
- Later commits diff against their first parent as today. `scanRange`'s merge-base already moves past the merged base commit, so base commits are not rescanned.

## 3. Questions for the Keeper (ruled)

- **Q-T031-1: which branch names bind a ticket?** (a) `waggle/T-<id>` and dispatch's own `t-<id>`, each optionally followed by `-<anything>`. (b) `waggle/T-<id>` exactly, as the note wrote. (c) Any branch containing `T-<id>`. **Ruled: (a), D-237.** Dispatch already names branches `t-<nnn>` (`internal/dispatch/request.go`), so this hive and any dispatch user bind with no new habit; the suffix covers `t-031-fix` style branches. (c) binds by accident (`revert-T-012-in-T-031`).
- **Q-T031-2: what shape does `gate.protected_paths` take?** (a) One comma-separated scalar. (b) Add block sequences to the YAML subset. **Ruled: (a), D-238.** The subset rejects sequences today (`yaml_subset.go`, D-006); widening the parser that reads a Tier 3 file is new attack surface for a cosmetic gain. The format goes in the G5 gate spec.
- **Q-T031-3: what does the gate do when the base config is present but invalid?** (a) Error, exit 3. (b) Warn and run with no repo entries. **Ruled: (a), D-239.** The base config already passed review to land on main, so an invalid one is a real fault, and (b) would let a broken config silently drop protection.

## 5. Threat model (D-203)

Attacker: an agent or contributor writing the PR inside its lease. It controls the commits, subjects, trailers, branch name, merge commits and tree of the head. It cannot write claim refs, push to the base branch, or change the base config or the workflow; those are a note, not a must-fix.

Must-fix: any policy read from the head tree, the worktree or the merge-base instead of `baseOID`; any way a PR commit escapes both lease and tier rules (a base merge diffed against its first parent or skipped, a merge whose second parent is not on base accepted, a merge accepted when `merge-base --all <M> <baseOID>` is not exactly its second parent, a conflict between sources ignored, a malformed trailer treated as absent); a repo entry that lowers any path's tier; trailer, branch or config text reaching output without `gateReport.print`'s encoders, or echoed raw in a new message; an unbounded read, meaning any read past the bounds in 2.1 and 2.2 (config blob over `config.MaxFileSize`, a trailer field over 256 bytes or 8 values, a trailer value over 16 bytes after trimming, a branch value over 255 bytes); a config symlink, tree or submodule read as config; a panic on hostile input; any change to `CheckChanges`'s signature, or to its results for existing callers other than the five T-008 entries. Note, not must-fix: binding a commit to another ticket's claim with a wider lease (already possible with a subject prefix; closed by the signature check later); over-matching from the prefix rule.

Guard prompt sentence (repeat verbatim): "Threat bar (D-203): a finding whose attacker needs to write claim refs, push to the base branch, or change the base revision's config or workflow is a note, not a must-fix; must-fix is for what a PR author inside its lease can trigger through commits, subjects, trailers, the branch name, merge commits or the head tree."

No code here sends a signal, calls `sweep()` or deletes files outside `t.TempDir()`, so the D-193 Colima rule does not apply and the full `go test -race ./...` runs on the host (D-195). If a fix round adds such code, the D-193 rule applies to it.

## 7. Acceptance criteria

All are tests that run in `go test -race ./...` on product-ci (linux), unless marked as review.

- [ ] AC1: `go build ./...`, `go vet ./...`, `gofmt -l .` and `go test -race ./...` pass; product-ci green on the PR.
- [ ] AC2 (review): the diff changes only the files the lease rule names; `go.mod` and `internal/dispatch/` unchanged.
- [ ] AC3: binding. A commit with no prefix passes inside its claim when bound by (i) a `Waggle-Ticket:` trailer and (ii) a `--branch t-031` value, and (iii) a `GITHUB_HEAD_REF` value with `GITHUB_ACTIONS=true` and no flag; each fails outside its claim with the claim's ticket in the message. `--branch hive-records-20` binds nothing.
- [ ] AC4: conflicts. Subject `T-031:` with trailer `T-032`, subject `T-031:` on branch `t-032`, and two different trailer values each fail leases with `ticket conflict`; subject `T-031:` with trailer `T-31` on branch `t-031-x` passes. A malformed trailer value fails and the value does not appear in output.
- [ ] AC5: a `Head Keeper: ` commit on branch `t-031` fails with today's bypass message and is not lease-checked against T-031.
- [ ] AC6: protected paths. With `gate.protected_paths: "deploy/,Infra/"` in the base config, a commit inside its claim touching `deploy/x` or `infra/y` fails tiers with the 2.2 message; the same entry added only on the head side does not apply; an entry under `.waggle/hive/` raises a hive file to Tier 3; no entry lowers a hardcoded Tier 3 path.
- [ ] AC7: config. Table tests reject each 2.2 validation case with `ErrInvalidConfig` and accept the valid forms; an existing config without `gate:` parses to the same `Config` as before. A base config that is invalid, a symlink (mode 120000, even when its target is a valid config), a directory or larger than `MaxFileSize` makes `gate verify` exit 3; a missing one exits by the other checks alone. Trailer and branch values past the 2.1 bounds fail or warn as 2.1 says, without echoing the value.
- [ ] AC8: base merges. An "Update branch" style merge (second parent on base) passes when the PR's net change since that base is inside the claim; a conflict resolution in it that edits a base-side file outside the lease fails leases on that path; a merge whose second parent is not on base, and an octopus merge, fail with the 2.3 message. Two crafted shapes also fail with the 2.3 message, each in a test where the merge tree reverts a base-side Tier 3 file: (i) the PR first merges a newer base commit, then makes a second merge whose second parent is an older base commit; (ii) the second parent is a side-branch commit that base merged later. In both, `merge-base --all <M> <baseOID>` is not exactly the second parent. Two successive genuine "Update branch" merges pass. `TestVerifyMergeCommit` passes unchanged.
- [ ] AC9: T-008. `HardcodedTier3Prefixes` ends with `go.mod`, `go.sum`, `go.work`, `go.work.sum`, `vendor/`; leases on them and their case variants fail with `ErrTier3Path` and write no ref; a PR commit touching `go.sum` fails tiers; `isTier3Dir` and `matchesPrefix` are unchanged (review).
- [ ] AC10: hostile text. A trailer and a branch name containing `%`, `\r`, `\n`, `::` and `,` cannot start a new output line or workflow command (extend `TestVerifyEncodesHostileText`).
- [ ] AC11: `CheckChanges` keeps its signature; existing `CheckChanges`, dispatch and gate tests pass unchanged (results change only for the five T-008 entries, which no existing test exercises), and no existing assertion is weakened (review).
