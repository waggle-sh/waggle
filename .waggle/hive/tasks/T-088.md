## 1. Goal

`init` is inline in `main()` with `flag.ExitOnError` and ignores stray positional arguments, so it has no command-level test.

## 2. Scope

- Move the init case from `cmd/waggle/main.go` to a new `cmd/waggle/init.go`: `runInit(args []string, cwd string, stdout, stderr io.Writer) int` with `flag.ContinueOnError`. It depends on T-087 only for the `run` shape; if T-087 is not merged, add the `init` case to call `runInit` directly.
- A positional argument (`waggle init foo`) exits 2 with `waggle init takes no arguments`.
- An invalid `--profile`, `--delivery`, `--forge` or `--comb-mode` exits 2 and the message lists the allowed values (the scaffold already words these; the exit code becomes 2).
- `--gate-only` in a temp git repo writes exactly the three files named in its success line and prints that line. A second run without `--force` does not change them.
- Table tests in a new `cmd/waggle/init_test.go`. The `init` section of `site/content/cli.md` states the exit codes.
- Do not change the `--forge` flag help or the set of accepted forges (see the dev-mgr decision D4 in the Origin).

## 3. Checks

`go test -race ./cmd/waggle/... ./internal/scaffold/...`, vet, gofmt.
