## 1. Goal

The gitlink rule is tested only at `internal/comb` level; `TestVerifySymlink` covers symlinks through `gate verify`. Renames are tested only into a claim.

## 2. Scope

In `cmd/waggle/gate_verify_test.go` or a new `cmd/waggle/gate_verify_modes_test.go`, using the existing `leaseRepo` helpers:

- A commit adding a gitlink (mode 160000) under the claim directory makes `gate verify` exit 1 with the rule text `symlink or submodule mode`.
- A commit that renames `.github/workflows/x.yml` to a path inside the claim directory fails `tiers` (the old path counts), exit 1.
- A commit that renames a Tier 2 file (`.waggle/hive/x.md`) into the claim directory under a `light` claim fails `tiers`.
- A commit that changes a file's mode to executable inside the claim passes.
- No change to gate code unless a test fails. Where a test exposes a real bug, fix it only if the fix is under 30 non-test lines and inside the lease; otherwise keep the test, mark it `t.Skip` with a one-line reason and say so in the PR body. Never weaken an assertion to pass.

## 3. Checks

`go test -race ./cmd/waggle/... ./internal/comb/...`, vet, gofmt.
