## 1. Goal

A hive changes the Waggle build it runs only through a logged upgrade (D-041), and product template changes reach a hive's installed copies only through this command, in a hive PR (D-042). The **target** build runs it (D-063): it renders its own templates over the hive's managed files, deletes managed files it no longer ships (D-083), moves `waggle.pin` to itself, and prints the decision input. The old pinned build never renders anything; it is only the "from" value. This replaces the manual phase C procedure in T-011 section 10.

## 3. Behavior

Dry run by default, `--apply` executes, the `waggle uninstall` convention. One function per layer: `scaffold.Upgrade(opts UpgradeOptions) error` (plan then execute, `ErrRefused` for preconditions) and `runUpgrade(args []string, stdout, stderr io.Writer) int` in `cmd/waggle/upgrade.go`, no `os.Exit` inside. Exit codes 0 ok (dry run or applied), 1 refused, 2 usage, 3 git or I/O.

### 3.1 Flags

`waggle upgrade [--apply] [--diff] [--allow-downgrade] [--runtime=claude-code|none]`. `--runtime` has init's default and values; `none` skips the shim step. No positional arguments (exit 2).

### 3.2 Preconditions (all before any write; failure exits 1 and changes nothing)

1. cwd is the work tree root (`git rev-parse --show-toplevel`, reuse `checkWorktreeRoot`).
2. Clean tree (`git status --porcelain=v1 --untracked-files=normal` empty; reuse `checkCleanTree`, message names the first dirty path).
3. `.waggle/control/config.yaml` exists. A legacy layout (`.waggle/config.yaml` or `.waggle/roles/`) gets the T-011 6.5 message. Not a hive at all: `not found; run waggle init first`.
4. `.waggle/control/run.sock` absent.
5. Every marked block in `.gitignore`, `CLAUDE.md`, `AGENTS.md` parses (`ErrMarkers` is a refusal).
6. The hive pin parses (3.5): exactly one `pin:` line under a top-level `waggle:` key, value a 40-hex commit, a release tag, or `unpinned`. A short hash or any other value is refused with `set waggle.pin to the full 40-hex commit (git rev-parse <short>) or a release tag, then rerun`.
7. The running build has a usable version: `resolvePin` returns ok (release tag, or `vcs.revision` with `vcs.modified=false`). An `unpinned` build is refused: `build waggle from a clean, stamped checkout of the target commit`.
8. Downgrade rule (Q-T016-3): when both pins are release tags and the target is lower, refuse unless `--allow-downgrade`.

### 3.3 Plan (one line per action, printed in every mode, in this order)

1. `[pin]     <old> -> <new>` (or `[pin]     <new> (unchanged)`). `<old>` comes from `config.yaml`, `<new>` from the running build.
2. For each managed file (3.4) the build ships, compare the rendered template bytes with the hive file: `[rewrite] <path>` when they differ (with a unified diff under `--diff`, produced by `git diff --no-index --no-color -- <hive file> <temp render>`; exit status 1 from git means "differs", not failure), `[same]    <path>` when equal, `[create]  <path>` when absent. The gate workflow is rewritten only when its hive copy carries `# waggle:managed`; otherwise `[skip]    <path> (warning: no "# waggle:managed" line, project file)`, as `uninstall` does.
3. `[remove]  <path>` for each managed file present in the hive that the build's template map does not contain (3.4). Never a seeded file, never anything under `.waggle/hive/`, never a workflow without the managed line.
4. `[skip]    <path> (seeded)` for `config.yaml`, `WAGGLE.md`, `local.yaml`. The pin line in `config.yaml` is the one exception (3.5). Under Q-T016-2, print one `[note]` line per top-level key the build's `config.yaml.tmpl` has and the hive file lacks.
5. `[edit]    .gitignore (waggle block)` and `[edit]    CLAUDE.md (waggle block)` or `AGENTS.md`, when the block body differs; `[same]` otherwise. Import target resolution is init's `importTarget`; never both files.
6. Shims (Q-T016-7): `[remove]  .claude/agents/waggle-<role>.md` for each shim carrying `# waggle:generated` whose role file is absent after step 3; `[shims]   regenerate .claude/agents/waggle-*.md` once, when `--runtime=claude-code`. A shim without `# waggle:generated` is never touched (T-011 section 7).
7. `[keep]    refs/waggle/* and .waggle/hive/**` as a reminder line.

### 3.4 How a file is known to be managed (the mechanism is T-011's)

A file is managed, and so eligible for `[rewrite]` or `[remove]`, when **one** of these holds:

- Its path is an entry of `layout.Managed`, or lies directly inside a directory entry of it (today `roles/` is the only directory entry, so every `*.md` directly under `.waggle/control/roles/` is managed, whatever its name; hand-added files there are not allowed, D-042, T-011 section 6.2).
- It is the gate workflow and carries the `# waggle:managed` line. (After T-018 phase C the workflow may leave `layout.Managed`; follow the merged state of `layout.go`, never a copy of the list.)
- It is a shim under `.claude/agents/waggle-*.md` with `# waggle:generated` as a line of its own (`runtime.IsGeneratedShim`).

"The build ships" means the entry is in `templateFiles()`, the embedded template-to-path map in `init.go`. "No longer ships" means in the hive under a managed location and absent from that map. Everything else is seeded, project-owned, or hive record, and `upgrade` never removes it.

### 3.5 Pin: format, read, write (Q-T016-8)

- **Format.** A pin is a full 40-hex commit (`^[0-9a-f]{40}$`), a release tag (`^v[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$`), or the literal `unpinned`. Never a short hash: T-011c finding 6 caught a short one, nothing on `main` validated it, and a short hash becomes ambiguous as history grows. `resolvePin` already produces only the first two; this ticket adds the validator and applies it to both the "from" and the "to" value.
- **Read.** Default: `scaffold.ReadPin(path string) (string, error)` exported from `internal/scaffold/upgrade.go`: a line scan of the `waggle:` block (same shape as `t-022a`'s `readPin`), returning the validated value or an error naming the line. `status` switches to it in a one-line follow-up (T-022 phase B, which already imports `scaffold`).
- **Write.** `scaffold.WritePin(content, newPin string) (string, error)` edits exactly that one line: the value is replaced, the key, indentation and trailing comment stay byte for byte, everything else in the file is untouched. Zero or two `pin:` lines under `waggle:` is an error (refused in 3.2 item 6). The file is never re-serialized through `config.Parse`: it is Head Keeper-owned and its comments must survive.

### 3.6 Apply

Only with `--apply`, in plan order: pin line, rewrites and creates, removals, marked blocks, shim removals, then `runtime.NewClaudeAdapter(...).Materialize(root)` for the regeneration (its `[shim]` lines go to `os.Stdout` as in init; the adapter is outside the lease, leave it). Never commit, never touch `refs/waggle/*` or `.waggle/hive/**`. Dry run runs nothing in this list, Materialize included.

### 3.7 Decision input and last lines

After the plan (both modes), print the `waggle decide` input (Q-T016-4) between `--- waggle decide input (save as upgrade-decision.json) ---` and `--- end ---`, valid against T-006 section 4.1: `kind` `technical`, `title` `Upgrade hive pin to <new>` (under 100 bytes with a 40-hex value), `question` `Which Waggle build does this hive run?`, `options` [`Stay on <old>`, `Move to <new>`], `recommendation` `Move to <new>`, `choice` `Move the pin from <old> to <new>; managed files re-rendered by waggle upgrade from the target build`, `rationale` `<new> is the known-good build chosen by the Head Keeper (D-041).`, `tickets` [`T-016`], `supersedes` []. Then the hint `Run: waggle decide --file upgrade-decision.json (same hive PR, Head Keeper or queen after an explicit Keeper answer, T-006 section 8).`

Last line, both modes: `Review with git status, then open a hive PR. This changes .waggle/control/ (Tier 3) and needs Head Keeper approval.` Dry run adds, before it, `Dry run: nothing changed. Rerun with --apply to execute the plan above.`

## 5. Design points

Resolved: **5.1** which binary runs it, by D-063 (the target build; section 1). **5.8** removed managed files, by D-083 (section 3.3 step 3 and 3.4).

The rest were queen defaults, each marked **Default pending Keeper**; the Head Keeper confirmed every default on 2026-10-17 (D-090 to D-097, section 12). The brief is written against the defaults, so no section changes.

- **5.2 Seeded-file migrations (Q-T016-2).** Default pending Keeper: report-only. `upgrade` prints a `[note]` per top-level key present in the build's `config.yaml.tmpl` and absent from the hive's `config.yaml`; the Head Keeper edits seeded files by hand in the same PR. Versioned migration functions keyed by a `schema` field come later, when a release first changes the schema. Alternative: in-place migration now, which re-serializes a Head Keeper-owned file and needs a parser that preserves comments.
- **5.3 Downgrades and ordering (Q-T016-3).** Default pending Keeper: refuse when both pins are release tags and the target is lower, unless `--allow-downgrade`; for commit pins print from and to with no ordering check (a host repo does not contain Waggle's history). Alternative: no downgrade check at all, since the Keeper picked the target on purpose.
- **5.4 Who writes the decision (Q-T016-4).** Default pending Keeper: `upgrade` prints the `waggle decide` input (3.7); the Head Keeper, or the queen after an explicit Keeper answer, runs `waggle decide` in the same hive PR (T-006 section 8). Alternative: `upgrade --apply` calls `decisions.Append` itself, which turns "a command ran" into "a decision was made", adds `internal/decisions` as an import, and makes T-006 a code dependency.
- **5.5 Pin edit inside a seeded file (Q-T016-5).** Default pending Keeper: the narrow line edit in 3.5, requiring exactly one `pin:` under `waggle:`, refusing otherwise; the file is never re-serialized. Alternative: parse and re-render through `internal/config`, which drops every comment in the file.
- **5.6 Hive-only changes to managed files (Q-T016-6).** Default pending Keeper: no per-hive exceptions, no exception list in config; a step a hive wants in the gate workflow goes into the template or not at all. T-007's `gate decisions` step therefore targets the template or waits for T-018 phase C's CI shim. Alternative: a recorded exception mechanism (an `upgrade.keep:` list in `config.yaml`), which reopens the hand-edit door D-042 closed.
- **5.7 Shim regeneration (Q-T016-7).** Default pending Keeper: `upgrade` regenerates and prunes the running Keeper's shims only (3.3 step 6, `--runtime`); other Keepers rerun `waggle init --force` or a future `waggle shims`. Alternative: leave shims alone entirely and tell every Keeper to rerun init, which makes T-020 7.2's "shims regenerated with `waggle-architect.md` removed" a manual step.
- **5.9 Pin format and reader home (Q-T016-8, new).** Default pending Keeper: pins are full 40-hex or release tags, validated on both ends (3.5), and `scaffold.ReadPin` is the shared reader; `internal/config/` stays read-only. Alternative: widen the lease to `internal/config/` and add `Config.Pin` (about 15 lines in `Parse` plus validation), the cleaner long-term home for `status`, `upgrade` and `doctor`, at the cost of a lease change on a package three tickets consume.
- **5.10 Untracked generated `CLAUDE.md` (Q-T016-9, new).** Default pending Keeper: `CLAUDE.md` (or `AGENTS.md`) is tracked like every other file init writes; the markers already separate generated from hand-written content, and a tracked file keeps every clean-tree check honest. No `git add` inside `init` or `upgrade` (neither runs a git write command today). Code change: the one closing hint in `init` (section 4). Our hive: the Head Keeper commits `CLAUDE.md` as step 0 of T-020 phase C 7.2 (Tier 2 minimum path), before the first `upgrade` run; otherwise precondition 2 refuses on `?? CLAUDE.md`. Alternative: ignore `CLAUDE.md` in the template block again (makes project content outside the markers unignorable) or let `upgrade` tolerate one untracked import file (a special case in the clean-tree rule).

## 6. Tests (T-011 style: pure Go, real repos, never `t.Skip`)

Real `git init` repos under `t.TempDir()` with `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `user.name` and `user.email` set through `GitEnv`. Build info injected through `BuildInfo` (the T-011 6.3 func) with fixed pins `A` = 40 times `a`, `B` = 40 times `b`. 1. **Round trip, the T-020 case.** `InitRepo` with templates `A` and pin `A`, commit everything. `Upgrade` with templates `B` and pin `B`: dry run prints `[pin] A -> B`, `[remove] .waggle/control/roles/oldrole.md`, `[remove] .claude/agents/waggle-oldrole.md`, `[same]` for every other managed file, and `git status` is empty afterwards. `--apply`: the files are gone, the pin line is `B` with its comment intact, every other byte of `config.yaml` is unchanged, `.waggle/control/roles/` and `.claude/agents/waggle-*.md` hold exactly the embedded role names. A rerun prints no `[remove]` and no `[rewrite]`, pin `(unchanged)`.
2. **Dry run changes nothing** (tree status empty, file hashes equal) and lists every managed file.
3. **Unchanged pin, untouched files:** all `[same]`, `--apply` is a no-op, exit 0.
4. **Hand-edited managed file** (`roster.json` with an extra byte) is reported `[rewrite]` and restored by `--apply`; with `--diff` the output contains `--- ` and `+++ ` lines.
5. **Seeded files** keep their bytes except the pin line; `WAGGLE.md` edited by the test survives `--apply`. A `config.yaml` with no `pin:` line, with two, or with a short hash is refused (exit 1, no change).
6. **Each precondition** (not root, dirty tree including an untracked file, legacy layout, missing config, socket present, broken markers, `unpinned` build) exits 1 with no change, `errors.Is(err, ErrRefused)`.
7. **Downgrade:** `v0.2.0` to `v0.1.0` refused, allowed with `--allow-downgrade`; `v0.1.0` to `v0.2.0` passes; `v0.1.0-rc1` below `v0.1.0`; commit to tag and tag to commit never refused; `unpinned` to anything allowed.

9. **Marked blocks:** a changed `.gitignore` body renders `[edit]`; an `AGENTS.md` hive never gains a `CLAUDE.md`.
10. **Decision input:** the printed JSON decodes with `DisallowUnknownFields` into a local struct mirroring T-006 4.1, every string single-line and within the byte limits, `title` equal to `Upgrade hive pin to B`.
11. **CLI (`cmd/waggle/upgrade_test.go`):** `--help` exits 0; a positional argument exits 2; a non-hive directory exits 1 with the message on stderr; `--apply` in a fresh init repo exits 0 and prints the last line.
