## 1. Goal

`internal/scaffold/templates/` generates the workflow, roster, config, role prompts, devcontainer and `WAGGLE.md` of every new hive. An injected template becomes control-plane code in every downstream repo, but the path is not Tier 3: `HardcodedTier3Prefixes` is universal across hives and must not name a path that only exists in the waggle repo (T-008 Q-T008-4).

Protect it in this repo only, with GitHub's own review routing: a `CODEOWNERS` entry that makes the Head Keeper a required reviewer for any PR touching the templates.

`README.md` gets the same protection (D-065): its Roles and Terms sections are the agent-read definition of every Waggle term (T-013), so an edit there steers every role. CODEOWNERS is used instead of a hardcoded tier entry, which would hit every host project's own README (D-043).

## 2. File: `.github/CODEOWNERS`

```
# SPDX-License-Identifier: MIT-0
# Head Keeper review required (T-015). Enforced only by the main-branch ruleset
# with "Require review from Code Owners" on. Last matching pattern wins.

/internal/scaffold/templates/   @paulternate
/README.md                      @paulternate
/.github/CODEOWNERS             @paulternate
```

- The second line protects the file itself. GitHub evaluates `CODEOWNERS` from the PR's base branch, so without it a PR could delete the protection with no owner review, and every later PR would be unprotected.
- Patterns are root-anchored (leading `/`) so a nested `templates/` or `README.md` elsewhere does not match.
- Owner is the Head Keeper's GitHub login. Switch to a team (`@waggle-sh/head-keepers`) once the org has one (Q-T015-1). The owner must have write access to the repo or GitHub ignores the line.
- Nothing else in this ticket. Adding the other Tier 3 paths is Q-T015-2.

## 4. GitHub setup (Head Keeper, outside the repo, not a Forager task)

CODEOWNERS on its own only suggests reviewers. It blocks merges only when a ruleset requires code owner review. Steps, in order:

1. **Organization and repo.** Create the `waggle-sh` organization and the private repo `waggle-sh/waggle` (D-024), push `main`, and point the local remote at it. T-010 must already have merged so the module path matches.
2. **Plan check.** Rulesets and required code owner reviews on a **private** repo are not available on GitHub Free for organizations. They need GitHub Team (currently $4 per user per month) or higher. Confirm the plan before step 3, or this ticket's enforcement does nothing (Q-T015-3).
3. **Ruleset on `main`** (Settings, Rules, Rulesets, new branch ruleset, target `main`, enforcement Active):
   - Require a pull request before merging; required approvals: 1.
   - Require review from Code Owners.
   - Dismiss stale pull request approvals when new commits are pushed.
   - Require status checks to pass: `verify-leases-and-tiers` (the T-014 job name; until T-014 lands, the existing job).
   - Require branches to be up to date before merging (D-064: the default merge strategy is the up-to-date check; GitHub re-runs the required check on the updated head). Do not enable merge queue; it is opt-in.
   - Block force pushes. Restrict deletions.
   - Bypass list: the Head Keeper only (by user, or by the repository admin role if the Head Keeper is the only admin). This is the bypass T-014 section 6 relies on.
4. **Record it.** The Head Keeper runs `waggle decide` with kind `policy` describing the ruleset, so the setting has a decision ID and can be audited later.
5. Run section 3.
