## 1. Goal

`waggle doctor` prints an informational `claims` finding today. It says "No malformed claim." or counts malformed claims and names the first (`cmd/waggle/doctor_claims.go:23, 35-40`), then one `force-release:` line about who may clear a claim. It does not say anything about two active claims that are one directory on a macOS or Windows checkout.

T-073 stopped new collisions at claim time and made `waggle status` print one warning per pair (`cmd/waggle/status.go:241-244`). ## 9. Open questions

Each has a recommended default. The scout decides none of them; the Head Keeper rules them, or adopts the defaults.

- **Q-T075-1: Which finding status should a collision use?**
  Options: (a) `missing`, as the malformed case does, so it prints in the same shape and carries Impact and Fix; (b) `unknown`; (c) stay `ok` and put the count in the summary only, with no Impact or Fix.
  Recommended: (a). `forge.Render` requires Impact and Fix on `missing` and `unknown` findings (`internal/forge/report.go:21-22`), and this one has real advice. It cannot change the exit code because the finding is never Required. Option (c) hides a state a Keeper should act on.

- **Q-T075-2: Should doctor sync claim refs from the remote before counting?**
  Options: (a) no, read this clone's refs only, as the malformed check does (`doctor_claims.go:27`); (b) fetch first, as `waggle status` does by default; (c) fetch only without `--no-write`.
  Recommended: (a). The finding is documented as writing no ref (`doctor_claims.go:19-20`), and a fetch writes local refs. Doctor's claim-refs probe already tells a Keeper whether this clone can reach the remote. The cost is that a stale clone can miss a collision; the Fix text is the same either way and `waggle status` syncs.

- **Q-T075-3: Should the Fix line carry `--ref`?**
  Options: (a) the same words as `waggle status`, no ref: `release one, or ask the first login in gate.approvers to clear it with waggle force-release.`; (b) add `--ref refs/waggle/claims/ticket-<n>` for the later ticket, as the malformed Fix does (`doctor_claims.go:40`).
  Recommended: (a). T-084 and this ticket should say the same thing as `waggle status`, and a Keeper picks which side to clear. The first `waggle force-release` run prints the ref and the exact second command (`docs/multi-keeper.md:64`).

- **Q-T075-4: How do T-075 and T-084 share wording, and in which order?**
  Options: (a) T-075 first; it creates `cmd/waggle/collisions.go` and moves `status.go` onto it; T-084 then reuses the three strings in `hives.go`; (b) T-084 first and T-075 reuses; (c) run in parallel and merge the wording by hand.
  Recommended: (a), one after the other, never parallel: both lease `cmd/waggle`, and the lease rule does not allow a silent overlap. T-084's brief should name `collisionPair`, `collisionImpact` and `collisionFix` as its source of words. If the Head Keeper prefers T-084 first, only the file's creator changes; the strings do not.

- **Q-T075-5: Keep the old `ok` summary text `No malformed claim.`?**
  Options: (a) change it to `No malformed claim or case collision.`; (b) keep `No malformed claim.` and print nothing about collisions when there are none.
  Recommended: (a). A Keeper reading `ok` should know collisions were checked. Cost: the existing test asserts `ok        claims` only (`doctor_claims_test.go:34`), so it needs no change.

- **Q-T075-6: Count directory pairs or ticket pairs?**
  Options: (a) the number of `CaseCollision` entries, which is directory pairs, as `waggle status` prints one line per entry; (b) distinct ticket pairs.
  Recommended: (a). It matches the number of warning lines `waggle status` prints, so the two commands agree, and it needs no extra code. The summary says `pair(s) of claims`, and two tickets with two colliding directories read as two pairs on both commands. If the Head Keeper wants (b), `status.go` should change too, which is a wider edit than this ticket.
