## 1. Goal

Every role becomes a recognizable bee job (D-074). Queen and guard stay. Three names change, and two of them swap meanings:

| Old name | New name | What the role does (unchanged) |
| :--- | :--- | :--- |
| `architect` | `scout` | Plans tasks, writes briefs, owns roadmap and specs. Scouts search ahead and dance directions to the hive. |
| `scout` | `forager` | Triage: reproduces bugs, writes failing tests, maps leases. Foragers bring material back from outside. |
| `forager` | `builder` | Writes code inside a Cell, within its lease. Builder bees make comb. |
| `queen` | `queen` | unchanged |
| `guard` | `guard` | unchanged |

No behavior changes. Only names, plus the lease compatibility rule in section 5 and the retired `drone` name (D-073) in section 6.

## 2. Why this cannot be a plain find and replace

`scout` and `forager` both exist before and after, with different meanings. A sequential replace collides:

- `forager -> builder`, then `scout -> forager`, then `architect -> scout` happens to work only in that exact order, and only for exact-word matches. Any other order merges two roles into one name (for example `scout -> forager` first, then `forager -> builder` turns the triage role into the builder).
- A half-done rename is ambiguous: a file that says `forager` could mean either role. So the rename is **atomic per layer**: one product commit for code and templates, and no state on `main` where some product files use the new names and others the old.
- T-013 section 7's rule (rename each file when the next ticket touches it) does **not** apply here. That rule was for Head Keeper, a pure synonym. A swap needs a sweep.

**Required method: two steps through neutral sentinels.** Sentinels contain no role word, so step order cannot collide.

Step 0. Assert no sentinel exists outside this brief: `git grep -n -i 'zzwr[123]zz' -- . ':!*T-020.md'` prints nothing.

Step 1 (old to sentinel), on every file in the lease except section 4's exclusions:

```
perl -pi -e '
  s/\bforager(s?)\b/zzwr1zz$1/g;   s/\bForager(s?)\b/Zzwr1zz$1/g;   s/\bFORAGER(S?)\b/ZZWR1ZZ$1/g;
  s/\bscout(s?)\b/zzwr2zz$1/g;     s/\bScout(s?)\b/Zzwr2zz$1/g;     s/\bSCOUT(S?)\b/ZZWR2ZZ$1/g;
  s/\barchitect(s?)\b/zzwr3zz$1/g; s/\bArchitect(s?)\b/Zzwr3zz$1/g; s/\bARCHITECT(S?)\b/ZZWR3ZZ$1/g;
  s/(?<=[a-z0-9_])Forager/Zzwr1zz/g; s/(?<=[a-z0-9_])Scout/Zzwr2zz/g; s/(?<=[a-z0-9_])Architect(?!ur)/Zzwr3zz/g;
' <files>
```

Step 2 (sentinel to new):

```
perl -pi -e '
  s/zzwr1zz/builder/g; s/Zzwr1zz/Builder/g; s/ZZWR1ZZ/BUILDER/g;
  s/zzwr2zz/forager/g; s/Zzwr2zz/Forager/g; s/ZZWR2ZZ/FORAGER/g;
  s/zzwr3zz/scout/g;   s/Zzwr3zz/Scout/g;   s/ZZWR3ZZ/SCOUT/g;
' <files>
```

Step 3. Assert no sentinel remains, then list every residual substring for manual review: `git grep -n -i -E 'forag|scout|architect' -- <lease>`. Expected residue: the word `architecture`, the new names, and the hand edits in section 5. Anything else is a bug in the sweep.

Notes on the patterns:
- `\barchitects?\b` never matches `architecture` (5 uses in the tree today). The identifier rule excludes `Architectur...` with `(?!ur)`.
- `\b` matches after `-` and `/`, so `waggle-forager.md`, `roles/scout.md` and `"forager"` all convert.
- The lookbehind rules catch identifiers such as `RoleForager` or `minArchitect` if T-012 or later tickets add them. Today role names appear in Go only as string literals.
- There is no `builder` anywhere in the tree today, so step 2 cannot collide with an existing word. Go's `strings.Builder` will appear in grep output later; audits must use `\bbuilder\b` in string literals and role contexts, not a bare `-i builder`.

**File renames use the same two steps,** because `scout.md` exists before and after:

```
git mv roles/forager.md roles/zzwr1zz.md; git mv roles/scout.md roles/zzwr2zz.md; git mv roles/architect.md roles/zzwr3zz.md
git mv roles/zzwr1zz.md roles/builder.md; git mv roles/zzwr2zz.md roles/forager.md; git mv roles/zzwr3zz.md roles/scout.md
```

Apply to `internal/scaffold/templates/roles/` and to any other file named after a role. Git will show `roles/scout.md` as a large content change; the guard reviews renames with section 8's mapping check, not with `git diff` alone.

## 9. Ordering and dispatch window

- Phase A touches most product directories, so every in-flight product ticket rebases over it, and their briefs' role words change in phase C. The cheapest window is before T-011 phase B, T-012, T-016 and T-018 phase C write new role-name code, so those tickets are born with the new names.
- **Order fixed by D-081:** merge T-011 phase A, then T-020 phases A and B (product), then T-011 phases B and C. "Right after T-011" in D-081 means after phase A only; T-011 phase B (`waggle uninstall`, `internal/scaffold/` and `cmd/waggle/`) waits for T-020 phase A so it is written with the new names. Phase A's lease is taken on `main` with T-011 phase A merged, so the T-011 phase A paths (`internal/layout/`, the templates under `.waggle/control/` names) are in the sweep's inventory.
- Phase C still needs T-016, which needs T-011 A and B. So: T-011 A, T-020 A and B, T-011 B, T-011 C, T-016, then T-020 C together with the first `waggle upgrade` of our hive. T-012 and T-018 phase C dispatch after T-020 A.
- **T-011 phase C pin: the phase A merge commit** (queen default, reversible; the Keeper can override). With this order a phase B pin would already contain T-020 phase A, so T-011 step C-3 would install the new role files, roster and shims into our hive while `waggle init --force` never removes `roles/architect.md`. Pinning phase A keeps our hive on the old names, consistently, until phase C here moves the pin through `waggle upgrade`, which deletes the dropped managed files (D-042, D-083, T-016 section 2.1). T-011 section 10 records the same choice. If the Keeper overrides to a phase B pin, C-3 must add `git rm .waggle/control/roles/architect.md` and section 7.3 (brief sweep) joins that hive PR.
- Between phase A and phase C our hive still runs the old pinned build and old names. That is consistent, not a gap. Briefs written in that window use the old names and get the phase C sweep.
