## 1. Goal

Every PR and every push to `main` builds, vets, format-checks and race-tests the product. Today nothing does: the only workflow, `waggle-gate.yml`, is hive tooling (Tier warnings and a placeholder commit loop) and runs no Go.

Product CI is its own workflow (D-072), separate from the hive gate:
- It checks the product, so it must not change when our hive upgrades its pinned build (D-041, D-042).
- Its check name is stable and can be required on `main` by itself.
- It needs only `contents: read`, while `waggle-gate.yml` still holds write scopes for `relay-claim` until T-014.

## 2. File: `.github/workflows/ci.yml`

```yaml
# SPDX-License-Identifier: MIT-0
# Product CI for the waggle repo (T-019, D-072). Not part of the hive gate
# (waggle-gate.yml) and not scaffolded into other hives.
name: Product CI

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read

concurrency:
  group: product-ci-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

jobs:
  product-ci:
    name: product-ci
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v5
        with:
          persist-credentials: false

      - uses: actions/setup-go@v6
        with:
          go-version-file: go.mod
          cache: false

      - name: Build
        run: go build ./...

      - name: Vet
        run: go vet ./...

      - name: gofmt (tracked files)
        run: |
          unformatted="$(git ls-files -z '*.go' | xargs -0 gofmt -l)"
          if [ -n "$unformatted" ]; then
            echo "::error::gofmt -l reports unformatted files:"
            echo "$unformatted"
            exit 1
          fi

      - name: Test (race)
        run: go test -race ./...
```

Notes for the Head Keeper and the guard:
- **Go version:** `go-version-file: go.mod` reads the `go 1.23` directive, so CI follows `go.mod` with no second place to bump.
- **`cache: false`:** the module is stdlib only and has no `go.sum`; setup-go's cache would only print a "dependencies file not found" warning on every run. Revisit when a dependency lands (a Tier 3 change anyway).
- **gofmt on tracked files only:** `gofmt -l .` also walks untracked agent worktrees (`.claude/worktrees/`) and reports their stale copies (T-017 section 4). `git ls-files -z` with `xargs -0` is safe for any path. There is always at least one `.go` file, so `gofmt` never falls back to reading stdin.
- **Action versions:** use the current major of each action at commit time (`actions/checkout@v5` and `actions/setup-go@v6` when this was written; confirm on the Marketplace). `waggle-gate.yml` still uses `checkout@v4`; aligning it is not this ticket. Pinning actions to full commit SHAs across both workflows is Q-T019-2.
- **`persist-credentials: false`:** no step pushes, so the checkout leaves no token in `.git/config` for a later step to reuse.
- **Job and check name `product-ci`:** the ruleset in section 6 requires it by this exact name. Renaming the job later silently drops the requirement, so a rename needs a ruleset edit in the same change.
- **Tests and git:** `go test` runs T-002's git-backed tests. They isolate git config themselves (`GIT_CONFIG_GLOBAL=/dev/null`), so the runner's git setup does not matter. No `fetch-depth: 0` is needed: no step reads history.
- **No `merge_group` trigger.** Native merge queue is opt-in (D-064, D-071). A hive that opts in adds `merge_group:` here in the same change.

The repo setting is on and the workflow is registered, so the trigger reached GitHub but no run was created. Check, in this order (Head Keeper, in the browser as org owner):

1. **Org Actions policy.** Org Settings, Actions, General: "Policies" must allow Actions for all repositories or for `waggle` by name. An org-level "Disable for all repositories", or "Allow for selected repositories" without `waggle`, overrides the repo setting the API reports. This is the most likely cause for a new org.
2. **Billing and account state.** Org Settings, Billing and plans: look for a banner about a missing or failed payment method, a locked account, or Actions minutes. Free orgs get included minutes for private repos, but a billing hold or a flagged new account (for example pending verification) can stop runs from being created. Upgrading to Team (D-047) may surface or clear this.
3. **Workflow permissions.** Org and repo Settings, Actions, General, "Workflow permissions". `waggle-gate.yml` asks for `contents`, `pull-requests` and `issues: write`. If the org caps the token at read, that should produce a failed run, not a missing one, so this is a lower-probability cause. Check it anyway because T-014 depends on it.
4. **Fork and approval settings.** "Require approval for first-time contributors" applies to forks only; PRs #1 and #2 came from branches in the same repo, so this should not matter. Confirm it is not set to "all outside collaborators" with the PR author excluded.
