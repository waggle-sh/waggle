## 1. Goal

The gate's main claim needs two corrections before G5. The forge has no template fix. The other had one, O1, which D-355 set aside.

**The check can be forged.** Test workflows on a probe repo, on a loose rule (not strict), approvals 0 to isolate the check unless stated (`media/T-046/probe-log.md`). All on a `pull_request_target` test workflow except the row marked:

| Route | Rule | Result |
|---|---|---|
| Workflow: POST a passing check of the required name, alone | Not bound | `BLOCKED`: a post alone does not clear the failure |
| Workflow: DELETE the failing run | Not bound | Check run and suite leave the commit; `BLOCKED` on the missing check |
| Workflow on a plain branch, `on: push`: delete, then post | Not bound | `CLEAN` |
| Another open PR's workflow | Not bound | `CLEAN`, and the victim **merged with no admin flag** |
| The PR's own job of the required name passes and deletes | Not bound | `CLEAN` (it posts nothing) |
| Plain branch, on a test workflow with today's `pull_request` job (one `exit 1` job, no review trigger) | Not bound | `UNSTABLE`, mergeable. Several failing runs would each need deleting; not run. The attack YAML deletes one |
| **Token, no workflow file** (holding `repo` and `workflow`, used through the API): POST a passing commit status, alone | Not bound | `BLOCKED` |
| Token: delete the run, status in place | Not bound | `UNSTABLE`, mergeable |
| Token: delete, status | **Bound to GitHub Actions** | `BLOCKED`: binding closes the status route |
| Workflow on a plain branch: delete, then post | **Bound to GitHub Actions** | `UNSTABLE`, mergeable: binding does not stop a workflow |
| Workflow on a plain branch: delete, then post | **1 approval required** | `REVIEW_REQUIRED BLOCKED`; a merge with no admin flag refused |

**S12** (fine-grained token, Contents write, no Workflows): a new workflow file was refused; a file identical to one on another branch was pushed, and that copy ran with its own write token and posted a passing check. One case; whether a copy must match path and bytes exactly was not tested further. **No row ran a token with Contents and Pull requests write, nor a token with only Contents write on the token route.**

**So three protections, none complete alone:**

1. **Bind the check to GitHub Actions.** Closes the status route only.
2. **Limit agent credentials to Contents and Pull requests, with no Workflows, Actions or Commit statuses permission.** S12 shows Contents write alone cannot plant a new workflow. The copy exception stands: this holds only while no attack workflow exists on any branch.
3. **A required review blocks a merge with no approval.** It keeps a person in the merge; it does not protect the check. An approver may see a forged green check. In the other order, an approver can approve a red PR and a forge from another branch can follow with no push to the head, so stale dismissal does not fire. That order was not run; it follows from the rows.

**An approval alone cannot turn the check green.** E1: with an approval standing and a passing review run on the head, `APPROVED BLOCKED`, because the earlier failing `pull_request` run stays. E2: a re-run of the failed run clears it. Both on test workflows; the real gate was not run, and the docs say so.

**What these do not cover.** Nothing here ran the real gate binary. S2 and S3 did not run and are not needed: D-355 stands without them.
