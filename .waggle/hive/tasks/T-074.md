## 1. Goal

Make the gate's head tree collision check catch paths that differ only in Unicode normalization. `caseCollisions` lists the head tree with `git ls-tree -r -z --name-only --full-tree` (`gate_commits.go:425`), keys each path by `strings.ToLower` (`:438`) and reports a pair only when `strings.EqualFold` agrees (`:439`). Neither call normalizes. A head tree holding `docs/café.md` as NFC (`e` with acute as one rune, U+00E9) and as NFD (`e` then U+0301) passes the gate today. On macOS APFS, which is normalization insensitive, those two names are one file: a checkout loses one of them.

The case half of the check already works for non-ASCII letters, because `ToLower` and `EqualFold` fold Unicode case (`É` against `é` fails today). This ticket adds the normalization half and keeps the case half.

## 2. Scope

1. **Key function.** An unexported `collisionKey(p string) string` in `gate_fold.go`: canonical decomposition of the path (as far as the chosen option reaches, Q-074-1 and Q-074-2), then Unicode lower casing, returned as the map key. An all ASCII path takes a fast path that is exactly `strings.ToLower(p)` as today, since ASCII is its own normal form. Invalid UTF-8 never panics.
2. **Wire it in.** `caseCollisions` uses `collisionKey` for the key. The `EqualFold` confirmation is replaced by `collisionKey(prev) == collisionKey(p)` (the map hit already says that, so the second test only keeps `prev != p`, byte difference, as today). The over-length rule (`:434-436`), the `continue` after a finding (`:441`, so later twins name the first path seen) and the `checkTiers` name stay.
3. **Finding text.** When `strings.ToLower(prev) == strings.ToLower(p)` (a pure case difference, which is every ASCII case), the message is byte for byte today's: `path collides with <prev> on case-insensitive checkouts`. Otherwise it is `path collides with <prev> on checkouts that treat Unicode normalization forms as one name` (Q-074-4). `TestVerifyCaseCollision` (`gate_verify_test.go:275-285`) keeps passing without an edit.
4. **Docs.** `docs/gate.md:47`: the head tree rule now says paths equal under case folding or Unicode normalization, or over 4096 bytes, fail; states what the normalization step covers and what it does not (section 7); refreshes the `gate_commits.go` and `gate_fold.go` cites. No new section, no new limit entry beyond one sentence.

## 3. Flow, end to end

1. A contributor on Linux opens a PR under a claim on `docs`. Base has `docs/café.md` in NFD (bytes `63 61 66 65 cc 81`). The PR adds `docs/café.md` in NFC (bytes `63 61 66 c3 a9`), perhaps a rewrite saved by an editor that composes.
2. Before this ticket: `ls-tree` lists two distinct byte paths, `ToLower` keeps both distinct, the check passes, and a macOS contributor's checkout of the merge result has one `café.md`.
3. After: both paths decompose to the same key. The second one `ls-tree` returns fails: `tiers: FAIL: docs/café.md: path collides with docs/café.md on checkouts that treat Unicode normalization forms as one name`. The two names print the same on screen; that is why the text says normalization (Q-074-4 asks whether to add bytes).
4. The contributor renames one of the files. The gate passes. No approval clears this finding, because it is raised after the lease and tier filters (`gate_verify.go:270-271`) and carries no `tier3` or `outside_lease` rule; a signed Head Keeper approval (T-071) does not touch it either (`docs/gate.md:109`).

## 5. Out of scope

- **A directory against a file with the same folded name.** `docs` as a file and `Docs/a` as a path are not compared; the check compares whole paths only. T-014b review F6 accepted this for the case rule; it is the same gap for normalization. Q-074-3 asks whether to open a follow-up.
- **Tier 3 and lease matching.** `HardcodedTier3Prefixes` (`internal/comb/backend.go:25-45`) is matched on lower cased bytes, and `leaseMatch` compares exact case. Neither normalizes. Every hardcoded prefix is ASCII, so a normalization variant of one cannot be a different byte string that APFS reads as the same name, except through characters with a canonical single-rune equivalent in ASCII (U+212A KELVIN SIGN, which lower cases to `k`; no hardcoded prefix has a `k`). Repo-defined `gate.protected_paths` could. Q-074-5.
- **Compatibility normalization (NFKC, NFKD).** APFS does not treat fullwidth or ligature forms as one name; the check does not either.
- **Warning on a lone decomposed path.** A path in NFD with no NFC twin passes as today.
- **A claim-time or `waggle` side check.** The gate is the only place this runs (T-073 Q-T073-8).

## 6. Does a normalization library change `go.mod`?

Yes. `go.mod` has two lines, `module github.com/waggle-sh/waggle` and `go 1.23`, no `require`, and no `go.sum` exists. Go's standard library has no NFC or NFD function: `unicode` holds category and case tables, and the normalizer the toolchain itself uses is vendored under `GOROOT/src/vendor/golang.org/x/text/` and cannot be imported. The usual choice is `golang.org/x/text/unicode/norm`. Adding it:

- adds a `require` line to `go.mod`, may raise the `go` directive (check the module's own directive at build time), and creates `go.sum`. `go.mod` and `go.sum` are hardcoded Tier 3 (`internal/comb/backend.go:36-37`), as is `vendor/` (`:41`), so the change needs the Head Keeper's approval and a two guard fix round (Risk Tier above).
- breaks the gate Action build as it stands: `gate/action.yml:38-39` builds with `GOPROXY: "off"` and `GOFLAGS: -mod=readonly`, and `actions/setup-go` runs with `cache: false` (`:31`). With no proxy and no module cache the build cannot fetch the module, so it would need a checked in `vendor/` tree.
- breaks an existing test: `TestSignedApprovalAddsNoDependency` (`gate_sign_test.go:315-336`) fails when `go.mod` contains `require`. T-071 chose no dependency on purpose; the test pins it, and it is outside this lease.

**Standard library option.** Normalize with the standard library only, in `gate_fold.go`, with no `go.mod` change (Q-074-1 option (b)):

- a small table of canonical decompositions for the characters in scope (Q-074-2), applied recursively (a decomposed rune can itself decompose, as `ế` does);
- the Hangul syllable decomposition, which is arithmetic over U+AC00 to U+D7A3 and needs no table (about 12 lines);
- `strings.ToLower` after decomposition, which also absorbs the three single-rune equivalents that have a lower case mapping (U+212A to `k`, U+212B to `å`, U+2126 to `ω`).

What the standard library option does not do: reorder combining marks by combining class when one base has several marks, and cover the rest of Unicode (other scripts, CJK compatibility ideographs, the Greek and Cyrillic precomposed forms unless Q-074-2 adds them). Those pairs still pass; the docs line says so. This is the cost of avoiding the dependency, and it is why Q-074-1 is a Head Keeper ruling.

## 7. Threat notes (D-203)

**Boundary.** The head tree is attacker influenced input (a PR author chooses every path name). The gate runs on the Action's own pinned tree (`gate/action.yml:44`), so the PR cannot change the rule it is checked by.

**Defended.**
- *A PR adds a normalization twin of an existing file so a macOS checkout silently drops one:* the second path fails `tiers`.
- *A PR adds both spellings itself:* same.
- *Hostile bytes in a path (newline, `::warning::`, invalid UTF-8):* the key function never panics and never changes the text that is printed; printing goes through the existing encoder (`TestVerifyEncodesHostileText`). A test feeds invalid UTF-8 and a lone combining mark.
- *A very long path:* the 4096 byte check runs before any decomposition (`:434`), so the table lookup never sees more than 4096 bytes; decomposition can lengthen a path by a few times, still bounded.
- *Cost:* one pass over the tree, one key per path, an ASCII fast path. No quadratic step. 500,000 paths cost about 500,000 key calls and one map.

**Not defended (stated in docs).** Pairs outside the table (Q-074-2), mark reordering within one base, compatibility forms, a directory against a file, and a merge that skips the gate (L2 in `docs/gate.md`).

**False positives.** A wrong table entry could fail a pair APFS keeps apart. N3 and N6 pin the table's shape and a set of near misses.

## 8. Test plan

All tests in `cmd/waggle/gate_fold_test.go`, built in a local temp repo with the existing helpers (`r.index` writes paths straight into the index, so it works on a case-insensitive filesystem too, `gate_verify_test.go:62`). Unicode is written as escapes in the Go source so the file does not depend on an editor keeping the form.

- N1. Key table: `café` NFC and NFD give one key; `CAFÉ`, `café` (NFC) and `café` (NFD) give one key; `a.md` and `A.md` give one key; `cafe` and `café` give different keys; `日本` and `本日` give different keys; U+212B and `å` give one key.
- N2. Verify, head tree holds `docs/café.md` in both forms: exit 1, `tiers` finding, text `path collides with` and `Unicode normalization forms`, no `leases` finding; `tiers` alone fails; `leases` alone does not.
- N3. Table sanity: every table entry's first rune is a letter (`unicode.IsLetter`), every following rune is in U+0300 to U+036F, and no entry maps a rune to itself. A typo in an entry fails this test.
- N4. Hangul: `한` (U+D55C) against U+1112 U+1161 U+11AB fails; `한` against `하` passes.
- N5. Three variants (`É`, `é`, `e` with U+0301): the second and third fail and both name the first path `ls-tree` returned; two findings, in tree order.
- N6. No false positive: `docs/café.md` with `docs/cafe.md`, `docs/naïve.md` with `docs/naive.md`, and two unrelated non-ASCII names, all pass.
- N7. Invalid UTF-8: paths `a/\xff` and `a/\xfe`, and a path that is a lone U+0301, run without panic; the result for the invalid pair is the same as on main before the change (the builder runs the existing code first and pins what it does; today `ToLower` and `EqualFold` both turn each invalid byte into U+FFFD, so the pair is expected to be reported).
- N8. ASCII: `TestVerifyCaseCollision` passes unchanged; an ASCII pair prints the old text; a tree with only distinct ASCII names passes; a path over 4096 bytes still fails with its old text.
- N9. Order independence: the same tree built in the index in two orders gives the same set of findings (git sorts `ls-tree` output by bytes, so this pins the first-seen rule).
- N10. `go.mod` has no `require` line and no `go.sum` exists after the build (`TestSignedApprovalAddsNoDependency` already pins the first; the build runs `git diff main --stat` for the rest).

## 11. Open questions

- **Q-074-1: How should the gate normalize path names?**
  Options: (a) `golang.org/x/text/unicode/norm`. Complete, but changes `go.mod` and `go.sum` (Tier 3), needs `vendor/` for the Action's no-network build, and breaks `TestSignedApprovalAddsNoDependency` (section 6). (b) Standard library only: a decomposition table, Hangul arithmetic and `ToLower` in `gate_fold.go`. No `go.mod` change; covers the ranges Q-074-2 names; known gaps listed in section 6. (c) Standard library, no table: fail any path with a rune in U+0300 to U+036F or U+1100 to U+11FF ("not in composed form"). About 25 lines and no table, but a tree that holds only decomposed names, with no twin, starts failing, which is a new rule, and single-rune equivalents are missed. (d) Do nothing and document the gap in `docs/gate.md`.
  Recommended: (b). It closes the macOS case the release names without touching a Tier 3 path or the Action build. (a) is the only complete option and is right if the Head Keeper accepts a dependency and a vendored tree; (c) changes what passes for brownfield repos with decomposed names.

- **Q-074-2: How wide is the table under option (b)?**
  Options: (i) Latin-1 Supplement and Latin Extended-A (U+00C0 to U+017F), plus Hangul. Covers Western and Central European names. (ii) (i) plus Latin Extended Additional (U+1E00 to U+1EFF, Vietnamese and others), about 90 more lines. (iii) (ii) plus Greek and Cyrillic precomposed letters.
  Recommended: (i) in the build, with (ii) as the planned cut `t-074b` if the Head Keeper wants it. The table grows only on a ruling because each entry is a merge rule on Tier 3 code.

- **Q-074-3: Compare whole paths only, or also directory against file?**
  Options: (a) whole paths only, as today. (b) also report a path whose parent directory folds to another entry's path (a file `Docs` against `docs/a`).
  Recommended: (a), and the Head Keeper opens a follow-up ticket for (b) covering case and normalization together. T-014b review F6 accepted the same gap for case. (b) needs a second index of directory names and a rule on which one fails.

- **Q-074-4: What does the finding say for a pair that differs only in normalization?**
  Options: (a) one fixed sentence: `path collides with <prev> on checkouts that treat Unicode normalization forms as one name`. (b) (a) plus the code points of the first differing rune (`U+00E9 against U+0065 U+0301`), because the two names print the same.
  Recommended: (a). The finding is unactionable only if the author cannot see which file to rename, and the path in the finding names the second file and the message names the first. (b) is a small addition if a guard finds that unclear.

- **Q-074-5: Should Tier 3 prefix matching and `gate.protected_paths` matching normalize too?**
  Options: (a) no, this ticket changes only the head tree collision check; (b) yes, add the key function to the protected path matcher.
  Recommended: (a). The hardcoded prefixes are ASCII (`internal/comb/backend.go:25-45`) and the one single-rune ASCII equivalent that matters, U+212A, already lower cases to `k`. A repo-defined protected path with a non-ASCII name is the open case; the Head Keeper decides whether it is a follow-up ticket. It is a different file set (`internal/comb`, lease `internal/comb`) and a different review.
