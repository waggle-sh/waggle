## 1. Goal

`waggle dispatch <ticket>` replaces the loop the queen runs by hand today (`.waggle/hive/handoff/queen.md`, "Habits that worked"): brief, isolated worktree branched from `origin/main`, builder run, sonnet guard, draft PR. One command claims the ticket's lease through the Comb, provisions a `git worktree` from the base revision, assembles the role prompt with T-021's `AssemblePrompt`, launches headless `claude -p` through the T-021 adapter, and checks the result against the claim before anything leaves the machine.

No daemon yet. Dispatch is a foreground process with a library core (`dispatch.Run`) that the run.sock loop (next D-014 slice) calls unchanged. No Cells yet. The worker runs as the Keeper's own OS user, and lease enforcement is a **post-run check** of every change against the claim (section 7). Real isolation (`ro` root, `rw` lease mounts, blocked egress, zero credentials, RFC-0003 sections 3.2 and 3.5) is the Cells slice. This ticket keeps one seam for it (section 7.3) and does not design it.

Go 1.23, module `github.com/waggle-sh/waggle`, **standard library only**. Do not touch `go.mod`.

## 4. CLI (phases C and D, `cmd/waggle/dispatch.go`)

```
waggle dispatch <ticket> --role builder|forager --dir <path> [--dir <path>...] --gate light|full --no-cell
                [--branch t-<nnn>[suffix]] [--base <rev>] [--tier 0|1|2|3] [--read <path>...]
                [--timeout 120m] [--no-push] [--keep-worktree] [--json] [--repo <dir>]
waggle dispatch <ticket> --role guard --branch <branch> --no-cell [--second] [--base <rev>] [--tier N] [--json]   (phase D)
waggle dispatch clean <ticket> [--role <role>] [--runs] [--repo <dir>]                                        (phase D2)
waggle dispatch clean --host-record [--accept <digest>] [--repo <dir>]                                        (phase D2)
waggle dispatch list                                                                     (phase D2 or E, Q-T023-28)
```

- `<ticket>` accepts what `comb.ParseTicketID` accepts. `--role` must be a claim role (`builder`, `forager`, `guard`); `queen`, `scout`, `waggled` and unknown roles are usage errors. The scout stays outside dispatch: briefs are hive files no lease can cover (D-043, D-057).
- `--dir` and `--gate` are the lease, copied by the queen from the brief's Lease line for the phase (Q-T023-5). Comb validation applies unchanged (Tier 3 and `.waggle/` refused, Tier 2 under `light` refused, at most `leases.max_directories_per_claim`).
- `--branch` defaults to `t-<nnn>` (lowercase canonical display form). It must start with `t-<nnn>` for this ticket and pass `git check-ref-format --branch`; `main` and the base branch are refused.
- `--base` defaults to `<forge.remote>/main` after a fetch when a remote is set, else `main`. It is resolved to an OID once and recorded; everything later uses the OID. When the branch already exists, the check base `merge-base(<branch>, <baseOID>)` must be an ancestor of (or equal to) the default base's OID; otherwise exit 2, "base is on the branch; earlier branch commits would skip the check". This catches every spelling of base equal to branch (`heads/t-023`, `origin/t-023`, `t-023~0`, a branch commit by OID), which phase B's string compare does not.
- `--tier` feeds `TaskContext.Tier`; absent means unknown, which policy treats as Tier 3 (the more generous guard). `--read` lists read-only context paths for `AssemblePrompt` (inlined under `thorough`).
- `--no-cell` is required in every phase of this ticket (Q-T023-2). Without it dispatch exits 2 and prints the not-enforced list of section 8.
- No flag skips the post-run check, lowers a model, or skips the guard. There is no `--force`.

Exit codes (one table, shared by the library's `Result.ExitCode` and the CLI):

| Code | Meaning |
| :--- | :--- |
| 0 | Session ended normally and every check passed (builder, forager), or a verdict was recorded (guard: `pass` and `must-fix` are both 0; the verdict is in the result) |
| 1 | Run failed: lease or tier violation, host-state violation, worktree dirty, no commits, agent or runtime error, interrupted |
| 2 | Usage error, before any git write |
| 3 | Environment: git, config, I/O, `claude` binary missing, brief absent at base, push rejected |
| 4 | Claim refused: held, overlapping, malformed, Tier 3 or `.waggle/` (section 6) |
| 5 | Needs the Keeper: `max_turns`, `max_tokens`, timeout, guard with no verdict, bad handoff, `max_sessions` |

Stdout carries one line per progress event (section 9.2) and a closing summary; `--json` prints only `result.json`. Stderr carries errors. No U+2013 or U+2014 in any output.

## 5. Dispatch sequence (`dispatch.Run`)

1. **Validate** flags, ticket, role, branch (exit 2). Load config (`config.Load`), policy (`config.LoadPolicy`, T-012 and T-021 phase B), `keeper_id` (5.4). Refuse a `--dir` the Comb will refuse (Tier 3 by `comb.RequiredMinTier`, under `.waggle/`) with exit 4 here, before any fetch or blob read (fable N7a); the Comb stays the authority at step 5.
2. **Resolve base**, fetching first when `forge.remote` is set (host side, the Keeper's git auth).
3. **Read inputs from base**: brief, role prompt, `WAGGLE.md`, review file (5.3). Missing brief: exit 3, "brief not on base; land it in a hive PR first".
4. **Resolve model and settings**: `Policy.Resolve(role, TaskContext{TaskID, Tier, GuardMustFix: CountMustFix(review at base)})`, then `ContextPolicy.Settings(role, task, nudge_tokens)`. No overrides in v0.1 (section 13).
5. **Claim** (builder, forager; section 6). The guard reads the claim instead (10.2).
6. **Worktree**: create or reuse, take the run lock (7.1).
7. **Snapshot host state** (7.2), then **launch** through the Cell seam with `Prepare` (phase A), stream into `Collect`, renew the claim at half its TTL while the session runs.
8. **Check** (7.2). **Push** only on a clean pass with a remote set, unless `--no-push`.
9. **Record** `result.json`, append the ledger line (phase D), release the run lock, remove the worktree on success unless `--keep-worktree`.

## 6. Claims (phase B, `claim.go`)

`comb.AcquireLease` with `KeeperID`, `Role`, `Gate`, `Directories`, TTL from config. In remote mode `AcquireClaim` takes the claim OID from the local mirror ref after `AcquireLease` (a local `rev-parse`, no third fetch); a failing post-write `ReadClaim` or `rev-parse` is a warning, never exit 4. Outcomes:

- **Free, or expired (anyone's):** acquired, or taken over as a child commit (RFC-0003 3.1). A takeover prints the previous owner.
- **Active, same Keeper:** renewal (the must-fix round case). If directories or role differ, print old and new before writing.
- **Active, another Keeper:** `ErrAlreadyClaimed`, exit 4, owner and expiry printed, nothing else touched (no worktree, no branch fetch).
- **Overlap, Tier 3, `.waggle/`, light on Tier 2, malformed target:** exit 4 with the comb error. A malformed target adds "a Head Keeper force-release clears it (T-005)".
- **Keepalive:** while the session runs, renew at `TTL/2`. A failed renewal does not kill the session; it is a warning in the result (`claim_renew_failed`), and the post-run check still runs against the claim as last read.
- The claim **stays** after the run, success or failure: the gate needs it until merge (T-014 section 4.3). Release after merge is a follow-up `waggle release` ticket (section 13); until then claims expire by TTL, and an expired claim passes the gate with a warning (D-053).

## 7. Worktree and lease enforcement

### 7.1 Worktree lifecycle (phase B, `worktree.go`)

- Path `layout.Worktrees/T-<nnn>-<role>` (gitignored runtime state). Run records go in `layout.Worktrees/runs/T-<nnn>-<role>-<seq>/`, never inside the worktree.
- New branch: `git worktree add -b <branch> <path> <baseOID>`. Existing branch (must-fix round): `git worktree add <path> <branch>`, and the check base becomes `merge-base(<branch>, <baseOID>)`.
- **Run lock:** `<path>.lock` created with `O_EXCL`, holding pid, hostname and start time. A live lock is exit 3 ("run in progress"). A lock whose pid is dead on this host is taken over with a warning.
- An existing worktree is reused only when clean and unlocked; a dirty one is exit 3 naming it.
- Success: `git worktree remove` (never `--force`), after re-running `adminDir` and requiring the admin dir pinned at provision; if that fails it is a warning and the worktree stays. Failure of any kind: the worktree stays for inspection and the result names it.
- Must-fix round on another machine (phase C, fable N7b): when `refs/heads/<branch>` is absent but `refs/remotes/<remote>/<branch>` exists after the fetch, create the local branch from the remote-tracking ref (no `--force`) before `worktree add`, instead of starting a fresh branch from base that the later push would reject.
- **Tainted worktree** (phase C): a run that ends with a host-state violation (7.2 rule 4) writes `<path>.tainted` beside the lock, holding the run directory name. While it exists, `Provision` refuses reuse with exit 3, "host state was changed by run <dir>; inspect, restore and run waggle dispatch clean". Reuse runs `git status` under the main repo's config, so a planted filter there would otherwise run on the host at the next dispatch (fable F3).
- **Repo lock** (phase C, D-167): `.waggle/worktrees/dispatch.lock` (`O_EXCL`, same body, bounded read and dead-pid rule as the run lock) is held from before the snapshot to the end of the checks; a second run exits 3 "another dispatch run is in progress in this repo".
- **Host record** (phase D1, 10.6 item 1, D-189, D-192): after every run that reached the checks, `layout.Worktrees/host-files.json` stores the snapshot the checks verified (common config as parsed keys, ignoring only `branch.<name>.merge` and `branch.<name>.remote` naming a configured remote); the next run compares it with fresh hashes before its first unpinned call, and a difference is exit 3 naming the earlier run.
- `waggle dispatch clean` (phase D2): specified in 10.7.3 items 5 and 6. It **never deletes a branch** and never touches a claim.

### 7.2 Post-run checks (phase C, `check.go`)

Before launch, snapshot: `git for-each-ref` (every ref with its OID), the main checkout's `git status --porcelain=v1 -z --untracked-files=all` and `HEAD`, and SHA-256 of these files (absent and non-regular are recorded as such, never followed; bounded reads as in phase B's `readSmall`, with a 1 MiB cap): in the common dir `config`, `config.worktree`, every file under `hooks/` and `info/`, `objects/info/alternates` and `shallow`; the Keeper's global git config (`$GIT_CONFIG_GLOBAL` when set, else `$XDG_CONFIG_HOME/git/config` and `~/.gitconfig`); and the **worktree admin directory** (opus and fable phase B carry): the set of entry names under `<common>/worktrees/`, and for every entry its `gitdir`, `commondir` and `config.worktree`, plus `HEAD` for every entry except this run's own. This run's own admin dir is the one phase B's `adminDir` returned at provision; record its path.

After the session ends, the checks run in this order, and every rule runs and every failure is reported (no stop at the first):

- **Files first.** Compare every hash above, re-run `adminDir` and require the same admin dir as before launch, and require this run's `HEAD` file to still name `refs/heads/<branch>`. These steps read files only and run no git process.
- **Git second, under pinned config.** Every git call in the worktree passes `--git-dir=<admin> --work-tree=<path>`, never relying on `<path>/.git` (the agent may have rewritten it). Every post-run git call, in the worktree and in the main checkout, and the pre-launch `status` snapshot, runs with `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1` and `GIT_ATTR_NOSYSTEM=1` on top of phase B's `-c core.hooksPath=/dev/null -c core.fsmonitor=false`, so only the repo config the file step just verified can name a filter. If the file step found a change to the common `config`, `config.worktree`, `info/` or the admin dir, the `status` calls are skipped and rules 3 and 4 report "not inspected: host config changed", which is a failure. `diff-tree` and `rev-list` run regardless; they run no filters. These calls also drop the Keeper's `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_*`, `GIT_CONFIG_VALUE_*` and `GIT_EXEC_PATH` (case-insensitive, by prefix for the numbered ones); dispatch's `redirectVars` must equal comb's `scrubbedGitEnv` (test 28).

The rules:

1. **Commits** in `<checkBase>..<branch>`: no merge commits; every subject starts with `T-<nnn>: ` for this ticket; at most 500 commits; every commit carries a `Signed-off-by:` trailer naming its author (D-132; rule `dco`, Q-T023-16).
2. **Paths** of every commit (`diff-tree -r -z --no-renames --raw`, deletions and both sides of a rename) pass `comb.CheckChanges` (D-114): inside a claim directory with exact case, no new symlink or submodule mode, no Tier 3 path, no Tier 2 path under `light`. This is the rule `waggle gate verify` applies at merge (D-017: same code locally and in CI). **Precondition (T-014b fable F5):** `CheckChanges` does not clean paths and skips the mode rule on an empty `NewMode`, so dispatch feeds it only paths and modes parsed from that `diff-tree -z` output, and before the call refuses any path that is empty, starts with `/`, contains `\`, differs from `path.Clean`, or has a `.`, `..` or `.git` component, as an `outside_lease` violation with detail "path is not canonical". The gate's head-tree case collision check lives in `cmd/waggle` and is not repeated here; the gate catches it at merge.
3. **Worktree clean:** any uncommitted or untracked change is a failure ("builder must commit"). A builder or forager run with zero commits ends `no_change`, exit 1.
4. **Host state:** refs equal the snapshot except `refs/heads/<branch>` and this ticket's claim ref (in remote mode also other tickets' claim mirror refs, which dispatch's own keepalive syncs move; a final claim sync after the session overwrites any tampered mirror from the remote); the main checkout's status and `HEAD` are unchanged; every hash in the snapshot is unchanged; the admin dir pin holds; no new `core.hooksPath`. A planted hook or filter would later run with the Keeper's credentials, so this is a failure, never a warning, and it marks the worktree tainted (7.1).
5. The guard (phase D) gets rules 3 and 4 with zero allowed changes: no commits, no ref moves.

Checks read git after the process exits. Nothing the agent could have written, run record files included, is trusted as input.

### 7.3 Cell seam (phase C, `cell.go`)

## 8. Credentials: RFC target and phase reality

**Target (RFC-0003 3.5, D-061):** a Cell holds zero credentials; egress reaches only the inference endpoint and package proxies.

**Reality in phases A to E:** the worker is the Keeper's OS user. It can read `$HOME` (SSH keys, the `gh` keyring through the `gh` binary, the macOS keychain, the Keeper's global Claude Code files), write anywhere that user can, and reach any network host. It holds the model credential Claude Code needs. Dispatch reduces exposure and makes violations visible; it does not stop a determined agent.

What dispatch does:
- **Env allowlist** (phase A, adapter-owned, one list): `PATH HOME USER LOGNAME SHELL TMPDIR TERM TZ LANG LC_ALL LC_CTYPE`, the adapter's model auth variables only if set (`ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`), T-021's `claudeEnv`, and fixed values: `GIT_TERMINAL_PROMPT=0` and a `GIT_CONFIG_COUNT` push tripwire (`url.waggle-push-blocked:.pushInsteadOf` for `https://`, `ssh://` and `git@`). Everything else is dropped, including `GITHUB_TOKEN`, `GH_TOKEN`, `SSH_AUTH_SOCK`, `GIT_ASKPASS`, `OP_SERVICE_ACCOUNT_TOKEN` and `AWS_*`.
- **Settings isolation** (phase A): the worker loads none of the Keeper's user settings, plugins, connectors or global `CLAUDE.md`, and none of the repo's `.claude/settings.json` hooks. Our hive's Stop hook (`.claude/hooks/handoff-check.sh`) would otherwise refuse to let a headless worker stop and push it to edit `.waggle/hive/handoff/queen.md`, outside any lease. Dispatch writes its own settings file into the run record (permissions per Q-T023-3) and passes it explicitly.
- **Tool permissions** per Q-T023-3; never `--dangerously-skip-permissions` by default.
- **No forge calls in the worker** (T-018 section 3): pushes, and any later PR calls, run on the host after the checks.
- Every run prints and records `not_enforced`: `read-only root`, `lease-scoped writes (checked after the run only)`, `network egress`, `host credentials readable via HOME`, `writes outside the repo (not detected)`, `code run by allowed build and test commands (test files, go test -exec) is not confined` (sonnet phase A N2: `--restricted` confines the file tools, not Bash subprocesses).

#### 10.7.3 Scope

1. **Group-leader sweep and a pure target list (D-194; opus N16, fable N22; opus N15's narrower alternative).** `observe` records in a `leaders` set the identity of every process it adds to `seen` whose pgid equals its pid. A pure method `targets(tab []proc) (pids, groups []int)` reads only `tab`, `live`, `leaders`, `self` and the tracker's own group; it calls no syscall and reads no clock or table. Pids: each `live` process with pid above 1 that is not `self`. Groups: the pid G of a recorded leader, only when G is above 1, the tracker's own group is known, above 1 and not G, `tab` lists at least one process whose pgid is G, and `tab` lists no process with pid G or lists pid G with the leader's recorded start time. A nil or empty `tab`, or one that does not list `self`, yields nothing: an empty table would make every leader look absent. This replaces D1's per-process `kill(-p.pgid)`, so a group is signalled only when its id is a pid the tracker saw lead it, and a descendant that joined a foreign group (N15) never turns the sweep on that group. `sweep` keeps only the loop: read, `observe`, `targets`, SIGKILL each group and then each pid, record each killed pid and each untracked member of a killed group that `tab` lists as a `Survivor` once, and repeat until `targets` is empty or 40 rounds pass. `newTracker` reads the own group once with `syscall.Getpgid(0)` (N19: `Getpgrp` is missing for solaris and illumos); an error leaves it 0, which yields no groups. The table read and the kill are two tracker fields defaulting to `procTable` and `syscall.Kill`, so the loop can be tested on fabricated data (D2-T3); production code never sets them.
2. **Worker in its own session (opus N15; fable confirmation N15).** `ownGroup` sets `SysProcAttr{Setsid: true}` in place of `Setpgid: true` (darwin, linux and the other unix systems; `cell_other.go` is `!unix` and unchanged). The worker leads a new session and a group whose id is its pid, so `signalGroup`'s `kill(-pid)` is unchanged, and since `setpgid` cannot cross sessions, no worker descendant can join a group of the Keeper's terminal session however dispatch was started. What else changes: the worker has no controlling terminal (opening `/dev/tty` fails at once, where a background read used to stop on SIGTTIN until the timeout); Ctrl-C still reaches only dispatch, which stops the worker through its context; a closed terminal's SIGHUP still reaches dispatch and not the worker. Claude Code's tool shells start their own sessions already (D1 fable N1), so the D-176 path and the tracker's ppid walk do not change. `cell.go` says "new session", and its macOS clause becomes: a background child that calls `setsid` or daemonizes before the next 25 ms read escapes until T-024; one that stays in its tool shell's group is killed by the group sweep.
3. **Leader start time before `Wait` (the `782e608` guard note; opus confirmation N9; fable N14 and N17).** `newTracker` takes the first table read itself, and `runSession` calls it right after `cmd.Start` and before the goroutine that runs `cmd.Wait`, so that read lists the leader (alive, or a zombie with its start time). `observe` sets `rootStart` only while it is empty, so a reused root pid after the reap cannot move the adoption threshold. If that first read fails or does not list the root, `blind` stays set and the run warns `survivors_unchecked`. The separate first `tr.poll()` in `runSession` goes.
4. **Sweep read retry (fable N18).** A failed read during the sweep is retried up to 3 times inside the 40-round bound and signals nothing; `blind` stays set.
5. **`waggle dispatch clean <ticket> [--role builder|forager|guard] [--runs] [--repo <dir>]` (7.1; item 13; fable phase B carry 6; D0b opus N4).** Without `--role`, every claim role whose worktree, lock or marker exists. In order: take `dispatch.lock` (held: exit 3 "a dispatch run is in progress in this repo"), because a prune inside another run's snapshot-to-check window moves admin entries that run checks; take the role's run lock with `takeLock` (live: exit 3; dead pid: taken over with a warning); refuse a worktree path that is a symlink or not a directory; read every `<common>/worktrees/<id>/gitdir` bounded and without following links, and if two entries name the same path after `filepath.Clean`, exit 3 naming both ids and the worktree relative to the repo, with nothing removed (a `git worktree prune` would drop the higher id silently, and that can be the live run's). Then, with every git call under the 7.2 pinned env, `git worktree remove --force <path>` when git lists the path, and `git worktree prune`; then remove `<path>.tainted` (printing the run dir it names, control characters stripped, at most 100 bytes), `<path>.lock.takeover` and the run lock. `--runs` also removes this ticket's entries of `layout.Worktrees/runs/` matching `^T-<nnn>-<role>-[0-9]+$` for the selected roles, after `requireRealDir` on `runs` (a symlinked `runs` is exit 3), without following links. `clean` never deletes a branch, never touches a claim ref and leaves `host-files.json` alone. A git failure is exit 3 naming the step. Scout default, no Keeper question: `clean` refuses duplicate admin entries and never chooses which one to delete, since the pinned admin dir of a tainted worktree is itself suspect.
6. **`waggle dispatch clean --host-record [--accept <digest>] [--repo <dir>]` (D-189, D-192; fable D1 N3).** Under `dispatch.lock`.
