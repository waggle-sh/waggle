## 1. Goal

`waggle dispatch <ticket>` replaces the loop the queen runs by hand today (`.waggle/hive/handoff/queen.md`, "Habits that worked"): brief, isolated worktree branched from `origin/main`, builder run, sonnet guard, draft PR. One command claims the ticket's lease through the Comb, provisions a `git worktree` from the base revision, assembles the role prompt with T-021's `AssemblePrompt`, launches headless `claude -p` through the T-021 adapter, and checks the result against the claim before anything leaves the machine.

No daemon yet. Dispatch is a foreground process with a library core (`dispatch.Run`) that the run.sock loop (next D-014 slice) calls unchanged. No Cells yet. The worker runs as the Keeper's own OS user, and lease enforcement is a **post-run check** of every change against the claim (section 7). Real isolation (`ro` root, `rw` lease mounts, blocked egress, zero credentials, RFC-0003 sections 3.2 and 3.5) is the Cells slice. This ticket keeps one seam for it (section 7.3) and does not design it.

Go 1.23, module `github.com/waggle-sh/waggle`, **standard library only**. Do not touch `go.mod`.

## 4. CLI (phases C and D, `cmd/waggle/dispatch.go`)

```
waggle dispatch <ticket> --role builder|forager --dir <path> [--dir <path>...] --gate light|full --no-cell
                [--branch t-<nnn>[suffix]] [--base <rev>] [--tier 0|1|2|3] [--read <path>...]
                [--timeout 120m] [--no-push] [--keep-worktree] [--json] [--repo <dir>]
waggle dispatch <ticket> --role guard --branch <branch> --no-cell [--second] [--base <rev>] [--tier N] [--json]   (phase D)
waggle dispatch clean <ticket> [--role <role>] [--runs]                                                         (phase D)
waggle dispatch list                                                                                            (phase D)
```

- `<ticket>` accepts what `comb.ParseTicketID` accepts. `--role` must be a claim role (`builder`, `forager`, `guard`); `queen`, `scout`, `waggled` and unknown roles are usage errors. The scout stays outside dispatch: briefs are hive files no lease can cover (D-043, D-057).
- `--dir` and `--gate` are the lease, copied by the queen from the brief's Lease line for the phase (Q-T023-5). Comb validation applies unchanged (Tier 3 and `.waggle/` refused, Tier 2 under `light` refused, at most `leases.max_directories_per_claim`).
- `--branch` defaults to `t-<nnn>` (lowercase canonical display form). It must start with `t-<nnn>` for this ticket and pass `git check-ref-format --branch`; `main` and the base branch are refused.
- `--base` defaults to `<forge.remote>/main` after a fetch when a remote is set, else `main`. It is resolved to an OID once and recorded; everything later uses the OID.
- `--tier` feeds `TaskContext.Tier`; absent means unknown, which policy treats as Tier 3 (the more generous guard). `--read` lists read-only context paths for `AssemblePrompt` (inlined under `thorough`).
- `--no-cell` is required in every phase of this ticket (Q-T023-2). Without it dispatch exits 2 and prints the not-enforced list of section 8.
- No flag skips the post-run check, lowers a model, or skips the guard. There is no `--force`.

Exit codes (one table, shared by the library's `Result.ExitCode` and the CLI):

| Code | Meaning |
| :--- | :--- |
| 0 | Session ended normally and every check passed (builder, forager), or a verdict was recorded (guard: `pass` and `must-fix` are both 0; the verdict is in the result) |
| 1 | Run failed: lease or tier violation, host-state violation, worktree dirty, no commits, agent or runtime error, interrupted |
| 2 | Usage error, before any git write |
| 3 | Environment: git, config, I/O, `claude` binary missing, brief absent at base, push rejected |
| 4 | Claim refused: held, overlapping, malformed, Tier 3 or `.waggle/` (section 6) |
| 5 | Needs the Keeper: `max_turns`, `max_tokens`, timeout, guard with no verdict, bad handoff, `max_sessions` |

Stdout carries one line per progress event (section 9.2) and a closing summary; `--json` prints only `result.json`. Stderr carries errors. No U+2013 or U+2014 in any output.

## 5. Dispatch sequence (`dispatch.Run`)

1. **Validate** flags, ticket, role, branch (exit 2). Load config (`config.Load`), policy (`config.LoadPolicy`, T-012 and T-021 phase B), `keeper_id` (5.4).
2. **Resolve base**, fetching first when `forge.remote` is set (host side, the Keeper's git auth).
3. **Read inputs from base**: brief, role prompt, `WAGGLE.md`, review file (5.3). Missing brief: exit 3, "brief not on base; land it in a hive PR first".
4. **Resolve model and settings**: `Policy.Resolve(role, TaskContext{TaskID, Tier, GuardMustFix: CountMustFix(review at base)})`, then `ContextPolicy.Settings(role, task, nudge_tokens)`. No overrides in v0.1 (section 13).
5. **Claim** (builder, forager; section 6). The guard reads the claim instead (10.2).
6. **Worktree**: create or reuse, take the run lock (7.1).
7. **Snapshot host state** (7.2), then **launch** through the Cell seam with `Prepare` (phase A), stream into `Collect`, renew the claim at half its TTL while the session runs.
8. **Check** (7.2). **Push** only on a clean pass with a remote set, unless `--no-push`.
9. **Record** `result.json`, append the ledger line (phase D), release the run lock, remove the worktree on success unless `--keep-worktree`.

### 5.3 Inputs from base

`git show <base>:<path>` for `layout.TasksDir/T-<nnn>.md`, `layout.RolesDir/<role>.md`, `layout.WaggleMD`, and `layout.ReviewsDir/T-<nnn>.md` (absent means zero must-fix). Never the main checkout's working tree: an uncommitted or injected steering edit cannot reach a worker. Caps: brief 400 KiB, role prompt and `WAGGLE.md` 128 KiB each. Task lines (variable part, after the brief): ticket, role, branch, base OID, lease directories, gate, and the fixed rules "commit every change with subject prefix `T-<nnn>: `", "do not push and do not open PRs", "end with your report as the final message".

### 5.4 Keeper identity (`internal/config/local.go`)

`LoadKeeperID(repoDir) (string, error)` reads `keeper_id` from `layout.Local` with the T-004 subset parser, ignoring other keys (the file is per Keeper and loosely shaped). An absent file or key is an error naming the file. The template placeholder `local-keeper` is refused when the Comb has a remote (it would collide across Keepers; D-016 says use the GitHub login) and allowed for local-only hives (Q-T023-11).

## 6. Claims (phase B, `claim.go`)

`comb.AcquireLease` with `KeeperID`, `Role`, `Gate`, `Directories`, TTL from config. Outcomes:

- **Free, or expired (anyone's):** acquired, or taken over as a child commit (RFC-0003 3.1). A takeover prints the previous owner.
- **Active, same Keeper:** renewal (the must-fix round case). If directories or role differ, print old and new before writing.
- **Active, another Keeper:** `ErrAlreadyClaimed`, exit 4, owner and expiry printed, nothing else touched (no worktree, no branch fetch).
- **Overlap, Tier 3, `.waggle/`, light on Tier 2, malformed target:** exit 4 with the comb error. A malformed target adds "a Head Keeper force-release clears it (T-005)".
- **Keepalive:** while the session runs, renew at `TTL/2`. A failed renewal does not kill the session; it is a warning in the result (`claim_renew_failed`), and the post-run check still runs against the claim as last read.
- The claim **stays** after the run, success or failure: the gate needs it until merge (T-014 section 4.3). Release after merge is a follow-up `waggle release` ticket (section 13); until then claims expire by TTL, and an expired claim passes the gate with a warning (D-053).

## 7. Worktree and lease enforcement

### 7.1 Worktree lifecycle (phase B, `worktree.go`)

- Path `layout.Worktrees/T-<nnn>-<role>` (gitignored runtime state). Run records go in `layout.Worktrees/runs/T-<nnn>-<role>-<seq>/`, never inside the worktree.
- New branch: `git worktree add -b <branch> <path> <baseOID>`. Existing branch (must-fix round): `git worktree add <path> <branch>`, and the check base becomes `merge-base(<branch>, <baseOID>)`.
- **Run lock:** `<path>.lock` created with `O_EXCL`, holding pid, hostname and start time. A live lock is exit 3 ("run in progress"). A lock whose pid is dead on this host is taken over with a warning.
- An existing worktree is reused only when clean and unlocked; a dirty one is exit 3 naming it.
- Success: `git worktree remove` (never `--force`); if that fails it is a warning and the worktree stays. Failure of any kind: the worktree stays for inspection and the result names it.
- `waggle dispatch clean` (phase D): refuses a live lock; `git worktree remove --force`, then `git worktree prune`; `--runs` also deletes the ticket's run records. It **never deletes a branch** and never touches a claim.

### 7.2 Post-run checks (phase C, `check.go`)

Before launch, snapshot: `git for-each-ref` (every ref with its OID), the main checkout's `git status --porcelain=v1 -z --untracked-files=all` and `HEAD`, and SHA-256 of the common dir's `config`, every file under `hooks/`, and the worktree's `config.worktree` if present. After the session ends, every rule runs and every failure is reported (no stop at the first):

1. **Commits** in `<checkBase>..<branch>`: no merge commits; every subject starts with `T-<nnn>: ` for this ticket; at most 500 commits.
2. **Paths** of every commit (`diff-tree -r -z --no-renames --raw`, deletions and both sides of a rename) pass the shared lease and tier check (Q-T023-7): inside a claim directory with exact case, no new symlink or submodule mode, no Tier 3 path, no Tier 2 path under `light`. This is the rule `waggle gate verify` applies at merge (D-017: same code locally and in CI).
3. **Worktree clean:** any uncommitted or untracked change is a failure ("builder must commit"). A builder or forager run with zero commits ends `no_change`, exit 1.
4. **Host state:** refs equal the snapshot except `refs/heads/<branch>` and this ticket's claim ref; the main checkout's status and `HEAD` are unchanged; config and hook hashes are unchanged; no new `core.hooksPath`. A planted hook would later run with the Keeper's credentials, so this is a failure, never a warning.
5. The guard (phase D) gets rules 3 and 4 with zero allowed changes: no commits, no ref moves.

Checks read git after the process exits. Nothing the agent could have written, run record files included, is trusted as input.

### 7.3 Cell seam (phase C, `cell.go`)

```go
// CellRuntime runs one worker process. v0.1 ships only "host": the Keeper's own
// user, no mounts, no egress control. The Cells slice adds real backends.
type CellRuntime interface {
    Name() string
    Command(ctx context.Context, spec CellSpec, launch runtime.LaunchSpec) (*exec.Cmd, []string, error) // []string: guarantees NOT enforced
}
type CellSpec struct { Worktree string; LeaseRW []string; Egress string }
```

`hostCell` sets `Dir`, `Env` and a new process group, and returns the not-enforced list of section 8. `dispatch.Run` owns the process (start, stream, stop: SIGTERM to the group, SIGKILL after 10 seconds), so a container or OS-sandbox backend changes only `Command`. Nothing else about Cells is decided here.

## 8. Credentials: RFC target and phase reality

**Target (RFC-0003 3.5, D-061):** a Cell holds zero credentials; egress reaches only the inference endpoint and package proxies.

**Reality in phases A to E:** the worker is the Keeper's OS user. It can read `$HOME` (SSH keys, the `gh` keyring through the `gh` binary, the macOS keychain, the Keeper's global Claude Code files), write anywhere that user can, and reach any network host. It holds the model credential Claude Code needs. Dispatch reduces exposure and makes violations visible; it does not stop a determined agent.

What dispatch does:
- **Env allowlist** (phase A, adapter-owned, one list): `PATH HOME USER LOGNAME SHELL TMPDIR TERM TZ LANG LC_ALL LC_CTYPE`, the adapter's model auth variables only if set (`ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`), T-021's `claudeEnv`, and fixed values: `GIT_TERMINAL_PROMPT=0` and a `GIT_CONFIG_COUNT` push tripwire (`url.waggle-push-blocked:.pushInsteadOf` for `https://`, `ssh://` and `git@`). Everything else is dropped, including `GITHUB_TOKEN`, `GH_TOKEN`, `SSH_AUTH_SOCK`, `GIT_ASKPASS`, `OP_SERVICE_ACCOUNT_TOKEN` and `AWS_*`.
- **Settings isolation** (phase A): the worker loads none of the Keeper's user settings, plugins, connectors or global `CLAUDE.md`, and none of the repo's `.claude/settings.json` hooks. Our hive's Stop hook (`.claude/hooks/handoff-check.sh`) would otherwise refuse to let a headless worker stop and push it to edit `.waggle/hive/handoff/queen.md`, outside any lease. Dispatch writes its own settings file into the run record (permissions per Q-T023-3) and passes it explicitly.
- **Tool permissions** per Q-T023-3; never `--dangerously-skip-permissions` by default.
- **No forge calls in the worker** (T-018 section 3): pushes, and any later PR calls, run on the host after the checks.
- Every run prints and records `not_enforced`: `read-only root`, `lease-scoped writes (checked after the run only)`, `network egress`, `host credentials readable via HOME`, `writes outside the repo (not detected)`.

## 9. Result and daemon-ready shape

### 9.1 `result.json` (phase C, `result.go`)

Written to the run record with mode 0600, `schema: 1`: `ticket`, `role`, `branch`, `base_oid`, `check_base_oid`, `head_oid`, `worktree`, `run_dir`, `keeper_id`, `claim_oid`, `cell` (`host`), `model`, `profile`, `floored`, `started_at`, `ended_at`, `end`, `exit_code`, `usage` (input, cache write, cache read, output), `cost_usd` (number or null), `violations` (`{rule, path, detail}`, at most 200 then a count), `warnings`, `not_enforced`, `verdict` (guard), `pushed`, and the names of `final.md`, `transcript.jsonl` and `stderr.log` in the same directory. The run record also holds `prompt.stable.txt`, `prompt.variable.txt` and `settings.json`.

`end` values and their ledger mapping (T-022 `Record.End`): `done`, `handoff`, `max_turns`, `max_sessions` and `max_tokens` map to themselves; `timeout`, `no_change`, `lease_violation`, `no_verdict`, `bad_handoff`, `interrupted` and `error` map to `error`.

### 9.2 Library surface

`dispatch.Run(ctx, Request, Deps) (Result, error)`. `Deps` injects the Comb backend, `CellRuntime`, `AgentRuntime`, git binary, clock and `OnEvent func(Event)`. Events: `claimed`, `worktree`, `launched`, `usage` (per assistant turn), `ended`, `checked`, `pushed`, `recorded`. The CLI prints them as lines; the run.sock loop will relay them. `Run` returns only after the child process group is gone and every goroutine has exited. Context cancellation ends the session as `interrupted` and still runs the checks.

## 10. Phase details

### 10.1 Phase A: adapter (`internal/runtime/launch.go`, `stream.go`)

- Replace `AgentRuntime.Run` with `Prepare(inv Invocation, s ContextSettings, stable, variable []byte) (LaunchSpec, error)` and `Collect(ctx, r io.Reader, lim Limits, stop func()) (RunResult, error)`: process ownership moves to the Cell seam. The `ErrUnresolved` check moves into `Prepare`; retarget T-012 test 9. `LaunchSpec{Argv, Env []string; Stdin []byte}`. `RunResult{Usage UsageStats; CostUSD *float64; End string; Final []byte; SessionID string; MalformedLines int}`; `UsageStats` gains the two cache fields.
- Argv: print mode, `--output-format stream-json` plus whatever the pinned version requires with it in print mode, `--model`, `--strict-mcp-config` (S6), `--max-turns`, the settings-isolation flags, the explicit settings file, the stable prompt appended to the system prompt (byte-identical across tasks, S3), then `DefaultArgs`. The variable prompt goes on stdin.
- T-021 phase B carry items that live in `claude.go` land here, since T-021 phase B's lease has no `internal/runtime/`: refuse in `DefaultArgs` every resume flag plus `--max-turns`, `--model`, `--mcp-config`, `-r*`, `--from-pr`, `--teleport`, `--print`, `-p`, `--output-format`, `--settings`, `--setting-sources`, `--permission-mode`, `--dangerously-skip-permissions`, `--allowedTools`, `--disallowedTools`, `--append-system-prompt`, `--system-prompt`, `--add-dir`; refuse `nudge_tokens >= max_tokens`.
- `Collect`: one JSON object per line, 4 MiB line cap. Per assistant turn, context is input plus cache read plus cache write; above `max_tokens`, call `stop` once and end `max_tokens`. The result event gives totals, `total_cost_usd` and the subtype (`error_max_turns` ends `max_turns`). No result event ends `error`. `Final` is capped at 256 KiB with a marker. Malformed lines are counted, never fatal.
- **Verify against the pinned Claude Code version** before merge: every flag and env name above, with `claude --version` and `claude --help` output saved in `.waggle/hive/media/T-023/`. A security flag (settings isolation, strict MCP, permissions) the version lacks makes `Prepare` fail closed; a missing cost knob degrades with one warning (T-021 Q-T021-6 pattern). Decide `DISABLE_AUTO_COMPACT` here (T-021 carry) and record in the result whether a session compacted when the stream reports it.

### 10.2 Phase D: guard

`--role guard` requires an existing claim for the ticket (`ReadClaim`, active or expired; none is exit 4) and an existing `--branch`. It writes no claim: there is one ref per ticket, and the builder's claim must stay until merge. The worktree is detached at the branch head; the check base is `merge-base(branch, base)`. The review is the final message, saved as `review.md` in the run record; dispatch never writes `.waggle/hive/` (the queen commits reviews and media, D-057). The last line matching `^Verdict: (pass|must-fix)$` sets `verdict`; none is `no_verdict`, exit 5, never a pass (T-021 section 5). `--second` resolves a model different from both the builder's and the first guard's (D-100, Q-T023-9). Ledger: `usage.Append` once per session (T-022). `list` prints worktrees, live locks and each ticket's last result line.

### 10.3 Phase E: handoff loop

Switch the session to stream-json input so dispatch can send a message mid-session. At `HandoffTokens` dispatch asks for a handoff in T-021 section 6.4 format, ends the session, writes it to `layout.Handoffs/T-<nnn>-<role>-<n>.md` on the host, and starts a fresh session seeded with it (S1, S5). A `ParseHandoff` failure is `bad_handoff`, exit 5. Reaching `MaxSessions` is `max_sessions`, exit 5. Verify the input mode against the pinned version as in 10.1.
