## 1. Goal

`AcquireLease` refuses a claim whose directory overlaps another ticket's active claim on a path-segment boundary after ASCII case folding, not only byte for byte. Today T-054 holds `internal/comb`, and a claim for T-099 on `Internal/Comb` passes (`DirsOverlap` is exact, `backend.go:393`). On a macOS or Windows checkout those are one directory, so two workers edit the same files under two claims.

The merge gate already catches the result late: a commit whose path differs in case from its own lease fails `case_differs` (`changecheck.go:88-89`), and a head tree with two paths equal under folding fails (`gate_commits.go:399-401`). This ticket moves the refusal to claim time, where it costs a refused claim instead of a wasted run, which is what RFC-0003 section 3.1 already does for Tier 3 paths (D-002) and `.waggle/` (D-043).

## 2. Scope by phase

### 2.1 Phase A: the comb rule

1. **ASCII fold helper.** An unexported `foldASCII(s string) string` in `backend.go` that maps only bytes `A` to `Z` to `a` to `z` and leaves every other byte alone. It does not call `strings.ToLower` or `strings.EqualFold`, which fold Unicode: `strings.EqualFold("K", "k")` is true (KELVIN SIGN) and so is `strings.EqualFold("ſ", "s")` (LONG S). Directories are ASCII by D-037 (`backend.go:354-358`) before any compare, so the two give the same answer today; the helper keeps the rule exact if D-037 is ever relaxed (Q-T073-2).
2. **Folded overlap.** An unexported `dirsOverlapFold(a, b string) bool` that returns `DirsOverlap(foldASCII(a), foldASCII(b))`. `DirsOverlap` itself is unchanged and stays exported with exact semantics.
3. **Overlap loop.** In `AcquireLeaseWithTrailers` (`git.go:576-588`), for each requested directory `d` and each directory `od` of another ticket's active, well-formed claim:
   - `DirsOverlap(d, od)`: refused as today, same message.
   - else `dirsOverlapFold(d, od)`: refused with `ErrLeaseOverlap` and the message `<ticket> directory "<d>" overlaps <other> directory "<od>" held by <owner> when letter case is ignored (macOS and Windows checkouts treat them as one directory): comb: directories overlap an active lease`, unless the grandfather rule in item 4 applies.
   - The sentinel stays `ErrLeaseOverlap`, so `waggle claim`, `waggle dispatch` and relay claims (T-065) keep exit 4 and outcome `overlap` with no change in `internal/dispatch` or `internal/relay`.
   - Malformed claims and expired claims of other tickets are skipped, as today (`git.go:577`).
4. **Grandfather rule for claims that already collide (Q-T073-1).** A same-owner renewal of an active claim (verb `renew`, `git.go:573`) skips the folded check, and only the folded check, for a requested directory that the stored claim already lists byte for byte. Everything else gets the full folded check: a new claim, a takeover of an expired claim, and any directory a renewal adds or recases. Exact overlap is never grandfathered. So a collision written before the pin moved (or by an older binary, or in a race) never grows and never transfers, and neither owner's in-flight PR loses its claim to the rollout.
5. **Write-time self check.** In `prepareLease` (`git.go:605-614`), after `validateLeaseFields`, refuse with `ErrInvalidLease` a lease in which two entries overlap under folding but not exactly: `["internal/Comb", "internal/comb"]` and `["internal", "Internal/comb"]` are refused; `["internal", "internal/comb"]` keeps passing as today. Message: `directories "<a>" and "<b>" differ only in letter case`. This runs only when a lease is written, like `Options.Protected`; `NormalizeDirectories` and `decodeLease` do not change, so a stored claim with such a pair is still read and still enforced, not marked malformed and skipped (Q-T073-3).
6. **Collision reader.** An exported `func (b *GitBackend) CaseCollisions(ctx context.Context) ([]CaseCollision, error)` that scans claims the way `ListActiveLeases` does (syncing first in remote mode), keeps active well-formed claims, and returns each pair of different tickets with a directory pair that overlaps under folding but not exactly. `CaseCollision` holds the two ticket IDs, the two directories and the two owners, sorted by ticket number then directory, each pair once. It writes nothing. Phase B calls it; it is not on the `Backend` interface (`backend.go:128-143`), so no other backend has to implement it.
7. **Doc comments.** `AcquireLease` (`git.go:511-521`) and `DirsOverlap` (`backend.go:390-391`) comments state the folded rule, the grandfather rule and that `DirsOverlap` stays exact.

## 5. Out of scope

- **Unicode in lease directories.** D-037 keeps them ASCII; this ticket does not relax it. A later ticket that allows non-ASCII must also choose Unicode normalization (NFC against NFD) and full case folding for overlap; that is named in Q-T073-2, not built here.
- **The gate's head tree collision check for Unicode paths.** `caseCollisions` (`cmd/waggle/gate_commits.go:399-401`) folds with `strings.ToLower` and `strings.EqualFold` and does not normalize, so a head tree with `café` (NFC) and `café` (NFD) passes the gate, while macOS APFS treats them as one name. This is a gate rule in `cmd/waggle`, a Tier 3 merge rule, and not a claim rule. Recorded as a follow-up gate ticket (Q-T073-8), not dropped.
- **A forced fix for existing collisions.** T-073 reports them and stops them growing; it never deletes or rewrites a claim. Clearing one is the owner's `waggle release` or T-072's force-release.
- **The directory-level race.** Two claims written at the same instant can still both pass, folded or not (compare-and-swap is per task ref, RFC-0003 section 3.1).
- **Doctor.** No doctor finding in this ticket (Q-T073-5).

## 7. Threat model (D-203)

**Boundary.** The claim-time check runs on the claimer's machine and is optimistic (RFC-0003 section 3.1). The gate is authoritative.

**Defended.**
- *Agent picks a case variant of a held directory to slip past the overlap check:* refused at claim time.
- *Agent renews a grandfathered claim to widen it into a colliding directory:* the grandfather rule covers only directories the stored claim lists byte for byte; added or recased directories get the full check.
- *Agent takes over an expired colliding claim:* takeover gets the full check.
- *Unicode lookalikes (KELVIN SIGN for `K`, LONG S for `s`, fullwidth letters):* rejected by the ASCII rule before any compare, and the fold helper does not map them even if they reach it.
- *Terminal injection through the status warning:* `CaseCollisions` returns only well-formed claims, so directories are ASCII safe-set and owners have passed the keeper ID check of `validateLeaseFields` (`backend.go:443`) before they reach the status line. A guard confirms no other field reaches it.

**Not defended (stated in docs).** An older binary, or a raw ref write, can still create a colliding claim; the gate's `case_differs` and head tree checks catch the commits at merge. Two same-instant claims can still race.

## 11. Open questions

- **Q-T073-1: What happens to two active claims that already collide when the pin moves?**
  Recommended: the grandfather rule in 2.1 item 4. Same-owner renewals keep directories they already list byte for byte; nothing else is grandfathered; `waggle status` reports the pair. Refusing those renewals outright would let a rollout expire a live claim and fail its open PR with `no claim` (L4), which narrows core item 1 for a collision nobody chose. Marking either claim malformed is worse: malformed claims are skipped by the overlap check, so it would remove protection, not add it. Today's hive has no such pair, so this matters for other hives and for mixed-version teams.

- **Q-T073-2: ASCII folding only, or Unicode case folding and normalization?**
  Recommended: ASCII only, by a byte helper, never `strings.EqualFold`. D-037 keeps lease directories ASCII, so ASCII folding is complete for every directory a claim can hold, and the byte helper cannot be fooled by KELVIN SIGN or LONG S if the input rule ever loosens. Unicode normalization (NFC against NFD, as HFS+ and APFS treat names) and full folding belong to whichever ticket relaxes D-037; record that as a condition on any such ticket so it cannot ship without them.

- **Q-T073-3: Should a lease with two case variants of one directory become malformed on read, or be refused only at write?**
  Recommended: refused only at write, in `prepareLease`, like `Options.Protected`. Changing `NormalizeDirectories` would re-validate every stored claim on read (RFC-0003 section 3.1), turn an existing claim malformed, and a malformed claim on another ticket is skipped by the overlap check. That trades a cosmetic rule for a real hole.

- **Q-T073-4: Should a repo be able to turn the folded check off (for example a `leases.case_folded_overlap: false` key) for case-sensitive brownfield repos that hold real case twins, such as `xt_DSCP.c` and `xt_dscp.c` in Linux netfilter?**
  Recommended: no key in v0.1. Such paths cannot be checked out side by side on macOS or Windows, and the gate already fails a head tree that has them (`gate_commits.go:399-401`), so the claim rule only matches what merge already requires. The cost is that two tasks over case twins serialize or one leases the parent; no work is lost. A new key under `leases:` makes older binaries exit with `unknown key` (`internal/config/config.go:223-226`). This is not a CUT of core item 4: the repo still drops in, and nothing it does today stops merging. If the Head Keeper wants an opt-out later, it is a follow-up with a top-level section, which older builds ignore.

- **Q-T073-5: Should `waggle doctor` report collisions too?**
  Recommended: not in T-073. T-072 phase B adds a `claims` finding to doctor; a second ticket editing the same finding at the same time invites a conflict. Record a follow-up that folds a collision count into T-072's `claims` finding once both are on main. `waggle status` is where Keepers look at claims, and it covers the need now.

- **Q-T073-6: T-072 phase B and T-073 phase B both edit `docs/multi-keeper.md:99`. Which goes first?**
  Recommended: T-072 phase B first. It rewrites the bullet to drop force-release and name T-073 (its section 2.2 item 5); T-073 phase B then removes the remaining half because it is built. The reverse order would have T-072 phase B name a ticket that has already merged. If T-072 phase B slips past the stop of its own schedule, T-073 phase B may go first and remove the whole case-folded half, and T-072 phase B drops its "name T-073" step; the queen records that swap in the dispatch note.
