## 1. Goal

Write the claim spec every client follows: the three visible parts (assignee, label, one sticky comment), the v1 comment block, states, issue reference forms, the write, re-read, earliest valid claim wins rule, expiry with server time and grace, and release. Ship it as a section a repo pastes into its own `AGENTS.md`.

## 2. Scope

- `docs/claims.md`: the v1 format, field rules, the protocol in T-124 sections 3 and 4.2, and a worked GitHub example. The format names nothing tracker-specific (D-412), and the reference grammar reserves `linear:KEY-N` for T-129.
- `examples/agents-md-claims.md`: the Level 0 rules in under 25 lines, using `gh` commands only.
- A test fixture set of valid and invalid v1 blocks that T-127 reads.
- The governance rules in T-124 section 8 for the `AGENTS.md` section: agents propose vision and roadmap changes by PR or issue and never merge them, pick in tracker priority order, and never change the priority of an issue they hold.
- The optional `priority:` field in the v1 block (claim-time priority, Q-T124-12).

## 3. Out of scope

- Any code. Changes to this repo's own `AGENTS.md`.
