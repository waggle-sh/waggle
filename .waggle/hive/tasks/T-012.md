## 1. Goal

Roles declare how capable a model they need, never which model. The roster carries a minimum **level** per role; the config maps each level to a concrete model per runtime adapter. The binary enforces the minimums, the guard's cross-model rule, and one automatic step-up, at the point where a role is launched.

Levels, lowest to highest: `fast`, `standard`, `frontier`.

| Role | Minimum | Rule enforced in the binary |
| :--- | :--- | :--- |
| `architect` | `frontier` | roster minimum |
| `queen` | `frontier` | roster minimum |
| `forager` | `standard` | roster minimum; steps up one level after two guard `must-fix` verdicts on the same task (section 4.3) |
| `guard` | at or above the forager's effective level on the same task, **and** a different model | cannot be lowered on Tier 2 or Tier 3 tasks (hard error); different-model rule never waived |
| `scout` | `fast` | roster minimum |
| `waggled` | no model | not a roster role; resolving a model for it is an error |

v0.1: the Keeper assigns models to levels by hand in config. No auto-detection, no price lookup.

Go 1.23, module `github.com/waggle-sh/waggle` (post-T-010), **standard library only**. Do not touch `go.mod`.

## 3. Schema

### 3.1 Roster (`.waggle/control/roster.json`, Tier 3)

Each role object gains one required key:

```json
{ "id": "forager", "min_level": "standard", ... }
```

- Values: `fast`, `standard`, `frontier`. Anything else, or a missing key on any role, fails the load (fail closed).
- Model names never appear in the roster. A roster value that is not one of the three level words fails, so `"min_level": "opus"` is rejected.
- `guard` keeps `require_cross_model: true` and gets `"min_level": "standard"`. The relational floor (at or above the forager) lives in the binary, not in data.
- A role with id `waggled` in the roster fails the load: the daemon is not an agent and has no model.
- **Top-level `mode` is dropped (D-070).** `"mode": "swarm"` had no definition and no reader. Section 7.1's Head Keeper commit deletes it from the template; our hive's roster loses it when the hive PR runs `waggle upgrade` (7.2). For one release the loader **ignores** a leftover top-level `mode` key, whatever its value, so hives scaffolded before phase B still load: no validation, no warning, no field in any Go type. After v0.1 a follow-up may reject it; this ticket does not.

### 3.2 Config (`.waggle/control/config.yaml`, Tier 3)

Extend the existing `runtimes.adapters.<name>` block. Nothing else in the file changes.

```yaml
runtimes:
  default: claude-code
  adapters:
    claude-code:
      binary: claude
      nudge_tokens: 200000
      max_tokens: 300000
      levels:            # Keeper-assigned in v0.1
        frontier: opus
        standard: sonnet
        fast: haiku
      alternates:        # optional; used only to satisfy the guard's different-model rule
        frontier: claude-opus-4-1
```

- `levels` is required for the default adapter and must map all three levels. Values match `^[A-Za-z0-9][A-Za-z0-9._:/@-]{0,127}$` (model IDs and CLI aliases; no spaces, no leading `-`, so a value can never become a flag in argv).
- `alternates` is optional, any subset of the three levels, same value pattern. An alternate equal to its own level's primary fails the load.
- Unknown keys inside `runtimes`, `runtimes.adapters`, or an adapter block fail with `ErrInvalidConfig` (same rule T-004 applies to `forge` and `leases`). `runtimes.default` must name an adapter that exists.
- Parsing uses T-004's YAML subset. Block mappings only, so no new grammar is needed.
- Model identity for the cross-model rule is the pair (adapter name, model string), compared exactly. See Q-T012-2.

## 4. Policy (phase A, `internal/runtime/levels.go`, `internal/runtime/policy.go`)

### 4.1 Types (suggested names; doc comments on every exported identifier)

```go
type Level int // LevelFast = 1, LevelStandard = 2, LevelFrontier = 3; zero is invalid
func ParseLevel(s string) (Level, error)
func (l Level) String() string

type Models struct {
    Adapter   string
    Primary   map[Level]string // all three levels required
    Alternate map[Level]string // optional
}

type Policy struct {
    Models   Models
    Minimums map[string]Level // role id to roster minimum
}

type Override struct {
    Level      Level
    DecisionID int // D-<n> recorded with `waggle decide`; required
}

type TaskContext struct {
    TaskID       string
    Tier         *comb.RiskTier   // nil means unknown and is treated as Tier 3
    GuardMustFix int              // must-fix verdicts on this task so far
    Overrides    map[string]Override // by role id
}

type Selection struct {
    Role, Adapter, Model string
    Level                Level
    SteppedUp            bool // forager step-up applied
    resolved             bool // set only by Resolve
}

func (p Policy) Validate() error
func (p Policy) Resolve(role string, task *TaskContext, decisionExists func(id int) bool) (Selection, error)
func CountMustFix(review []byte) int
```

`internal/runtime` may import `internal/comb` (stdlib only, no cycle). It must not import `internal/config` or `internal/decisions`: `internal/config` imports `internal/runtime` in phase B, and the decision lookup is a callback.

### 4.2 Sentinels

`ErrInvalidLevel`, `ErrUnknownRole`, `ErrNoModelRole` (`waggled`), `ErrLevelUnmapped`, `ErrBelowMinimum`, `ErrGuardFloor`, `ErrNoCrossModel`, `ErrOverrideUnrecorded`, `ErrUnresolved`. Every failure wraps one of them and names the role, task and level involved.

### 4.3 Resolution rules (evaluate in this order)

1. `role == "waggled"`: `ErrNoModelRole`. Role not in `Minimums`: `ErrUnknownRole`.
2. **Base level** = roster minimum.
3. **Forager step-up** (role `forager`, or computing the forager's level for a guard): if `GuardMustFix >= 2`, base becomes base + 1, capped at `frontier`. One step only, however many verdicts follow (Q-T012-4). `SteppedUp` reports it.
4. **Override** (if `Overrides[role]` exists):
   - `decisionExists == nil`, `DecisionID <= 0`, or `!decisionExists(DecisionID)`: `ErrOverrideUnrecorded`. An override never applies without a recorded decision.
   - Any level, up or down, is allowed for `architect`, `queen`, `scout`, `forager` once recorded.
   - The forager's overridden level replaces step 2; step 3 then applies on top.
5. **Guard floor:** the guard's floor is `max(roster guard minimum, forager effective level from steps 2 to 4)`. A guard override below that floor is `ErrGuardFloor` when the task tier is 2, 3, or unknown, even with a recorded decision. On Tier 0 or 1 a recorded override may lower it.
6. **Model pick:** `Models.Primary[level]`; empty is `ErrLevelUnmapped` naming the level and the config path (`runtimes.adapters.<name>.levels.<level>`).
7. **Cross-model (guard only):** compute the forager's model the same way. Walk levels from the guard's level up to `frontier`; at each, try the primary, then the alternate; take the first model that differs from the forager's. None: `ErrNoCrossModel` with a hint to set `alternates.<level>`. Never fall back to the same model. Not overridable at any tier.
8. Return the `Selection` with `resolved = true`.

`Validate` checks: every level in `Minimums` is valid, all three primaries are non-empty, no alternate equals its own primary, and `guard` and `forager` are both present.

### 4.4 Launch enforcement

- `Invocation` gains `Selection Selection`.
- `ClaudeAdapter.Run` returns `ErrUnresolved` when `!inv.Selection.resolved` or `inv.Selection.Role != inv.Role`, before anything else. It still returns the existing "requires waggled" error after that check; actual execution is not in scope.
- Add an unexported `claudeArgs(inv Invocation) []string` that returns `--model <Selection.Model>` plus `DefaultArgs`. `Run` does not call it yet; tests do. The future `waggled` launch path uses it, so the model always comes from a resolved selection.

### 4.5 `CountMustFix`

Counts lines in a review file (`.waggle/hive/reviews/T-<id>.md`) that equal `Verdict: must-fix` after trimming trailing spaces and `\r`. Heading text such as `(verdict: must-fix)` does not count. This assumes the guard appends one `Verdict:` line per review round and never rewrites earlier ones; see Q-T012-3.

## 5. Phase A tests (`internal/runtime/*_test.go`, pure, never skip)

1. `ParseLevel` accepts the three words, rejects `Frontier`, `opus`, `""`, ` fast`.
2. Default roster minimums (section 1) with mapping `opus`/`sonnet`/`haiku`: architect and queen get `opus`, forager `sonnet`, scout `haiku`.
3. Guard, forager at `standard`: guard resolves to `opus` (standard primary equals the forager's model, so it walks up).
4. Guard, forager stepped up to `frontier` (`GuardMustFix = 2`), no alternate: `ErrNoCrossModel`. With `alternates.frontier` set: guard gets the alternate.
5. Step-up: `GuardMustFix` 0 and 1 give `standard`; 2 and 5 give `frontier`; a forager already at `frontier` stays there.
6. Overrides: forager to `fast` with a recorded decision succeeds; with `decisionExists == nil`, `DecisionID = 0`, or an unknown ID returns `ErrOverrideUnrecorded`.
7. Guard override to `fast` on Tier 2, Tier 3 and nil tier: `ErrGuardFloor` even with a recorded decision. On Tier 1 with a recorded decision: allowed, but still a different model than the forager.
8. `waggled`: `ErrNoModelRole`. `weaver`: `ErrUnknownRole`. Unmapped level: `ErrLevelUnmapped` naming the config path.
9. `Run` with a zero `Selection`, or with a selection for a different role: `ErrUnresolved`. `claudeArgs` contains `--model`, the model, then `DefaultArgs` in order.
10. `CountMustFix`: mixed file with two `Verdict: must-fix`, one `Verdict: pass`, one heading `(verdict: must-fix)`, and CRLF endings returns 2.
