## 2. Background

- The merge gate stays authoritative for directory leases. These are claim-time defense in depth and output-safety fixes; do not try to close the TOCTOU window documented in T-002.
- No claim refs exist anywhere yet (no CLI wiring, no published refs), so tightening the rules breaks no stored data. A claim written by T-002 code that violates the new rules is reported as malformed (section 3.2).
- Prompt injection cannot be neutralized by Markdown escaping alone: plain words like "Ignore prior instructions" survive any escaping. The real defense is that only identifier-shaped values ever reach the file. That is why section 3.3 replaces invalid values instead of escaping them.

## 3. Changes

### 3.1 Directory rules (`normalizeDir` in `backend.go`) (F1, F2)

Rewrite the per-entry checks in this order. Every failure returns `ErrInvalidLease` (wrapped, naming the entry), except root-like entries, which keep returning `ErrTier3Path`.

1. Empty or whitespace-only: reject (unchanged).
2. Length over 1024 bytes: reject.
3. **Allow-list:** every byte of the raw entry is in `[A-Za-z0-9._/-]`. This replaces the separate whitespace, control-character, backslash and glob checks (keep them only if it makes the error message clearer; the sentinel is the same). It also rejects spaces, backticks, `<`, `>`, `:` (drive letters, NTFS alternate data streams), `~` (NTFS 8.3 short names such as `GIT~1`), `$`, quotes, and all non-ASCII.
4. Absolute (leading `/`): reject. The `filepath.IsAbs`, `VolumeName` and `hasDriveLetter` checks may stay; they are now unreachable but harmless.
5. Clean to slash form, trim trailing `/`. Root-like (`.`, `""`): `ErrTier3Path`. `..` or `../` prefix: reject (unchanged).
6. First segment equal to `.git` case-insensitively: reject (unchanged).
7. **Per segment** of the cleaned path:
   - Ends with `.`: reject (F1). Windows strips trailing dots, so `.waggle.` would resolve to `.waggle` and `.git.` to `.git`. Trailing spaces are already rejected by step 3.
   - Starts with `-`: reject (a directory must never look like a flag if a later caller passes it to argv).
   - Longer than 255 bytes: reject.
   - **Windows reserved device name:** reject when the part of the segment before its first `.` equals, case-insensitively, `CON`, `PRN`, `AUX`, `NUL`, `COM0` to `COM9`, or `LPT0` to `LPT9`. So `nul`, `Aux`, `con.d`, `lpt1.txt` are rejected; `console`, `auxiliary`, `com10` are allowed. Rationale: a hive is shared across Keepers on unknown OSes; such a path cannot be checked out on Windows, and Git for Windows refuses it. Keeper-approved (Q-T009-1).

Update the `NormalizeDirectories` doc comment to state the allow-list and segment rules. Valid input that passed before and still passes must normalize to the same output (for example `./internal//comb` to `internal/comb`).

Expose one unexported helper the renderer can reuse (suggested `isCanonicalDir(d string) bool`: true iff `normalizeDir(d)` succeeds and returns `d` unchanged).

### 3.2 Stored claims are re-validated and normalized (`decodeLease` in `git.go`) (F4)

Today `decodeLease` checks directories with `NormalizeDirectories` but keeps the raw strings, so a hand-forged claim on `foo/` does not block a later claim on `foo/bar`. It also never checks `KeeperID`, `Role` or `Gate`, so those reach `ListActiveLeases` callers (and the renderer) unvalidated.

New behavior:
1. After the JSON decode and the existing `TicketID == ticketDisplay(num)` check, run the same field validation `AcquireLease` uses (`validateLeaseFields`, with `maxDirs = math.MaxInt` so a later config change to the directory limit never turns an existing claim malformed).
2. Any validation failure marks the claim malformed with a reason that names the field (`invalid keeper_id`, `invalid directories: ...`, `directory ".waggle" is Tier 3`, and so on). This includes stored claims that violate the Tier 3 rule or the Tier 2 light-gate floor.
3. On success, the decoded lease carries the **normalized** directory list and canonical ticket ID returned by `validateLeaseFields`. Overlap checks, `ListActiveLeases` and every other consumer see only normalized values.
4. Also mark malformed: `Version != 1`, and `ClaimedAt` after `ExpiresAt`.

A stored claim whose directories normalize cleanly but were not stored in canonical form (`foo/`) is **not** malformed: it is normalized and enforced. Marking it malformed would let it be skipped by the overlap check, which is the bypass F4 describes.

Document on `AcquireLease` and `ListActiveLeases` that stored claims are re-validated with current rules, so a rule change can surface an existing claim as malformed.

### 3.3 Defensive WORKPLAN rendering (`workplan.go`) (F2)

`RenderWorkplan` still accepts any `[]Lease` and must never emit a value that fails validation. Per cell:

| Cell | Rendered when valid | Valid when |
| :--- | :--- | :--- |
| Ticket | canonical form from `ParseTicketID` (so `T-1` renders `T-001`) | `ParseTicketID` succeeds |
| Keeper | as is | matches `keeperIDPattern` |
| Role | as is | `scout`, `forager`, or `guard` |
| Gate | as is | `light` or `full` |
| Directories | each entry wrapped in backticks, joined by `, ` | each entry `isCanonicalDir` |
| Claimed, Expires | `formatUTC` (unchanged) | always |

- An invalid value renders as the literal `(invalid)` (no backticks, even in the Directories cell). Never echo any part of the invalid value. Keep the row so a reader sees that something is wrong.
- Keep the existing `|` and newline replacement as a final pass on every cell (a no-op for valid values; defense in depth).
- Sorting stays as today (numeric by parsed ticket, unparseable last by raw string). The raw string only influences order, never output bytes.
- Add one line to the `RenderWorkplan` doc comment: values failing validation render as `(invalid)` so `WORKPLAN.md` never carries free text.
- Update `testdata/workplan.golden` with `-update`. The expected diff: the `T-1` row becomes `T-001`; the `bogus` row becomes `| (invalid) | (invalid) | forager | light | (invalid), (invalid) | ... |`. The guard checks that this is the whole golden diff.

### 3.4 Scrub inherited git environment (`git` helper in `git.go`) (F3)

Build the child environment with a pure, unexported function (suggested `childEnv(parent, extra, call []string) []string`) so it can be unit tested:

1. Start from `os.Environ()` and **drop** every entry whose key matches, case-insensitively, one of:
   `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_COMMON_DIR`, `GIT_NAMESPACE`, `GIT_QUARANTINE_PATH`, `GIT_PREFIX`, `GIT_CEILING_DIRECTORIES`, `GIT_DISCOVERY_ACROSS_FILESYSTEM`, `GIT_REPLACE_REF_BASE`, `GIT_NO_REPLACE_OBJECTS`, `GIT_GRAFT_FILE`, `GIT_SHALLOW_FILE`.
   These redirect which repository, index, object store, ref namespace or object substitutions git uses. Set by a parent git process (waggle run from a hook, or `git -C other` wrappers), they override `-C repoDir` and could write claims into the wrong repo or a hidden namespace. Keep the list in one unexported package-level slice with a short comment on why each group is there.
2. Append `GIT_TERMINAL_PROMPT=0`, `LC_ALL=C` (unchanged) and **`GIT_NO_REPLACE_OBJECTS=1`**, so a local `refs/replace/*` entry can never substitute a different `lease.json` under a claim commit.
3. Append `Options.ExtraEnv`, then the per-call env (unchanged order). These are explicit caller input and may set any variable, including scrubbed ones; document that on `Options.ExtraEnv`.
4. Do **not** scrub `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_COUNT`/`KEY_n`/`VALUE_n`, `GIT_SSH_COMMAND`, `GIT_ASKPASS`, `GIT_EXEC_PATH`, `HOME`, `PATH`, or `GIT_TRACE*`. They carry the user's own credentials and config, at the same trust level as `~/.gitconfig`, and remote mode needs them for auth.

Update the doc comment on the `git` helper and the T-002 section 6 behavior it implements ("`os.Environ()` minus the scrub list, plus ...").

### 3.5 Local release retries lock contention (F5)

`ReleaseLease` in local mode uses the same retry rule as `casLocal`: when `update-ref -d <ref> <oid>` fails, re-read the ref. Changed or gone: `ErrConcurrentUpdate` (unchanged). Unchanged and `isLockContention`: back off and retry up to `maxCASRetries`, then return the wrapped git error. Reuse the existing loop shape or factor a shared helper; keep it small.

### 3.6 Test seam

Add one unexported field next to `hookBeforeWrite`:

```go
// hookBeforeRetry, when set by tests, runs before each backoff in a CAS retry
// loop (local acquire, local release, remote push) with the 0-based attempt.
hookBeforeRetry func(attempt int)
```

Call it immediately before `sleepBackoff` in all three loops. No other production behavior depends on it.
