## 3. Design

### 3.1 The flag

`waggle dispatch <ticket> --role guard ... --keeper-commit` states that the head under review was committed by the Head Keeper and that no dispatched builder worked on this branch (Q-T045-1 (a)). `Request` gains `KeeperCommit bool`; `Validate` refuses it on any other role with exit 2 and `--keeper-commit is for the guard role` (next to the `--second` case, `request.go:105-106`). `cmd/waggle/dispatch.go` adds the flag (help text `guard: the head is a Head Keeper commit with no builder run on this branch`) and `[--keeper-commit]` in the guard usage line (`:41`). `Result` gains `KeeperCommit bool` as `json:"keeper_commit"`, set from the request.

The flag does not skip a check; it swaps the builder-record requirement for its opposite, which is also checked. The `runDispatch` comment (`dispatch.go:32`, "no flag that skips a check, lowers a model or forces") stays true and unchanged.

### 3.2 The builder record must be absent

With `--keeper-commit`, plain or `--second`, a builder record on the branch (`builderRun` finds one, any head, any end) refuses before launch, exit 3:

`--keeper-commit: builder run <record name> is on branch <branch>; drop --keeper-commit`

A Head Keeper fix commit on top of a builder's branch keeps the builder record, so it is reviewed without the flag, as today (`--second` already works there: the record exists, and the first guard on the new head is found by `head_oid`).

### 3.3 Model choice

- **Plain guard with the flag:** no change in resolution. With no builder record, `guardModel` already avoids only the policy's builder model (`guard.go:164-166` leaves `AvoidModels` empty) and alternates on the previous round's record as T-034 2.1 says. Hive shape (`hiveShape(true)`): opus first, then fable on a confirming round.
- **`--second` with the flag:** require this round's first guard record (`guardRun` on the branch with `head_oid` equal to the head, `second: false`, a verdict). None found, exit 3: `--second needs a first guard run of <ticket> on head <short head> in .waggle/worktrees/runs`. Its `model` must be non-empty (today's `--second: run record <name> has no model`, `guard.go:176-178`). Set `AvoidModels` to the first guard's model only; `RecordedBuilder` stays empty. `Resolve` then avoids the policy's builder model and the first guard's (`policy.go:147-160`), with the D-179 walk bounded by D-180. Hive shape: first opus, second fable. With `hiveShape(false)` the outcome is today's `ErrNoCrossModel` with its hint, unchanged.
- **Without the flag:** `guardModel` and `secondMissing` behave and word exactly as today, so a builder branch whose records were cleaned still refuses (D-188 fails closed).

### 3.4 `checkSecond` with the flag

In order, each refusal exit 3:

1. No first guard record on this head: the 3.3 text.
2. First guard `base_oid` not 40 or 64 lowercase hex: today's `--second: run record <name> has no valid base_oid`.
3. Second guard base differs from the first guard's: today's `--second: base <base> differs from the first guard's base <first>; pass --base <first>`. The D-254 default makes this rare.
4. No ancestry rule: there is no builder base. Nothing calls `merge-base`.
5. The selected model equals the first guard's: `--second would use <model>, the model of the first guard (<model>)`.

The 3.2 check runs first. Without the flag, `checkSecond` is unchanged, word for word.

### 3.5 The claim (Q-T045-2 (a))

With `--keeper-commit`, `guardTarget` still reads the claim when one exists, but a missing claim is accepted:

- **No claim ref** (`comb.ErrNotFound`): accepted. `claimOID` is empty and `ClaimVerb` is `none`.
- **Claim whose `branches` list names this branch:** refused, exit 3: `--keeper-commit: the claim for <ticket> lists branch <branch>; drop --keeper-commit`. A claim lists the branches dispatch worked on, so this is a second sign that a builder ran here. A list that does not name the branch proves nothing (renewal keeps the old list, `claim.go:65-67`: the T-025 claim at `bae5b28` lists only `t-025c1` though C2 ran on `t-025c2`), so it is only used to refuse.
- **Any other claim:** read as today for `claimOID`, but its directories and gate are a builder phase's, not this head's. Either way the guard prompt reads `Lease directories: none (Head Keeper commit)` and `Gate: full` (`guardTaskLines`, `guard.go:92-93`): every Head Keeper branch this flag exists for is Tier 3, and Tier 3 is always gate `full`.
- A malformed claim or any other read error still refuses as today (`claimError`).

The returned `comb.Lease` has `TicketID` set to the request's ticket in every case: the post-run check names the ticket's own claim ref from it (`check.go:214`). The post-run check for a guard is otherwise unchanged (`check.go:204-206`, `:235-236`).

Without the flag, `guardTarget` is unchanged and a missing claim still exits 4 with today's text.

## 7. Threat model (D-203)

**Attacker:** a dispatched builder (its commits and branch head on its own branch), a dispatched guard (its final message and so its verdict), and ordinary repo state (main moving, a rebase, cleaned run records, released claims). **Trusted:** the queen and her flags (including `--keeper-commit`), the Head Keeper's commits, the base config, run records under `.waggle/worktrees/runs/` and claim refs, which no worker lease covers.

**Must-fix:** any behavior or message change on a run without `--keeper-commit`; `--keeper-commit` accepted on a non-guard role, on a branch with a builder record, or with a claim that lists the branch; a `--second` run whose model equals this round's first guard's or the policy's builder model; a `--second` run on a base other than the first guard's; a first guard record on another head, branch or ticket (including a number prefix such as `T-0250`), or a `second: true` or verdict-less record, counted as this round's first guard; a record value reaching git without the hex check; a panic on a malformed record; the guard prompt showing a builder phase's directories under the flag; a guard run with the flag that writes, moves or deletes a claim ref; files changed outside the lease rule.

**Note, not must-fix:** the queen passing `--keeper-commit` on a builder branch whose records were cleaned and whose claim list does not name it (trusted flag, cleaned records: the builder's model is then avoided only as the policy names it, the same accepted note as T-034 section 5); a planted run record or claim ref (needs host or ref write outside every lease).

**Guard prompt sentence (repeat verbatim):** "Threat bar (D-203): a finding whose attacker needs to write or edit a run record under .waggle/worktrees/runs or a claim ref, push to the base branch, change the base config, or pass dispatch flags of its choosing is a note, not a must-fix; must-fix is for any change to a run without --keeper-commit, any way --keeper-commit runs on a branch with a builder record or a claim that lists it, and any second guard on the first guard's model or base other than the first guard's."
