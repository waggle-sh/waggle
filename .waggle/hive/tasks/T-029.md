## 1. Goal

Three trial findings and one review note.

1. **Reused branch (follow-up 4).** Run 1's rerun reused the `t-026` branch from try 1, whose branch point is `5df0422`; main had moved to `8deba1c` (the brief fix, #67). Dispatch reads the brief and role from `8deba1c` (correct: the fix had to reach the worker) and tells the worker `Base: 8deba1c` (`TaskLines`), while the worktree sits on the old branch. `result.json` already records both: `base_oid` is the base the inputs were read from, `check_base_oid` is `merge-base(branch, base)`, which here is the real parent `5df0422`. So the record is not wrong, but nothing says which is which, and the worker is told a base its tree is not on.
2. **Progress line (follow-up 5a).** On a timeout, stdout prints `ended: interrupted, ...` because the `ended` emit prints the stream's own end (`Collect` sees a cancelled context and says `interrupted`), while `outcome` later maps `TimedOut` to `end: timeout`.
3. **Cost (follow-up 5b).** `cost_usd` is null on `timeout` and `interrupted`, because Claude Code's `result` event, which carries `total_cost_usd`, never arrives when the session is stopped. `waggle status` already prints `n/a` for a ticket with any null cost (`internal/usage/summary.go`).
4. **Proving test (follow-up 8).** `TestRunPlantDuringAutoMaintenance` proves that the worker's env turns off auto maintenance (`tripwireEnv`). Since T-026, `newFixture` also writes `maintenance.auto=false` and `gc.auto=0` into the repo config, so the test passes even if the worker-side keys are removed. It no longer proves what it says.

## 2. Design

### 2.1 Reused branch (recommended option of Q-T029-1)

- Compute the branch point before the prompts: `offBranch` already runs `merge-base(rev, baseOID)`; have it (or a sibling helper) return that OID, equal to `baseOID` for a new branch, so `Run` has it before `BuildPrompts`. `Provision` keeps setting `w.CheckBase` as now and stays the authority for the record and the checked range. Since `Provision` runs after `AcquireClaim`, a disagreement between the two (the branch moved between the reads) cannot be a refusal; it adds the warning `branch_moved` and the record keeps `Provision`'s value.
- `TaskLines` and `guardTaskLines` keep `Base: <baseOID>` and add, only when the branch point differs from it, `Branch point: <oid> (this branch was not rebased onto Base; Base is where the brief and role were read from)`.
- `result.json` field comments in `result.go` say: `base_oid` is the revision the brief, role prompt, WAGGLE.md and review files were read from; `check_base_oid` is the branch's merge-base with it, the real parent of the first new commit, and the start of the checked range.
- When they differ, add the warning `branch_behind_base: branch forks at <check_base_oid short>, base is <base_oid short>; rebase before merge`.

### 2.2 Progress line

Factor the cut detection out of `outcome` (the `TimedOut`, `error_max_budget_usd`, `max_turns` and `max_tokens` cases) into one helper used by both, and have the `ended` emit print the cut when there is one, else the stream end. A timeout then prints `ended: timeout, <n> tokens`. `end` in `result.json` does not change.

### 2.3 Cost (recommended option of Q-T029-2)

No price computation. `result.go` documents `cost_usd` as the runtime's own figure, null when the session ended without a `result` event (timeout, interrupt, crash). Nothing else changes; `waggle status` already shows `n/a`. The phase E stream-json input work (T-023 10.3) can end a timed-out session with a message instead of a signal, which may yield a `result` event; the queen adds that as one line to the phase E carry in the next records batch.

### 2.4 Proving test

Brief fix round (round 1 Colima result, `media/T-029/plant-with-keys.txt`, `plant-without-keys.txt`, `fix-removal.diff`): unsetting the fixture's local keys is not enough. The test passed with and without the two keys in `tripwireEnv`, because with the keys unset git's defaults apply and nothing ever triggers. `git commit` runs `git maintenance run --auto`, whose only default task is `gc`, gated by the same check as `git gc --auto`: the loose object estimate counts the files in `objects/17/` and triggers only above `ceil(gc.auto / 256)`, 27 at the default 6700, or with more than `gc.autoPackLimit` (50) packs. The fixture has a few hundred objects at most, so `objects/17/` holds 0 to 3 files and auto gc never starts, whatever the worker env says. The test as first written in T-023 had the same gap. It never proved the keys either.

The test must force auto gc at the second worker commit, so that only the worker-side keys stop it. Recipe, all in `internal/dispatch/maintenance_test.go`, inside `TestRunPlantDuringAutoMaintenance` and one helper next to it:

1. After `newFixture`, set the work repo's local config through `sh` (`config --local`, which overwrites `quietGit`'s values): `maintenance.auto true`, `gc.auto 6700`, `gc.autoDetach true`, `maintenance.autoDetach true` (git 2.47 and later; older git ignores it) and `maintenance.gc.enabled true`. This replaces the round 1 `--unset` lines. Leave `origin.git`'s keys set (the test does not push). This runs before `f.run`, so it is in the pre-run `config` snapshot and is not a violation.
2. A helper, for example `seedLoose17(t) string`, computes in Go (`crypto/sha1`) 40 blob bodies whose git blob id (`sha1("blob <len>\x00" + body)`) starts with byte `0x17`, by counting through `seed-<n>\n` until 40 match (about 10,000 hashes), and writes each as a file in a fresh `t.TempDir()`, returning that directory. 40 is above the threshold of 27 with margin. Before the run, a sanity check runs `sh(t, f.real, "hash-object", <one seed file>)` (no `-w`) and calls `t.Fatal` unless the id starts with `17`, so a future SHA-256 default fails loudly instead of quietly proving nothing.
3. The scenario becomes: `okScenario`, then `mkdir '<planted>'`, then `git hash-object -w '<seeddir>'/*`, then the second `commitFile`, then `sleep 3`, then the `printf ... > '<planted>/gitdir'` line as now. The seeds go in after the first commit so that commit stays below the threshold (no gc before the entry exists) and the second commit is above it. `sleep 1` becomes `sleep 3` because the queen runs the container with `--cpus 1`.
4. The assertion, `eachRepoSpelling`, `hasViolation(res.Violations, ruleHost, "worktrees/planted")` and the `Fatalf` text stay as they are (section 7: no weakened assertion). Update the doc comment above the test to say it forces auto gc in the fixture's config and seeds loose objects, so only the worker env can stop it.

Why this fails without the keys: with `maintenance.auto` and `gc.auto` gone from `tripwireEnv`, the second commit reads the local config, `objects/17/` holds 40 or more files, and auto gc starts detached (git 2.39 in `golang:1.23-bookworm`: `git gc --auto` daemonizes after `pack-refs` and reflog expiry; git 2.47 and later: the maintenance process detaches). The detached gc runs `git worktree prune`, which removes a `worktrees/<id>` entry without a `gitdir` file at once, whatever `gc.worktreePruneExpire` says. The plant's `printf` then fails because its directory is gone, the post-run check sees no `worktrees/planted` entry and no violation, and the test fails. With the keys, `GIT_CONFIG_COUNT` overrides the local config (either key alone stops it), no gc runs, the entry gets its `gitdir`, the host check flags it, and the test passes. The seeded blobs are unreachable loose objects; the host check does not look at `objects/` beyond `objects/info/alternates`.

Scope: this proves the D-181 mechanism (a worker commit starting a detached gc that edits the common dir). It does not reproduce the T-026 flakes (`info/refs` rewritten and a non-empty `t.TempDir` after a push to `origin.git`); those come from `receive-pack` in the origin, which local transport runs without the client's `GIT_CONFIG_*`, so `tripwireEnv` cannot affect them and `quietGit` on the origin stays their fix.

The queen runs the test and its fix-removal check in the Colima container (section 5): with `maintenance.auto` and `gc.auto` dropped from `tripwireEnv` (the change in `media/T-029/fix-removal.diff`), the test must fail; with them, it must pass.

## 3. Questions

- **Q-T029-1: what does dispatch do with a reused branch whose branch point is behind the base?** (a) Record and say the truth (2.1): keep the branch as is, tell the worker the branch point, document the fields, warn. (b) Rebase the branch onto the base on the host before the run. (c) Refuse unless `--base` names the branch point. **Recommended: (a).** (b) rewrites commits a guard may already have reviewed, needs a force push that dispatch never does (it pushes the checked OID without force, so the push after a rebase is rejected), and adds a conflict failure mode on the host. (c) would have blocked the trial's own rerun: the brief fix that made it work was on main, not on the branch, and `--base` set to the branch point would have hidden it from the worker. The queen already rebases at merge and checks the patch-id against the reviewed head (`handoff/queen.md`).
- **Q-T029-2: what goes in `cost_usd` when no `result` event arrives?** (a) Null, documented (2.3). (b) An estimate from `usage` and a price table in config. **Recommended: (a).** Waggle holds no prices, and a table would be a second source of spend figures that drifts from the runtime's; the token counts are recorded either way, and the null keeps `waggle status` honest with `n/a`.

## 7. Threat model (D-203)

Must-fix: any change to which revision the brief, role prompt, WAGGLE.md or review files are read from; any change to the checked range, the push or the claim; a new git call that runs unpinned or before `checkHostRecord`; a task line or warning that carries text from the brief, the branch or the run other than OIDs dispatch resolved itself; a weakened assertion in an existing test, including the plant test's violation check. Note, not must-fix: a branch moved by another process between `offBranch` and `Provision` (the `branch_moved` warning names it and `Provision`'s value stays authoritative); an attack that needs write access to the git dir, to `.waggle/worktrees/` outside the worker's own tree or to another ticket's worktree, or a process that already escaped the tracker.
