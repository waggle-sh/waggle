## 1. Goal

Today the gate checks a commit against the claim of whichever ticket the commit names (`classify`, `gate_commits.go:259-309`, then `claimFor`, `:313-335`), and nothing ties that claim to the PR. A PR on any branch can carry `T-040: ` commits and pass for T-040's live lease. After this ticket a claim records the branches its work may arrive on, and a bound commit passes only when its claim names the PR's head branch. Binding sources (D-234, D-237) do not change; this adds a check after binding.

One ticket per PR (the other D-278 example) was not chosen: it stops mixing tickets but not a PR naming a ticket it does not own, which is the gap.

## 2. Design

### 2.1 A claim records branches (`internal/comb/`)

`Lease` (`backend.go:112-121`) gains `Branches []string` with JSON tag `branches,omitempty`, after `Directories`. Under Q-T039-4 (a) `LeaseVersion` stays 2 (`backend.go:88`): `parseLease` decodes with plain `json.Unmarshal` (`git.go:441-462`), so an older binary reads a claim with `branches` as before and ignores the field, and a claim with no field reads as `nil`.

`ValidateBranches(list []string) error` (exported, next to `validateLeaseFields`) refuses with `ErrInvalidLease`: more than 4 entries (`branches: at most 4`); a duplicate entry (exact bytes); an entry over 255 bytes; an entry that is not one of these two forms:

- **Branch:** a short branch name as `git check-ref-format --branch` accepts it, restricted to bytes 0x21 to 0x7e minus `~ ^ : ? * [ \`; no `..`, `@{` or `//`; not starting with `-`, `/` or `.`; not ending with `/`, `.` or `.lock`; not `@`; not starting with `refs/`.
- **Fork branch** (under Q-T039-3 (a) only): `<owner>/<repo>:<branch>`, owner matching `^[A-Za-z0-9][A-Za-z0-9-]{0,38}$`, repo matching `^[A-Za-z0-9._-]{1,100}$` and not `.` or `..`, branch as above. A colon cannot appear in a git ref, so the form is unambiguous. Under Q-T039-3 (b), or after the planned cut (section 9), an entry with a colon is refused.

`validateLeaseFields` calls `ValidateBranches(l.Branches)`. Because `decodeLease` re-validates every stored claim with it (`git.go:477`), a stored claim with a bad list is a malformed claim, which the gate already fails (`claimFor`, `:323-324`). An empty or nil list is valid (Q-T039-1 decides what the gate does with it). Error text may quote an entry only through `%q`.

### 2.2 Writers record branches (`internal/dispatch/`, `cmd/waggle/claim.go`)

- **`Request.ClaimBranches []string`** (`request.go`, struct only): the branch list a claim records. `Validate` does not read it.
- **`AcquireClaim`** (`claim.go:42`): `want.Branches` is `req.ClaimBranches` when it is not empty, else `[]string{req.Branch}`. `Validate` always sets `req.Branch` (default `t-<nnn>`, `request.go:115-117`), so dispatch records the branch it creates and pushes, phase suffix included (`t-036a`; `checkBranch`, `request.go:144-158`, allows it). The renewal note (`:58-61`) also compares `Branches` and prints old and new lists after the directories, in the same `%v` shape.
- **The dispatch renewal** (`run.go:409`): the `comb.Lease` literal gains `Branches: []string{req.Branch}`, so a keepalive renewal never drops the list. This is the only change in `run.go`.
- **`ClaimTask`** (`task.go`): `ClaimTaskRequest` gains `Branches []string`; `ClaimTask` refuses a bad list with `failf(ExitUsage, "%w", err)` from `comb.ValidateBranches` (error code `usage`) before `refuseHardcoded`, and passes the list as `ClaimBranches`. With no `--branch` the claim records `t-<nnn>` (Q-T039-2 (a)).
- **`waggle claim --branch <name>`** (`cmd/waggle/claim.go`): repeatable, up to 4; usage line gains `[--branch <name>]...`. A renewal replaces the stored list with the given list (or the default), and the note says so. The claim JSON body (`claimBodyJSON`, `claim.go:37-46`) gains `branches` (always an array, `nonNil`), a field added under schema version 1 (`claim.go:19-21`). Text output is unchanged apart from the note.

**Copilot cloud agent (D-279).** Copilot picks its branch (`copilot/<slug>`, `tasks/T-037.md` row G3) after the task starts. The human or orchestrator who assigned the task renews the claim with `--branch copilot/<slug>` (and `--branch t-<nnn>` if it also works there) once the PR opens. Until then the gate fails the PR with the 2.4 message, which fails closed. The T-037 recipe states this; this ticket changes no docs.

### 2.3 The gate knows the PR head (`cmd/waggle/gate_approve.go`, `gate_verify.go`)

- **`readPREvent`** also reads `pull_request.head.repo.full_name` (a null `head.repo` reads as `""`) and `pull_request.base.repo.full_name`; `prEvent` gains `headRepo` and `baseRepo`. Missing fields do not make the event malformed (the approver path must keep working on today's payloads).
- **Head identity**, resolved once in `runGateRange` and carried in `scanInput` as a new field (so the approver rescan, which reuses `p.in`, `gate_approve.go:218-221`, sees the same head): `name` is today's branch name (`--branch`, else `GITHUB_HEAD_REF` under Actions, else the event's head ref; `gate_verify.go:132-139`), kept raw; `fork` is true when an event was read and its `headRepo` is empty, its `baseRepo` is empty, or the two differ under ASCII case folding; also true under Actions when `GITHUB_EVENT_NAME` is `pull_request` or `pull_request_review` but no event was read (fail safe); otherwise false (local runs, Actions without a PR event). `known` is `name != ""`.
- A name that `branchTicket` ignores (over 255 bytes or a control byte) is still known: it binds nothing, as today, and matches no claim entry, so a bound commit fails. It is never echoed.

### 2.4 `claimFor` checks the head (`cmd/waggle/gate_commits.go`)

After a claim reads and decodes (the `default:` case, `:325-331`), and once per ticket (the `s.claims` cache, `:316`), a new unexported function decides:

1. **Head unknown** (`name == ""`): no check. Outside Actions, the first such claim in a run adds one warning `no pull request branch; claim branches not checked (pass --branch)` under `leases`; under Actions nothing is added. The gate workflow runs only on `pull_request` and `pull_request_review` (`waggle-gate.yml.tmpl:5-16`), where the runner sets `GITHUB_HEAD_REF` or the event carries `head.ref`, so a PR author cannot reach this case there.
2. **Claim lists branches:** a same-repo head passes when `name` equals a plain entry byte for byte. A fork head passes, under Q-T039-3 (a), only when an entry `<owner>/<repo>:<branch>` has `<owner>/<repo>` equal to `headRepo` under ASCII case folding and `<branch>` equal to `name`; under (b) never. Otherwise one failure: `<id>: claim does not name this pull request's branch`.
3. **Claim lists no branch** (written before this ticket, or by an older binary): per Q-T039-1. (a) one failure `<id>: claim names no branch; renew it with waggle claim --branch`. (b) a same-repo head whose `name` matches `^(?:waggle/T-|t-)([0-9]{3,6})(?:[^0-9].*)?$` with digits that parse to `<id>` passes with one warning `claim for <id> names no branch; accepted on ticket branch name`; a fork head or any other name gets the (a) failure. The pattern is D-237's names plus dispatch's suffixes without a dash (`t-036a`). (c) one warning, as (b)'s, and it passes.

The failure is filed under `leases` with no path, so the approver filter (`in.filter`, `gate_commits.go:224`) never drops it and no approval clears it. The claim still applies its path rules (`cl.ok` stays true), so the report stays complete. Messages carry only the canonical ticket ID: never the head name, the repo names or a claim entry. Base merges reuse their first parent's ticket and its cached result. `classify` does not change.

### 2.5 What remains for the T-037 docs (L1 restated from the merged code)

- Anyone who can push to a branch a claim names can add commits under that claim (same-repo branches are writable by every repo writer unless protected).
- Whoever writes the claim chooses its branch list; an agent that can run `waggle claim` can name its own branch (L3, unchanged).
- Under Q-T039-1 (b), a claim written before the upgrade accepts any same-repo ticket branch name for its ticket until it is renewed or released, and the gate accepts expired claims with a warning (`gate_commits.go:327-330`).
- A local run without `--branch` skips the check with a warning.
- An older binary that renews a claim (dispatch keepalive included) drops `branches` silently (Q-T039-4 (a)).

## 3. Questions for the Head Keeper (open)

- **Q-T039-1: what does the gate do with a claim that names no branch?** (a) Fail closed with a renew hint. (b) Fall back to the ticket's own branch names (D-237's `waggle/T-<id>` and `t-<id>`, plus dispatch's `t-<id><suffix>` without a dash), same-repo heads only, with a warning; any other head fails. (c) Warn only. Recommended: (b). Every claim on every repo today has no list, and the hive's claims keep having none until the pin moves; (b) keeps those PRs passing on the branches dispatch and D-237 already tie to the ticket, while a feature branch or fork carrying another ticket's commits fails. Cost: a pre-upgrade claim stays borrowable by a same-repo branch named for its ticket until renewed or released (2.5). (a) is strictest and costs a renewal of every live claim at upgrade and a pin move before the next hive dispatch; (c) leaves the gap open for every old claim. Reversible: (b) to (a) is one branch of the function, once old claims are gone.
- **Q-T039-2: is `--branch` optional or required on `waggle claim`?** (a) Optional; with none the claim records `t-<nnn>`, the branch dispatch would use. (b) Required. Recommended: (a). It matches dispatch, keeps existing `waggle claim` calls and tests working, and a wrong default fails closed at the gate with a message that names the fix. Cost: a human who works on `feature/x` learns about `--branch` from the gate failure. (b) breaks every `waggle claim` call in `claim_test.go` and in T-037's draft recipes. Reversible.
- **Q-T039-3: can a fork PR match a claim?** (a) Only through entries of the form `<owner>/<repo>:<branch>`, matched against the event's `head.repo.full_name`. (b) Never; bound commits from forks always fail leases. Recommended: (a). Public repos take outside PRs from forks, and the claim writer (never the PR author, L3) can name the fork branch; about 20 doubled lines. Cost: the event's repo fields become trusted inputs (GitHub writes them). A fork named for a ticket branch never matches a plain entry under either answer. (b) is the planned cut (section 9). Reversible.
- **Q-T039-4: does the field ship at lease version 2 or 3?** (a) Optional `branches` at version 2. (b) Version 3. Recommended: (a). Older binaries read new claims unchanged (`parseLease` ignores unknown fields), so the pinned hive dispatch and any installed CLI keep working. Cost: an older binary that renews a claim drops the list without saying so (2.5). (b) makes every older binary treat new claims as malformed (`git.go:457-458`), which breaks the hive's pinned dispatch the moment a new binary writes one, and adds `git.go` to the lease. Hard to reverse after G5.

## 5. Threat model (D-203)

**Attacker.** The PR author (agent or person): it controls commits, subjects, trailers, the branch name (any valid ref, up to git's limits), the PR body and, for a fork, the fork's name and branch. It cannot write claim refs, the base revision, the base config, the workflow, or the event file and runner variables GitHub writes.

**Trusted.** Claim refs and whoever writes them (L3), the base revision and its config, the workflow, GitHub's event payload and `GITHUB_HEAD_REF`, the Head Keeper.

**Must-fix:** a bound commit that passes the gate while its claim lists branches and none matches the PR head; a fork head that matches a plain entry, or any entry under Q-T039-3 (b); a fork head that takes the Q-T039-1 (b) fallback; a head name that the fallback accepts for a ticket other than the claim's, or by substring (`t-0400` for T-040, `xt-040`); a match that folds case on the branch part; a head the author can make unknown or empty in a PR event run, or an ignored name that skips the check; the failure dropped by the approver filter or cleared by an approval; the head name, a repo name or a claim entry echoed in a gate message; a claim write path (`AcquireClaim`, the `run.go:409` renewal, `ClaimTask`) that drops or alters the list it was asked to record; a stored claim with an invalid list read as valid; more than 4 entries, a duplicate, or an entry over 255 bytes accepted; any change to `classify`'s results or messages; any `LeaseVersion` change under Q-T039-4 (a); an older-format claim (no field) read differently by the comb; a test that sends a signal, sets a session `Timeout` or cancels a running session (D-193); files changed outside the lease rule; any em or en dash added.

**Note, not must-fix:** anything that needs a claim ref written (L3), including a claim that lists the attacker's branch; a repo writer pushing commits onto a branch a claim names (2.5); an older binary dropping the list on renewal; a pre-upgrade claim borrowed through the Q-T039-1 (b) fallback; a hand-written workflow that runs the gate outside a PR event and so skips the check.

**Guard prompt sentence (repeat verbatim):** "Threat bar (D-203): a finding whose attacker needs to write claim refs, the base revision, the base config, the workflow or GitHub's event payload is a note, not a must-fix; must-fix is for any way a PR author, through commits, subjects, trailers, the branch name, the PR body or a fork, gets a bound commit past a claim that does not name the PR's head branch, and for any claim writer that loses the branch list."
