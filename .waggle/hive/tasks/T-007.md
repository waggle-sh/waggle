## 1. Goal

Make the merge gate refuse any PR whose net change to `.waggle/hive/DECISIONS.md` (called `DECISIONS.md` below) is anything other than one or more new, well-formed entries appended at the end. T-006 makes `waggle decide` the only writer, but nothing stops a hand edit that keeps the format valid (a reworded rationale, a deleted entry renumbered away). This closes that gap at merge time, where it is authoritative.

Go 1.23, module `github.com/waggle-sh/waggle`, **standard library only**. Do not touch `go.mod` / `go.sum`.

## 4. Comparison rules (`internal/decisions/gate.go`)

```go
// VerifyTransition reports whether a DECISIONS.md change from old to next is a
// pure append of well-formed entries. oldExists and nextExists say whether the
// file is present at each revision. It returns the IDs of the appended entries.
func VerifyTransition(old []byte, oldExists bool, next []byte, nextExists bool) (added []int, err error)
```

Evaluate in this order; the first failure wins. Every failure wraps `ErrNotAppendOnly` or `ErrCorrupt` (both from T-006) and names the side (`base` or `head`) and, where known, the entry ID or line number.

1. `!oldExists && !nextExists`: pass, no entries added.
2. `oldExists && !nextExists`: `ErrNotAppendOnly` ("DECISIONS.md deleted").
3. A missing or zero-length side is zero entries. Otherwise `Parse(old)`; failure is `ErrCorrupt` naming `base` (see 4.2).
4. `Parse(next)`; failure is `ErrCorrupt` naming `head`. This gives, for the whole head file: byte-exact round trip, IDs `1..n` contiguous, valid non-decreasing dates, `supersedes` only pointing backward.
5. `bytes.Equal(old, next)`: pass, no entries added.
6. Let `o = len(oldEntries)`, `n = len(nextEntries)`. Require `n > o`, else `ErrNotAppendOnly` ("entries removed or rewritten").
7. **Existing entries byte-identical:** `old` must be an exact byte prefix of `next`. Report the first differing line number in `head` and the old entry ID that contains it.
8. **New entries only at the end:** for `o > 0`, `next[len(old):]` must equal the concatenation over `i = o..n-1` of `"\n" + RenderEntry(nextEntries[i])`. For `o == 0`, `next` must equal `Render(nextEntries)` (header plus entries). Any extra or missing byte is `ErrNotAppendOnly`.
9. **IDs sequential:** `nextEntries[i].ID == i+1` for every `i`, so the new IDs are `o+1..n` with no gaps. (Implied by step 4; assert it explicitly anyway so the error message names the bad ID.)
10. **Dates:** the first new entry's date is not earlier than the last old entry's date (implied by step 4; same reasoning).
11. Pass. Return `added = [o+1..n]`.

Steps 7 and 8 are what T-006's `VerifyAppendOnly(old, next)` already promises. **Call it** for those steps when `o > 0`; do not reimplement the byte logic. The steps are spelled out here so the guard can check the combined behavior.

### 4.1 What this does not check
- That the Keeper approved an entry. Under D-017 that is the PR approval; the gate checks shape only.
- That a new entry's date is "today". Dates come from `waggle decide`'s clock; a hand-written entry with a plausible date passes if well-formed. Acceptable: the PR is still a Full gate on a Tier 2 path.

### 4.2 Corrupt base
If `base` fails `Parse`, the check fails with `ErrCorrupt` and the message `base DECISIONS.md fails integrity; repair needs a Head Keeper admin merge`. The gate never "accepts anything" because the starting point is bad. Every PR that touches `DECISIONS.md` fails until a Head Keeper admin-merges a repair and records a `waggle decide` entry explaining it. A repair PR cannot pass this check by design. There is no skip flag (Q-T007-3, resolved).

### 4.3 If T-006's `VerifyAppendOnly` differs from this brief
If the merged `VerifyAppendOnly` rejects `old == next` or a zero-length `old`, handle those cases in `VerifyTransition` before calling it (steps 3 and 5 already do). Do **not** change `VerifyAppendOnly` semantics: `Append` uses it as a self-check. If it accepts something section 4 rejects, stop and report to the architect rather than patching T-006 code.

## 5. Which two revisions are compared

The CLI takes `--base` and `--head`, but compares **`merge-base(base, head)` to `head`**, not `base` to `head`.

Reason: in CI, `pull_request.base.sha` is the current tip of `main`. If `main` gained `D-019` after the branch was cut and the PR never touched `DECISIONS.md`, a `base` vs `head` comparison would see `D-019` "removed" and fail a clean PR. Against the merge-base, that PR shows no change.

Two PRs that both append `D-019` each pass against their own merge-base. The second one cannot merge anyway: both append after the same final line, so git reports a textual conflict, and after the author merges `main` the merge-base moves and the check reruns against the new `D-019`. State this reasoning in the `gate decisions` doc comment.

Only the net change matters. Intermediate commits on the branch that edit and then revert an entry are not inspected; what lands is `head`.

## 6. CLI (`cmd/waggle/gate.go`)

```
waggle gate decisions --base <rev> --head <rev> [--repo <dir>]
```

- `waggle gate` with no check, or an unknown check, prints gate usage to stderr and exits 2.
- `--base`, `--head` required. `--repo` default `.`.
- Use `flag.NewFlagSet("gate decisions", flag.ContinueOnError)`. `runGate` never calls `os.Exit`.
- **Exit codes:** `0` pass or unchanged, `1` check failed (not a pure append, corrupt, bad path), `2` usage, `3` git or I/O error (bad revision, no merge-base, shallow clone). CI fails on any non-zero.
- **Output (stdout on pass):** `decisions: unchanged` or `decisions: ok, appended D-019, D-020`.
- **Output (stderr on failure):** `decisions: FAIL: <reason>`. When `getenv("GITHUB_ACTIONS") == "true"`, print instead `::error file=.waggle/hive/DECISIONS.md::<reason>` so the annotation lands on the PR. `<reason>` is single-line; replace `\n` and `\r` with spaces.
- No `--skip`, `--allow`, or override flag. Overrides are a Keeper admin merge, never a flag an agent can pass.

### 6.1 Git steps
1. Validate each of `--base` and `--head`: non-empty, at most 255 bytes, no leading `-`, no NUL, no whitespace. Else exit 2.
2. Resolve each with `git rev-parse --verify --quiet --end-of-options <rev>^{commit}`. Validate the output against `^[0-9a-f]{40}([0-9a-f]{24})?$`. Failure exits 3.
3. `git merge-base <baseOID> <headOID>`. No output or failure exits 3 with a hint: `no merge-base; is the clone shallow? use fetch-depth: 0`.
4. `git diff-tree -r -z --name-only --no-renames <mb> <headOID>`. Split on NUL.
   - The path is `layout.Decisions` (`.waggle/hive/DECISIONS.md`, from T-011's `internal/layout`). Do not hardcode the string; call it `decisionsPath` below. Any path where `strings.EqualFold(p, decisionsPath) && p != decisionsPath` fails (exit 1): a case variant would shadow the real file on macOS and Windows checkouts.
   - If `decisionsPath` is not in the list: print `decisions: unchanged`, exit 0.
5. For each of `mb` and `headOID`: `git ls-tree -z <oid> -- .waggle/hive/DECISIONS.md`. No entry means absent. Otherwise require mode `100644` and type `blob`; a symlink (`120000`), executable, submodule, or tree fails (exit 1).
6. `git cat-file -s <blob>`: over 4 MiB fails (exit 1, same cap as T-006 `Append`). Then `git cat-file blob <blob>`. Read raw blobs only, never the working tree, so `.gitattributes` line-ending conversion cannot change the bytes.
7. `decisions.VerifyTransition(old, oldExists, next, nextExists)`.

### 6.2 Git execution rules (same as T-002 section 6)
One helper: `exec.CommandContext(ctx, "git", "-C", repo, args...)`, separate argv, no shell. Env: `os.Environ()` plus `GIT_TERMINAL_PROMPT=0`, `LC_ALL=C`. Capture stdout and stderr separately; wrap failures with the subcommand and trimmed stderr. Read-only plumbing only: `rev-parse`, `merge-base`, `diff-tree`, `ls-tree`, `cat-file`. No writes, no fetch. Use `context.Background()` with a 60 second timeout for the whole check. Do not import `internal/comb`.

## 9. Tests

`go test -race ./...`. All files under `t.TempDir()`.

### 9.1 Pure (`internal/decisions/gate_test.go`, never skips)
Build fixtures with T-006's `Render` / `RenderEntry` and a fixed clock, then mutate bytes. Assert `errors.Is` against the right sentinel and, for failures, that the message names the side and the ID or line.

1. Both absent: pass, `added` empty.
2. Absent to one entry (the T-006 backfill PR shape, also 18 entries): pass, `added = [1..n]`.
3. Absent to zero-length file: pass, `added` empty.
4. Unchanged (non-empty): pass, `added` empty.
5. Append one; append three: pass, correct `added`.
6. Deleted file: `ErrNotAppendOnly`.
7. One byte changed inside an old entry's rationale, with a new entry also appended: `ErrNotAppendOnly`, message names the old ID.
8. Old entry removed and the rest renumbered so `Parse` passes: `ErrNotAppendOnly`.
9. New entry inserted between `D-001` and `D-002` (IDs renumbered to stay contiguous): `ErrNotAppendOnly`.
10. Two old entries swapped: `ErrNotAppendOnly` or `ErrCorrupt` (either is acceptable; assert one of them and a non-nil error).
11. Appended entry with ID gap (`D-003` then `D-005`): `ErrCorrupt` naming `head`.
12. Appended entry duplicating the last ID: `ErrCorrupt` naming `head`.
13. Appended entry dated before the last old entry: `ErrCorrupt` naming `head`.
14. Appended entry with an extra blank line or CRLF endings: `ErrCorrupt` naming `head`.
15. Truncated new entry (last line cut): `ErrCorrupt` naming `head`.
16. Header line edited while appending: `ErrNotAppendOnly`.
17. Corrupt base (missing trailing newline) with a valid-looking head: `ErrCorrupt` naming `base`.

### 9.2 CLI (`cmd/waggle/gate_test.go`)
Helper: `exec.LookPath("git")` or `t.Skip`. Each test `git init -q` a repo, commits with env `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, fixed `GIT_AUTHOR_*` / `GIT_COMMITTER_*`. Call `runGate` directly with buffers and a fake `getenv`.

18. PR branch that does not touch `DECISIONS.md`: exit 0, `decisions: unchanged`.
19. PR appends `D-002`: exit 0, stdout `decisions: ok, appended D-002`.
20. PR edits `D-001`: exit 1, stderr starts `decisions: FAIL:`.
21. Same as 20 with `GITHUB_ACTIONS=true`: stderr is a single `::error file=.waggle/hive/DECISIONS.md::` line.
22. **Moved base:** branch cut at `D-001`, does not touch the file; `main` then appends `D-002`. `--base main --head branch`: exit 0 (merge-base semantics).
23. **Moved base with append:** same as 22 but the branch appends its own `D-002`: exit 0 against the merge-base (git conflict blocks the real merge; document in the test comment).
24. Branch deletes `DECISIONS.md`: exit 1.
25. Branch replaces `DECISIONS.md` with a symlink to a valid copy: exit 1.
26. Branch adds `.waggle/hive/decisions.md` alongside the real file: exit 1. (Use `git update-index --add --cacheinfo` or `hash-object` plus `update-index` so the test works on case-insensitive filesystems.)
27. Branch commits a 5 MiB `DECISIONS.md`: exit 1.
28. File created on the branch (absent at merge-base) with valid content: exit 0.
29. `--base` missing: exit 2. `--base -x`: exit 2. `--base nosuchref`: exit 3. Unknown check `waggle gate frobnicate`: exit 2. No check: exit 2.
30. Repos with no common history (two unrelated roots): exit 3 with the merge-base hint.
31. Working tree dirty (uncommitted edit to `DECISIONS.md`) does not affect the result: only blobs are read.
