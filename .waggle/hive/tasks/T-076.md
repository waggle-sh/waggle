## 1. Goal

Add `gate.mode` (`open` or `guard` in this ticket), parse it, and make `verify` honor `open` (record and report would-be violations, always pass except a gate that cannot run) and `guard` (today's behavior). Existing v0.1 hives and a missing key default to `guard`.

## 2. Scope

- `gate.mode` key and parsing.
- `open` and `guard` behavior in `verify`. Exit 3 on a broken base config stays a failure in every mode (D-382, open question 3). Raising the mode stays Tier 3, with no carve-out (D-382, open question 2).
- Tests for both modes and for a missing key.

## 3. Out of scope

- `watch` (T-077). `waggle gate status` (T-078). `waggle gate guard` and `waggle gate open` (T-079). Scaffold, init prompt and docs (T-080).
- RFC open questions 4 to 8, which are not decided.
