## 1. Goal

The worker environment carries `GIT_CONFIG_COUNT` entries `url.file:///dev/null/.pushInsteadOf=<prefix>` for every prefix in `pushBlocked`, `/` and `.` included (`tripwireEnv`, `launch.go` near line 118). Every process the worker starts inherits them, `go test` and the test binaries included. A test that creates a bare origin under `t.TempDir()` and pushes to it by absolute path is rewritten to `file:///dev/null/...` and fails. In the trial both the T-026 builder and its guard hit this, so tests that push to a local origin (most of `internal/dispatch`'s remote-mode tests, `internal/comb`'s remote tests) ran only on the host and in product-ci.

Goal: pushes into a scratch directory that dispatch creates for this one run go through; every push the tripwire rewrites today outside that directory is still rewritten; real remotes stay blocked exactly as now.

## 2. Design (recommended option of Q-T028-1)

1. Before `Prepare`, `Run` creates one scratch directory per run with `os.MkdirTemp(os.TempDir(), "waggle-<ticket>-<role>-")` (mode 0700), on the host, before the claim like every other step that can refuse (T-023 10.6 item 4). Failure is exit 3, nothing written.
2. `runtime.Invocation` gains `ScratchDir string`. `workerEnv` sets the worker's `TMPDIR` to it (replacing the inherited value from `envAllowed`; the last value of a variable wins in `os/exec`, but build the slice so only one `TMPDIR` entry exists). `t.TempDir()` and `os.MkdirTemp("", ...)` in the worker's tests then land under it.
3. `tripwireEnv` takes the scratch path and, when it is set, adds keys that rewrite the scratch prefix to itself, which beats the shorter `/` prefix because git applies the longest matching `insteadOf`:
   - `url.<scratch>/.pushInsteadOf=<scratch>/`
   - `url.file://<scratch>/.pushInsteadOf=file://<scratch>/`
   - the same two for `filepath.EvalSymlinks(<scratch>)` when it differs (macOS `/var` is a link to `/private/var`, and a test that resolves its temp dir pushes to the `/private` form).
   - `url.file:///dev/null/.pushInsteadOf=<scratch>/../` and `url.file:///dev/null/.pushInsteadOf=file://<scratch>/../`, and the same two for the resolved form. Each is longer than its exemption and closes the top-level `..` case for that spelling. They do not close any `..` path that does not begin with `<scratch>/../` or `file://<scratch>/../` itself (for example `<scratch>/a/../../` once `<scratch>/a` exists, `<scratch>/./../` or `<scratch>//../`), which stays a listed bypass (item 6).
   The trailing slash on every exemption key and value is load-bearing: without it, `<scratch>-evil/` would also match the prefix. The scratch path must be absolute, equal to its `filepath.Clean`, and hold no byte below 0x20; otherwise `Prepare` refuses with `ErrAdapterConfig` (exit 3). `envFixed` becomes a function of the scratch path, or the scratch keys are appended after it with the count adjusted; either way there is exactly one `GIT_CONFIG_COUNT` and the indexes are contiguous. With an empty `ScratchDir` (every caller other than dispatch, and `Verify`) the emitted keys are byte-identical to today.
4. Every other key stays as it is: all `pushBlocked` prefixes, `core.excludesFile`, `core.attributesFile`, `maintenance.auto`, `gc.auto`.
5. After the run (after the post-run checks and before the record is written), dispatch removes the scratch directory only if it is empty, with a single `os.Remove`; a non-empty directory stays and adds the warning `scratch_left: <base name of the dir>` (Q-T028-2). Every return after `MkdirTemp`, refusals included, runs the same empty-only `os.Remove` (a defer): the defer covers every earlier return; on the normal path the pre-record remove runs first and the deferred one is a no-op whose error is ignored. Dispatch never removes anything inside it.
6. Update the `pushBlocked` doc comment and the `not_enforced` "push tripwire is best effort" text (`cell.go`): name the scratch exemption and its two bypasses (a symlink the worker plants inside the scratch directory, and any `..` path that does not begin with `<scratch>/../` or `file://<scratch>/../` itself (for example `<scratch>/a/../../` once `<scratch>/a` exists, `<scratch>/./../` or `<scratch>//../`), both of which reach any local repo the worker can name; git matches `insteadOf` on the URL string, not the resolved path).

## 3. Questions

- **Q-T028-1: how to let local test pushes through?** (a) Per-run scratch `TMPDIR` with a self-rewrite for that prefix (section 2). (b) Drop `/`, `.` and `file://` from `pushBlocked`: every local path push goes through, the main checkout's git dir included. (c) No product change: tests that push clear `GIT_CONFIG_*` for their own git calls (the tripwire already misses a process that does so). **Recommended: (a).** (b) reopens absolute-path pushes into the Keeper's repo with no exemption boundary. (c) fixes only this repo's tests, not any other hive's, and teaches tests to strip the tripwire. (a) exempts one directory that exists for one run, keeps every network prefix, and its two bypasses are the same reach as the existing relative-path bypass (`pushBlocked` comment), with the post-run ref check and the config hash still the backstop.
- **Q-T028-2: what happens to the scratch directory after the run?** (a) `os.Remove` only when empty, else keep it with a `scratch_left` warning; the OS temp cleaner or the Keeper removes the rest. (b) `os.RemoveAll` at run end. (c) Create it under the run directory (`runs/<run>/tmp`) and let `clean --runs` remove it. **Recommended: (a).** It adds no recursive delete of a worker-written tree (D-205 counts deletes; D-203 counts deletes outside the worker's own tree), and `t.TempDir()` already cleans up after itself, so it is usually empty. (c) puts worker test files inside the main checkout's working tree and makes paths long enough to break unix socket tests (104 bytes on macOS).

## 4. Out of scope

- The other tripwire misses listed in `pushBlocked`'s comment (bare relative paths, scp forms without `git@`, upper-case schemes, `<transport>::<address>`, `pushurl`, a longer `pushInsteadOf` from `git -c`).
- Fetches: the tripwire rewrites pushes only.
- `GOTMPDIR`, `GOCACHE` and other tool caches: unchanged.

## 5. Verification

The worker's Bash allowlist is `WAGGLE.md` section 3 plus git. Run, in this order:

- `go build ./...`
- `go vet ./...`
- `go test -race ./... -run '<regexp>'` naming only `TestTripwireBlocksPush`, `TestPrepareEnv`, the new tests, and any other runtime or dispatch test that stays git and file only.

Do not run tests that go through `Run`, the tracker or `sweep()` on this host (D-193, D-195): no full `go test -race ./...` and no `-run` pattern that matches `TestRun*`, `TestGuard*`, `TestClean*` or the `reap_*` tests. The scratch directory's creation and removal are tested through a small function the builder factors out of `Run` (for example `newScratch` and `dropScratch`), called directly on a `t.TempDir()` parent; no new test calls `Run`, `sweep()` or sends a signal. product-ci (ubuntu) runs the full packages with race on the PR. After merge, the queen's first dispatched builder whose tests push to a local origin is the field check: those tests must pass in the worker (record it in the trial media or the next records batch). Claude Code, Node and go also write to `$TMPDIR`, so the field check also records whether the scratch dir was empty after a normal run and how often `scratch_left` fires; if it is routinely non-empty, Q-T028-2 is reopened.

## 7. Threat model (D-203)

This ticket narrows a security control on purpose, so the bar is explicit.

Must-fix: any push URL that reaches a network remote and is rewritten today but not after the change (any `https://`, `ssh://`, `git@`, `http://`, `git://`, `git+ssh://`, `ssh+git://` form, with or without the scratch path inside it); any absolute or `file://` path outside the scratch directory that is rewritten today and not after the change, without a symlink or `..` component the worker had to create or type; an exemption key built from anything other than the path dispatch itself created this run (a value from the brief, the repo config, the worker's env or the run record); a scratch directory shared between runs or roles, or one whose path a worker can choose; a recursive delete, or any delete outside the scratch directory itself; a change to the deny rules or to `gitAllowed`; the exemption or its two bypasses left out of the `pushBlocked` comment or `not_enforced`.

Note, not must-fix: a push through a symlink the worker plants inside the scratch directory, or through any `..` path that does not begin with `<scratch>/../` or `file://<scratch>/../` itself (for example `<scratch>/a/../../` once `<scratch>/a` exists, `<scratch>/./../` or `<scratch>//../`), that reaches another local repo (same reach as the bare relative path bypass already listed; the post-run ref check of the hive repo and the config hash remain the backstop); a worker or test that clears `GIT_CONFIG_*` (already listed); anything that needs write access to the git dir, to `.waggle/worktrees/` outside the worker's own tree or to another ticket's worktree, or a process that already escaped the tracker.

Guard prompt sentence (repeat verbatim): "Threat bar (D-203): a finding whose attacker needs write access to the git dir, to `.waggle/worktrees/` outside the worker's own tree or to another ticket's worktree, or a process that already escaped the tracker, is a note, not a must-fix; must-fix is for what a worker inside its lease, a guard or ordinary repo state can trigger, and for any signal or delete outside the worker's own tree from ordinary inputs."

Add for this ticket: "In T-028 any push to a network remote, or to a local path outside the per-run scratch directory reached without a worker-made symlink or `..`, that the old tripwire rewrote and the new one does not is a must-fix."
