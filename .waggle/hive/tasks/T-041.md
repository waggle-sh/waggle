**How a page gets its HTML.** `astro/markdown` exports no renderer and the Satteri packages stay unimported (2.2), so the one call that takes a markdown string and runs the configured processor is `renderMarkdown` on a content loader's context. `site/src/content.config.ts` exports `collections = { docs }`, one `defineCollection` (from `astro:content`) with an inline loader, `{ name, load: async ({ store, renderMarkdown }) => ... }`: `store.clear()`, then for each piece from `sources.ts`, `const rendered = await renderMarkdown(body, { fileURL: pathToFileURL(absoluteSourcePath) })` and `store.set({ id, data: { title }, rendered })`. The pieces: one per manifest file but the README, `home-pitch` and `home-rest` for the README (2.4), and `glossary`. A page calls `getEntry('docs', id)` and `render(entry)` from `astro:content` and places `<Content />`; `[...slug].astro` returns `{ params: { slug }, props: { id } }` from `getStaticPaths`. Astro's `glob` loader is not used (rule 1).

Rules:

1. Files are read at build time with `node:fs` from the repo root, computed as `path.resolve(process.cwd(), '..')`: `process.cwd()` is the project root during `astro build` (verified in the loader, section 12), and Vercel's build (Root Directory `site`) runs there, which a queen check still has to confirm. Do not use `import.meta.url` in `sources.ts`; Astro bundles it into a build chunk, so the URL names the chunk, not `src/lib/`. The build fails, naming the resolved root, unless `README.md` and `go.mod` exist there. No text from the sources is copied into `site/`. No glob: nothing under `docs/rfc-notes/`, `docs/RFC-0003.md`, `.waggle/` or any path off the manifest is read, so a private file cannot reach the site by being added to `docs/` (section 5).
2. The build fails, naming the file, when a manifest source is missing, when either CONTRIBUTING heading the include needs (`## 4. Words in this repo's records`, `### Roles`) is missing, or when a source holds a `<<` placeholder marker (T-037 AC7; no source holds `<<` at `9b830bc`).
3. Each page's title is the source's first H1; the H1 is rendered once by the layout, not twice. `sources.ts` takes the H1 out of the text before `renderMarkdown`. Every cut on the text (the H1, the README pitch paragraph, the include's headings) skips fenced code, which holds `#` lines in some sources. Heading ids restart per piece; the README pieces do not collide at `9b830bc`.
4. Markdown options, all in `astro.config.mjs`: `output: 'static'`, `build: { format: 'directory' }`, `trailingSlash: 'always'`, `markdown: { syntaxHighlight: false }` (Shiki themes add hues the brand rules out, 2.5), and one inline integration, `integrations: [{ name, hooks: { 'astro:config:setup': ({ config }) => { const o = config.markdown.processor.options; o.features.gfm = true; o.features.smartPunctuation = false; o.mdastPlugins.push(rewriteLinks); } } }]`, with `rewriteLinks` imported from `./src/lib/links.ts`. Smart punctuation defaults to on and turns `--` into an en dash and `---` into an em dash, which would break `--dirs` in prose and the dash rule (both shown by a build with and without that line). Do not set `markdown.gfm` or `markdown.smartypants` (deprecated) or `markdown.remarkPlugins` or `rehypePlugins` (they throw). Heading ids follow GitHub's slug rule (`github-slugger`), so `docs/gate.md#10-limits-and-known-bypasses` and `docs/gate.md#3-the-claims-branch-check` (both linked from the sources) resolve the same on GitHub and on the site (section 12, Astro facts).
5. `site/src/lib/links.ts` exports `rewriteLinks`, a plain object that is a Satteri mdast plugin, with no import from any Satteri package: `{ name, link(node, ctx), definition(node, ctx), html(node), image(node) }`. It uses type annotations only (`astro.config.mjs` loads it directly) and takes the routes from `sources.ts`, so the manifest stays the one list. `link` and `definition` compute the new URL from `node.url` and the source path `fileURLToPath(ctx.fileURL)`, and when it differs call `ctx.setProperty(node, 'url', next)`; nodes are read-only in the types, so no direct assignment. A `link` node has the keys `type`, `children`, `url` and `title`. `html` and `image` throw, naming the file: no source holds raw HTML or an image at `9b830bc`, a raw tag would pass through unrewritten, and an image would render as a broken marker (the SPDX comment is gone before this runs, rule 6). A throw in a visitor fails the build (exit 1, section 12). Fragments are kept, not checked. ## 5. Threat model (D-203)

1. **Supply chain.** npm code runs at install and at build, and `--ignore-scripts` blocks install hooks only: `astro build` runs Astro, Vite, Rollup, esbuild and every transitive module. Mitigations: exact pins and a lockfile resolved with `--before` two weeks back (2.2 step 3); `npm ci --ignore-scripts` everywhere (the queen confirms the build needs no install script, section 12); one direct dependency under Q-T041-1 (a), with the markdown processor coming in through it and never imported (2.2); the three protected paths once the post-merge control commit lists them (Q-T041-5). **On the host,** every npm step runs in a throwaway container or VM that mounts only a copy of the branch (no home directory, no `~/.config`, no credential, no SSH agent, no Docker socket), with network on for `npm install` and `npm ci` and off (`--network none` or the VM equivalent) for `npm run build`; `dist/` is copied out and served from the host as static files, which run no npm code. A host without a container runtime is a card, not a bare run. **On Vercel,** the project holds no environment variable or secret, so a hostile package reaches no credential, but it can read the whole checkout and has egress; that residual is on the Q-T041-4 card.
2. **Publishing a private file.** The manifest is an allowlist (2.3 rule 1) and `check-dist.mjs` fails when `dist/` holds any file outside the expected set (section 7).
3. **Drift.** The site has no copy of the docs' text (AC4); a missing source, heading or link target fails the build. `check-dist.mjs` is a drift and accident check, not a security boundary, since a PR can edit it; the PR body says so.
4. **Injected markup.** The sources hold no raw HTML at `9b830bc` and `rewriteLinks` fails the build on any (2.3 rule 5), which is a drift check, since a PR can edit it; `script-src 'none'` is the backstop, and check-dist's resource-load rule catches an off-site load.
5. **The Vercel GitHub App** gets write access to deployments and statuses, so it is one more app that posts statuses (`docs/gate.md` limit L11 covers forged checks and how binding the check to GitHub Actions kept the status route blocked on a test rule); a deployment status is not a check run, so branch protection does not take it for the required check, though a reader may see it. It also comments preview URLs on every PR (protected under Q-T041-4 (a), but one more bot in a private repo). The Head Keeper installs it on this repository only (section 10).
6. **Weakening the header check (phase A).** A too-broad exempt pattern (for example `site/**` exempt) would silently drop the header check for builder files. Mitigations: the exempt row names four patterns only, all copied or fetched content; `TestWantRows` pins a checked result for one file of each builder kind; the guards diff the `rules` table against 2.8.
