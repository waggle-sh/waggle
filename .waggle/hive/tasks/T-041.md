4. ### 2.5 Brand and design rules (D-290; the studio's `brand.md` at the recorded commit)

- **Tokens.** `site.css` imports the copied `tokens.css` and uses only its variables; no hex, rgb or hsl literal anywhere in `site/src/` outside that file. Light by default, dark from the OS. No theme toggle (it needs JavaScript, 2.6).

- **Type.** Public Sans for everything but code; Martian Mono (`font-stretch: 87.5%`) for code, paths, SHAs and trailers only. H1 44 px at 1440 and 32 px at 375, weight 600, line 1.1; H2 28/600/1.2; H3 20/600/1.3; body 17/400/1.6 at max 68ch; small 14/400/1.45 muted; code 14 px in blocks, 0.9em inline. Sentence case. No all caps, letter-spaced eyebrows or mono labels above headings.
- **Fonts.** Two `@font-face` rules on the self-hosted files, `font-display: swap`, both preloaded (`<link rel="preload" as="font" type="font/woff2" crossorigin>`). No request to Google Fonts or any other host.
- **Layout.** Left-aligned, one column at 68ch, diagrams to 1120 px. 8 px grid. Square corners (`--wg-radius: 0`). Borders 1 or 1.5 px in `--wg-rule`. No shadows, gradients, glass, glow, icons, bee, wing, hexagon or stripe motifs, and no AI imagery.
- **Diagrams.** `Diagram.astro` inlines an SVG by raw import (no `<img>`, no `<object>`): the wide and the narrow file both inline, the wide shown at 768 px and up and the narrow below, by a CSS media query on `display` (the hidden one leaves the accessibility tree). Each SVG keeps its own `role="img"` and accessible name (a `<title>` and `<desc>` on the diagrams, `aria-label` on the lockup), and their ids are unique across files. ## 5. Threat model (D-203)

1. **Supply chain.** npm code runs at install and at build, and `--ignore-scripts` blocks install hooks only: `astro build` runs Astro, Vite, Rollup, esbuild and every transitive module. Mitigations: exact pins and a lockfile resolved with `--before` two weeks back (2.2 step 3); `npm ci --ignore-scripts` everywhere (the queen confirms the build needs no install script, section 12); one direct dependency under Q-T041-1 (a); the three protected paths once the post-merge control commit lists them (Q-T041-5). **On the host,** every npm step runs in a throwaway container or VM that mounts only a copy of the branch (no home directory, no `~/.config`, no credential, no SSH agent, no Docker socket), with network on for `npm install` and `npm ci` and off (`--network none` or the VM equivalent) for `npm run build`; `dist/` is copied out and served from the host as static files, which run no npm code. A host without a container runtime is a card, not a bare run. **On Vercel,** the project holds no environment variable or secret, so a hostile package reaches no credential, but it can read the whole checkout and has egress; that residual is on the Q-T041-4 card.
2. **Publishing a private file.** The manifest is an allowlist (2.3 rule 1) and `check-dist.mjs` fails when `dist/` holds any file outside the expected set (section 7).
3. **Drift.** The site has no copy of the docs' text (AC4); a missing source, heading or link target fails the build. `check-dist.mjs` is a drift and accident check, not a security boundary, since a PR can edit it; the PR body says so.
4. **Injected markup.** Raw HTML in the markdown sources is reviewed text under T-037's gate; `script-src 'none'` is the backstop, and check-dist's resource-load rule catches an off-site load.
5. **The Vercel GitHub App** gets write access to deployments and statuses, so it is one more app that could post a status named like the required check (T-037 limit L11); a deployment status is not a check run, so branch protection does not take it for the required check, though a reader may see it. 6. **Weakening the header check (phase A).** A too-broad exempt pattern (for example `site/**` exempt) would silently drop the header check for builder files. Mitigations: the exempt row names four patterns only, all copied or fetched content; `TestWantRows` pins a checked result for one file of each builder kind; the guards diff the `rules` table against 2.8.
