## 1. Goal

A stranger lands on the site and, without JavaScript, reads what Waggle Gate checks, what it does not, and how to install it, in the same words as the README and the gate spec, because the site is built from those files. Concretely:

1. A static site in `site/` with five product pages rendered from T-037's markdown, a home page with the gate hero diagram, and one secondary page on how Waggle builds Waggle, the only place bee roles appear (D-287).
2. The studio's Lease direction (D-290): tokens from `tokens.css`, self-hosted Public Sans and Martian Mono, inlined SVG diagrams with narrow cuts, color only for verdicts.
3. A build that fails when a source file, a link target or a required heading is missing, so the site cannot drift from the docs or quietly publish a file that was never meant to be public.
4. The Vercel setup pinned in `site/vercel.json` where Vercel allows it, and the rest written down as queen and Head Keeper follow-ups (section 10).

### 2.3 Reading T-037's markdown without forking it

`site/src/lib/sources.ts` holds one manifest, the only list of what the site publishes:

| Route | Source (repo root relative) |
| :--- | :--- |
| `/` | `README.md` |
| `/gate/` | `docs/gate.md` |
| `/recipes/` | `docs/recipes/README.md` |
| `/recipes/claude-code-agent-teams/` | `docs/recipes/claude-code-agent-teams.md` |
| `/recipes/copilot-cloud-agent/` | `docs/recipes/copilot-cloud-agent.md` |
| `/how-waggle-builds-waggle/` | the glossary section of `CONTRIBUTING.md` (D-280), found by its heading, under Q-T041-6 (a) |

Rules:

1. Files are read at build time with `node:fs` from the repo root, computed as `path.resolve(process.cwd(), '..')`: both `npm run build` on the host and Vercel's build (Root Directory `site`) run in `site/`. Do not use `import.meta.url` in `sources.ts`; Astro bundles it into a build chunk, so the URL names the chunk, not `src/lib/`. The build fails, naming the resolved root, unless `README.md` and `go.mod` exist there. No text from the sources is copied into `site/`. No glob: nothing under `docs/rfc-notes/`, `docs/RFC-0003.md`, `.waggle/` or any path off the manifest is read, so a private file cannot reach the site by being added to `docs/` (section 5).
2. The build fails, naming the file, when a manifest source is missing, when the CONTRIBUTING glossary heading is missing, or when a source holds a `<<G4` marker (T-037 AC7).
3. Each page's title is the source's first H1; the H1 is rendered once by the layout, not twice.
4. Markdown options: GitHub-flavored markdown on; `smartypants` off (it turns `--` into an en dash and `---` into an em dash, which would break `--dirs` in prose and the dash rule); syntax highlighting off (Shiki themes add hues the brand rules out, 2.5); heading ids by GitHub's slug rule, so `docs/gate.md#limits` resolves the same on GitHub and on the site (section 12, Astro facts).
5. `site/src/lib/links.ts`, a remark or rehype plugin. A relative link is resolved against its source file's directory, then: a link to a manifest file becomes its route, keeping the `#fragment`; a link to `CONTRIBUTING.md` becomes `/how-waggle-builds-waggle/#<fragment>` only when the fragment is a heading inside the glossary section, and otherwise the GitHub URL (the rest of CONTRIBUTING is contributor rules, not on the site); a link to any other path that exists in the build checkout (a path on disk from the repo root; Vercel gives no `.git` guarantee) becomes `https://github.com/waggle-sh/waggle/blob/main/<path>`; a link to a path that does not exist fails the build; absolute URLs pass unchanged. Fragments are kept, not checked. The README's install anchor is the target of the home page's "Add the gate to a repo" link, so a renamed heading fails the build there too.
6. The SPDX line 1 HTML comment of each source is dropped from the output.

### 2.5 Brand and design rules (D-290; the studio's `brand.md` at the recorded commit)

- **Tokens.** `site.css` imports the copied `tokens.css` and uses only its variables; no hex, rgb or hsl literal anywhere in `site/src/` outside that file. Light by default, dark from the OS. No theme toggle (it needs JavaScript, 2.6).
- **Color only for verdicts.** `site.css` never references `--wg-pass`, `--wg-block` or `--wg-wait`; verdict color reaches the page only inside the diagrams. Links are ink with an underline; a button is an ink fill with page-colored text; focus is a 2 px ink outline offset 2 px (`--wg-focus`).
- **Type.** Public Sans for everything but code; Martian Mono (`font-stretch: 87.5%`) for code, paths, SHAs and trailers only. H1 44 px at 1440 and 32 px at 375, weight 600, line 1.1; H2 28/600/1.2; H3 20/600/1.3; body 17/400/1.6 at max 68ch; small 14/400/1.45 muted; code 14 px in blocks, 0.9em inline. Sentence case. No all caps, letter-spaced eyebrows or mono labels above headings.
- **Fonts.** Two `@font-face` rules on the self-hosted files, `font-display: swap`, both preloaded (`<link rel="preload" as="font" type="font/woff2" crossorigin>`). No request to Google Fonts or any other host.
- **Layout.** Left-aligned, one column at 68ch, diagrams to 1120 px. 8 px grid. Square corners (`--wg-radius: 0`). Borders 1 or 1.5 px in `--wg-rule`. No shadows, gradients, glass, glow, icons, bee, wing, hexagon or stripe motifs, and no AI imagery.
- **Diagrams.** `Diagram.astro` inlines an SVG by raw import (no `<img>`, no `<object>`): the wide and the narrow file both inline, the wide shown at 768 px and up and the narrow below, by a CSS media query on `display` (the hidden one leaves the accessibility tree). Each SVG keeps its own `role="img"` and accessible name (a `<title>` and `<desc>` on the diagrams, `aria-label` on the lockup), and their ids are unique across files. CSS sets `width: 100%; height: auto` on the inlined `svg`. The SVG files are not edited.

### 2.6 Accessibility and JavaScript off

- The built pages ship no JavaScript: `dist/` holds no `<script>` element and no `.js` file, and `vercel.json` sets `Content-Security-Policy: default-src 'self'; script-src 'none'; style-src 'self' 'unsafe-inline'; img-src 'self'; font-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'` (inline styles stay because each inlined SVG carries a `<style>` and Astro inlines small stylesheets), plus `X-Content-Type-Options: nosniff` and `Referrer-Policy: strict-origin-when-cross-origin`. A local static server ignores `vercel.json`, so the headers get a `curl -sI` check on the first protected preview (section 10 item 8); Vercel's preview toolbar is blocked by `script-src 'none'`, as expected. Every page works with JavaScript off because none needs it. Search is out of scope (section 4).
- `<html lang="en">`, a skip link to `<main>`, landmarks (`header`, `nav`, `main`, `footer`), one H1 per page, heading levels in order (markdown sources are trusted for their own order).
- Contrast: the token pairs measured in `tokens.css` and `brand.md` (ink 17.3:1 and 16.3:1, muted 6.8:1 and 7.6:1, verdicts 4.9:1 or more) are the only text colors; `--wg-rule` is never text.
- Focus: every link and button shows the 2.5 focus ring under `:focus-visible`; nothing removes an outline without replacing it.
- Motion: no animation or transition anywhere (no `@keyframes`, `animation`, `transition` or `scroll-behavior: smooth` in `site/src/`), so reduced motion holds by construction; the check script enforces it.
- Color is never the only signal: the diagrams always print the verdict word.

### 2.7 Build, product-ci and the gate

- **The Go module.** `go build ./...` and `go vet ./...` descend into any directory without its own `go.mod`, including `node_modules/`, and some npm packages ship `.go` files (section 12): one with an import the module cannot resolve breaks `go build ./...` on any host that ran `npm ci`. The stub `site/go.mod` (two lines: a comment saying why, and `module waggle.invalid/site`, no `go` or `require` line) makes `site/` its own module, so `./...` skips it. `gofmt -l .` ignores module boundaries and still walks `site/node_modules/` on such a host; product-ci formats only tracked files (`ci.yml`, `git ls-files`) and dispatched worktrees have no `node_modules/`, so only a host run of WAGGLE.md's `gofmt -l .` can list a third-party file. Stated as a known limit in the PR body, not fixed here.
- **product-ci** (`.github/workflows/ci.yml`) runs no npm step and needs none; nothing changes there.
- **The gate.** Every commit names T-041 and stays in `site`; no hardcoded Tier 3 path is touched. This PR is Tier 3 by review rule and merges by admin bypass. After the post-merge control commit (Q-T041-5), `site/package.json`, `site/package-lock.json` and `site/vercel.json` are repo-listed protected paths, so every later change to them needs a listed approver at the head or an admin merge; with no `gate.approvers` set, an admin merge. From then on no lease can be `site`: later work leases a narrower directory such as `site/src` or `site/scripts`, and files at the `site/` root change only by a Head Keeper commit.
- **Vercel** builds outside GitHub Actions from `site/` with the commands `vercel.json` pins (2.2), so `check-dist.mjs` runs on every deploy and a failed check fails the deploy. Its GitHub deployment status is a status, never a required check. No workflow is added: a site build job in `.github/workflows/` would be a Head Keeper commit for little gain over Vercel's preview build.

## 3. Questions for the Head Keeper (ruled, D-310 to D-318)

- **Q-T041-1: framework.** (a) Astro, static output, no UI framework integration: pages are plain HTML at build time and ship no JavaScript unless a component asks for it; markdown, raw SVG imports and static output are built in, and Vercel serves `dist/` with no adapter. (b) Next.js 16 App Router with `output: 'export'`, the stack default: static HTML that reads with JavaScript off, but every page still loads the React and RSC runtime for no interactive feature, markdown needs remark and rehype wiring by hand, and the dependency tree is larger. (c) A docs framework (Starlight, VitePress, Docusaurus): fast to stand up, but their default look is the generic docs look the studio rules out, restyling fights the theme, and VitePress and Docusaurus hydrate as single-page apps. (d) No npm: a Go generator in this module, which needs a markdown library in `go.mod`, the module's first requirement and a Tier 3 input for the product itself. **Recommended: (a).** The site has no interactive feature, so a framework built for zero JavaScript fits it, keeps the CSP at `script-src 'none'`, and is one dependency to review. (b) is the fallback if one toolchain across l19 apps matters more than the runtime weight; the brief's structure holds, with `app/` routes in place of `src/pages/` and the finalize round rewriting 2.2 and the facts list.

## 5. Threat model (D-203)

1. **Supply chain.** npm code runs at install and at build, and `--ignore-scripts` blocks install hooks only: `astro build` runs Astro, Vite, Rollup, esbuild and every transitive module. Mitigations: exact pins and a lockfile resolved with `--before` two weeks back (2.2 step 3); `npm ci --ignore-scripts` everywhere (the queen confirms the build needs no install script, section 12); one direct dependency under Q-T041-1 (a); the three protected paths once the post-merge control commit lists them (Q-T041-5). **On the host,** every npm step runs in a throwaway container or VM that mounts only a copy of the branch (no home directory, no `~/.config`, no credential, no SSH agent, no Docker socket), with network on for `npm install` and `npm ci` and off (`--network none` or the VM equivalent) for `npm run build`; `dist/` is copied out and served from the host as static files, which run no npm code. A host without a container runtime is a card, not a bare run. **On Vercel,** the project holds no environment variable or secret, so a hostile package reaches no credential, but it can read the whole checkout and has egress; that residual is on the Q-T041-4 card.
2. **Publishing a private file.** The manifest is an allowlist (2.3 rule 1) and `check-dist.mjs` fails when `dist/` holds any file outside the expected set (section 7).
3. **Drift.** The site has no copy of the docs' text (AC4); a missing source, heading or link target fails the build. `check-dist.mjs` is a drift and accident check, not a security boundary, since a PR can edit it; the PR body says so.
4. **Injected markup.** Raw HTML in the markdown sources is reviewed text under T-037's gate; `script-src 'none'` is the backstop, and check-dist's resource-load rule catches an off-site load.
5. **The Vercel GitHub App** gets write access to deployments and statuses, so it is one more app that could post a status named like the required check (T-037 limit L11); a deployment status is not a check run, so branch protection does not take it for the required check, though a reader may see it. It also comments preview URLs on every PR (protected under Q-T041-4 (a), but one more bot in a private repo). The Head Keeper installs it on this repository only (section 10).
