## 1. Goal

A stranger lands on the site and, without JavaScript, reads what Waggle Gate checks, what it does not, and how to install it, in the same words as the README and the gate spec, because the site is built from those files. Concretely:

1. A static site in `site/` with five product pages rendered from T-037's markdown, a home page with the gate hero diagram, and one secondary page on how Waggle builds Waggle, the only place bee roles appear (D-287).
2. The studio's Lease direction (D-290): tokens from `tokens.css`, self-hosted Public Sans and Martian Mono, inlined SVG diagrams with narrow cuts, color only for verdicts.
3. A build that fails when a source file, a link target or a required heading is missing, so the site cannot drift from the docs or quietly publish a file that was never meant to be public.
4. The Vercel setup written down as queen and Head Keeper follow-ups (section 10).

### 2.3 Reading T-037's markdown without forking it

`site/src/lib/sources.ts` holds one manifest, the only list of what the site publishes:

| Route | Source (repo root relative) |
| :--- | :--- |
| `/` | `README.md` |
| `/gate/` | `docs/gate.md` |
| `/recipes/` | `docs/recipes/README.md` |
| `/recipes/claude-code-agent-teams/` | `docs/recipes/claude-code-agent-teams.md` |
| `/recipes/copilot-cloud-agent/` | `docs/recipes/copilot-cloud-agent.md` |
| `/how-waggle-builds-waggle/` | the glossary section of `CONTRIBUTING.md` (D-280), found by its heading, under Q-T041-6 (a) |

Rules:

1. Files are read at build time with `node:fs` from the repo root (`new URL('../../..', import.meta.url)` from `sources.ts`, or the config's root); no text from them is copied into `site/`. No glob: nothing under `docs/rfc-notes/`, `docs/RFC-0003.md`, `.waggle/` or any path off the manifest is read, so a private file cannot reach the site by being added to `docs/` (section 5).
2. The build fails, naming the file, when a manifest source is missing, when the CONTRIBUTING glossary heading is missing, or when a source holds a `<<G4` marker (T-037 AC7).
3. Each page's title is the source's first H1; the H1 is rendered once by the layout, not twice.
4. Markdown options: GitHub-flavored markdown on; `smartypants` off (it turns `--` into an en dash and `---` into an em dash, which would break `--dirs` in prose and the dash rule); syntax highlighting off (Shiki themes add hues the brand rules out, 2.5); heading ids by GitHub's slug rule, so `docs/gate.md#limits` resolves the same on GitHub and on the site (section 12, queen check).
5. `site/src/lib/links.ts`, a remark or rehype plugin: a relative link to a manifest file becomes its route, keeping the `#fragment`; a relative link to any other tracked file becomes `https://github.com/waggle-sh/waggle/blob/main/<path>`; a relative link to a path that does not exist fails the build; absolute URLs pass unchanged. The README's install anchor is the target of the home page's "Add the gate to a repo" link, so a renamed heading fails the build there too.
6. The SPDX line 1 HTML comment of each source is dropped from the output.

### 2.5 Brand and design rules (D-290; the studio's `brand.md` at the recorded commit)

- **Tokens.** `site.css` imports the copied `tokens.css` and uses only its variables; no hex, rgb or hsl literal anywhere in `site/src/` outside that file. Light by default, dark from the OS. No theme toggle (it needs JavaScript, 2.6).
- **Color only for verdicts.** `site.css` never references `--wg-pass`, `--wg-block` or `--wg-wait`; verdict color reaches the page only inside the diagrams. Links are ink with an underline; a button is an ink fill with page-colored text; focus is a 2 px ink outline offset 2 px (`--wg-focus`).
- **Type.** Public Sans for everything but code; Martian Mono (`font-stretch: 87.5%`) for code, paths, SHAs and trailers only. H1 44 px at 1440 and 32 px at 375, weight 600, line 1.1; H2 28/600/1.2; H3 20/600/1.3; body 17/400/1.6 at max 68ch; small 14/400/1.45 muted; code 14 px in blocks, 0.9em inline. Sentence case. No all caps, letter-spaced eyebrows or mono labels above headings.
- **Fonts.** Two `@font-face` rules on the self-hosted files, `font-display: swap`, both preloaded (`<link rel="preload" as="font" type="font/woff2" crossorigin>`). No request to Google Fonts or any other host.
- **Layout.** Left-aligned, one column at 68ch, diagrams to 1120 px. 8 px grid. Square corners (`--wg-radius: 0`). Borders 1 or 1.5 px in `--wg-rule`. No shadows, gradients, glass, glow, icons, bee, wing, hexagon or stripe motifs, and no AI imagery.
- **Diagrams.** `Diagram.astro` inlines an SVG by raw import (no `<img>`, no `<object>`): the wide and the narrow file both inline, the wide shown at 768 px and up and the narrow below, by a CSS media query on `display` (the hidden one leaves the accessibility tree). Each SVG's own `role="img"`, `<title>` and `<desc>` stay, and their ids are unique across files. CSS sets `width: 100%; height: auto` on the inlined `svg`. The SVG files are not edited.

### 2.6 Accessibility and JavaScript off

- The built pages ship no JavaScript: `dist/` holds no `<script>` element and no `.js` file, and `vercel.json` sets `Content-Security-Policy: default-src 'self'; script-src 'none'; style-src 'self' 'unsafe-inline'; img-src 'self'; font-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'` (inline styles stay because each inlined SVG carries a `<style>`), plus `X-Content-Type-Options: nosniff` and `Referrer-Policy: strict-origin-when-cross-origin`. Every page works with JavaScript off because none needs it. Search is out of scope (section 4).
- `<html lang="en">`, a skip link to `<main>`, landmarks (`header`, `nav`, `main`, `footer`), one H1 per page, heading levels in order (markdown sources are trusted for their own order).
- Contrast: the token pairs measured in `tokens.css` and `brand.md` (ink 17.3:1 and 16.3:1, muted 6.8:1 and 7.6:1, verdicts 4.9:1 or more) are the only text colors; `--wg-rule` is never text.
- Focus: every link and button shows the 2.5 focus ring under `:focus-visible`; nothing removes an outline without replacing it.
- Motion: no animation or transition anywhere (no `@keyframes`, `animation`, `transition` or `scroll-behavior: smooth` in `site/src/`), so reduced motion holds by construction; the check script enforces it.
- Color is never the only signal: the diagrams always print the verdict word.

### 2.7 Build, product-ci and the gate

- **The Go module.** `go build ./...` and `go vet ./...` descend into any directory without its own `go.mod`, including `node_modules/`, and some npm packages ship `.go` files (section 12): one with an import the module cannot resolve breaks `go build ./...` on any host that ran `npm ci`. The stub `site/go.mod` (two lines: a comment saying why, and `module waggle.invalid/site`, no `go` or `require` line) makes `site/` its own module, so `./...` skips it. `gofmt -l .` ignores module boundaries and still walks `site/node_modules/` on such a host; product-ci formats only tracked files (`ci.yml`, `git ls-files`) and dispatched worktrees have no `node_modules/`, so only a host run of WAGGLE.md's `gofmt -l .` can list a third-party file. Stated as a known limit in the PR body, not fixed here.
- **product-ci** (`.github/workflows/ci.yml`) runs no npm step and needs none; nothing changes there.
- **The gate.** Every commit names T-041 and stays in `site`; no hardcoded Tier 3 path is touched. WAGGLE.md section 2 gains `site/` before dispatch (precondition 1). Under Q-T041-5 (a), after merge, `site/package.json` and `site/package-lock.json` join `gate.protected_paths` (a Head Keeper control change), so a later dependency change needs a listed approver or an admin merge.
- **Vercel** builds outside GitHub Actions from `site/`, with `npm ci --ignore-scripts` then `npm run build`, so `check-dist.mjs` runs on every deploy and a failed check fails the deploy. Its GitHub deployment status is never a required check. No workflow is added: a site build job in `.github/workflows/` would be a Head Keeper commit for little gain over Vercel's preview build.
- **WAGGLE.md section 3 stays Go only.** Adding `npm` there would let every worker in this hive run it.

## 5. Threat model (D-203)

1. **Supply chain.** npm code runs at install and build on the host and on Vercel. Mitigations: exact pins and a lockfile; `npm ci --ignore-scripts` everywhere (the queen confirms the build needs no install script, section 12); one direct dependency under Q-T041-1 (a); Q-T041-5 (a) for later changes; and the Vercel project holds no environment variable or secret, so a hostile package can deface the site but reaches no credential.
2. **Publishing a private file.** The manifest is an allowlist (2.3 rule 1) and `check-dist.mjs` fails when `dist/` holds a page not in the expected set (manifest routes, the hive page, 404).
3. **Drift.** The site has no copy of the docs' text (AC4); a missing source, heading or link target fails the build.
4. **Injected markup.** Raw HTML in the markdown sources is reviewed text under T-037's gate; `script-src 'none'` is the backstop.
5. **The Vercel GitHub App** gets write access to deployments and statuses, so it is one more app that could post a status named like the required check (T-037 limit L11). The Head Keeper installs it on this repository only (section 10).
