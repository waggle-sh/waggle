## 1. Goal

Bring RFC-0003 in line with the Keeper decisions recorded in T-002 section 4 (D-001, D-002, D-003), so that no agent reading the RFC as steering context is told that claims are "JSON blobs". Record four things (scope widened by D-012):

1. Claim storage is a commit-wrapped `lease.json`, not a bare JSON blob.
2. Ticket ID canonicalization (display `T-%03d`, ref `ticket-<n>` unpadded).
3. Tier 3 paths are rejected at claim time, not only at merge time.
4. The remaining T-002 claim-time validation rules, plus `docs/tasks/**` in the section 3.3 Tier 2 minimum list.

This is a wording change to a frozen document. It changes no code and no behavior.

## 2. Where the amendment lives (decision and reason)

**Decision:** amend `docs/RFC-0003.md` in place and append an amendment log. Do **not** create anything under `docs/specs/` in this task.

**Why:**
- RFC-0003 is the single normative source for v0.1. A second copy under `docs/specs/` (for example `docs/specs/comb-claims.md`) would create two documents agents can read as authoritative, and they would drift. That is exactly the steering-context risk RFC section 3.3 warns about.
- An in-place edit keeps the normative text correct where agents already read it. The amendment log keeps the frozen history auditable: a reader can see what changed, when, and who approved it.
- `docs/specs/**` is better used later for new detailed specs (for example a full Comb wire-format spec for the relay mode), which this amendment can point to once they exist.

**Gap this exposes (resolved, D-011):** `docs/RFC-0003.md` is **not** covered by `HardcodedTier2MinPrefixes` or the `waggle-gate.yml` Tier 2 case, so today the binary and CI classify an edit to it as Tier 0. This brief classifies T-003 as Tier 2 / Full by policy. Per D-011, a later task moves RFCs into `docs/specs/`, which inherits the existing Tier 2 floor. That move is not part of T-003.

### 3.2 Section 3.1, "Unified Ref Storage" bullet (replace)

Replace the current first bullet of section 3.1 with wording equivalent to the following. Exact phrasing is the author's call; every fact below must be present.

- All task claims and leases live behind `CombBackend` as one Git ref per ticket: `refs/waggle/claims/ticket-<n>`.
- The ref points to a **commit**. The commit's tree holds exactly one entry, `lease.json` (mode `100644`), the JSON-encoded lease.
- A first claim is a root commit (no parent).
- A **renewal** (the same Keeper re-acquiring its own active claim) and a **takeover** (any Keeper acquiring an expired claim) write a **child commit whose single parent is the previous claim commit**. While the ref exists, `git log refs/waggle/claims/ticket-<n>` is the claim's audit chain.
- **Release deletes the ref.** After release the chain is no longer reachable from any ref and may be garbage collected; claim history is not durable past release in v0.1. (Durable audit of Controller force-release is specified separately in T-005; do not describe T-005 mechanics here unless T-005 has merged.)
- Writes are atomic Compare-And-Swap on the ref: local mode uses `git update-ref <ref> <new> <old>` against the exact OID read; distributed mode fetches the claim namespace from the configured remote and pushes with `--atomic --force-with-lease`. The remote is authoritative; local claim refs are a mirror.
- Keep the existing sentence about solo local mode versus distributed mode (`origin`).

Mark the bullet `(Amended: A1)` at its end so readers know to check Appendix A.

### 3.3 Section 3.1, new "Ticket ID Canonicalization" bullet

Add after the storage bullet:

- Accepted ticket ID input: `T-<digits>` or `<digits>`, matching `^(T-)?[0-9]{1,6}$`, value `>= 1`, uppercase `T-` only. Anything else is rejected before any Git call (this also blocks ref-name injection).
- **Canonical display form:** `T-%03d` (`1`, `001`, `T-1`, `T-001` all display as `T-001`; `T-1234` stays `T-1234`). This matches `docs/tasks/T-<id>.md` and the `T-<id>:` commit prefix used by `waggle-gate.yml`. The lease's `ticket_id` field always stores the display form.
- **Canonical ref form:** `ticket-<n>` with the decimal integer and **no zero padding** (`T-001` is `refs/waggle/claims/ticket-1`). Leading zeros can therefore never produce two refs for one ticket.
- A ref under `refs/waggle/claims/` whose suffix is not canonical `ticket-<n>` (for example `ticket-007`) is **malformed**: it is reported, never parsed or silently honored.

Also update the one other place where the placeholder appears so the RFC is consistent: in sections 2.1, 3.1 (TOCTOU bullet), 3.2, and 4 item 2, `ticket-<id>` may stay as written, but add one sentence in the new bullet stating that `<id>` in `ticket-<id>` throughout this RFC means the unpadded integer `<n>`. Do not rewrite those other sections.

### 3.4 Section 3.1, new "Claim-Time Tier 3 Rejection" bullet

Add after the TOCTOU bullet (the TOCTOU invariant itself stays unchanged):

- `CombBackend` refuses, at claim time and before any Git write, a lease where any directory **equals**, **is contained by**, or **contains** a hardcoded Tier 3 path from section 3.3. Examples: `.github` contains `.github/workflows/`; the repository root (`.`, `./`, or anything that cleans to the root) contains `WAGGLE.md` and `.gitlab-ci.yml`.
- Tier 3 membership is compared **case-insensitively** at claim time, because macOS and Windows checkouts are case-insensitive (`.WAGGLE/` and `waggle.md` are rejected).
- This is a defense-in-depth check. It does **not** replace merge-time enforcement: `waggle-gate.yml` remains authoritative, and Tier 3 changes still require Master Keeper approval under section 3.3.

### 3.5 Section 3.1, new "Other Claim-Time Validation (v0.1)" bullet (required, D-012)
