## Checks

1. **Digest design (item 1).** `hostDigest` hashes `fileState(record)` then `key\x00value\x00` for the sorted keys of `cur`. Over the real domain the encoding is injective: the record state is one of 64 hex characters, `absent` or `other`; keys are common-dir-relative paths and the fixed roles, which cannot contain NUL; values are hex or the fixed state words. So two different states cannot produce the same input bytes. 64 bits is enough for its purpose: the digest guards the Keeper's card against change between the listing and `--accept` (D-198, 10.8.1), not against a writer of the record, and an accidental collision is 2^-64; forcing a second preimage costs 2^64 and needs host write access, which is the D-203 note class. `--accept` takes `dispatch.lock` in `lockRepo` before reading the record and computing `cur`, compares, and writes `cur` itself (never a fresh hash) under the same lock, with `release` deferred; `Run` takes the same `dispatch.lock` before `Provision`, so an accept and a dispatch cannot interleave. Probed (`fable-probes.txt` P6): a key only the record has prints `recorded abc current missing`; a one-byte whitespace edit of the record after the listing is exit 3 with nothing written; accept writes `run: accepted`; a second accept with the same digest prints `host record matches`; `checkHostRecord` passes after the accept (D2b-T3). The listing of a readable differing record, an unreadable one (bad JSON, oversize, symlink) and the absent one match item 1's text (D2b-T2 in the suite plus P6). A symlinked record is replaced by `writeFile`'s rename and its target keeps its bytes (suite).

2. **`clean` paths through `cleaner.role` (item 3).** Enumerated from the code and probed on this Mac (APFS, case-insensitive, git 2.54):
   - Nothing at all for the role (no entry, directory, lock, tainted or takeover file): early return, nothing printed; `Clean` prints `nothing to clean for <ticket>` when every role did that and `--runs` removed nothing. Exit 0.
   - A bad admin entry anywhere under `worktrees/` (unreadable gitdir, symlinked entry, two entries naming the path): exit 3 from `entryFor`, nothing removed, markers kept.
   - A live `<wt>.lock`: exit 3 from `takeLock`, nothing removed.
   - Directory present and a symlink or a file: exit 3, nothing removed, markers kept.
   - Directory present and registered: `worktree remove --force`, then the tainted line, then markers removed. Exit 0. Probed with a trailing slash on `--repo` (P2), a symlinked repo path (P3) and `worktree.useRelativePaths=true` (P4, gitdir line `../../../.waggle/worktrees/T-023-builder/.git`): all three removed the tree and markers.
   - Directory present and registered but `worktree remove` fails (locked entry, submodules, git error): exit 3 `cleaning <rel>`, markers kept, because `lerr` is checked before `!listed`.
   - Directory present and not listed (a plain directory, or a mis-cased `--repo`): exit 3 `<rel> is not a registered worktree of this repo; nothing was removed`, directory and `.tainted` kept. Probed on APFS with `REPO` for `repo` (P1): exit 3, both kept. Fix removal confirms the suite catches its absence.

   - Directory gone and no entry: `no worktree entry for <rel>`, markers removed. Exit 0.
   I found no ordinary state where clean strips `.tainted` from a tree it keeps: every branch that keeps the directory returns before the marker loop. The one marker drop while an entry survives is a mis-cased `--repo` with the directory already gone (the marker is the same file on APFS, the entry's spelling does not match): the directory the marker guards is gone, so D2b-AC3 holds, and the next correctly-spelled provision refuses on git's own check and names clean. 4. **Pinned `worktree add` (item 4b).** All four forms (`--detach`, existing local branch, `--no-track -b` from the remote-tracking ref, `-b` from the base) run through `pg := g.pinned()`, and `Run` passes `Provision` the unpinned `g`, so the pin is real in production. `pinnedEnv` drops the Keeper's `GIT_CONFIG_*` variables and points global and system config and system attributes at nothing; `-c core.hooksPath=/dev/null` stays. A global `filter.<x>.smudge` therefore cannot be resolved during the checkout of a builder-written `.gitattributes`, whatever `.lfsconfig` says; the canary test proves it for all four forms, and my fix removal of the `-b` form's pin makes `new_branch` fail. 5. **SIGHUP (item 4a).** `stopSignals` is the only change; `signal.NotifyContext` cancels the same context SIGINT and SIGTERM cancel, so SIGHUP takes the existing stop path (`EndInterrupted`, `interrupted`, exit 1) with the sweep and checks it already runs. Read only; no signal sent. Two behavior edges, neither covered by a test and neither new in kind: writes of stop-path events to a hung-up pty fail with EIO and are ignored, while a dead pipe reader raises SIGPIPE on fd 1 and ends dispatch mid-stop, the same as SIGINT today; and Go installs the handler even when SIGHUP was inherited ignored (`nohup`), so `nohup waggle dispatch` now stops on a hangup instead of running on (note N5). `syscall.SIGHUP` exists on windows, solaris and illumos: vet passes for all three.

## Notes

- **N1 (digest encoding, no action).** The record-state prefix is neither length-prefixed nor terminated. It is unambiguous today only because `fileState` returns a fixed vocabulary and no key or value can hold NUL. If a later phase adds a free-form term, add a NUL after the state.
- **N2 (mis-cased `--repo`, 1 line if wanted).** The unregistered refusal could add `use the --repo spelling the dispatch used` so a Keeper on APFS does not read "not a registered worktree" as a lost entry. With the directory gone, a mis-cased clean drops the marker but leaves the entry; the next provision's git refusal and hint recover it.
- **N3 (hint wording).** The clean hint is appended to every `worktree add` failure on an absent path, including `already used by worktree at <other>` where clean has nothing to do. The conditional "if a stale entry ... remains" keeps it honest, and git's text names the real cause. A 2-line check that the failure text contains "registered" or "locked" would narrow it; not needed for D2b.
- **N4 (reuse path still unpinned, phase E candidate).** `checkReusable` runs `worktree list` and `checkClean` runs `git status` through the unpinned `g` on a reused builder worktree (a must-fix round). `git status` runs `filter.<x>.clean` from the Keeper's global config on a stat-dirty file, and a branch `.gitattributes` is builder-written. The effect is bounded (the filter output is compared, then the tree is refused as dirty) and the brief leased 4b to the four `worktree add` calls only, so this is a note: pin `checkClean`'s `status` (one `g.pinned()`), 1 line.
- **N5 (SIGHUP under nohup).** `signal.Notify` installs a handler even if SIGHUP was ignored at start, so `nohup waggle dispatch` now stops on hangup. That is consistent with opus N3's intent (the worker leads its own session and would otherwise run on unobserved). If the phase F queen template ever runs dispatch under nohup, gate the entry with `signal.Ignored(syscall.SIGHUP)`, 3 lines.
- **N6 (headroom).** 184 of 190 target: any fix round crosses the target. D-206's cut applies "past 190 before review", so a small post-review round stays under the 240 stop without moving 4a and 4b; the queen should record which reading applies if a round is needed.
- **N7 (lock takeover output).** `lockRepo` prints `warning: took over stale run lock` for `dispatch.lock` before any listing line, including before `host record matches`. Fine for a human; a phase F template that parses `--host-record` output should match on the digest line, as `listedDigest` does.
- **N8 (P5 messages).** Provision's exit 3 text embeds git's absolute worktree path. It goes to the Keeper's stderr, never to a worker or a review, and predates D2b.
