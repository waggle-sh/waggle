## Blocking Issues

B1. **`--gate` is "copied from the brief's Lease line", which carries no gate.** Rule 1: "with `--dir` and `--gate` copied from the brief's Lease line". No brief in this hive puts the gate on the Lease line: all 24 briefs with a `**Lease` line carry the gate on a separate `- **Gate:**` line (`grep -h '^- \*\*Gate' .waggle/hive/tasks/*.md`), and the scaffold's `scout.md` defines no Lease line format at all. Dispatch does not cross-check `--gate` against the brief (`Request.Validate` only requires `light` or `full`), so the queen's reading is the only source of the gate. A queen that follows the line literally finds no gate there and has to guess, and a `light` guess on a `full` task lowers a gate, which the D-203 threat bar and the queen's own "Never ... lower a verification gate" forbid. Fix: "with one `--dir` per leased directory from the brief's Lease line and `--gate` from its Gate line; if either is missing or unclear, ask the Keeper".

B2. **The review filename drops the branch suffix and overwrites earlier rounds, so the D-177 must-fix count misses them.** Rule 3: "commit the run's `review.md` unchanged as `.waggle/hive/reviews/T-<nnn>-<model>.md`". `roundMustFix` (`internal/dispatch/inputs.go:126`) counts `Verdict: must-fix` lines only in files whose name starts `T-<nnn><suffix>-`, where `<suffix>` is the branch's part after `t-<nnn>` (D-177: "every `reviews/T-<nnn><suffix>-*.md` at base, where `<suffix>` is the branch suffix"). For any suffixed branch (`--branch t-023f`, which the template's own guard line passes and this hive uses for every phase), a file named `T-023-opus.md` is never counted, so the T-012 builder step-up (`policy.go:177`, two must-fix rounds) never fires. For an unsuffixed branch it counts, but a second round by the same model writes the same path, and "commit ... unchanged" replaces the first round's file, dropping its must-fix line; `CountMustFix`'s doc comment assumes earlier verdict lines are never rewritten. This contradicts a Keeper ruling (D-177). Fix: "as `.waggle/hive/reviews/T-<nnn><suffix>-<model>.md`, where `<suffix>` is what follows `t-<nnn>` in the branch name and `<model>` is `result.json`'s `model`; if that file exists, append the new review below the old one instead of replacing it".

## Notes

N1. **A worker can forge a `pushed:` line on stdout.** `note: survivors_killed: ...` prints `%v` of `[]Survivor`, whose `Command` is the raw process `comm` (`reap_unix.go:153`), up to 15 bytes on linux and 16 on macOS, unsanitized. A worker tool that leaves a background process named `\npushed: x` puts a line starting `pushed:` on stdout of a clean (exit 0) run. With no `forge.remote` or with `--no-push`, rule 3 then sends the queen to open a draft PR for a branch dispatch never pushed. Impact is low (the commits passed every check, and `gh` fails on an unpushed head), so a note. Fix in the template: key on `result.json`'s `pushed: true` instead of the stdout line; a phase E carry could also pass survivor commands through `printable`.

N2. **The stale lock warning text is a prefix.** The line is `warning: took over stale run lock of dead pid <n>` (`worktree.go:514`, `clean.go:82`). "A line starting `warning: took over stale run lock`" would be exact.

N3. **"The last line of the exact form `digest ...`" reads two ways.** The listing's last line is the suggested `waggle dispatch clean --host-record --accept <digest>` command, not the digest line. The intended reading (the last line that has that form) is safe, per check 5. "The `digest <16 lowercase hex>` line" says the same thing without the ambiguity.

N4. **Rule 3's guard step does not require exit 0.** `review.md` is written for every guard run, including `no_verdict` (exit 5), a timed-out run and a guard that changed files (exit 1). As written, the queen could commit that review before rule 2's "bring every nonzero exit to the Keeper". "After a guard run that exited 0" closes it.

N5. **`--dir <path>...` and bad flags.** `--dir` is a repeatable flag; `--dir a b` makes `b` a positional argument and exits 2 (fails closed). B1's fix wording covers it. A mistyped flag exits 2 with the `flag` package's message and no `waggle dispatch:` prefix, so rule 2's "the `waggle dispatch:` line on stderr says why" does not hold for that case; harmless because rule 2 sends every nonzero exit to the Keeper.

N6. **Rule 7's parenthetical is unverified.** "(it still checks and records the run)" holds for SIGHUP, SIGTERM and SIGINT. It does not hold for SIGKILL, nor if a dead stdout pipe raises SIGPIPE mid-stop (fable D2b N5), which ends dispatch before the checks and leaves `dispatch.lock` and the worktree. D-213 keeps the wording and has the trial record what happens; the trial should also record whether `dispatch.lock` and the worktree remain afterwards.

N7. **Escalation rule 4's "starts".** The printed line is `waggle upgrade refused: model policy for claude-code shims: refused: ...` (`cmd/waggle/upgrade.go:62`, `internal/scaffold/upgrade.go:530`), and `init` prints `loading the model policy for claude-code shims:`. "Contains" would be literal. D-212 removes the sentence in a later follow-up, so not worth a round on its own.

N8. **Host-record trigger is narrower than the code.** An unreadable `host-files.json` is also exit 3 and also names `waggle dispatch clean --host-record` (`prerun.go:125`); its listing prints `host record unreadable:` plus every key and a digest. Rule 5 says "because host files changed", so that case falls to rule 2 (Keeper) instead, which is safe. A listing that prints `host record matches` or `no host record` has no digest; the template is silent and rule 2 again applies.

N9. **Committed reviews feed `CountMustFix` as is.** It counts every line exactly `Verdict: must-fix`, so a guard can repeat the line and lift the count; committing `review.md` unchanged keeps that. Effect is at most a one-level builder step-up (a spend increase, never a lowered guard), and it predates this template (D-177 design). Note only.
