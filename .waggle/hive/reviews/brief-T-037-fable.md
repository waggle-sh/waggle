## Blocking issues (must-fix)

**M1. The limits list in 3.2 omits the gate's largest known bypass: a commit's ticket is author-chosen, so an agent can ride any other ticket's live claim.** `classify` (`cmd/waggle/gate_commits.go:259-308`) binds a commit to whatever ticket its subject, trailer or branch names, and `claimFor` (`:313-334`) reads that ticket's claim with no check that the ticket relates to the PR, its author, or the task the agent was given. An agent assigned T-1 (lease `a/`) that writes `T-2: ...` subjects while T-2 holds a live claim on `b/` passes the lease check for `b/`. The `Waggle-Ticket` PR-body trailer check only warns, and the body is author text too (D-263 rationale). The repositioning pitch the README must carry ("know that each PR touched only what its task was given", note section 2) is true only when the reader also checks that the bound ticket is the assigned one, or runs one live claim at a time. The 3.2 limits list names eleven bypasses (required check, who can push claim refs, expired claims, edited workflow, admin bypass, trailers, approver token, renamed login, off Actions, forks, no push access) and not this one; AC9 then requires the spec to state "every 3.2 limit", so the spec as briefed would omit it, and the brief's own threat model (section 7) makes "a 3.2 limit or bypass left out of `docs/gate.md`" a must-fix for the build. Fix: add the limit to 3.2 with the mitigation (reviewers check the bound ticket against the assignment; the PR-body trailer warning surfaces a mismatch; keep one live claim per agent where possible), and have the README's "What it does not do" name it (AC9 list).

**M2. The 3.2 limits list states a false fact about forks: "fork PRs cannot read claim refs they cannot push".** The gate runs in the base repository's Actions and the template fetches `refs/waggle/claims/*` from `origin`, the base repository (`internal/scaffold/templates/waggle-gate.yml.tmpl`, step "Fetch Comb Claim Refs"; T-036 2.2 step 3 does the same in the Action). A fork PR's gate run therefore reads the base repository's claims normally; what a fork contributor cannot do is write one. The second half of the sentence ("contributors without push access cannot write claims") is the true limit, and D-232's rationale states it that way. As written the sentence would land in the spec as an enforcement limit that the code does not have. Fix: replace with "contributors without push access to the base repository, fork PRs included, cannot write claims; a maintainer or the orchestrator writes the claim for them, and the gate reads the base repository's claim refs for every PR".
