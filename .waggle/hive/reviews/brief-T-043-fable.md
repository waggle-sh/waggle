### Must-fix

1. **Section 2.5 and AC5 (T-043.md:85, :207): the darwin decoder as specified cannot read `vm.loadavg` on a real Mac.** The brief says `syscall.Sysctl("vm.loadavg")` is "decoded as `struct loadavg`" and AC5 says the decoder "reads a fixed 24-byte `struct loadavg`". Go's `syscall.Sysctl` returns a string and strips one trailing NUL byte (GOROOT `src/syscall/syscall_bsd.go:434-460`, "Throw away terminating NUL"). `struct loadavg` on darwin is three `uint32` plus padding plus `fscale` as a `long` (24 bytes); `fscale` is 2048, so the buffer's last byte is always 0 and the call always returns 23 bytes. A decoder that requires 24 bytes fails on every Mac. The standard library has no `SysctlRaw` (only `Sysctl` and `SysctlUint32` in `syscall_bsd.go`), `go.mod` has no dependencies and a new one is a must-fix per section 5, so the builder must do what `internal/dispatch/reap_darwin.go:35` already does ("Sysctl drops one trailing NUL byte") and pad back. The brief cites `reap_darwin.go:31` only for "no new dependency" and `internal/dispatch/` is not in phase A's read-only context list. Because the darwin test is fixed-bytes only and product-ci is linux (section 11), nothing before merge catches this; the queen's post-merge `bin/waggle doctor` run would be the first failure. Fix: state in 2.5 that `syscall.Sysctl` drops a trailing NUL, require the decoder to accept 23 or 24 bytes by padding to 24 (as `reap_darwin.go:35` does), and make AC5 feed both a 24-byte and a 23-byte fixture.
