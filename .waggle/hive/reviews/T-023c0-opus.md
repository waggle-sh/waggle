## Rulings on the builder's interpretations

The allowlist itself still runs in `Prepare` against the live slice, so a `DefaultArgs` edit after `Verify` still cannot introduce any flag beyond the two. ## Notes

- **N1 (fix in phase C, or as a small follow-up commit before merge if the Keeper prefers).** The `pushBlocked` comment says the prefixes are "every URL scheme and path form a push could use". The probe shows that is false: `git+ssh://`, `ssh+git://`, scp-like forms with a user other than `git` or an ssh alias, mixed-case schemes, `<transport>::<address>` and a `GIT_CONFIG_COUNT=0` env prefix all get past it, and HOME is kept, so `~/.ssh` keys and any credential helper in the user or system git config are reachable. The brief only required the five prefixes and the three named bypasses, and the worker reaches `git push` only by getting around the D-110 Bash rules (for example `go test -exec`, already in phase C's `not_enforced`). So this is no spec violation, and C0 narrows the gap; it widens nothing. Suggested change, about 3 lines: add `git+ssh://` and `ssh+git://` to `pushBlocked`, and rewrite the comment to say the tripwire is best effort and list the other forms. Phase C's `not_enforced` text should say the same. Real enforcement is the Cell's blocked egress and zero credentials.
- **N2 (phase C).** A renamed allowed flag surfaces as `ErrUnverified` from `Verify`, not `ErrRefusedArg` from `Prepare` as 10.5.1 words it. Phase C must map both to the same exit code. It should also build the adapter from a slice it does not keep (`slices.Clone`), so the `DefaultArgs` edit-after-`Verify` window cannot arise in practice.
- **N3 (low).** The help check is a substring match, as `helpTokens` already is. `--debug` is a substring of `--debug-file`, so a release that drops `--debug` but keeps `--debug-file` would pass `Verify`. Matching the token followed by a space, comma or line end would close it; not worth a fix round now.
- **N4 (low).** Duplicate allowed entries are accepted. They are harmless (the last budget wins in commander, and a repeated `--debug` does nothing), and 10.5.1 does not list them as a refusal class. If the Keeper wants one budget value without ambiguity, refusing a repeat costs two lines.
- **N5 (phase C).** A run that hits `--max-budget-usd` ends with result subtype `error_max_budget_usd`, which `Collect` maps to `EndError`. That fails closed, but phase C's `result.json` should name it (an `EndMaxBudget` or the raw subtype) so the queen can tell a budget stop from a crash.
- **N6 (low).** `--debug` writes Claude Code debug logs that can hold prompt and tool content, into the Keeper's home unless `--debug-file` is used, and `--no-session-persistence` does not cover them. That is acceptable for an opt-in flag; phase C docs should mention it.
- **N7 (test gap, low).** The tests cover `http://`, `git://`, absolute and `../` as the brief asks. `file://`, `ssh://` and `git@` stay unexercised by a push (the env test asserts their presence only). The ssh forms would need a `GIT_SSH_COMMAND` stub to prove no ssh attempt; worth adding when N1 lands.
