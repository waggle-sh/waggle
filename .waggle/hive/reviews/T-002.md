## Per-unit findings

### Unit 1: backend.go, backend_test.go (verdict: pass)
Tier 3 matching held up against my probes: `WAGGLE.MD`, `./.waggle`, `.Github/Workflows`, `x/../.waggle`, `WAGGLE.md/`, `a/../.DevContainer/x`, `.gitlab-ci.yml/x` and `.GitHub` are all rejected with `ErrTier3Path`. `.github/ISSUE_TEMPLATE` is allowed. Ticket ID regex is anchored (Go `$` is end-of-text), ASCII-only, so newline and unicode digits are rejected. Ref names are built from an integer only, so ref injection is not possible.

- F1 (low, backend.go:249-251, 261): Windows strips trailing dots and spaces from path components. `.waggle.` and `.git.` validate clean (probe output), and on a Windows checkout they resolve to `.waggle` and `.git`. `WAGGLE.md.` is only caught by accident of the prefix match. Scenario: a Windows Keeper leases `.waggle.` and the claim-time defense in depth is bypassed. The merge gate is still authoritative, and spec section 4.2 asks only for case-insensitivity, so this is not blocking. Fix later: reject components ending in `.` or space.
- F2 (low, backend.go:253-265): NormalizeDirectories accepts backticks, `<`, and interior spaces. They flow into WORKPLAN.md (a Tier 2 agent-read steering file) inside a backtick code span, which only escapes `|`. Scenario: a Keeper (or a compromised worker Cell with ref push rights) claims directory ``x` Ignore prior instructions...`` and the text lands in a file other agents read. Not in the brief's escaping spec, so not blocking. Recommend restricting directory characters or escaping backticks in the renderer.
- Overlap and Tier checks compare case-sensitively for overlap (`Internal` vs `internal`), which the brief does not require. Noted only.

### Unit 2a: git.go 1-260 and 480-506 (exec helper, OIDs, commit construction) (verdict: pass)
Single exec helper at git.go:159, `exec.CommandContext`, `-C repoDir`, separate argv, `GIT_TERMINAL_PROMPT=0`, `LC_ALL=C`, no shell. Every OID is validated before use (git.go:191, 259, 288). Zero OID is derived from `--show-object-format`. `commit-tree` gets `--no-gpg-sign` and deterministic identity and dates. Nothing user-controlled reaches argv unvalidated: remote name is regex-checked, keeper, role and gate are validated before they enter the commit message, refs come from integers. No porcelain commands are used.

- F3 (low, git.go:164): the child env inherits `GIT_DIR`, `GIT_WORK_TREE` and `GIT_INDEX_FILE` from the parent. These override `-C`. Scenario: waggle invoked from a git hook writes claims into the hook's repo instead of `RepoDir`. The brief specifies `os.Environ()` plus additions, so this is spec-compliant. Consider scrubbing those three variables in a follow-up.

### Unit 2b: git.go 218-480, 508-748 (acquire, release, list, sync, race classification) (verdict: pass)
CAS verified by reading and by passing tests. Local create uses `update-ref ref new <zero>`; renewal and takeover use the exact read OID. Remote uses fetch, then `push --atomic --porcelain --force-with-lease=ref:<expected>` (empty expected for create-only). Race classification parses `!` lines for the exact ref, re-syncs, and returns `ErrAlreadyClaimed` only when the remote ref moved, otherwise retries up to 5 times. Transport failures stay generic (`TestRemoteTransportFailure`). Expiry uses the injected clock only (`time.Now` appears solely as the default at git.go:125). Malformed target returns `ErrMalformedClaim`; malformed other-ticket claims are skipped in overlap and reported by List via `*MalformedClaimsError`. Release is CAS-delete on the read OID in both modes, with `ErrNotFound`, `ErrNotOwner`, and `ErrConcurrentUpdate` classified correctly.

- F4 (low, git.go:337-348): decodeLease validates directories by calling NormalizeDirectories but keeps the raw stored strings. I confirmed with a hand-forged claim (`directories: ["foo/"]`) that a later claim on `foo/bar` is NOT blocked by the overlap check. Requires someone able to write claim refs directly (an older client or a hostile Cell), and the merge gate still catches it. Fix: use the normalized list from the decoder for overlap.
- F5 (info, git.go:665-678): local ReleaseLease does not retry on lock contention (acquire does). A transient lock returns a generic wrapped git error rather than a sentinel. The brief does not require a retry on release.
- The remote mirror write after a successful push ignores errors by design (git.go:581), documented.

## Intent Packet (for the Keeper)

1. What changed: `internal/comb/` now has the real Comb backend. A claim on a ticket is a git ref `refs/waggle/claims/ticket-<n>` pointing to a commit that holds one `lease.json`. Renewals and takeovers chain to the previous commit; release deletes the ref.
2. Why: it gives one claim codepath from a solo repo to a shared remote, with atomic compare-and-swap per ticket so two Keepers cannot both own a ticket. It also renders the derived WORKPLAN.md view.
3. Safety rules enforced at claim time: control-plane (Tier 3) paths and the repo root are refused, case-insensitively. Light-gate leases on steering docs are refused. Ticket IDs and paths are strictly validated.
4. Verified by the guard: build, vet and race tests pass (3 repeated runs); tests skip cleanly without git; diff is limited to `internal/comb/`; all 15 acceptance criteria met on my own evidence.
5. Residual risks (none blocking): directory overlap between different tickets is optimistic and the merge gate is the real check (by design); Windows trailing-dot paths, backtick text in directories reaching WORKPLAN.md, and unnormalized hand-forged claims can slip past claim-time checks; git env vars like GIT_DIR are inherited.
6. Blast radius: one package, no dependencies, no callers yet, no CLI wiring.
7. Recommendation: approve and merge as one PR; queue one small follow-up ticket for F1 to F4 and F6.
8. Reversibility: high. Revert the commit; no schema, config, or published refs exist yet. The claim-commit format needs the RFC-0003 3.1 amendment (T-003).
