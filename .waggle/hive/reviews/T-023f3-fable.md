## Blocking issues

### 1. The run 0 gate cannot produce the D-197 evidence on the real timeout path, and its outcome text lets a benign result read as a pass or a block

Facts from `790ade0`: `killGrace` is 10 s (`internal/dispatch/cell.go:32`); `stop()` sends SIGTERM to the worker's group first and SIGKILL only after that grace (`internal/dispatch/run.go:515-523`); a survivor is recorded only when the sweep's SIGKILL was delivered (`reap_unix.go` `note` runs after `t.kill(...) == nil`). The D-176 probe 1 record (`media/T-023/d176-probe.txt`, run 1) shows Claude Code 2.1.304 kills its own tool shell and the `perl` child when it receives SIGTERM. Probe 2 (`d176-probe-2.txt`) listed `zsh` and `perl` in `survivors_killed` only because the harness forced `killGrace` to 1 ns, a package variable no CLI flag can set.

Walking run 0 as written: the 90 s timeout fires while `perl probe/probe.pl` runs, dispatch sends SIGTERM, Claude Code cleans up the shell and the child within the 10 s grace, the leader exits, the sweep finds nothing, `survivors_killed` is `[]`, `end: timeout`, exit 5, both pids dead in `ps-after.txt`. Step 2.7 then says "cutover is blocked", for a benign result the runbook never names. The opposite misreading is as easy: "both gone" taken as the gate passing, with the sweep never having fired (the threat model's "cutover without the D-197 proof"). Only when Claude Code is still alive 10 s after SIGTERM does the probe 2 shape appear, and the runbook cannot make that happen.

Fix (runbook section 2, and the gate text in 2.7 and 8.1):

- Name the SIGTERM-cleanup outcome (`survivors_killed` empty, `probe.pl` and its shell dead in `ps-after.txt`, `end: timeout`) as "Claude Code's own cleanup, not D-197 evidence and not a block". Keep recording it.
- Add a shape that reaches the sweep on the product path with the real grace: a child the tracker has listed and that outlives the worker's normal exit. For example `probe/hold.sh` = `perl probe/held.pl & sleep 1` (`held.pl` writes `t023-held.pid` and sleeps 120 s), listed in section 3 as ``- **Hold:** `sh probe/hold.sh` ``, and a T-901 step that runs it and then ends the session. The shell lives 1 s, so the 25 ms tracker lists it and its group; on the worker's exit `cmd.Wait` runs `signalGroup` and the sweep (`run.go:506`, `:579`), the group's leader is absent, and the group sweep kills `held.pl`. Expected: `survivors_killed` lists that `perl` pid and `ps-after.txt` shows it dead.
- Restate the gate as: every pid file whose shell the tracker could list (`held`, and `probe` when the SIGKILL path was taken) is in `survivors_killed` and dead in `ps-after.txt`; any such pid alive after the run blocks cutover; record whether the SIGKILL path (both `zsh` and `perl` listed, the probe 2 shape) was reached, since that proves the kill of a shell Claude Code failed to clean up.
- If the Head Keeper would rather keep D-197's literal wording, the runbook needs a Keeper card that says so before the trial; the runbook as written sends the queen to a card either way, but with no outcome table the card cannot be answered from the evidence.

### 3. `tasks/T-026.md` states the guard model wrongly, and dispatch reads the brief only from base

The Risk Tier line says "One guard through dispatch (sonnet by policy, or a stronger model when the run has no `--tier`)". Per `internal/runtime/policy.go` the guard level is `max(guard minimum, builder level)` = `standard`, the pick must avoid the builder's `sonnet`, `standard` has no alternate in our `config.yaml`, so `pick` walks up to `frontier` and returns `opus`; `--tier` changes nothing without a recorded override. The runbook (1.6, 6.1) and the 10.4 pointer say opus. Fix the sentence: "One guard through dispatch, opus by policy (the guard must differ from the sonnet builder and `standard` has no alternate; `--tier` does not change this); no D-100 second guard." Also drop or soften the `--tier` remark in the runbook's 5.1 if any.
