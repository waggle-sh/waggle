## Intent summary

T-044 makes a `waggle dispatch` renewal of the keeper's own live claim append the run's branch to the stored branch list when the list does not already name it, so a later-phase or cut PR (`t-<nnn>b`, `t-<nnn>c2`) passes the gate's `checkHead` without the queen first renewing by hand with `waggle claim --branch`. A full list (4 entries, none the run's) refuses with `ExitClaim` before any write. `waggle claim` and `ClaimTask` keep D-292 behavior (a renewal with no `--branch` keeps the stored list), a takeover still resets the list, and the guard still writes nothing. The lease is `internal/dispatch/` only, with a file-level rule naming `claim.go`, `request.go`, the `Run` claim step in `run.go` and tests. Blast radius at merge is zero for the hive until a Head Keeper pin move, since the hive runs `bin/waggle` at pin `0d102ca`; after the pin move every hive claim can carry up to four ticket-named branches until release.

## Findings

1. **must-fix (AC4 as written cannot pass; one-line amendment).** AC4 writes the pre-claim through `claimEnv(t, f.real)`, whose backend clock is pinned at `t0` (`dispatch_test.go:19`, 2026-10-18 12:00 UTC) with `DefaultTTL: time.Hour` (`dispatch_test.go:145-151`), so the stored claim expires at `t0` plus one hour. `Run` then passes `now()` to `AcquireClaim` (`run.go:360`), and `now` is `time.Now` unless `Deps.Now` is set (`run.go:209-211`). On any real date after 2026-10-18, `!old.ExpiresAt.After(now)` is true at `claim.go:60`, so the verb is `takeover`, the list resets to `[t-023b]`, and the assertions `res.ClaimVerb` is `renew` and every lease carries `[t-023 t-023b]` fail. `TestRunKeepaliveKeepsBranches` does not hit this because its claim is fresh. Fix in the brief: AC4 must say either that the `f.run` mutation sets `d.Now = func() time.Time { return t0 }` (any time before `t0` plus one hour; `Deps.Now` reaches `AcquireClaim` at `run.go:360` and stamps `StartedAt` only), or that the test sets `*now = time.Now()` on the pointer `claimEnv` returns before writing the pre-claim. Without one of these the builder either ships a failing test or silently departs from the AC text in a Tier 3 ticket.

2. **note (concurrent runs of one ticket).** The brief says the keepalive needs no change, and that is right for the sequential cases in scope. For two builder runs of the same ticket by the same keeper alive at once on different branches, each keepalive rewrites the list it read back at its own claim time (`run.go:411`), so the list flaps between `[t-044]` and `[t-044 t-044b]`. This is not a regression this ticket introduces: the same keepalive already flaps `Directories` and `Gate` between the two runs, and the post-run check at `check.go:220-221` (`own claim ref changed after the last renewal`) already fails whichever run did not write the ref last, so concurrent builders on one ticket are unsupported today. Worth one sentence in section 5 so the next reader does not rediscover it.

3. **note (AC3 message and entry choice).** The refusal message by design contains the ticket id `T-023` and the text `waggle claim T-023 --branch`. AC3's assertion that the message contains none of the four stored entries holds only because `strings.Contains` is case-sensitive and the entries are lowercase `t-023...` names or unrelated strings; the builder should pick four entries that are not substrings of the message (for example `t-023a`, `t-023b`, `copilot/x`, `owner/repo:t-023z`). No brief change needed.

4. **note (cite precision).** `backend.go:489-516` for `ValidateBranches`: the function closes at `:518`. The lines the brief relies on (`:494-495`) are exact. No change needed.

5. **note (hive effect).** The hive's `ticket-25` claim on origin still lists only `t-025c1` (`01608e6`). Until the pin moves, section 9's manual renewal step stays the queen's responsibility before every later-phase dispatch; the brief says so and gives the exact command.
