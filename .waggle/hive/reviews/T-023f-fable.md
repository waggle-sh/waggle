## Blocking Issues

- **B1 (item 3: the review file name does not match what dispatch counts, D-177).** The template says to commit a guard's `review.md` as `.waggle/hive/reviews/T-<nnn>-<model>.md`. `roundMustFix` in `internal/dispatch/inputs.go` counts `Verdict: must-fix` lines in `reviews/T-<nnn><suffix>-*.md`, where `<suffix>` is the branch name after `t-<nnn>` (`prefix := req.Ticket + strings.TrimPrefix(req.Branch, "t-"+...) + "-"`), exactly as D-177 rules. `checkBranch` in `request.go` accepts any `[A-Za-z0-9._-]` suffix and the template's own guard command takes `--branch <branch>`. So on any suffixed branch (`t-023f` gives the prefix `T-023f-`) a review committed under the template's name `T-023-<model>.md` is invisible to the count: the D-188 model step-up and the D-116 second-guard count never fire, with no error anywhere. On the default branch `t-<nnn>` the two names coincide, which is why nothing fails today. Fix: name the file after the branch, for example "as `.waggle/hive/reviews/T-<branch suffix>-<model>.md` (branch `t-023f` gives `T-023f-<model>.md`; the default branch gives `T-<nnn>-<model>.md`)", so the file is one of the `T-<nnn><suffix>-*.md` files dispatch reads at base. `<model>` is well defined: `result.json` `model` is the config's level name (`opus`, `sonnet`, `haiku` in the seeded `config.yaml.tmpl`).

## Checks

1. **Item 1, flags.** `--role builder|forager`, repeatable `--dir`, `--gate light|full`, `--no-cell`, `--role guard`, `--branch`, `--second` all exist in `runDispatch`; its usage text is the same two lines. Dispatch refuses without `--no-cell` (exit 2 with the NotEnforced list), which D-211 keeps for v0.1 with no first-dispatch card. "Never under `nohup`" is the right reading of my D2b N5: `signal.NotifyContext` with `stopSignals` (SIGHUP included) stops dispatch regardless of nohup, so nohup would only mislead. "Never poll, sleep or wait" matches rule 3 and the role's Never line.

2. **Item 2, outputs and exits.** With no `--json`, `runDispatch` prints `verdict:`, `violation:` and `note:` lines and then `<ticket> <role> ended <end> (exit <n>), record <run_dir>` as the last stdout line; the record line is printed after every worker-derived line, so a violation path or warning cannot displace it. When `Run` returns an error there is no record line and stderr gets `waggle dispatch: <err>`. The exit table matches `request.go` (0 done, 1 failed, 2 usage, 3 environment, 4 claim, 5 needs the Keeper). A guard with a `must-fix` verdict is `done`, exit 0 (`outcome` with `commits = 1`), and a missing verdict is `no_verdict`, exit 5, so "exit 0 is a clean run or a recorded guard verdict" is exact. `result.json` has `verdict` and `head_oid` (`result.go`), and `head_oid` for a guard is the OID the review was of (`ck.head = req.Head`). "Never rerun with other flags to get past a refusal" is the right rule: `--base`, `--branch` and `--second` are the only flags that change a refusal's outcome and each needs a Keeper's reason.

3. **Item 3, `pushed:` and `review.md`.** `d.emit("pushed", "%s to %s", ...)` prints `pushed: <branch> <remote>` only after a clean builder run with a remote and without `--no-push`. `review.md` is written in the run directory for a guard (`run.go`, `writeFile(runDir, "review.md", s.Final)`) and equals `final.md`. The name the queen commits it under is B1.

4. **Item 4.** Correct and the key line of the threat bar: `final.md`, `review.md`, the transcript, `note:` (warnings and NotEnforced) and `violation:` (rule, worker path, detail) all carry worker-chosen bytes.

5. **Item 5, host record.** `checkHostRecord` exits 3 with `host files changed since run <n>: <keys>; inspect them, then run waggle dispatch clean --host-record`. `HostRecord` without `--accept` writes nothing; with `--accept` it exits 3 (`host files changed since the listing; list them again`) when the digest moved, so "list again and ask again" is right. The digest is `digest <16 lowercase hex>` and `digestRe` only accepts that form. `lockRepo` prints its takeover warning to stdout before any listing line (my D2b N7). The template takes the digest from the digest line, not from the warning or the keys, which is the matching `listedDigest` uses. Wording notes N1 and N2.

6. **Item 6, clean.** `Clean` removes the ticket's worktree (`worktree remove --force`), its own admin entry when the directory is gone, the `.tainted` and `.lock.takeover` markers and the role lock, never a repo-wide prune (D-202) and never a branch or claim. Dispatch's own refusals that mention removing a lock (`worktree.go` 493 and 504) and the provision hint (D-207) are the "error text that suggests one" the template routes to the Keeper. Consistent.

7. **Item 7.** `stream.go` maps a cancelled context to `EndInterrupted`, `outcome` maps it to `interrupted`, exit 1; the checks run under `context.WithoutCancel` and `res.Write()` still runs, so "it still checks and records the run" is exact. D-213 keeps this wording and has the trial measure what the host sends.

8. **Rule 4.** `upgrade.go` 530 wraps every `ParsePolicy` failure as `model policy for claude-code shims:`; the policy load parses the whole config including `forge:` and runs `ParseContext`, so the second sentence is true today and D-212 removes it with the rename.

## Notes

- **N1 (item 5, "last line").** The listing ends with a ready-made `waggle dispatch clean --host-record --accept <digest>` line after the `digest <hex>` line (`hostrecord.go`), so the digest line is the second to last line of the output, not the last. "The last line of the exact form" reads either way; "the one line of the exact form `digest <16 lowercase hex>`" removes the ambiguity, and the template could say the following command line is the same digest and is run only after the card. 1 line.
- **N2 (item 5, warning text).** The real line is `warning: took over stale run lock of dead pid <n>`; the template quotes its prefix. "A line starting `warning: took over stale run lock`" is exact. 1 word.
- **N3 (item 3, no PR).** "Check that the PR head still equals `head_oid`" could read "the branch head (the PR head when there is one)", so a hive without a forge has a referent. The guard's stdout `verdict: <v> (head <oid>)` line prints the same OID.
- **N4 (item 2, exit 2 text).** A flag parse error exits 2 with the flag package's own line (`flag provided but not defined: -x`) and the usage text, with no `waggle dispatch:` prefix; the `--no-cell` refusal and every exit from `Run` do carry it. Rule 4's "quote errors with their prefix" still works.
- **N5 (item 3, "unchanged").** The queen still has to read the review to relay it and, in a hive with a scan such as D-183's, run the scan before the commit; "unchanged" rightly forbids editing, not reading. Separately, `CountMustFix` counts every `Verdict: must-fix` line in a file, so a guard that repeats the line inflates the step-up count; pre-existing and not this PR's.
- **N6 (D-212 and D-213).** Rule 4's second sentence and item 7's wording are both what the Keeper ruled on 2026-10-21; neither needs a change here.
