## Intent Summary

Phase A replaces `AgentRuntime.Run` with `Verify`, `Prepare` and `Collect` in `internal/runtime/` so that `waggle dispatch` (phase C) can launch headless Claude Code workers. `Prepare` builds a fixed argv (`--print`, stream-json, resolved model, `--setting-sources=` empty, an inline `--settings` JSON with the D-110 allow and deny rules, `--strict-mcp-config`, `--tools=Bash,Edit,Glob,Grep,Read,Write`, `--permission-mode=dontAsk`, `--max-turns`, the stable prompt on `--append-system-prompt`), an allowlisted environment (section 8 list plus `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`, `DISABLE_AUTO_COMPACT=1`, `GIT_TERMINAL_PROMPT=0` and a `GIT_CONFIG_COUNT` push tripwire), and puts the variable prompt on stdin. `Verify` pins the binary by `--help` tokens so a missing security flag fails closed. `Collect` parses the stream, sums usage, applies the `max_tokens` cap and maps the end reason. Blast radius: nothing calls this code yet (phase C does), `go.mod` untouched, stdlib only, diff inside `internal/runtime/`. The code decides which credentials and config a future worker can reach, hence Tier 3 by content. I found no blocking issue; the isolation boundary holds live against the pinned Claude Code 2.1.302 for everything D-110 and section 8 promise, with the known gaps the brief already lists as not enforced.

Three worker sessions plus five one-turn calls. Spend about 1.2 cents in total (session costs 0.0028, 0.0053 and 0.0015 USD from the result events, the rest under 0.001 each).

The builder's control run (same argv minus `--setting-sources=`) fired 12 hook events, so the flag is what blocks them. Plugins in the worker init event: only the two built-ins; the Keeper's three installed plugins (vercel, frontend-design, typescript-lsp) are absent. MCP servers: none, although `~/.claude.json` lists four user servers (github, supabase, context7, cloudflare); the builder's control run also showed none, so `--strict-mcp-config` holds even when user settings load. 2. Permission enforcement under `--permission-mode=dontAsk` with the D-110 rules (`fable-run1-permissions.jsonl`, `fable-run2-tools.jsonl`, 19 denials recorded in the result events' `permission_denials`). Refused: `git push origin ...`, `curl`, `gh --version`, `ssh -V`, `wget`, `python3 -c`, `env`, `cat /etc/hosts`, `git remote set-url --push ...`, `git -c url.x.pushInsteadOf=y push ...`, `git  push` (double space), and every compound form tried: `go test ./... && curl ...`, `go test ./...; git push ...`, `go test ./... | curl ...` (the pipeline was split and the `curl` half refused), `go test ./... $(curl ...)`, backtick substitution, `go test ./... > /dev/null || git push ...`, `git log --oneline -1 && git push ...`. Allowed: `git status`, `go test ./...`, `ls` (no rule covers `ls`; Claude Code has a built-in read-only safelist, so D-110's "Bash limited to" is slightly wider than the rule text; no isolation effect). WebFetch and WebSearch do not exist in the worker (`tools` in the init event is exactly the six built-ins). A denied call returns an error to the model and the session continues, so the D-110 cost ("some runs end on a denied tool") is a retry by the model, not a dead session.

3. Git push tripwire (`fable-tripwire.txt`, `fable-go-test-push-result.txt`). Under the exact worker env, `git push` to `https://`, `ssh://` and `git@` remotes is rewritten to host `waggle-push-blocked` and fails ("Could not resolve hostname waggle-push-blocked"), also when invoked by `exec` from inside an allowed `go test ./...`, which the Bash rules cannot see. `git fetch` and `git ls-remote` over `https://` are unaffected. Not covered: `http://` remotes and local path remotes (a `go test` pushed to a bare repo in the scratch directory; that stays on the machine, and phase C's ref snapshot would see a push into the shared common dir). Bypasses that work: a longer `url.<prefix>.pushInsteadOf` passed with `git -c` (longest prefix wins), and `remote.<name>.pushurl` (git ignores `pushInsteadOf` when a pushurl is set). Both need a determined agent going through `go test` or an `Edit` of `.git/config`, which section 8 says the tripwire does not stop. Note that the rewritten URL is scp-style, so git actually runs `ssh waggle-push-blocked ...`; a `~/.ssh/config` Host entry of that name would redirect it. A `waggle-push-blocked::` remote-helper form or a `file:///dev/null` target would be a dead end rather than an ssh attempt.

## Rulings requested

**argv: denylist or allowlist.** Ruling: an allowlist for `default_args` is required before phase C launches anything; it is not required to merge phase A. Reasons: the brief (10.1) specified a denylist and the builder implemented it faithfully and wider; `config.yaml` is Tier 3, so only the Head Keeper can put a flag there; and phase A has no caller. But the denylist is structurally unsound against a third-party CLI whose flag set changes every release. In 2.1.302 these are not refused and each widens the worker or breaks policy: `--fallback-model` (silently swaps the T-012 model under load), `--remote-control` (lets a remote claude.ai session drive the worker), `--environment` (uploads the run to a cloud session), `--chrome` and `--ide` (browser and IDE channels), `--plugin-url` is refused but `--file` (downloads resources at startup) is not, `--betas`, `--debug-file <path>` (writes anywhere), and a bare positional word (prompt injection from config). A small `allowedDefaultArgs` set (`--effort`, `--max-budget-usd`, `--no-session-persistence`, `--disable-slash-commands`, `--debug`, `--restricted`, `--permission-prompts`) with "anything else refused" is a few lines and matches how `Verify` already pins known flags. Suggest the queen records this as a phase C precondition or an amendment to 10.1.

**`DISABLE_AUTO_COMPACT=1` (T-021 carry).** Within builder authority. T-023 section 10.1 says "Decide `DISABLE_AUTO_COMPACT` here", T-021 S5 says compaction is turned off where the adapter can do so, and Q-T021-6 only asks that the knob be verified against the pinned version. The builder set it, records `Compacted` from `compact_boundary` events, and the env reached the child in my runs. Consequence to note for phase E: with compaction off, a session that outgrows the model's window before `max_tokens` triggers ends with an API error (`error`), not a handoff; `Collect`'s cap at 300000 is above a 200k-window model, so the handoff threshold (`nudge_tokens` 200000) must stay the effective stop. That is phase E's problem and is consistent with S5. One `waggle decide` line closing the T-021 item would be tidy; not a condition.

## Non-blocking findings and recommendations (for the builder or the queen)

1. `Collect` counts every `system/permission_denied` event as malformed: that event carries `"message": "<string>"` while `streamEvent.Message` is a struct, so `json.Unmarshal` rejects the whole line (9, 10 and 3 "malformed" lines in my three runs, all valid JSON). Assistant and result events decode fine, so usage and the cap are unaffected, but `result.json` will report `MalformedLines` equal to the number of denials in every real run. Fix: decode `message` as `json.RawMessage` and parse it only for `assistant` events, or decode the usage in a second small struct. Two lines; worth doing in this PR. (`internal/runtime/stream.go`, `streamEvent`.)
2. Add `--restricted` to the fixed argv. Verified live: it confines Read, Edit and Write to the working directory and refuses edits to `.git/config`, settings and tool-config files, while the named `--tools` keep Bash. It turns "writes outside the repo (not detected)" from a not-enforced item into an enforced one for the file tools (Bash via `go test` still can). Needs a `Verify` token and a check that the worktree's `.git` file does not trip it (phase C can test).
3. Add `--no-session-persistence`: worker transcripts otherwise land in the Keeper's `~/.claude/projects/` and are resumable; dispatch keeps its own `transcript.jsonl`.
4. Add `--disable-slash-commands` (drops the bundled skills from the init event) and consider `--permission-prompts=none` (print-mode form of "anything that would prompt is denied"), both belt and braces.
5. Tripwire: document that `http://`, local paths, `pushurl` and a longer `pushInsteadOf` prefix bypass it, and consider rewriting to `file:///dev/null` or a `::` helper scheme so the failure is not an ssh attempt to a resolvable name.
6. Size (AC3): the PR says 458 non-test lines. `wc -l` gives 425 for the new files, 577 for new plus rewritten (`claude.go`, `launch.go`, `stream.go`, `runtime.go`), 934 for every non-test file touched (the branch also edits `policy.go`, one comment line, and `profile.go`, 10 lines for the `nudge_tokens` upper bound). The stop value is 520. Which reading D-089 intends is the queen's call; the `profile.go` change is the right companion of `MaxNudgeTokens` and inside the directory lease.
7. `ls` is allowed with no rule (Claude Code's own read-only safelist). Harmless; worth one line in the dispatch docs so D-110's list is not read as exhaustive.
