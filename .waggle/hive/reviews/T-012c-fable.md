## Intent Summary

Phase C closes the phase B gap (sonnet finding 1, fable F12): `waggle upgrade --runtime claude-code` now builds the model policy at plan time from the hive's `config.yaml` bytes it already holds and the roster it is about to write (the rendered template, never the on-disk file), validates it, resolves a base model for every roster role, and refuses with `ErrRefused` before any write when that fails, in the dry run and with `--apply` alike. The resolved policy rides on `upgradePlan` into `Materialize`, so regenerated shims keep their `model:` lines. `internal/config/roster.go` gains `ParseRoster(data)` and `ParsePolicy(cfg, roster)`, with `LoadRoster` and `LoadPolicy` delegating to them through a shared `policy` helper; a missing or malformed `levels` block now carries a hint naming the fix, which reaches `waggle init` too. The `checkSymlinks` message no longer says "upgrade" when `init` is the caller, and the empty-roles message no longer prints `(<nil>)`. Blast radius: every `waggle upgrade` run by a Claude Code Keeper now requires a parseable `config.yaml` with a `levels` block; `--runtime none` is unchanged. This is the change that makes section 7.2 runnable. `go.mod` unchanged, stdlib only.
