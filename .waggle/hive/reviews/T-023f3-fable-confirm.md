## Blocking issues

### 1. `probe/hold.sh` leaves `held.pl` holding the tool shell's stdout, so the outliving child may never outlive the session; and the gate can pass with no `held.pid`

Runbook 2.2 defines `probe/hold.sh` as `perl probe/held.pl & sleep 1`. The background perl inherits the tool shell's stdout and stderr, which Claude Code reads through a pipe (the probe 2 capture shows the shell command line with no output redirection: `/bin/zsh -c source <snapshot> ... && eval 'perl probe.pl' < /dev/null && pwd -P >| <tmp>/cwd`). A tool call whose pipe is still held open does not return when the shell exits: it returns when the last holder closes it, or when the Bash tool's own timeout (120 s by default, the same length as `held.pl`'s sleep) ends the call and Claude Code kills the tool shell's group. Either way `held.pl` is dead before the worker's normal exit, `survivors_killed` is empty, and the runbook's last gate bullet reads it as "Claude Code also cleans up `held.pl` itself", which is a misattribution: it was the pipe, not a cleanup. The only shape that exercises the D-214 gate is then spent, with the Keeper present, on a session that spends up to two minutes in one tool call.

A second hole: if `held.pid` never appears (the call refused, the shape wrong, the write failed), run 0a's step 3 loop over `/tmp/t023-trial-pids/` does nothing, `ps-0a-after.txt` is empty, and the Pass bullet ("every listable leftover pid is in `survivors_killed` and dead") holds over zero pids. The gate must not be satisfiable by an empty pid dir.

Fix (runbook 2.2, the gate in section 2, and run 0a):

- 2.2: `probe/hold.sh` is `perl probe/held.pl >/dev/null 2>&1 & sleep 1` (the redirection closes the pipe with the shell; `sleep 1` still keeps the shell listed for the 25 ms tracker). Keep `bg.sh` as it is: the two shapes differ only in the 1 s the shell stays alive.
- Gate: add one bullet before Pass: "Required: `held.pid` exists after run 0a and the transcript shows `sh probe/hold.sh` ran. Without it the gate has no listable leftover, is not met, and run 0a is repeated once after the Keeper has seen the transcript; it never counts as a pass."
- Run 0a step 3: say the expected `end` is `no_change` (a done session with no commits, `outcome()` in `run.go`), not "the session's normal end".
