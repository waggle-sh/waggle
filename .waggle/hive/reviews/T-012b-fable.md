## Intent Summary

Phase B turns the T-012 policy into something the binary reads. `internal/config/runtimes.go` parses `runtimes:` (default adapter, per-adapter `binary`, `nudge_tokens`, `max_tokens`, `levels`, `alternates`) through T-004's YAML subset with the key path and line on every failure. `internal/config/roster.go` reads `roster.json` under the 64 KiB cap, returns each role's `min_level`, ignores a leftover top-level `mode` (D-070), and `LoadPolicy` joins the two and runs `Policy.Validate`. `ClaudeAdapter.WithPolicy` makes `Materialize` resolve a model per role file before any write and emit a `model:` frontmatter line, so the guard shim carries the cross-model pick against the builder's base model. `waggle init` loads the policy after writing the templates and fails closed when `levels` is missing; it also JSON-escapes every value substituted into a `.json` destination (in `init` and `upgrade`), refuses symlinked destinations with the T-016 `os.Lstat` check, and now validates `--forge` against `github|none`. The Head Keeper commit adds `min_level` per role and removes `mode` from the roster template and adds the `levels` block and one comment line to the config template. Blast radius: every new hive gets `model:` lines in its shims and a roster with `min_level`; existing hives are untouched until their Keeper runs `waggle upgrade` (which, see F12, does not yet write model lines). `go.mod` unchanged, stdlib only.

8. Frontmatter writer. The model line is `model: <value>\n` placed after `name:`. The value is constrained by `modelPattern` (no whitespace, no `#`, no leading YAML indicator) and `shimModels` additionally refuses `\r` or `\n` in case a policy arrives from somewhere other than `config`. The role name in `name:` comes from the file name, as before. Writes are per file with `os.WriteFile`, so a write error mid-loop leaves earlier shims in place; that is the pre-existing behavior for gitignored runtime state and not a regression, and all resolution errors happen before the first write.

9. `waggle init` JSON escaping. `placeholders` clones the pair list, runs `json.Marshal` on each value for a `.json` destination and strips the quotes, so a value cannot close its string or add keys; the input slice is not mutated and non-JSON destinations get the raw value. `upgrade.go` uses the same helper for its re-rendered roster, and the shipped test proves a hand-edited `hive.profile` of `cli","entry":"x` yields valid JSON with `entry` still `queen`. In `init` the six values are already validated against allowed sets or come from build info, so the escaping is belt and braces there; in `upgrade` it closes the D-107 hole. The only placeholder in any JSON template is `{{PROFILE}}` in `roster.json.tmpl`; the gate workflow's `${{ ... }}` are GitHub expressions, not Waggle placeholders.

10. Symlink refusal. `checkSymlinks` is called before the first write with `writePaths` (`.gitignore`, the import target, every template destination, `layout.Managed`, `.claude/agents` and any existing `waggle-*` entry) plus the three hive directories. Every path prefix is `Lstat`ed, so a symlinked `.waggle`, `.waggle/control`, `.github`, `.github/workflows` or `.claude` is caught, not only the leaf. Live: a symlinked `.claude` and a symlinked `.waggle/hive/media` were refused with `ErrRefused`, the targets stayed empty and nothing else was written. The only writes not on the list are shim files that do not yet exist, which cannot be symlinks at check time. The check is a precondition and `os.WriteFile` still follows symlinks, so a link planted between the check and the write would be followed; that is the same TOCTOU window T-016 accepted for `upgrade`, and the brief asks for the same precondition, so I accept it here (N2 suggests the cheap hardening). Two side notes: `planBlock` reads `.gitignore` and `CLAUDE.md` before the symlink check (a read through the owner's own link, no write), and the refusal text says "upgrade writes only regular files" when `init` is the caller (N3).
