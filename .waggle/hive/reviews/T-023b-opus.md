## Intent Summary

Phase B adds the inert library core of `waggle dispatch` in a new `internal/dispatch/` package plus `config.LoadKeeperID`. `Request.Validate` checks ticket, claim role, gate, directories (through `comb.NormalizeDirectories`), branch (`t-<nnn>` plus a `[A-Za-z0-9._-]` suffix), base and read paths without touching git. `AcquireClaim` wraps `comb.AcquireLease` and adds claim, renew or takeover notes from a pre-read. `Provision` takes an `O_EXCL` run lock and creates or reuses `.waggle/worktrees/T-<nnn>-<role>`, computing the merge-base for a must-fix round. `ReadInputs` reads brief, role prompt, `WAGGLE.md`, review and read-only paths from the base commit through `ls-tree` and `cat-file` with size caps, and `WritePrompts` saves the assembled prompt into a run directory outside the worktree. `LoadKeeperID` reads `keeper_id` from `local.yaml` and refuses the `local-keeper` placeholder when `forge.remote` is set (D-118). Blast radius today: none at runtime, no caller. From phase C on, this code decides which directory an agent with write access runs in and what claim it holds, which is why it is Tier 3 by content. Two blocking issues: worktree reuse trusts any git repo or symlink at the target path and runs git in it (arbitrary command execution through a planted repo's config), and in remote mode a takeover of another Keeper's expired claim is reported as a plain claim with no note.

## Blocking Issues (Must-Fix Only)

**B1. `checkReusable` accepts a foreign repository or a symlink at the worktree path, and runs git inside it before checking it belongs to this repo.** (`internal/dispatch/worktree.go`, `provision` and `checkReusable`.) The doc comment says it "accepts an existing path only when it is a registered worktree", but nothing checks registration. It checks only that `rev-parse --show-prefix` is empty (true at the root of any repo), that the main repo has the branch, that the path's HEAD names the same branch, and that `git status` is clean. Demonstrated (`TestProbeForeignRepoReused`): a plain `git init -b t-023` repo planted at `.waggle/worktrees/T-023-builder` with one clean commit is reused (`Reused=true`, no error), and its `core.fsmonitor` command executed on the host during `checkReusable`'s `git status`. A symlink at the path pointing to another registered worktree on the same branch (for example the `T-023-forager` worktree) is also reused (`TestProbeSymlinkReused`). `.waggle/worktrees` is gitignored, so phase C's main-checkout `git status` snapshot will not see such a plant, and no-Cell workers in phase C can write there. Consequences: arbitrary host command execution with the Keeper's credentials at the next dispatch, and an agent run in a directory whose history is not this repo's while `CheckBase` is computed in the main repo. Spec 7.1 reuses "an existing worktree", meaning one of this repo.

Fix (small): before any git call in `w.Path`, `os.Lstat` it and refuse anything that is not a real directory; then require that the main repo's `git worktree list --porcelain` lists `w.Path` (compare after `filepath.EvalSymlinks` of the parent, since macOS temp paths go through `/private`) with `branch refs/heads/<branch>`. Also `Lstat` `.waggle/worktrees` after `MkdirAll` and refuse a symlink, so the lock and run records cannot be redirected. Add both probes as tests.

**B2. In remote mode a takeover of another Keeper's expired claim is reported as `claim` with no note.** (`internal/dispatch/claim.go`, `AcquireClaim`.) Spec section 6: "A takeover prints the previous owner." The pre-read uses `ReadClaim`, which never syncs, and `ResolveBase`'s plain `git fetch <remote>` does not fetch `refs/waggle/claims/*`, so the local mirror is as old as the last Comb write from this clone. Demonstrated (`TestProbeRemoteStale`): alice claims T-023 from clone A, the clock passes expiry, bob dispatches from clone B; `AcquireLease` correctly takes over, and `AcquireClaim` returns `Verb=claim`, `Notes=[]`. Remote mode is the multi-Keeper mode, the one where silently taking another Keeper's ticket matters, and phase C will write this verb into `result.json`. The same stale pre-read also yields a wrong renew label, misses a "renewal changes the claim" note when the same Keeper's other clone changed directories, and refuses outright (exit 4) on a malformed ref that only the stale mirror still holds. The builder's note 2 calls this "a missing note"; the decision itself is indeed `AcquireLease`'s and stays correct, but the notes are a spec requirement, not decoration.

Fix (one to three lines): sync before the pre-read. The cheapest form with the existing interface is to call `cb.ClaimOID(ctx, req.Ticket)` first (it syncs in remote mode; ignore `ErrNotFound`), then `ReadClaim`. Alternatively derive `Verb` from the claim commit message after the write (`waggle: <verb> T-<nnn> by ...`). Add the two-clone test.

## Non-blocking notes

1. **Stale-lock takeover is racy.** Two dispatchers that both read the same dead-pid lock can interleave: A removes it and creates its own, then B's `os.Remove` deletes A's fresh lock and B creates its own; both proceed into the same worktree. Needs a crash plus two simultaneous starts for the same ticket and role, so not blocking here, but phase C should close it: re-read and compare the lock body immediately before removing, and after creating, or hold `syscall.Flock` on the lock file for the run.
2. **Base equal to the branch is not refused.** Spec section 4: "`main` and the base branch are refused." `main` cannot pass the prefix rule, but `--base t-023 --branch t-023` passes and makes `CheckBase` the branch tip, so phase C's check would only see the new session's commits. Refuse `Base` equal to `Branch` or `refs/heads/<Branch>` in `Validate`, or have `ResolveBase` callers compare the resolved OID with the branch tip. Can ride with the B fixes.
3. **Read path `.` and pathspec magic pass `Validate`.** `.` returns the first root entry (the root `.gitignore` in the probe) labeled as `.`; `:(top)x` is accepted as magic. Harmless (base content only), but refuse `.` and a leading `:` for a clear error.
4. **Env scrub keeps `GIT_CONFIG_*`, `GIT_CONFIG_PARAMETERS`, `GIT_EXEC_PATH` and the Keeper's global config.** Consistent with `comb` (the Keeper's own environment, needed for remote auth), and the duplication of the list is forced by the lease. Host-side `git worktree add` runs the repo's `post-checkout` hook and `git status` runs `core.fsmonitor` from the shared `.git/config`; phase C's `core.hooksPath` check (test 12) covers an agent setting those, but only after the run that set them. Worth a follow-up: pass `-c core.hooksPath=/dev/null -c core.fsmonitor=false` on dispatch's own host git calls, and keep the two scrub lists in sync with a test once `comb` can export its list.
5. **`LoadKeeperID` fails on any unsupported YAML construct elsewhere in `local.yaml`** (a sequence under an unrelated key, a flow map), despite spec 5.4's "ignoring other keys". It fails closed with a line-numbered error naming the file, which is acceptable for v0.1; say so in the doc comment and the scaffold's `local.yaml` header.
6. **Placeholder match is case sensitive.** `Local-Keeper` passes with a remote set. GitHub logins are case-insensitive, so `strings.EqualFold` is the closer rule. One line.
7. **Run-record comment overclaims.** `NewRunDir` says run records live outside the worktree "so the agent cannot rewrite them"; a no-Cell agent can write anywhere the Keeper can. "So the worktree diff never includes them" is accurate.
8. **Post-claim reads.** After a successful `AcquireLease`, a failing mirror `update-ref` (ignored inside `pushClaim`) would make the follow-up `ReadClaim` fail and `AcquireClaim` report a refusal for a claim that was written. Rare; phase C should treat that as a warning, not exit 4.

### Non-blocking notes

1. **Relative-path worktrees are refused (usability, fail closed).** With `worktree.useRelativePaths=true` (git 2.48+, honored from the Keeper's global config), git writes `../../../.waggle/worktrees/T-023-builder/.git` into `<admin>/gitdir`. `adminDir` passes that relative string straight to `EvalSymlinks`, which resolves it against the process's working directory, so `TestProbe4RelativePaths` ends in "no registration for .../.git" and every must-fix reuse is exit 3 for such a Keeper.
