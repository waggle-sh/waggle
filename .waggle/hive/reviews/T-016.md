## Intent Summary

Adds `waggle upgrade [--apply] [--diff] [--allow-downgrade] [--runtime=claude-code|none]`, run by the target build. It re-renders the managed files (roster.json, devcontainer.json, roles/*.md, the managed gate workflow) from its embedded templates, removes managed files the build no longer ships (roles/architect.md, its generated shim), edits the one `pin:` line in the seeded config.yaml, refreshes the marked blocks in .gitignore and CLAUDE.md or AGENTS.md, prints a ready `waggle decide` input, and regenerates this Keeper's shims. Dry run is the default and writes nothing. It lifts the git helpers out of `uninstall.go` into `git.go` and adds a `Templates` seam to `InitOptions`. Blast radius: every hive that runs it rewrites Tier 3 control-plane files, so each run needs Head Keeper approval; the code sits in Tier 2 paths. It never commits and never touches refs/waggle/* or .waggle/hive/**. Two defects below let it write a malformed pin and write or delete outside the repo through committed symlinks.

## Blocking issues

1. **Malformed pin with trailing text is accepted and then corrupted on write.** `ReadPin` validates only the first whitespace-delimited token (`valueToken` stops at a space). `pin: v1.0.0 beta` reads as `v1.0.0`, passes `ValidPin`, and `--apply` rewrites the line to `pin: fa85121f60c3846be294b03b5e8ec4a799abdaa1 beta` (hostile.txt, last block). The brief (3.2 item 6, AC3) requires a malformed pin on either end to be refused, and a tag with spaces is on the required hostile list. Same for `pin: <40-hex> junk`. Fix in the forager's lane: after the value token, the rest of the line must be empty or start with `#` (after optional whitespace); otherwise return the "not a full 40-hex commit or a release tag" error naming the line. Add a test (trailing text, and quoted value followed by text).
2. **Writes and deletes follow symlinks out of the repo.** `plan.write` (`os.WriteFile`), `os.Remove` on paths inside a symlinked directory, and the reads all follow links, with no Lstat check. Committed-symlink probes (hostile4-symlinks.txt):
   - `.waggle/control/roster.json` -> a file outside the repo: `--apply` exits 0 and overwrites the outside file with the rendered roster; the symlink stays.
   - `.waggle/control/roles` -> a directory outside the repo: `--apply` creates builder, forager, guard, scout and rewrites queen in the outside directory, and deletes the outside `extra.md` (listed `[remove]`).
   - `.waggle/control/config.yaml` -> outside file: the pin edit lands in the outside file.
   A symlink inside a hand-added `roles/evil.md` is handled correctly (the link is removed, the target survives). The brief's AC2 and this review's rule are that nothing outside `.waggle/control/` and `.claude/agents/` is ever written. Fix: during planning, `os.Lstat` every managed destination, every seeded file edited, and each parent directory component under `.waggle/control/` and the two block files; refuse (ErrRefused, nothing written, name the path) when any is a symlink. Add tests for a symlinked file and a symlinked `roles/`. The same hole exists in `init` today (pre-existing, out of this lease); mention it to the queen as a follow-up, do not widen this fix to init.

## Non-blocking notes

- `--diff` headers: the a side is repo-relative (`a/.waggle/control/roster.json`), the b side is the temp render path (`b/var/folders/.../roster.json`). Matches the intent of fa85121 only half. Cosmetic.
- `{{PROFILE}}`, `{{DELIVERY}}`, `{{FORGE}}`, `{{COMB_MODE}}` are scanned from config.yaml and substituted without validation. `../../../etc/passwd`, `{{PIN}}`, `{{PROFILE}}` and `$(id)` stay inert (single-pass replacer, values are never used as paths or executed). `x","evil":"1` lands unescaped in roster.json and produces valid JSON with an extra key. config.yaml is Tier 3, Head Keeper owned, and the rewrite shows in the PR diff, so low risk. Suggest validating against init's allowed sets (profile `cli` at least) in a follow-up. A missing key renders an empty string.
- Hand-added file under `.waggle/control/roles/` is listed `[remove]` and deleted on `--apply`, as 3.4 specifies. A same-pin run also rewrites a hand-edited managed file (samepin-edit.txt). That is the brief's test 4 behavior; with unchanged templates and pin every managed file is `[same]` and nothing is written.
- `--runtime=none` skips shim pruning and regeneration (D-095). A stale generated shim for a removed role stays on disk for that Keeper. Accepted per D-095, worth a line in the T-020 7.2 runbook.
- A tag pin with a leading-`v` prerelease compare uses string order between two prereleases (`rc10` < `rc2`). Documented in the code comment; harmless for a refuse-downgrade guard.
- `ErrRefused` text changed to `scaffold: refused, nothing written`, so `waggle uninstall` refusal lines now read differently. Tests pass, uninstall_test.go is untouched. Accepted (judgment call 5).
- Size: 688 net non-test physical lines against a 550 target and 700 stop. 25 percent over target, under the stop. Fixes above will add roughly 20 to 30 lines; confirm the count stays under 700 or report.
