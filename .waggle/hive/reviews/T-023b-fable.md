## Findings (non-blocking; N1 and N2 are the ones I would fix in this PR)

**N1. Stale lock takeover is a remove-then-create race.** `takeLock` (worktree.go, the `os.Remove(path)` after the dead-pid check) lets two dispatches that both read the same stale lock each remove the other's fresh lock: A removes stale, A creates; B removes A's lock, B creates; both hold the "lock" on the same worktree, and A's `Unlock` later deletes B's. It needs a crashed prior run plus two concurrent starts for the same ticket and role, which the queen does not do by hand today but the run.sock loop could. Fix in two lines: replace the stale lock with `os.Rename(path, path+".stale")` (atomic; the loser gets `ErrNotExist` and continues), then let the `O_EXCL` create decide, with the second loop iteration reading the winner's live pid and refusing.

**N2. `checkReusable` accepts a symlink to a foreign repository.** The reuse check proves the path is a work tree root on the right branch name, not that it belongs to this repository. Any process running as the Keeper's user, including a worker from another ticket (section 8: writes outside the repo are not detected), can plant `.waggle/worktrees/T-<nnn>-<role>` as a symlink to a repo it controls; on a must-fix round the next worker then runs in that directory with the brief. The main repo's branch stays unchanged, so phase C would end the run `no_change`, but the run is wasted and the worker's prompt and session landed in a foreign tree. Two cheap checks: refuse a symlink at `w.Path` (`Lstat` mode), and require `git rev-parse --git-common-dir` from inside the path to resolve to the main repo's common dir (or require the path in `git worktree list --porcelain`).

**N3. Takeover note missing in remote mode** (section 6 above). Sync before the pre-read, or read the written claim's parent.

**N4. `Validate` does not refuse `Base == Branch`**, which section 4 lists. One compare, also against `<remote>/<branch>`.

**N5. `blobAt` does not check the returned path.** Compare the path after the tab with the request; that also removes the `.` oddity and any future pathspec magic from the threat surface.

**N6. Tests.** Assert the absence of the claim ref in the Tier 3 and `.waggle/hive` refusal loop (test 6's "no git write"), and drop or relabel the vacuous `.waggle/worktrees` assertion in the held-claim case so phase C adds the real one in `Run`.

**N7. For phase C (not phase B defects).** (a) The brief's sequence fetches the remote (step 2) and reads inputs (step 3) before the claim (step 5), so a request that the Comb will refuse (`.waggle/hive`, `.github`, Tier 3 paths) does a fetch and four `cat-file`s first; section 6 says a refused claim touches nothing else. `comb.CheckChanges` or a small pre-claim call to the Comb's directory rules would let `Run` refuse these with exit 4 before the fetch. (b) On a second machine, a must-fix round's branch exists only as `<remote>/<branch>` after the fetch; `provision` sees no local branch and starts a fresh one from base, which the later non-force push would reject with exit 3. Consider creating the local branch from the remote-tracking ref when it exists. (c) `LoadKeeperID` could apply the Comb's keeper id pattern so a bad login is exit 3 at config time.
