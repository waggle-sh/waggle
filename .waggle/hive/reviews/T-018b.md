### Forager judgment calls

1. gh child env is `os.Environ()` plus `GH_HOST=github.com`, `GH_PROMPT_DISABLED=1`, `NO_COLOR=1`: acceptable. Verified with a fake gh that dumps its env under a parent with `GH_HOST=evil.example.com`, `GH_REPO`, `GH_ENTERPRISE_TOKEN`, `GH_TOKEN`, `GITHUB_TOKEN`: the child saw `GH_HOST=github.com` (exec keeps the last duplicate). `GH_REPO` is harmless because no endpoint contains a `{owner}`/`{repo}` placeholder. `GH_ENTERPRISE_TOKEN` is ignored by gh for github.com. An inherited `GH_TOKEN`/`GITHUB_TOKEN` is used by gh; that is the Keeper's own credential and the report label "gh CLI" is then slightly generous (N3). Note the child reads the real environment while `Options.Getenv` is injectable, so a test-injected Getenv does not reach gh.
2. `--input -` on every call, leading `/` stripped, branch query-escaped: acceptable. Argv for six hostile branches (`{owner}`, `{repo}`, `a/{branch}`, `x&state=closed`, `a%7Bowner%7D`, non-ASCII) never starts with `-` and the 422 lookup goes out as `?head=o%3A%7Bowner%7Dx&state=open` through the real `OpenChange` (ops-probe.txt). The branch never appears in a POST path.
3. Token scrubbed from GitHub error text; remote errors name only the host: acceptable, see Probes.
4. `github.OpenChange` reuses `none.OpenChange` validation: acceptable. Same title, body and `check-ref-format` rules; `-X`, newline, NUL, `../`, `a b`, `a@{1}` all rejected before any request. `{owner}` and `{repo}` are valid git names and pass, safely (above).
5. Auto-merge checks `head.sha` before the mutation, other GraphQL errors plain: acceptable with N5. The mutation also pins `expectedHeadOid` server side, so skipping the check when `head.sha` is empty is safe.
6. HTTP 200 with `merged: false` maps to `ErrNotMergeable`: acceptable; probed.
7. `New` returns untyped nil on error; forge imports layout: acceptable. The test asserts `f != nil` is false. `go list -deps` shows layout does not import forge.
8. 1 MiB cap checked after buffering all of gh's stdout: not blocking, see N1.

### Non-blocking notes

- N1 (gh stdout is unbounded): a fake gh writing 600 MiB made the transport allocate 4096 MiB in total and peak at about 6.5 GB RSS under `-race` (23 s), then fail with "over 1 MiB". Judgment call 8 is correct about the cause. It is not blocking: the producer is the Keeper's own gh talking to the endpoints used here (responses of a few KB), and a replaced gh is already code execution. The cost is one cheap fix: cap the stdout writer at `maxBody+headers` and kill the child past it. Do it in phase C or with N2, in `github_transport.go`.
- N2 (gh transport has no timeout and cancel can hang): the token transport has a 30 s client timeout (verified: `pickTransport` sets `client.Timeout = 30s`), but `ghTransport.do` applies no deadline of its own, and `exec.CommandContext` kill does not return while a descendant holds the stdout pipe. A fake gh that was `sleep 60` under a shell, with the context cancelled at 500 ms, returned after 60 s (with and without an orphaned grandchild). A real gh is one process, so this is unlikely in practice, but section 5.1's timeout intent and the D-067 "never silently hang" posture suggest a per-call 30 s context plus `cmd.WaitDelay` (and stderr is also unbounded). Callers that pass a deadline are covered by the first half only. Fix before `waggled` calls this without its own deadline.
- N3: `pickTransport` runs `gh auth status` and trusts exit 0. With an inherited `GITHUB_TOKEN` that gh accepts, the transport is labelled "gh CLI". Cosmetic for the report; the token still never touches argv or errors.
- N4 (redirects): Go strips `Authorization` on a redirect to a different host name (verified: an `localhost` target behind a `127.0.0.1` server saw an empty header). It keeps it for the same host name on another port, and no `CheckRedirect` pins the scheme or host, so a same-host https to http downgrade would forward the token in clear. Needs a network attacker on GitHub's own host; add `CheckRedirect` refusing anything but `https://api.github.com` when convenient.
- N5: a GraphQL "Head branch was modified" error (when the head moves between the pre-check and the mutation) maps to a plain error, not `ErrHeadMoved` (probed). Callers that retry on `ErrHeadMoved` will treat it as fatal. The 422 lookup also returns the first open PR for the head without checking its base, so `Change.Base` can name a base the PR does not have.
- N6: gh exiting 1 with an `HTTP/2.0 200` block is treated as success; gh exiting 0 with no HTTP block returns the uninformative `gh api GET /x: <nil>: ` (probed: exit0-garbage, exit0-empty, http-999). Both fail closed on no status; only the message is poor. Garbage stdout is correctly never echoed into the error.
- N7 (phase A code, inherited): a title containing NUL passes `OpenChange` validation and is sent JSON-escaped; GitHub rejects it. Errors from `Merge` with a bad request print an empty `( into )` because the Change is empty. Cosmetic.
- N8: `https://github.com/o/.git` parses as repo `.git`, and a trailing slash (`.../r.git/`) is rejected as an unsupported form. Both are strict or harmless; a Keeper with a trailing-slash remote gets the "unsupported form" message, which names the three accepted forms.

### New probes

- Stdout cap: total stdout exactly at 1 MiB + 64 KiB is accepted by the writer and then rejected by `finish` as `errBodyTooLarge` (the header block counts against the total, so a body of 1 MiB with a small header is the largest accepted). Total cap+1 kills gh and returns `errBodyTooLarge` wrapped as `gh api GET /x: ...`. Body exactly 1 MiB passes the size check (then fails JSON decode on blank input, as expected); 1 MiB + 1 returns `errBodyTooLarge`. The net/http path returns the same sentinel (`errors.Is` true in the Forager's test and mine). No off-by-one.
- Stderr cap: 10 MiB on stderr with a valid response is ignored (success); 10 MiB on stderr with no status line yields an error carrying at most 64 KiB of stderr text. See N9.
- Grandchild past the deadline: a `sleep 30 &` grandchild holding stdout open while gh exits cleanly returns the successful response after 2.11 s (WaitDelay closes the pipe); a gh that sleeps with a grandchild is killed and returns at 2.50 s. Neither hangs. The kill signals only gh, so the orphan `sleep` outlives the call; that is a real gh's non-issue.
- Redirects, driven through the real `tokenClient()` with a fake RoundTripper (no network): `https://api.github.com/other/path` and `/relative/path` are followed with the Authorization header intact. Refused, with the request count staying at 1: `https://API.GITHUB.COM/x`, `https://api.github.com./x`, `https://api.github.com:443/x`, `:8443`, `http://` same host, `https://api.github.com@evil.example/x`, `https://evil.example/x`, `https://uploads.github.com/x`. A loop stops after 10 requests. The uppercase, trailing-dot and explicit `:443` forms are the same server in DNS terms, but the check compares `URL.Host` as a string, so it fails closed. GitHub does not issue those forms; acceptable and safe. Note `via[0]` is the original request, so the pin is to the origin of the first call, not to a literal `api.github.com`.
- Pre-cancelled context: gh path returns in 1 ms with "context canceled" and never runs the binary to completion; token path returns "context canceled" in 1 ms. No hang.
- Token in any new path: `errBodyTooLarge`, the gh stdout and stderr cap errors, redirect refusals (message names scheme and host only; the wrapped `url.Error` shows the target URL, which never holds the token) and cancellations: `leak=false` in every case, token and bad-token probes from the first review also rerun green.

## Intent Packet

What changed: T-018 phase B wires `forge.New("github", ...)`. The new adapter resolves owner and repo from `git remote get-url` (github.com https, scp and ssh forms only), picks `gh` when logged in or `GITHUB_TOKEN` over net/http, and implements OpenChange (with the already-exists lookup), Comment and Merge (real merge commit pinned to the expected head, 409 to `ErrHeadMoved`, 405 to `ErrNotMergeable`, GraphQL auto-merge). `Probe` still returns `ErrUnsupported` until phase C. The hardening commit c85c783 adds: gh stdout capped at 1 MiB plus 64 KiB header room (gh is killed past it, same `errBodyTooLarge` as the net/http path) and stderr capped at 64 KiB; a 30 s deadline per gh call derived from the caller's context plus a 2 s `WaitDelay`, also on `gh auth status`; and a token client (30 s timeout) that refuses redirects leaving https, changing host or port, or past 10 hops. Token is scrubbed from GitHub error text and never reaches argv or errors. Why: D-061 and D-067 put every code-host call behind the Forge interface; this is the only real adapter before v0.1 (D-069). Blast radius: `internal/forge/` only, no core package imports it, nothing calls it yet; the merge into main c94df60 is clean and green. It holds the GitHub credential path and merge authority, so Tier 3 and Head Keeper approval at merge. Size by D-089 is 687 non-test lines over the four touched files, over the 650 stop; the Keeper rules on that. N1, N2 and N4 are closed; remaining notes (N3, N5 to N10) are non-blocking.
