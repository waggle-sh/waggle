# Guard review: T-023 phase D0b (PR #55), fable

Verdict: pass
Risk-Tier: 3

PR #55, branch `t-023d0b`, head `1599c2b`, base `53941e6`. Second independent guard (fable); no coordination with the other model.

## Intent Summary

Phase D0b closes 10.6 item 23 (D-181): git's detached auto maintenance, started by any `git commit` or `git fetch` since the geometric strategy became the `--auto` default in git 2.54, ran `worktree prune` in the hive repo's common dir between the worker's writes and the post-run check and deleted the planted admin entry that `TestRunHostState/new_admin_entry` expects to find. The fix turns `maintenance.auto` off and `gc.auto` to 0 in three places: two more `GIT_CONFIG_KEY_n` entries in the worker's `tripwireEnv` (`internal/runtime/launch.go`, count 12 to 14), two more `-c` flags on every host-side `Git.RunIn` call (`internal/dispatch/worktree.go`), and the comb's `ExtraEnv` for the claim backend (`internal/dispatch/run.go`, count 1 to 3). Two tests: `TestRunPlantDuringAutoMaintenance` (the proving test: plant after the result line, a second worker commit, a one second gap, then the gitdir write) and `TestRunInDisablesAutoMaintenance` (a fake git records its argv). One commit, signed off, 8 added non-test lines (run.go 2, worktree.go 1, launch.go 5; stop 20). Every changed file is inside the D-181 lease, the run.go hunk is the `ExtraEnv` literal only, stdlib only, no en or em dash.

Blast radius: Tier 3 by content, since it changes the git environment of every worker and every host git call dispatch makes. I reproduced the mechanism with real git on linux (git 2.56.0, arm64 container; amd64 was not possible here without qemu) and macOS (Apple git 2.54.0), end to end through `Run` with every git process traced: on main, a worker commit under the `Prepare` env spawns `maintenance run --auto --quiet --detach` whose `worktree prune --expire 3.months.ago` removes the plant, and host-side the comb's claim fetch (twice) and dispatch's own `fetch origin` each spawn the same daemon; on the fix tree none of those spawn anything and the plant survives to the check as the expected `host_state worktrees/planted` violation. The proving test fails 10 of 10 on main (linux) and 6 of 6 (macOS), and passes `-race -count=20` on linux, `-count=5` on macOS, at sleep 0, 1 and 3, and under four concurrent `-race` package runs. `TestRunHostState/new_admin_entry` itself fails 5 of 6 on main in the container and 6 of 6 pass on the fix, which is item 23 closed. The one daemon that still appears in a host trace comes from `git-receive-pack` on the fixture's local bare origin (git clears `GIT_CONFIG_COUNT` and `GIT_CONFIG_PARAMETERS` for a local-transport child) and works in that remote repo, never in the hive's common dir. The command-scope keys beat a repo-local `maintenance.auto=true`; `git -c`, `GIT_CONFIG_PARAMETERS` and an unset `GIT_CONFIG_COUNT` beat them back, which is the existing NotEnforced class (a worker that wants a daemon can run `git maintenance run` directly). What remains are notes.

## Checks

- **Mechanism on main, linux git 2.56:** worker commit under the real `Prepare` env (traced from inside the fake worker): `commit => maintenance run --auto --quiet --detach`. Git level: a planted `worktrees/planted` without a gitdir file is gone after the commit's daemon runs `worktree prune --expire 3.months.ago`; `maintenance.strategy`, `maintenance.auto` and `gc.auto` are all unset by default. Host side on main, one `Run` in remote mode: four daemons, from `git -C <repo> fetch --prune --no-tags --quiet origin +refs/waggle/claims/*:...` (comb, twice), from `git -c core.hooksPath=/dev/null ... fetch origin` (dispatch `inputs.go:35`, through `RunIn`) and from `git-receive-pack <origin>` under the comb's claim push.
- **Fix removes it:** same probe on `1599c2b`: the worker's plain commit spawns one process (itself); the comb fetches and the `RunIn` fetch spawn nothing; git-level traces of `fetch` under the comb env form (`GIT_CONFIG_COUNT=3`) and the `RunIn` `-c` form show `fetch`, `upload-pack` and `rev-list` only, where the no-keys fetch spawns the daemon. A planted entry survives a commit under either key alone and under both (`entries after: planted w`). The worker env has `GIT_CONFIG_COUNT=14`, keys 0 to 13 each with a value, key 12 `maintenance.auto=false`, key 13 `gc.auto=0`, no duplicate keys, no `GIT_TRACE2_EVENT` leak (the scenario sets its own).
- **Proving test:** main plus the test only: linux `-count=5` fails 10 of 10 subtests, macOS `-count=3` fails 6 of 6, each with `violations [] (planted stat after run: no such file or directory)`. Fix: linux `-race -count=20` ok (44 s), macOS `-race -count=5` ok, linux `-race -count=10` ok with four `internal/comb` `-race -count=3` runs in the background. The plant follows the result line (`okScenario` ends with `okResult`; the plant, second commit, sleep and gitdir write are appended after it). `go test -race ./...` on macOS: every package ok.
- **Timing:** the fixed tree passes at `sleep 0`, `sleep 1` and `sleep 3`, so a slow runner cannot turn a fixed run into a failure (there is no daemon to race). On the unfixed tree the sleep is what makes the failure deterministic: at `sleep 3` 6 of 6 fail, at `sleep 1` 10 of 10 (and the forager's 16 of 16), at `sleep 0` only 4 of 6, because the gitdir write sometimes lands before the daemon's prune and the duplicate-entry prune did not then remove the plant. A much slower daemon would turn an unfixed run into a false pass, never a fixed run into a false fail. Acceptable.
- **Scope precedence (both git 2.54 and 2.56):** with a repo-local `maintenance.auto=true` and `gc.auto=1` written by the worker, `git config --show-scope --get-all` lists `local true` then `command false`, the effective value is `false`, and the commit spawns no daemon. `git -c maintenance.auto=true` and `GIT_CONFIG_PARAMETERS="'maintenance.auto=true'"` list after the `GIT_CONFIG_COUNT` entry and win (`effective=true`, daemon spawned, plant gone), and `env -u GIT_CONFIG_COUNT` spawns it too. So the fix stops every accidental daemon and no deliberate one; a worker can also simply run `git maintenance run`. This is the class the push tripwire's NotEnforced line already names ("a longer pushInsteadOf from git -c ... any process that clears the GIT_CONFIG_* variables"); see N1.
- **Worker-run maintenance and the check:** (a) a planted duplicate entry whose id sorts before the run's own (`A-dup`, same gitdir) plus `git worktree prune` or `git maintenance run --task=worktree-prune`: `prune_dups` deletes `T-023-builder`, and the check reports `worktrees/T-023-builder` (entry, gitdir, commondir, config.worktree) changed, `.git worktree admin dir pin lost`, `HEAD worktree HEAD no longer names the branch`, plus the `A-dup` entry itself: exit 1, 13 violations. The deletion of the run's own entry is caught. (b) a plant that sorts after (`planted`) plus `git worktree prune`, or an early plant plus `git maintenance run --auto`: the plant is the one removed, exit 0, no violations. The check does not catch a plant the worker itself removes before the check, and I say plainly it cannot: nothing is left in host state to see. (c) a worker-run `gc`, `repack` or `pack-refs` rewrites `objects/` and `packed-refs`, neither of which `hostFiles` snapshots, and `listRefs` compares by name and OID, so a pure repack is invisible; pre-existing NotEnforced class ("a process that leaves the worker's process group"), not changed by this PR.
- **Comb `ExtraEnv` count:** `run.go:223` is the only non-test setter (`grep ExtraEnv`); `childEnv` (`internal/comb/git.go:196`) appends it after the scrubbed parent env and before the per-call entries, which are `GIT_AUTHOR_*` and `GIT_COMMITTER_*` only (`git.go:654`); `os/exec` keeps the last duplicate, so a Keeper `GIT_CONFIG_COUNT` or `GIT_CONFIG_KEY_0` in the parent env is overridden and parent keys above index 2 are ignored by the count. No duplicate keys in the literal. Not pinned by a test; see N2.
- **Other host git call sites (not through `RunIn`):** `cmd/waggle/gate.go:198` (rev-parse, merge-base, diff-tree, ls-tree, cat-file), `cmd/waggle/status.go:122` (rev-parse --show-toplevel), `internal/scaffold/git.go:28` (status, diff --no-index, rev-parse), `internal/forge/forge.go:156` (rev-parse, check-ref-format, remote get-url, merge-tree --write-tree, commit-tree, update-ref, push --porcelain), `internal/comb/git.go:226` (fetch, push, for-each-ref, cat-file, hash-object, mktree, update-ref, rev-parse). ## Notes

- **N1 (phase D, `not_enforced`, outside this lease):** the two new keys are command scope, and `git -c`, `GIT_CONFIG_PARAMETERS` and an unset or lowered `GIT_CONFIG_COUNT` beat them (proved on 2.54 and 2.56). The push tripwire line in `cell.go` `NotEnforced` already names this class for `pushInsteadOf`; one clause should say auto maintenance is in the same class, so a reader of `result.json` does not take "no detached git daemon" as a promise. A worker that wants one can also run `git maintenance run` or `git gc` by hand, and (c) above says what the check then sees.
- **N2 (builder, optional, test only):** the comb `ExtraEnv` hunk is the only product change nothing pins; reverting it fails no test. The claim fetch runs before any worktree exists, so the proving test cannot see it. If a pin is wanted, a `Run` under `t.Setenv("GIT_TRACE2_EVENT", ...)` can assert no `maintenance run` argv in the host trace (the probe does exactly that); cheap, but not required for D-181.
- **N3 (docs at most):** on a push to a local-path remote git drops `GIT_CONFIG_COUNT` and `GIT_CONFIG_PARAMETERS` for the `receive-pack` child (`local_repo_env`), so the remote repo still runs its own auto maintenance. It edits that repo, not the hive's common dir, and production remotes are GitHub. Only a Keeper with a file-path `forge.remote` sees it.
- **N4 (test fixture, minor):** `shIn` (`dispatch_test.go:27`) and `newFixture`'s own `commit` and `fetch` run without the keys, so every fixture setup still starts one detached daemon in the hive repo under test before `Run` is called. It finds no worktrees then and is harmless, but adding `-c maintenance.auto=false` to `shIn` would leave the test tree with no stray daemons at all.
- **Deviation declared by the builder:** none. The builder's count of 8 and the "comb ExtraEnv only" scope of the run.go change both hold.
