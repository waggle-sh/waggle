## Intent Summary

Adds the config side of T-012. `ParseRuntimes` reads the `runtimes:` block of `config.yaml` (binary, token limits, `levels`, `alternates`) through T-004's tree parser, and `LoadRoster` reads `min_level` per role from `roster.json` (leftover top-level `mode` ignored, `waggled` and duplicate ids rejected). `LoadPolicy` joins them into a validated `runtime.Policy`. `ClaudeAdapter.WithPolicy` makes `Materialize` write `model: <resolved>` into each `.claude/agents/waggle-<role>.md`, resolving every role before any write and failing closed. `waggle init` loads the policy before materializing and, per D-107, JSON-escapes substituted values in `.json` destinations (init and upgrade), validates `--forge`, and refuses symlinked destinations. Head Keeper commit f7c2953 adds `min_level` and the `levels` block to the two templates. Blast radius: `init` with `--runtime claude-code` now fails when the hive's config lacks `levels` or the roster lacks `min_level`; `upgrade` behaves as before apart from escaping, which leaves a gap (finding 1).

## Findings

**1. (Keeper ruling) `waggle upgrade --apply` regenerates shims without `model:` lines, and section 7.2 cannot work as written.** `upgrade.go:373` calls `Materialize` on an adapter with no policy, so after this PR merges, `upgrade --apply` on any hive rewrites its shims with the model lines removed. Guard-vs-builder model separation (AC5) then holds only for shims written by `init`; the others fall back to the session model, which is the "no silent fallback" case section 6.3 forbids. Only a Keeper who runs upgrade is exposed. Two further problems block a naive fix: `plan.execute()` runs before `Materialize`, so a policy load there fails after the managed files are already rewritten (breaking T-016's "all preconditions before any write" rule), and 7.2 puts the config `levels` edit (step 3) after `upgrade --apply` (step 2), so a policy-aware upgrade would fail inside the hive PR itself.

Options:
- (a) In this PR: about 6 lines in `upgrade.go` after `execute`. Not recommended. It pushes the phase to roughly 304, over the stop; it is outside the lease; and it fails after writing.
- (b) **Recommended: a small follow-up ticket leasing `internal/scaffold/upgrade.go`.** Build the policy from the hive's config plus the roster bytes the plan is about to write, check it in `planUpgrade` (so a missing `levels` is a plan-time `ErrRefused` before any write, visible in the dry run too), and pass the policy to `Materialize`. Add an `upgrade` test asserting `model:` lines. Merge it before the hive PR.
- (c) Reorder 7.2 so the hand edit of `config.yaml` (add `levels`) comes first, then `upgrade --apply`. This is needed once upgrade is policy-aware, and costs nothing. Caution: the hive's pinned old build rejects unknown `levels` keys (T-004 rule) until the pin moves, so the edit and the upgrade must land in the same PR with no old-binary run in between.

Do (b) plus (c), and do not run 7.2 step 2 until (b) merges. Until then, do not run `upgrade --apply` on a hive where `model:` lines matter. Brief 7.2 and its "former test 12" should be amended: as written they promise something phase B's lease could not deliver.

**2. (Keeper ruling) `init` refuses a symlinked `CLAUDE.md`, including `CLAUDE.md -> AGENTS.md`.** This is the correct safe default for the D-107 hole (a write through the link lands outside the repo or in a file the Keeper did not name), and it matches `upgrade`. It is also a behavior regression for the common layout where `CLAUDE.md` links to `AGENTS.md`; the error tells the Keeper to replace the link first. Recommend keeping the refusal in this PR and ruling on a follow-up: allow a symlink whose resolved target is a regular file inside the repo root (`filepath.EvalSymlinks`, reject if it leaves `root`), for `init` and `upgrade` together in one change so they stay consistent. Not worth the lines now. Related and trivial: the refusal text says "upgrade writes only regular files..." even when `init` is the caller. Fix the wording when the shared helper is next touched (changing it now alters `upgrade` test strings, outside this lease).

**3. `init` on an existing hive without `levels` (or a roster without `min_level`) fails after earlier writes.** Policy loading is last, after template files, hive dirs and the CLAUDE.md and .gitignore blocks. On a pre-phase-B hive the seeded `config.yaml` is skipped and has no `levels`; the run edits the marker blocks (and with `--force` rewrites managed files such as the roster), then errors with `runtimes.adapters.claude-code.levels.fast` before writing shims. Nothing is destroyed, the run is idempotent, and the error names the missing key, so after adding `levels` a rerun finishes. Acceptable for pre-release, and the check cannot move earlier for a fresh target (the config does not exist yet). The error should say what to do ("add the levels block from T-012 section 3.2, or run waggle upgrade"). `TestInitFailsWithoutLevels` covers the failure and the absence of shims but not the partial writes. Non-blocking.

**4. `LoadRoster` takes the last of duplicate keys within a role object.** `encoding/json` into `map[string]json.RawMessage` keeps the last `min_level` or `id`. Only the Keeper edits this Tier 3 file and this is stdlib behavior used throughout, so it is not exploitable. Noted, not a request.

**5. The model pattern admits a trailing `:`.** `^[A-Za-z0-9][A-Za-z0-9._:/@-]{0,127}$` accepts `opus:`. Written unquoted as `model: opus:` it is not a valid plain YAML scalar for a strict parser. It cannot inject a key (no space, no newline, no leading indicator), so this is a Keeper typo that gives a confusing frontmatter error, not a safety flaw. The brief fixes the pattern; leave it, or quote the value in the shim later.

**6. `--forge` help text still reads "Forge adapter (v0.1: 'github')"** (`cmd/waggle/main.go:26`) while `none` is also accepted. Cosmetic and outside the lease; pick it up in the next brief that leases `cmd/waggle/`.

**7. (Keeper to confirm) Size metric.** 298 is the count of added non-test Go lines, the metric used for earlier phases. A literal D-089 reading ("`wc -l` of the non-test Go files the phase touches") is far larger because `init.go` and `upgrade.go` are long files touched for a few lines. I accept 298 against the 300 stop, but it leaves no room for finding 1(a), and D-089 should be restated as "added lines" if that is the intended practice.
