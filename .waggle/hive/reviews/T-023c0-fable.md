The lease does not need to widen; see N1 for a one-line close inside `launch.go`.
2. **No SPDX headers: acceptable.** `internal/license/` does not exist on `main` (T-025 is not built), one of 114 Go files on `main` carries an SPDX line, and no `internal/runtime/` file had one. D-128 to D-130 set the policy, not a check this PR can fail. Adding headers would be out of phase scope.
3. **60 added non-test lines: verified.** `git diff --numstat origin/main...e71d298`: `launch.go` 60 added, 26 removed; `launch_test.go` 87 added, 19 removed. Under stop 130 with room for one fix round.
4. **Tripwire on git 2.39: judged sound.** `product-ci` passed on Linux (ubuntu-24.04, git 2.55.0) with `TestTripwireBlocksPush` unconditional, so the rewrite is proven on 2.54 (macOS) and 2.55 (Linux). Every mechanism used predates 2.39: `GIT_CONFIG_COUNT` (2.31), `url.<base>.pushInsteadOf` longest-prefix rewrite, and the `file://` transport, which strips the scheme and runs a local `git-receive-pack` against the path, failing with "does not appear to be a git repository" when `/dev/null/...` is not a directory. No code path touches a network or ssh. I could not run 2.39 itself.

## Notes

- N1 (recommend, one line, carry to a fix round only if one happens anyway): in `Verify`, after the help check passes, set `c.cfg.DefaultArgs = slices.Clone(c.cfg.DefaultArgs)`. This closes the caller-held-slice mutation gap without widening the lease; only package-internal code could then skip the help check.
- N2 (carry to phase C): the `pushBlocked` doc comment says the list covers "every URL scheme and path form a push could use". It does not: `git+ssh://`, `ssh+git://`, scp form without `git@` (`host:path`, `user@host:path`), upper-case schemes, and a longer `pushInsteadOf` in the Keeper's global git config all bypass it (probes above). Reword the comment to name these, add `git+ssh://` and `ssh+git://` to `pushBlocked` (zero added lines), and have phase C decide whether workers get `GIT_CONFIG_GLOBAL=/dev/null` with the author identity passed as `GIT_AUTHOR_*`/`GIT_COMMITTER_*`, which would close the global-config bypass and also stop the Keeper's global `insteadOf` rules from steering clones. The Bash deny rules and 7.2 rule 4 remain the primary controls either way; the tripwire is defense in depth.
- N3 (carry to phase C): `Verify` matches help tokens by substring, so `--debug` is satisfied by `--debug-file` alone if `--debug` were ever renamed. The failure mode is loud (Claude Code exits on an unknown flag), so this is not a widening; a word-boundary match would make the check mean what it says.
- N4 (information): a bare relative path can reach outside the worktree through a symlink the worker creates (`ln -s ../../ link; git push link/.git ...`). The brief accepts bare relative paths and 7.2 rule 4 catches the ref move; recorded so the phase C doc comment can say so.
- N5 (information): `--debug` writes Claude Code debug logs under the Keeper's `HOME`, which the worker inherits by design (section 8). D-162 approved the flag; no action.
