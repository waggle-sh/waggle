## Findings

Blocking issues: none.

Non-blocking notes:
- `backend.go` is unchanged, as the brief allows (3.1: change nothing if the tests pass). Mutation check on a scratch copy: dropping `ToLower` fails `TestRequiredMinTierCaseInsensitive`; making the hive carve-out case-insensitive fails it too (`.waggle/HIVE/tasks/a`, `.Waggle/hive/tasks/a` drop to Tier 2). The carve-out is exact case.
- The exact-ref filter in `ReadClaim` (`if r.ref != ref`) is dead against a real repo: `git for-each-ref <pattern>` already matches whole path components, so `ticket-10` never answers for `ticket-1`. Removing the filter keeps every test green, so `TestReadClaimNotFound` does not actually guard it. The filter is harmless defense in depth. Nit, no action.
- `loadClaims` buffers the whole `cat-file --batch` output and has no size cap on `lease.json`. A 64 MB padded forged claim decoded without error in 112 ms. This is shared with `ListActiveLeases` and out of this lease. Claim refs are writable only by whoever can push `refs/waggle/*`, not by a PR author, so it is not exploitable from a PR. Worth a cap (for example 64 KiB) in a later comb ticket, before phase B runs `ReadClaim` once per ticket commit in CI.
- Tier matching is a prefix test on the lowercased path, so `claude.mdx`, `.gitlab-ci.yml.bak` and `.github/workflows/x/` over-match upward. Pre-existing, only tightens.
- Not covered by any normalization (phase B should rely on Linux CI byte paths, not a macOS or Windows checkout): `.github/workflows ` (trailing space), `.github/workflows.` , zero-width characters and fullwidth lookalikes classify Tier 0 because they are different names on git and ext4. HFS+ and NTFS can alias some of them. Phase B's case-collision check (4.4) is the place to consider a stricter allowed-character rule for paths under `.github/` and `.waggle/`.
